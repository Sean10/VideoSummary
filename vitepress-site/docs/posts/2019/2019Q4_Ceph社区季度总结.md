# Ceph 社区季度进展报告：2019 Q4

---

## 一、本季度重点议题

本季度（2019年10月至12月）社区讨论高度集中在以下几个技术方向：

**1. Crimson/SeaStar OSD 新一代存储引擎**

Crimson 项目是本季度最活跃的议题，几乎每周都有专项会议。核心目标是构建一个基于 SeaStar 框架的高性能 OSD，减少传统 OSD 的线程切换和锁竞争开销。详见 [2019-10-15_-_-_Crimson_SeaStor_OSD_Weekly_Meeting](/posts/2019/2019-10-15_-_-_Crimson_SeaStor_OSD_Weekly_Meeting)) 和 [2019-11-12_-_-_Crimson_SeaStor_OSD_Weekly_Meeting](/posts/2019/2019-11-12_-_-_Crimson_SeaStor_OSD_Weekly_Meeting))。

**2. Orchestrator 框架与集群部署自动化**

Orchestrator 会议贯穿整个季度，重点讨论 SSH Orchestrator、Rook Orchestrator 的功能完善，以及与 Ceph Dashboard 的集成。详见 [2019-12-04_-_-_Ceph_Developer_Monthly](2019-12-04_-_Ceph_Developer_Monthly)。

**3. BlueStore 性能优化**

BlueStore 的min_alloc_size 调整（4K vs 16K）、PG Log 优化、RocksDB 分片等议题在性能会议中反复出现。详见 [2019-10-17_-_-_Ceph_Performance_Meeting](/posts/2019/2019-10-17_-_-_Ceph_Performance_Meeting)) 和 [2019-12_-_-_Ceph_Performance_Meeting](/posts/2019/2019-12-12_-_-_Ceph_Performance_Meeting))。

**4. Python 3迁移**

多个会议涉及从 Python 2 向 Python 3 的迁移工作，影响测试框架、Orchestrator 模块和 Dashboard 等多个组件。详见 [2019-10-16_-_-_Ceph_Orchestration_Meeting](/posts/2019/2019-10-16_-_-_Ceph_Orchestration_Meeting)) 和 [2019-11-19_-_-_Ceph_Testing_Meeting](/posts/2019/2019-11-19_-_-_Ceph_Testing_Meeting))。

**5. Octopus 版本准备**

社区开始为下一个主要版本 Octopus 做准备，包括功能规划、Rook 兼容性、OMAP 转换等。详见 [2019-11-04_-_-_Ceph_Orchestration_Meeting](/posts/2019/2019-11-04_-_-_Ceph_Orchestration_Meeting))。

---

## 二、技术亮点

### BlueStore 与存储引擎

- **4K min_alloc_size 测试**：Intel 捐赠的新测试节点上进行了大量测试，发现 4K min_alloc_size 在写入性能上有显著提升，但读取性能有所下降，需要针对 RGW 等混合工作负载进一步评估。详见 [2019-11-21_-_-_Ceph_Performance_Meeting](/posts/2019/2019-11-21_-_-_Ceph_Performance_Meeting))。
- **PG Log 优化**：通过移除 PG Log 的 OMAP 写入，观察到性能和尾部延迟的显著改善，并探索了循环缓冲区等新存储机制。详见 [2019-12-12_-_-_Ceph_Performance_Meeting](/posts/2019/2019-12-12_-_-_Ceph_Performance_Meeting))。
- **RocksDB 分片测试**：Adam 的测试结果表明，RocksDB 分片对延迟影响不大，但写放大和压缩时间有所改善。详见 [2019-10-31_-_-_Ceph_Performance_Meeting](/posts/2019/2019-10-31_-_-_Ceph_Performance_Meeting))。
- **BlueStore 小对象存储优化**：讨论将小对象数据存储在 RocksDB 中以减少空间浪费，并探讨将 RocksDB 分配粒度降低到 4KB 的可行性。详见 [2019-10-02_-_-_Ceph_Developer_Monthly](/posts/2019/2019-10-02_-_-_Ceph_Developer_Monthly))。
- **I/O Uring 引擎**：引入 I/O Uring 作为实验性功能，测试结果表明性能表现良好，但需要新内核支持。详见 [2019-10-17_-_-_Ceph_Performance_Meeting](/posts/2019/2019-10-17_-_-_Ceph_Performance_Meeting))。

### Crimson OSD

- **性能基准**：多客户端高并发场景下，Crimson 在特定配置（TP Strata 端口数为 2）时性能优于传统 OSD。详见 [2019-10-15_-_-_Crimson_SeaStor_OSD_Weekly_Meeting](/posts/2019/2019-10-15_-_-_Crimson_SeaStor_OSD_Weekly_Meeting))。
- **对象上下文（Object Context）**：实现了 intrusive LRU 和 snap context，推进了对象状态管理的完善。
- **BlueStore 移植**：开始将 BlueStore 移植到 Crimson 存储引擎，同时使用内存储进行原型设计。详见 [2019-11-06_-_-_Ceph_Developer_Monthly](/posts/2019/2019-11-06_-_-_Ceph_Developer_Monthly))。
- **Native Stack评估**：讨论了 DPDK/Native Stack 与POSIX Stack 的取舍，暂定以 POSIX Stack 为主，但持续进行性能对比测试。详见 [2019-11-12_-_-_Crimson_SeaStor_OSD_Weekly_Meeting](/posts/2019/2019-11-12_-_-_Crimson_SeaStor_OSD_Weekly_Meeting))。
- **新 BlueStore 设计文档**：讨论了类似日志结构文件系统（Log-Structured）的新数据布局方案，旨在减少写放大，类似 ButerFS 设计理念。详见 [2019-12-10_-_-_Crimson_SeaStor_OSD_Weekly_Meeting](/posts/2019/2019-12-10_-_-_Crimson_SeaStor_OSD_Weekly_Meeting))。

### Orchestrator 与部署

- **SSH Orchestrator**：本季度取得重大进展，实现了 bug 修复、权限处理、安装模式改进，并新增主机标签功能和简单调度算法。详见 [2019-11-25_-_-_Ceph_Orchestration_Meeting](2019-11-25_-_Ceph_Orchestration_Meeting)。
- **Drive Group预览功能**：新增在 Dashboard 和 Orchestrator 中预览 Drive Group 的功能。详见 [2019-10-23_-_-_CephOrchestration_Meeting](/posts/2019/2019-10-23_-_-_Ceph_Orchestration_Meeting))。
- **监控系统集成**：讨论了通过 Orchestrator 管理 Prometheus 和 Grafana 的部署，实现监控组件的统一管理。详见 [2019-12-04_-_-_Ceph_Developer_Monthly](2019-12-04_-_Ceph_Developer_Monthly)。
- **并行 SSH 优化**：针对 Orchestrator 单线程池性能瓶颈，探讨使用 parallel SSH（psh）工具并行处理多主机操作。详见 [2019-11-27_-_-_Ceph_Orchestration_Meeting](2019-11-27_-_Ceph_Orchestration_Meeting)。

### RGW

- **动态分片（Dynamic Sharding）**：Eric 提交了关于 RGW 动态分片数量的 PR，并将额外的过滤功能移动到 CLS 代码中，减少发送给 RGW 的数据量。详见 [2019-10_-_-_Ceph_Performance_Meeting](/posts/2019/2019-10-10_-_-_Ceph_Performance_Meeting))。
- **多站点 RGW 设计**：讨论了多站点 RGW 的设计进展，对未来对象存储 CR 有重要影响。详见 [2019-12-16_-_-_CephOrchestration_Meeting](/posts/2019/2019-12-16_-_-_Ceph_Orchestration_Meeting))。

### CephFS

- **Ephemeral Pining（瞬时挂载）**：使用一致哈希算法实现元数据的随机分布式分区，优化 MDS 元数据分布。详见 [2019-11-06_-_-_Ceph_Developer_Monthly](/posts/2019/2019-11-06_-_-_Ceph_Developer_Monthly))。
- **MDS 缓存内存限制**：通过优先级缓存管理器为 MDS 缓存设置内存限制，并更新了 CPU亲和性设置。

### 持久内存（Persistent Memory）

- 讨论了利用持久内存 API 优化 PG 日志存储和恢复过程的可能性，并计划组建工作组进行深入研究。详见 [2019-12-05_-_-_Ceph_Performance_Meeting](/posts/2019/2019-12-05_-_-_Ceph_Performance_Meeting))。

### 去重（Deduplication）

- DeeDup 项目完成了大部分基础设施和基本功能，进入完善和测试阶段，通过内容地址存储和引用计数实现重复数据删除。详见 [2019-11-06_-_-_Ceph_Developer_Monthly](/posts/2019/2019-11-06_-_-_Ceph_Developer_Monthly))。

## 三、重要决策与里程碑

### 版本发布

- **Nautilus 维护版本**：本季度持续推进 Nautilus 的 bug 修复和维护，包括修复 BlueStore 数据损坏回归问题、GCC 分段错误等。详见 [2019-11-12_-_-_Ceph_Testing_Meeting](/posts/2019/2019-11-12_-_-_Ceph_Testing_Meeting))。
- **Rook 1.1.3 发布**：修复了 OSD 配置覆盖未正确应用和升级过程中 OSD pod 同步问题。详见 [2019-10-21_-_-_Ceph_Orchestration_Meeting](2019-10-21_-_Ceph_Orchestration_Meeting)。
- **Rook 1.2 版本**：12月完成发布，重要变更包括不再自动删除 OSD（改为用户手动操作，以避免数据丢失）。详见 [2019-12-16_-_-_Ceph_Orchestration_Meeting](2019-12-16_-_Ceph_Orchestration_Meeting)。

### 重大设计决定

- **DepSea Orchestrator 停止开发**：社区决定停止 DeepSea Orchestrator 的开发工作，将资源集中到 Cephadm（SSH Orchestrator）和 Rook 两个 Orchestrator。详见 [2019-11_-_-_Ceph_Orchestration_Meeting](2019-11-11_-_Ceph_Orchestration_Meeting)。
- **PG Autoscaler 默认值调整**：将最小默认 PG 数量从 4 增加到 16，以提升并行性和可扩展性。详见 [2019-11_-_-_Crimson_SeaStor_OSD_Weekly_Meeting](/posts/2019/2019-11-11_-_-_Crimson_SeaStor_OSD_Weekly_Meeting))。
- **RocksDB 范围删除（Delete Range）禁用**：发现范围删除可能与 RocksDB 损坏问题相关，决定在 Nautilus 版本中禁用。详见 [2019-11-07_-_-_Ceph_Performance_Meeting](/posts/2019/2019-11-07_-_-_Ceph_Performance_Meeting))。
- **OMAP 转换策略**：升级到 Octopus 时不自动转换 OMAP，改为通过文档告知用户，未来考虑自动化处理。详见 [2019-12-09_-_-_Ceph_Orchestration_Meeting](2019-12-09_-_Ceph_Orchestration_Meeting)。
- **客户端自动恢复功能**：Ceph 15.2 引入客户端在黑名单（blacklist）后自动恢复连接的功能，支持 no 和 clean 两种模式。详见 [2019-10-02_-_-_Ceph_Developer_Monthly](/posts/2019/2019-10-02_-_-_Ceph_Developer_Monthly))。
- **崩溃报告收集**：Ceph 开始收集崩溃报告并发送到上游实验室，包含堆栈跟踪、版本信息和崩溃签名，用于优先处理高频问题。详见 [2019-11-06_-_-_Ceph_Developer_Monthly](2019-11-06_-_Ceph_Developer_Monthly)。

## 四、社区动态

### 会议与活动

- **Ceph Tech Talk：NASA 大气科学中的 Ceph 应用**（2019年10月24日）：NASA 团队分享了使用 Ceph 处理卫星数据的实践经验，每年产生约 10PB 数据，使用 RADOS、RGW、S3 和 FusedFS，并计划迁移到 BlueStore 后端。详见 [2019-Oct-24_-_-_Ceph_Tech_Talk_-_Ceph_at_Nasa](/posts/2019/2019-Oct-24_-_-_Ceph_Tech_Talk_-_Ceph_at_Nasa))。
- **Ceph Science User Group 会议**（2019年10月23日）：科学用户分享了 Nautilus 升级经验、大规模集群运维实践，以及 CephFS 与 HPC 集群集成的讨论。详见 [2019-10-23_-_-_Ceph_Science_User_Group_Meeting](/posts/2019/2019-10-23_-_-_Ceph_Science_User_Group_Meeting))。
- **CERN CEPhta 项目**：CERN 的 Ceph 相关项目取得显著成果，在 Science User Group 会议中获得认可。
- **布宜诺斯艾利斯 TrueIT 演讲**：Charlotte 在布宜诺斯艾利斯参加了关于如何为 TrueIT 项目贡献的西班牙语演讲。详见 [2019-10-07_-_-_Ceph_Orchestration_Meeting](2019-10-07_-_Ceph_Orchestration_Meeting)。
- **KubeCon 2019**：部分社区成员参加了 KubeCon，影响了 11 月下旬的会议出席情况。详见 [2019-11-25_-_-_Ceph_Orchestration_Meeting](2019-11-25_-_Ceph_Orchestration_Meeting)。

### 基础设施改进

- **Intel 测试节点捐赠**：Intel 捐赠了新的测试节点，用于性能测试，在单 OSD 测试中发现性能显著提升。详见 [2019-10_-_-_Ceph_Performance_Meeting](/posts/2019/2019-10-10_-_-_Ceph_Performance_Meeting))。
- **Jenkins 升级**：升级了 Jenkins 版本并更新插件，解决了 CPU 使用率过高问题，并清理了磁盘空间。详见 [2019-10-07_-_-_CephOrchestration_Meeting](/posts/2019/2019-10-07_-_-_Ceph_Orchestration_Meeting))。
- **CI 测试改进**：讨论了将测试自动化作为默认设置，在每次 PR 提交时自动运行测试。详见 [2019-10-14_-_-_CephOrchestration_Meeting](/posts/2019/2019-10-14_-_-_Ceph_Orchestration_Meeting))。

### 文档工作

- **DocUBetter 会议**：新成员 Zach Dover 加入文档团队，负责编写入门指南（Getting Started Guide）和更新硬件推荐文档。详见 [2019-11-13_-_-_Ceph_DocUBetter_Meeting](/posts/2019/2019-11-13_-_-_Ceph_DocUBetter_Meeting))。
- **硬件推荐文档更新**：更新了 OSD 内存推荐（基于 BlueStore 实际情况调整了 1GB/TB 的旧建议），并讨论了 Sphinx 模板更新和网站迁移到静态站点生成器的计划。详见 [2019-12-11_-_-_Ceph_DocUBetter_Meeting](2019-12-11_-_Ceph_DocUBetter_Meeting)。

### 人员动态

- Crimson 项目新成员 Alan（来自以色列 Ra'anana 办公室）加入，带来了文件系统设计方面的专业背景。
- Joshua Hesketh 加入存储团队，开始学习 Orchestrator 组件。
- Tim 宣布将离开 Orchestrator 项目三个月（11 月底结束工作）。
- 会议时间进行了调整，使用 Doodle 工具投票，以适应不同时区成员的参与需求。

## 五、下季度展望

基于本季度的讨论内容，预计 2020 Q1 将重点推进以下方向：

1. **Octopus 版本冲刺**：Octopus 是下一个主要版本，社区已开始规划功能列表，Rook 团队也在确保与 Octopus 的兼容性。预计 Q1 将进入功能冻结阶段。

2. **Cephadm（SSH Orchestrator）成熟化**：随着 DepSea 停止开发，SSH Orchestrator（后更名为 Cephadm）将成为官方推荐的裸机部署工具，预计 Q1 将完善声明式配置、升级流程和监控集成。

3. **Crimson OSD 功能完整性**：BlueStore 移植、快照支持、对象读写锁定等核心功能将在 Q1 继续推进，并进行更系统的性能基准测试。

4. **持久内存（Persistent Memory）集成**：工作组将获取测试硬件，开始实验性地将持久内存用于 PG 日志优化。

5. **Python 3 全面迁移**：Python 3 迁移工作将在 Q1 完成，覆盖 Nautilus、Mimic 和 Luminous 的向后移植。

6. **BlueStore 4K min_alloc_size 决策**：基于本季度的测试数据，Q1 将对是否将 4K 设为默认值做出最终决定，重点评估对 RGW 混合工作负载的影响。

7. **去重（Deduplication）用户测试**：Dee Dup 项目将进入用户测试阶段，收集实际使用反馈。
