# Ceph 社区季度进展报告 · 2019 Q3

**报告周期**：2019年7月 — 2019年9月

---

## 一、本季度重点议题

本季度 Ceph 社区围绕以下几个方向持续深入讨论：

**1. Crimson/SeaStar OSD 的工程化推进**

Crimson 作为下一代 OSD 实现，本季度几乎每周都有专项会议（[2019-07-02](2019-07-02_-_Crimson_SeaStor_OSD_Weekly_Meeting)、[2019-07-09](2019-07-09_-_Crimson_SeaStor_OSD_Weekly_Meeting)、[2019-07-16](/posts/2019/2019-07-16_-_-_Crimson_SeaStor_OSD_Weekly_Meeting)) 等），涵盖 BlueStore 集成、RocksDB 移植、错误处理、性能测试基础设施、UNIX 域套接字支持、Protocol v2 等多个子方向，是本季度技术投入最密集的领域。

**2. Orchestrator 框架与多后端集成**

Orchestrator 会议贯穿整个季度（[2019-07-01](/posts/2019/2019-07-01_-_-_Ceph_Orchestration_Meeting))、[2019-07-08](/posts/2019/2019-07-08_-_-_Ceph_Orchestration_Meeting))、[2019-07-15](/posts/2019/2019-07-15_-_-_Ceph_Orchestration_Meeting)) 等），重点讨论 Drive Groups设计、Rook 与 SSH Orchestrator 的兼容性、Dashboard 集成、OSD 替换流程、Completion 可组合性等，是本季度架构演进的核心议题。

**3. BlueStore 与 RocksDB 性能优化**

性能会议（[2019-07-18](/posts/2019/2019-07-18_-_-_Ceph_Performance_Meeting))、[2019-07-25](/posts/2019/2019-07-25_-_-_Ceph_Performance_Meeting))、[2019-08-01](2019-08-01_-_Ceph_Performance_Meeting) 等）持续关注 BlueStore 的 alloc size 调整、RocksDB 版本升级与 delete range 功能、OpTracker 性能开销、QoS 实现等，多个 PR 在本季度合并或进入测试阶段。

**4. Rook 1.1 发布与 CI体系建设**

Rook 1.1 的特性冻结、发布、以及后续 1.1.1/1.1.2 补丁版本贯穿本季度后半段，同时社区开始认真讨论 Rook CI 的长期自动化方案（[2019-09-25](/posts/2019/2019-09-25_-_-_Ceph_Testing_Meeting))）。

**5. 文档质量改进（DocUBetter）**

文档专项会议（[2019-07-10](/posts/2019/2019-07-10_-_-_Ceph_DocUBetter_meeting))、[2019-07-24](/posts/2019/2019-07-24_-_-_Ceph_DocUBetter_Meeting))、[2019-08-14](/posts/2019/2019-08-14_-_-_Ceph_DocUBetter_Meeting))、[2019-08-28](/posts/2019/2019-08-28_-_-_Ceph_DocUBetter_Meeting))、[2019-09-11](/posts/2019/2019-09-11_-_-_Ceph_DocUBetter_Meeting))）持续推进，涉及 CephFS 文档重组、签核流程优化、上游文档岗位招聘等。

## 二、技术亮点

### 2.1 Crimson OSD

- **BlueStore 集成路径确定**：[2019-07-23](/posts/2019/2019-07-23_-_-_Crimson_SeaStor_OSD_Weekly_Meeting)) 会议系统讨论了将 BlueStore 移植到 Crimson/SeaStar 环境的多种方案（代码修改、进程分离、命名空间隔离等），并评估了各方案的可行性。
- **RocksDB 移植**：同步推进 RocksDB 在 Crimson 环境下的适配，解决宏定义冲突问题，采用命名空间方案区分代码分支。
- **UNIX 域套接字支持**：[2019-08-06](/posts/2019/2019-08-06_-_-_Crimson_SeaStor_OSD_Weekly_Meeting))、[2019-08-20](/posts/2019/2019-08-20_-_-_Crimson_SeaStor_OSD_Weekly_Meeting)) 等会议持续推进 UNIX domain socket 的实现，并计划合并回主线。
- **Protocol v2 清理**：[2019-07-09](/posts/2019/2019-07-09_-_-_Crimson_SeaStor_OSD_Weekly_Meeting)) 讨论了 Crimson 消息传递 bug 修复、协议 v2 日志清理及握手流程理解，并提出开发 Wireshark 插件的需求。
- **对象类（Object Class）支持**：[2019-07-30](/posts/2019/2019-07-30_-_-_Crimson_SeaStor_OSD_Weekly_Meeting))、[2019-08-06](/posts/2019/2019-08-06_-_-_Crimson_SeaStor_OSD_Weekly_Meeting)) 讨论了在 Crimson 中实现 object class DPI 及安全类的方案。
- **性能测试基础设施**：[2019-08-13](/posts/2019/2019-08-13_-_-_Crimson_SeaStor_OSD_Weekly_Meeting))、[2019-09-03](/posts/2019/2019-09-03_-_-_Crimson_SeaStor_OSD_Weekly_Meeting)) 推进将 CBT 性能测试集成到 Jenkins，并探索通过 GitHub API 在 PR 页面展示测试结果差异。

### 2.2 BlueStore 与存储引擎

- **Alloc size 统一**：[2019-08-01](/posts/2019/2019-08-01_-_-_Ceph_Performance_Meeting)) 讨论了将 BlueFS 与 BlueStore 的 alloc size 统一设置为 16K 的 RFC，以解决碎片化差异问题，作为高优先级任务推进测试。
- **随机小写性能提升**：[2019-08-01](/posts/2019/2019-08-01_-_-_Ceph_Performance_Meeting)) 提到某 PR 通过测试，为 BlueStore 带来 25-30% 的随机小写性能提升。
- **QoS 功能**：[2019-08-15](/posts/2019/2019-08-15_-_-_Ceph_Performance_Meeting)) 讨论了 BlueStore QoS 的实现方案，通过节流值控制不同用户的 I/O 请求，并分析了 NVMe 并发性对性能的显著影响。
- **RocksDB 升级**：[2019-07-25](/posts/2019/2019-07-25_-_-_Ceph_Performance_Meeting))、[2019-08-01](/posts/2019/2019-08-01_-_-_Ceph_Performance_Meeting)) 讨论了 RocksDB 版本选择（5.17.2 用于 Nautilus，6.1.2 合并至 master），以及 delete range 功能回溯到 Nautilus 的可行性。
- **OpTracker 优化**：[2019-07-18](/posts/2019/2019-07-18_-_-_Ceph_Performance_Meeting)) 讨论了 OpTracker 对随机写入的性能影响，提出采样优化和字符串复制修复方案，避免完全重写。

### 2.3 RGW

- **数据副本删除**：[2019-07-25](/posts/2019/2019-07-25_-_-_Ceph_Performance_Meeting)) 讨论了 RGW 中删除数据副本的功能实现，并评估回溯到 Nautilus 的可能性。
- **目录条目过滤与 OMAP 缓存**：[2019-08-29](/posts/2019/2019-08-29_-_-_Ceph_Performance_Meeting)) 讨论了通过优化目录条目过滤、引入 OMAP 缓存减少重复数据访问，以及优化 JSON 格式输出来提升 RGW 性能。
- **CLS 过滤功能**：[2019-09-12](/posts/2019/2019-09-12_-_-_Ceph_Performance_Meeting)) 讨论了在 OSD 的 CLS 代码中实现过滤功能，评估其对性能提升和网络流量减少的影响。
- **Bucket Resharding 优化**：[2019-09-12](/posts/2019/2019-09-12_-_-_Ceph_Performance_Meeting)) 讨论了 resharding 过程中允许客户端写入和优化锁定机制的方案。
- **RBD 镜像简化**：[2019-09-04](/posts/2019/2019-09-04_-_-_Ceph_Developer_Monthly)) 讨论了通过 base64 编码 JSON 文件简化集群镜像配置的方案，支持单向和双向镜像，降低 Rook 集群镜像的配置复杂度。

### 2.4 Orchestrator 框架

- **Completion 可组合性**：[2019-09-11](/posts/2019/2019-09-11_-_-_Ceph_Orchestration_Meeting))、[2019-09-16](/posts/2019/2019-09-16_-_-_Ceph_Orchestration_Meeting)) 讨论了 PR 3026，使 completions 可组合，引入 Progress Reference 机制，对 Dashboard 和 Orchestrator 的并发操作控制至关重要。
- **Drive Groups 设计**：[2019-07-01](/posts/2019/2019-07-01_-_-_Ceph_Orchestration_Meeting))、[2019-07-15](/posts/2019/2019-07-15_-_-_Ceph_Orchestration_Meeting))、[2019-09-02](/posts/2019/2019-09-02_-_-_Ceph_Orchestration_Meeting)) 持续讨论 Drive Groups 的持久化存储、与 Ceph Volume 的集成，以及其在 OSD 替换流程中的作用，最终认为当前规范复杂度偏高，需要 UI 层反馈。
- **OSD 替换流程**：[2019-08-19](/posts/2019/2019-08-19_-_-_Ceph_Orchestration_Meeting))、[2019-09-02](2019-09-02_-_Ceph_Orchestration_Meeting) 讨论了通过 Orchestrator API 实现 OSD 替换（销毁旧 OSD + 创建新 OSD 的组合操作）的设计。
- **Dashboard 集成**：[2019-07-08](/posts/2019/2019-07-08_-_-_Ceph_Orchestration_Meeting))、[2019-09-23](/posts/2019/2019-09-23_-_-_Ceph_Orchestration_Meeting)) 推进将 Orchestrator 界面集成到 Dashboard，包括主机列表、设备库存展示、Drive Group 创建等功能。
- **OSD 权重渐进添加**：[2019-09-23](/posts/2019/2019-09-23_-_-_Ceph_Orchestration_Meeting)) 讨论了新添加 OSD 时将初始权重设为 0，由 balancer 逐步映射到 CRUSH map，避免大量数据迁移流量。

### 2.5 CephFS

- **文档重组**：[2019-09-11](/posts/2019/2019-09-11_-_-_Ceph_DocUBetter_Meeting)) 讨论了 CephFS 文档的系统性改进，包括架构图、高级概念（分布式元数据缓存、MDS 日志、元数据池）、客户端直接访问数据池、Rados 命名空间使用等方面的文档补充。

### 2.6 监控与可观测性

- **慢速连接检测**：[July_2019](/posts/2019/July_2019_-_-_Ceph_Developer_Monthly)) 讨论了检测慢速网络连接的工具，支持设置警告级别和不同时间间隔的平均 ping 时间。
- **健康警报静音**：同次会议讨论了"静音"功能，支持按模式匹配处理 OSD 失败、性能下降等健康警报。
- **IO_uring 探索**：[2019-07-02](/posts/2019/2019-07-02_-_-_Crimson_SeaStor_OSD_Weekly_Meeting)) 提及了使用 IO_uring 优化 CephFS 在内核网络栈中性能的可性。

## 三、重要决策与里程碑

### 版本发布

- **Ceph 14.2.x（Nautilus）持续维护**：本季度多次提及 14.2.2、14.2.4 版本的修复，包括 NFS 打包问题修复（[2019-07-22](/posts/2019/2019-07-22_-_-_Ceph_Orchestration_Meeting))）。
- **Rook 1.1 发布**：[2019-07-15](/posts/2019/2019-07-15_-_-_Ceph_Orchestration_Meeting)) 确定 Rook 1.1 目标在 8月中旬完成特性开发、8 月底发布，最低支持 Ceph Mimic 13.4。[2019-08-19](/posts/2019/2019-08-19_-_-_Ceph_Orchestration_Meeting)) 确认特性冻结在 8 月底进行。
- **Rook 1.1.1 发布**：[2019-09-23](/posts/2019/2019-09-23_-_-_Ceph_Orchestration_Meeting)) 确认 Rook 1.1 已发布，包含大量修复和稳定性改进，并规划 1.1.2 补丁版本。

### 重大设计决定

- **Python 代码统一**：[2019-07-01](/posts/2019/2019-07-01_-_-_Ceph_Orchestration_Meeting)) 提出将 Ceph 中分散的 Python 代码统一到一个公共包（`ceph-common`），以减少重复并提高代码质量，获得社区积极响应。
- **API 生成机制**：确定 API 发生变化时触发重新生成，由 API 变更者负责重建文件并提交新生成的 API 方法。
- **Orchestrator 队列安全清除**：[2019-07-29](/posts/2019/2019-07-29_-_-_Ceph_Orchestration_Meeting)) 讨论了添加安全 Orchestrator 文本层以便在不重启 Manager 的情况下清除挂起任务的方案。
- **PG 自动缩放器默认启用**：[2019-07-29](/posts/2019/2019-07-29_-_-_Ceph_Orchestration_Meeting)) 讨论了是否将 PG autoscaler 设置为默认启用。
- **OSD 资源限制**：[2019-09-30](/posts/2019/2019-09-30_-_-_Ceph_Orchestration_Meeting)) 讨论了为 OSD 设置默认资源限制，防止升级过程中 OSD 使用全部内存导致崩溃。
- **小对象 OMAP 存储**：[2019-09-12](/posts/2019/2019-09-12_-_-_Ceph_Performance_Meeting)) 讨论了在 OMAP 中使用 4K 块大小存储小对象（< 4K）的改进方案，评估其对性能和空间利用率的影响。

### 贡献者活动

- **文档岗位招聘**：[2019-08-14](/posts/2019/2019-08-14_-_-_Ceph_DocUBetter_Meeting)) 讨论了上游文档职位的开放，要求具备基本技术文档编写经验，通过 SEF 邮箱接收申请。
- **实习生贡献**：[2019-07-24](/posts/2019/2019-07-24_-_-_Ceph_DocUBetter_Meeting)) 中来自 Truman 大学的实习生 Gabriela 参与审阅入门文档，发现并修复了多处问题。
- **签核流程讨论**：[2019-07-24](/posts/2019/2019-07-24_-_-_Ceph_DocUBetter_Meeting))、[2019-08-14](/posts/2019/2019-08-14_-_-_Ceph_DocUBetter_Meeting)) 讨论了是否放宽 DCO 签核要求以降低新贡献者门槛，并计划制作视频教程。

- **Rook 与 Ceph 上游协作**：本季度 Rook 团队与 Ceph Orchestrator 团队深度协作，推进 Rook 模块的上游维护、CRD 验证、事件报告等功能（[2019-08-05](/posts/2019/2019-08-05_-_-_Ceph_Orchestration_Meeting))、[2019-08-12](/posts/2019/2019-08-12_-_-_Ceph_Orchestration_Meeting))）。

## 五、下季度展望

基于本季度的讨论内容，预计 2019 Q4 将重点推进以下方向：

1. **Crimson OSD 功能完善**：BlueStore 与 Crimson 的集成方案将进入实质性实现阶段，性能测试基础设施（Jenkins + GitHub API）将趋于完善，复制副本（replica）支持将进入测试验证。

2. **Orchestrator 框架成熟**：Drive Groups 设计将在获取 UI 层反馈后进一步明确，Completion 可组合性（PR 3026）合并后将推动 Dashboard OSD 管理功能的完整实现，SSH Orchestrator 将作为 Rook 的替代部署方案得到更多关注。

3. **Rook CI 自动化**：[2019-09-25](/posts/2019/2019-09-25_-_-_Ceph_Testing_Meeting)) 已启动 Rook CI 专项讨论，预计 Q4 将形成基于 Teuthology 或类似框架的自动化测试方案，并与上游 CI 整合。

4. **RGW 性能持续优化**：Bucket resharding 锁优化、CLS 过滤功能、OMAP 小对象存储改进等多个 PR 将在 Q4 进入合并或回溯阶段。

5. **BlueStore QoS 落地**：QoS 功能的跟踪点集成和实验证将在 Q4 推进，为多租户场景提供 I/O 隔离能力。

6. **CephFS 文档与功能**：CephFS 文档重组工作将持续推进，分布式元数据缓存、MDS 日志等高级概念的文档将逐步完善。

7. **Octopus 版本规划**：随着 Nautilus 维护趋于稳定，社区将开始更多讨论下一个主要版本（Octopus）的特性规划，Crimson、新 Orchestrator 框架等将是重要候选特性。
