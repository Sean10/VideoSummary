# Ceph 2017 年社区年度进展报告

---

## 一、全年技术演进概述

2017 年是 Ceph 项目技术架构发生重大转变的一年。全年的技术主线围绕三个核心方向展开：**BlueStore 存储后端的成熟与 GA**、**Ceph Manager 的引入**，以及**面向下一代硬件（NVMe、ARM）的性能重构**。

从年初的密集性能优化，到年中 Luminous 版本的发布，再到年底对未来架构（DPDK/SPDK、C++ 协程、Crimson）的前瞻性讨论，2017 年完成了从"让 BlueStore 可用"到"让 Ceph 面向未来"的跨越。

---

## 二、重大里程碑

### Luminous 版本发布

2017 年最重要的里程碑是 **Luminous（v12）** 版本的发布。根据 [2017-AUG-02 开发者月度会议](/posts/2017/2017-AUG-02_-_-_Ceph_Developer_Monthly)) 的记录，Luminous 在发布前进行了大量最终 bug 修复，并带来了以下重要特性 GA：

- **BlueStore** 成为默认存储后端，取代 FileStore
- **Ceph Manager（ceph-mgr）** 正式引入，承担分析 API 和管理功能，使 Monitor 专注于关键集群状态
- 新的 **Web Dashboard**，提供集群监控和管理界面
- **应用程序标签（Application Tags）** 功能，允许对存储池打标签
- **平衡器模块（Balancer Module）**，支持数据均衡操作
- **速率限制（Rate Limiting）** 功能
- **跨集群复制** 和 **共享读取缓存** 功能
- 与 **Prometheus** 的集成

[2017-JUN-07 开发者月度会议](/posts/2017/2017-JUN-07_-_-_Ceph_Developer_Monthly)) 中还讨论了 Luminous 前的最后准备工作，包括存储池标签元数据设计和 OSD 部署工具（ceph-volume/LVM 方向）的简化。

---

## 三、核心组件年度进展

### 3.1 BlueStore

BlueStore 是 2017 年投入最多的组件，贯穿全年的性能周会。主要进展包括：

**存储引擎优化**
- 全年持续优化 RocksDB 配置，包括 column families、WAL 设置、compaction read-ahead 等，详见 [2017-MAY-04 性能周会](/posts/2017/2017-MAY-04_-_-_Ceph_Performance_Weekly)) 和 [2017-MAR-08 性能周会](2017-MAR-08_-_Ceph_Performance_Weekly)
- Bitmap 分配器优化，减少锁争用和内存占用
- 延迟写入（deferred write）路径优化，实现灵活批处理策略
- BlueStore 启动速度优化，减少初始化时间

**缓存管理**
- 新增多个缓存池用于 BlueStore，提高数据可见性
- 调整 BlueStore Cache 与 RocksDB Cache 的协同配置，详见 [2017-JUN-08 性能周会](2017-JUN-08_-_Ceph_Performance_Weekly)
- 自适应限流（adaptive throttle）机制，基于目标延迟动态调整

**性能成果**
- 相比 FileStore，大型对象写入性能提升约 2倍（[2017-FEB-22 性能周会](2017-FEB-22_-_Ceph_Performance_Weekly)）
- 小随机写入性能比 FileStore 快约 20-25%
- Luminous 版本整体性能表现良好

### 3.2 RADOS / OSD

- **PG 重映射（PG Remapping）** 功能实现，允许在 PG 已映射后重新映射以优化数据分布，详见 [2017-MAR-22 性能周会](2017-MAR-22_-_Ceph_Performance_Weekly)
- **Fast Dispatch** 优化合并，减少 OSD 消息处理延迟
- **PG 日志优化**：[2017-NOV-01 开发者月度会议](2017-NOV-01_-_Ceph_Developer_Monthly) 讨论了在 SD 上使用环形缓冲区存储 PG 日志、FIFO 压缩模式，以减少写放大
- **快照修剪（Snapshot Trimming）** 优化，使用增量数据结构提高效率
- **去重（Deduplication）** 方案讨论，提出使用对象映射和内容地址存储池

### 3.3 RGW（RADOS Gateway）

- 全年持续进行 RGW 性能测试，NVMe 环境下网络成为瓶颈
- **跨集群复制（Cross-cluster Replication）** 功能进入 Luminous
- **云同步（Cloud Sync）** 功能开发，详见 [2017-DEC-06 开发者月度会议](2017-DEC-06_-_Ceph_Developer_Monthly)
- 大数据分析集成方向：[2017-FEB-23 Tech Talk](2017-FEB-23_--Ceph_Tech_Talks_-_Big_Data_Analytics) 展示了通过 Luxio 加速 Spark 访问 Swift/RGW 存储，性能提升超 30 倍

### 3.4 RBD（RADOS Block Device）

- **BD 持久缓存（Persistent Cache）** 框架开发，[2017-JUN-07 开发者月度会议](/posts/2017/2017-JUN-07_-_-_Ceph_Developer_Monthly)) 讨论了基于日志存储的缓存架构
- 写回节流（writeback throttle）设置优化，平衡吞吐量与读延迟
- **Commit Majority** 功能（阿里巴巴团队贡献），提高平均延迟和延迟抖动表现，详见 [2017-MAY-11 性能周会](2017-MAY-11_-_Ceph_Performance_Weekly)
- 异步恢复（async recovery）机制优化

### 3.5 CephFS

- 全年 CephFS 相关讨论相对较少，主要集中在稳定性和 MDS 内存管理优化
- 跨数据中心复制的全局顺序维护方案讨论，详见 [2017-SEP-06 开发者月度会议](/posts/2017/2017-SEP-06_-_-_Ceph_Developer_Monthly))

### 3.6 Ceph Manager 与 Dashboard

Luminous 引入的 ceph-mgr 是 2017 年架构层面最重要的新增组件：

- [2017-APR-12 开发者月度会议](/posts/2017/2017-APR-12_-_-_Ceph_Developer_Monthly)) 讨论了为 Manager 添加 REST API（作为实验性功能）
- 配置选项注释系统（config option annotations）设计，支持文档自动生成
- 新 Web Dashboard 提供集群状态可视化
- 服务映射（Service Map）功能，支持从命令行或模块访问服务信息

### 3.7 网络层（Messenger）

- **Async Messenger** 成为默认消息传递后端，全年持续优化锁争用问题
- **RDMA 异步消息传递** 开发推进，[2017-FEB-22 性能周会](2017-FEB-22_-_Ceph_Performance_Weekly) 记录了性能计数器和零拷贝代码的添加
- 零拷贝（zero-copy）优化工作持续推进

## 四、社区生态

### 平台与部署工具

- **Ceph on ARM** 专题 Tech Talk（[2017-MAY-25 Tech Talk](/posts/2017/2017-MAY-25_--_Ceph_Tech_Talk_-_Ceph_on_ARM))）汇聚了 Red Hat、Cavium、SUSE、Deutsche Telekom、ARM 等多家公司，讨论 ARM64 平台的 CI/CD 建设和二进制发布
- **Juju/Charm** 部署工具（Canonical）展示了跨平台自动化部署能力，详见 [2017-MAR-23 Tech Talk](2017-MAR-23_--_Ceph_Tech_Talks_-_Ceph_at_Scale_Writing_Applicationswith_Language_Bindings)
- **Ceph Rust绑定** 开发，为新语言生态提供支持

### 开发者社区

- [2017-JAN-26 Tech Talk](2017-JAN-26_--_Ceph_Tech_Talk_-_Getting_Started_with_CephDevelopment) 专门面向新贡献者，介绍开发流程、构建环境和 PR 提交规范，体现社区对降低贡献门槛的重视
- 阿里巴巴团队深度参与性能优化，贡献了 Commit Majority、OST 性能优化等多项工作
- Nokia 团队持续参与 BlueStore 测试，提供云 DVR 场景的真实负载反馈
- CERN 部署了 200节点临时集群用于新代码测试

### 性能周会制度

全年坚持每周性能会议（Ceph Performance Weekly），形成了高效的性能问题跟踪和 PR 审查机制，是 2017 年 BlueStore 快速成熟的重要保障。

---

## 五、下一年展望

基于 [2017-DEC-06 开发者月度会议](/posts/2017/2017-DEC-06_-_-_Ceph_Developer_Monthly)) 的路线图讨论，2018 年的技术方向已经清晰：

### 性能重构（Crimson/SeaStore 前身）

- 采用 **DPDK** 和 **SPDK** 进行网络和存储 IO，绕过内核栈
- 对 OSD 进行大规模重构，使其更加**模块化、异步和事件驱动**
- 探索使用 **C++ 协程**（Seastar 框架方向）重构 OSD，简化异步代码
- 减少数据结构和数据复制，提高 CPU 利用率

### 存储池多样化

- 非复制池（直接写入 SPDK）
- 并行写入多副本的池（不同一致性和容错模型）
- 适用于 NVMe-oF fabrics 的池

### 消息协议改进

- 新一代消息传递协议（msgr2），提高效率和安全性

### 运维与管理

- ceph-mgr 模块生态持续扩展
- Dashboard 功能增强，向完整管理界面演进
- 统一 QoS（mClock 调度器）完善

---

## 总结

2017 年，Ceph 以 **Luminous 版本发布**为核心里程碑，完成了 BlueStore 的生产就绪、ceph-mgr 的架构引入，以及 ARM/NVMe 等新硬件平台的适配。社区在保持高频迭代的同时，已开始为下一代架构（Crimson OSD、SPDK 集成）奠定基础。阿里巴巴、Nokia、CERN、Canonical 等生态伙伴的深度参与，标志着 Ceph 正从"Red Hat 主导的项目"向"真正的多厂商开源社区"演进。
