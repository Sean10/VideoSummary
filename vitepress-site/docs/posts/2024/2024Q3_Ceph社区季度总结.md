# Ceph 社区 2024 Q3 季度进展报告

## 1. 本季度重点议题

2024年第三季度，Ceph 社区围绕以下几个核心方向展开了密集讨论：

**性能优化与新硬件适配**
Erasure Coding（EC）性能优化是本季度最高频的技术议题，贯穿多个会议。随着 NVMe 存储设备的普及，如何充分发挥硬件性能成为核心关切，Crimson 项目的推进正是这一背景下的战略响应。详见 [Next Generation Erasure Coding Ceph Days London 2024](/posts/2024/Next_Generation_Erasure_Coding_Ceph_Days_London_2024)) 和 [Crimson Project Updates Ceph Days London 2024](/posts/2024/Crimson_Project_Updates_Ceph_Days_London_2024))。

**Tentacle 版本功能规划**
多个 CDS（Ceph Developer Summit）Tentacle 专题会议密集召开，覆盖 BlueStore、CephFS、RGW、RBD、Dashboard、Cephadm、NVMe-oF、Crimson、Telemetry 等几乎所有子系统，为下一个主要版本奠定功能基线。

**多集群与多站点管理**
Dashboard 多集群功能、RGW 多站点复制优化在多个会议中反复出现，反映了用户规模扩大后的运维需求。

**用户体验与易用性**
"Ice Pick Initiative"（冰镐倡议）、文档改进、硬件选型指南等议题表明社区在降低使用门槛方面投入了更多精力。详见 [Ceph User + Dev Monthly Meeting2024-08-21](/posts/2024/Ceph_User_+_Dev_Monthly_Meeting_2024-08-21))。

## 2. 技术亮点

### 2.1 Erasure Coding 下一代优化

[Next Generation Erasure Coding Ceph Days London 2024](/posts/2024/Next_Generation_Erasure_Coding_Ceph_Days_London_2024)) 中，Bill 详细介绍了 EC 性能优化路线：

- **部分读取（Partial Read）**：客户端仅读取所需数据块，减少网络带宽和 CPU 开销，已接近合并主分支
- **直接读取（Direct Read）**：客户端直接向持有数据的 OSD 发送请求，减少网络跳数
- **Apparity Delta写入优化**：通过计算新旧数据的 Delta 并应用于校验码，减少 IOPS
- **动态块大小调整**：根据对象大小选择合适的 chunk size，目标在 Tentacle 版本中落地

### 2.2 Crimson OSD 进入技术预览

[Crimson Project Updates Ceph Days London 2024](/posts/2024/Crimson_Project_Updates_Ceph_Days_London_2024)) 显示 Crimson 已进入技术评审阶段：

- 支持多核 CPU，采用 Seastar 框架的异步编程模型
- 支持 BlueStore 和 CStore 两种后端
- 支持 RBD 工作负载在副本池中运行
- 支持快速部署、垃圾回收、快照及 RBD 快照复制
- [Morning Lightning Talks Ceph Days London 2024](/posts/2024/Morning_Lightning_Talks_Ceph_Days_London_2024)) 中 IBM 团队分享了 Crimson CPU 利用率测试结果，验证了其性能潜力

### 2.3 NVMe-oF 网关集成成熟化

[Unlocking Ceph's Potential with NVMe-oF Integration Ceph Days London 2024](/posts/2024/Unlocking_Ceph_s_Potential_with_NVMe_oF_Integration_Ceph_Days_London_2024)) 展示了 Ceph 与 NVMe-oF 集成的完整进展：

- 基于 SPDK 框架实现，支持 TCP、iSCSI、RoCE 等多种网络协议
- 网关组（Gateway Group）实现高可用，支持自动故障转移和负载均衡
- 支持 NVMe-oF 发现服务，可自动连接所有目标
- 计划将 NVMe-oF CLI 集成到 Ceph 主 CLI，并支持 In-Band 消息通知

[CDS Tentacle - NVMe](/posts/2024/CDS_Tentacle_-_NVMe)) 进一步讨论了 xcopy 支持、SPDK 动态调度器、用户认证 namespace mask scheme 等增强方向。

### 2.4 RGW 功能扩展

本季度 RGW 相关会议密集，技术亮点包括：

- **Bucket 日志功能**：[Ceph RGW Refactoring Meeting 2024-08-28](/posts/2024/Ceph_RGW_Refactoring_Meeting_2024-08-28)) 详细讨论了类 AWS S3 Server Access Logging 的实现，重点保证日志持久性和可靠性
- **数据去重（ddop）**：[Ceph RGW Refactoring Meeting 2024-09-04](/posts/2024/Ceph_RGW_Refactoring_Meeting_2024-09-04)) 演示了基于 ref 计数和 manifest 共享的去重方案，支持大于 4MB 对象，采用 sharding 并行处理
- **端到端追踪（Tracing）**：[Ceph RGW Refactoring Meeting 2024-08-21](/posts/2024/Ceph_RGW_Refactoring_Meeting_2024-08-21)) 梳理了从 RGW 前端到 OSD 的完整追踪链路，计划迁移至 OpenTelemetry 协议
- **Resharding 优化**：[Ceph RGW Refactoring Meeting 2024-09-11](/posts/2024/Ceph_RGW_Refactoring_Meeting_2024-09-11)) 中改进已合并，最后合并步骤仅阻塞写操作，并计划引入 C++20 协程进一步优化
- **云对象恢复（Cloud Restore）**：基本功能已就绪，正在内部审查，讨论了时间戳冲突处理和错误状态返回机制

### 2.5 BlueStore 性能深化

[CDS Tentacle - BlueStore](CDS_Tentacle_-_BlueStore) 会议记录了多项优化工作：

- 开发了 OSD 操作日志抓取和重放工具，用于分析真实工作负载下的性能退化
- KVS 线程优化，减少写操作延迟
- 研究 RocksDB 管道功能以提高键值排序效率
- Igor 开发了新的分配器，改善内存组织和队列性能
- 新压缩算法允许用户在压缩率和 CPU 消耗之间权衡

### 2.6 CephFS 新特性

[CDS Tentacle - CephFS](/posts/2024/CDS_Tentacle_-_CephFS)) 讨论了多项功能：

- **大小写不敏感目录（Case-insensitive Directory）**：通过客户端驱动实现，依赖新增的 alternate name 元数据，提升 Samba 等网关兼容性
- **Layout Transformation**：允许用户设置目录期望布局，MDS 逐步迁移数据
- **Subvolume 元数据迁移至 SQLite**：提高元数据可靠性和事务支持能力
- **快照快速克隆（Fast Clone from Snapshots）**：解决硬链接文件快照问题

### 2.7 Dashboard 多集群与Carbon 迁移

[CDS Tentacle - Dashboard](/posts/2024/CDS_Tentacle_-_Dashboard)) 和 [Taming a Cephalopod Swarm Ceph Days London 2024](/posts/2024/Taming_a_Cephalopod_Swarm_Ceph_Days_London_2024)) 显示：

- Tentacle 将是首个支持多集群管理的版本，目标支持 50-100 个集群
- 引入 SE 管理网关（Admin Gateway），提供单点登录和反向代理，提高安全性
- 全面迁移至 Carbon Design System，[Ceph User + Dev Monthly Meeting 2024-09-25](/posts/2024/Ceph_User_+_Dev_Monthly_Meeting_2024-09-25)) 展示了导航栏和数据表的更新效果

## 3. 重要决策与里程碑

### 3.1 Squid 版本发布

[State of the Cephalopod Ceph Days London 2024](/posts/2024/State_of_the_Cephalopod_Ceph_Days_London_2024)) 确认 Squid 版本已发布，主要亮点包括：RADOS 低延迟快照密集型工作负载优化、Scrub 调度改进、Telemetry 新指标、Dashboard 管理功能增强、Cephadm 协议支持扩展、RBD 快照镜像改进、RGW S3 功能增强、CephFS 代码加固。

[Ceph RGW Refactoring Meeting 2024-09-11](/posts/2024/Ceph_RGW_Refactoring_Meeting_2024-09-11)) 记录了 RGW Squid 发布获批，预计一周内完成，期间遇到 Python 依赖变更导致 Ragweed 测试失败的问题。

### 3.2 Tentacle 版本规划确立

[Ceph RGW Refactoring Meeting 2024-09-25](/posts/2024/Ceph_RGW_Refactoring_Meeting_2024-09-25)) 确认下一个版本号为 19.2.1，并明确了从 squid 分支创建发布分支的流程。多个 CDS Tentacle 专题会议确立了各子系统的功能目标。

### 3.3 CentOS Stream 生命周期应对

[Ceph Developer Monthly2024-08-07](/posts/2024/Ceph_Developer_Monthly_2024-08-07)) 讨论了 CentOS Stream 生命周期结束对 Ceph 发布计划的影响，团队正在评估替代发行版方案。

### 3.4 Upmap Remapper 集成平衡器

[Ceph User + Dev Monthly Meeting 2024-09-25](/posts/2024/Ceph_User_+_Dev_Monthly_Meeting_2024-09-25)) 提出将 upmap remap PG remapper 集成到 Ceph 平衡器模块的设计提案，旨在减少添加/移除 OSD 时的多次 pering 事件，处理集群中大量 misplaced objects。

### 3.5 Ceph 与 VMware 集成

[Afternoon Lightning Talks Ceph Days London 2024](/posts/2024/Afternoon_Lightning_Talks_Ceph_Days_London_2024)) 中 IBM 宣布开发了 Ceph 与 VMware 的集成插件，提供部署、扩展和生命周期管理功能，计划后续支持数据路径和数据保护。

- **Canonical/Sunbeam**：[Sunbeam and Ceph Sitting in a Tree Ceph Days London 2024](/posts/2024/Sunbeam_and_Ceph_Sitting_in_a_Tree_Ceph_Days_London_2024)) 介绍了基于 Ceph Snap + Juju + Kubernetes 的 OpenStack 部署方案，预计 2023 年底发布稳定版
- **Sanger Institute**：[Morning Lightning Talks Ceph Days London 2024](/posts/2024/Morning_Lightning_Talks_Ceph_Days_London_2024)) 分享了基因组研究场景下的 Ceph 使用经验

## 5. 下季度展望

基于本季度讨论内容，预计 2024 Q4 将重点推进以下方向：

**Tentacle 版本功能收敛**
各子系统已完成功能规划，Q4 将进入实现和集成阶段。EC 部分读取优化、BlueStore 新分配器、CephFS 大小写不敏感目录等功能有望合并主分支。

**Crimson 扩大测试覆盖**
技术预览版本将扩展测试范围，包括 PG 拆分/合并、RBD 快照复制、动态 CPU 核心分配等，逐步向生产可用迈进。

**RGW 功能落地**
Bucket 日志、数据去重（ddop）、端到端追踪、云对象恢复等功能将完成代码审查并推进合并，多站点复制的图形索引方案将进入详细设计。

**Dashboard 多集群 GA**
多集群功能完成性能测试后，将作为 Tentacle 的核心特性发布，Carbon Design System 迁移同步推进。

**NVMe-oF CLI 统一**
NVMe-oF CLI 集成到 Ceph 主 CLI 的工作将推进，子系统级访问控制和 namespace屏蔽功能将完善。

**CentOS Stream 替代方案确定**
社区需要在 Q4 明确 Ceph 构建和测试基础设施的操作系统策略，以保障后续版本的发布流程。

**CBT 性能评估标准化**
[Ceph Developer Monthly 2024-08-07](/posts/2024/Ceph_Developer_Monthly_2024-08-07)) 中提出的 CBT 改进方向（自动化、数据后处理、标准化报告）将推动社区建立统一的性能基准体系。
