# Ceph 2024 年度社区进展报告

---

## 一、全年技术演进

2024年是Ceph从 Squid 版本走向成熟、并全面规划下一代架构 Tentacle 的关键一年。技术演进呈现出三条主线：**性能极限突破**、**存储协议现代化**、**运维自动化深化**。

### 性能极限突破

全闪存集群性能成为年度最受关注的话题。[Ceph - A Journey to 1 TiB/s](/posts/2024/Ceph_-_A_Journey_to_1_TiB_s_Ceph_Days_NYC_2024)) 记录了一个里程碑式的工程实践：通过 320 个 NVMe OSD、100GigE 网络、NUMA 调优和 BIOS 优化，在 3x 复制模式下实现了 1 TiB/s 读取吞吐量。[Designing and Tuning for All-Flash Ceph RBD Storage](/posts/2024/Designing_and_Tuning_for_All-Flash_Ceph_RBD_Storage_Ceph_Days_NYC_2024)) 则从 Bloomberg 的生产实践角度，系统总结了 NUMA 绑定、CRC32 优化、NIC RSS 调优等关键技术。

Erasure Coding 性能优化是另一个重大方向。[Next Generation Erasure Coding](/posts/2024/Next_Generation_Erasure_Coding_Ceph_Days_London_2024)) 提出了部分读取（partial read）、直接读取（direct read）、Parity Delta 写入等优化方案，目标是让 EC 池在块存储和文件存储场景下具备与副本池竞争的能力。[CDS Tentacle - CoreRADOS](/posts/2024/CDS_Tentacle_-_Core_RADOS)) 中进一步讨论了 EC 的chunk size 增大、零压缩（zero compression）等配套优化。

### 存储协议现代化

NVMe-oF 成为 2024 年最活跃的新协议方向。从 [NVMe-Over-Fabrics Support for Ceph](NVMe-Over-Fabrics_Support_for_Ceph_Days_NYC_2024) 到 [CDS Tentacle - NVMe](/posts/2024/CDS_Tentacle_-_NVMe))，NVMe over TCP Gateway 从技术预览走向生产就绪，引入了 Gateway Group、自动故障转移、TLS PSK 加密、多路径负载均衡等关键特性。[Ceph Days Asia - NVMe-oF recovery](Ceph_Days_Asia_-_NVMe-oF_recovery_-_Robust_Ceph_designthrough_disagregating_domains) 探索了通过 NVMe Fabric 实现计算域与存储域分离的新架构，为 AI 训练等高故障率场景提供快速恢复能力。

### 运维自动化深化

Cephadm 在 Tentacle 规划中获得大量改进，包括多架构镜像支持、断网安装、OSD 替换流程优化等（详见 [CDS Tentacle - Cephadm](/posts/2024/CDS_Tentacle_-_Cephadm))）。MicroCeph 作为轻量化部署方案持续演进，[Ceph Days Asia - MicroCeph](/posts/2024/Ceph_Days_Asia_-_MicroCeph_-_Flexible_Ceph_Orchestration)) 展示了其灵活编排能力和远程复制功能的开发进展。

## 二、重大里程碑

### Squid 版本发布

Squid（Ceph 19.x）是 2024 年最重要的版本里程碑。[Diving Deep with Squid](/posts/2024/Diving_Deep_with_Squid_Ceph_Days_NYC_2024)) 系统梳理了 Squid 的核心亮点：

- **BlueStore 优化**：引入 Elastic Shared Blob，显著降低快照工作负载的延迟和 CPU 消耗；RocksDB 切换为 LZ4 压缩，提升性能并减少空间占用
- **EC 改进**：允许更灵活的 EC 配置，改进 CRUSH 算法
- **Balancer 增强**：支持在线平衡（online balancing）
- **Manager OP Tracker**：简化生产环境调试
- **Crimson 读取性能**：显著提升，稳定性增强
- **Telemetry 更新**：新增 Crimson 运行识别，收集更多性能指标

Squid 代码冻结于 2024 年 2 月初完成（见 [Ceph RGW Refactoring Meeting 2024-01-31](/posts/2024/Ceph_RGW_Refactoring_Meeting_2024-01-31))），随后进入候选版本阶段，并于 2024 年 9 月发布正式版本（见 [Ceph RGW Refactoring Meeting 2024-09-25](/posts/2024/Ceph_RGW_Refactoring_Meeting_2024-09-25))）。

### Tentacle 版本规划启动

2024 年下半年，社区全面启动了下一个主要版本 Tentacle 的规划工作。CDS Tentacle 系列开发者峰会覆盖了所有核心组件，包括 [BlueStore](/posts/2024/CDS_Tenctacle_-_BlueStore))、[CephFS](/posts/2024/CDS_Tentacle_-_CephFS))、[Crimson](/posts/2024/CDS_Tentacle_-_Crimson))、[RGW](/posts/2024/CDS_Tentacle_-_RGW))、[RBD](/posts/2024/CDS_Tentacle_-_RBD))、[Dashboard](/posts/2024/CDS_Tentacle_-_Dashboard))、[NVMe](/posts/2024/CDS_Tentacle_-_NVMe))、[Cephadm](/posts/2024/CDS_Tentacle_-_Cephadm)) 等，为下一版本确立了技术方向。

### 存储规模里程碑

[Ceph Days Asia - State of the Cephalopod](/posts/2024/Ceph_Days_Asia_-_State_of_the_Cephalopod_with_Josh_Durgin_IBM)) 披露，通过 Telemetry 系统收集的数据显示，Ceph 集群管理的数据总量已超过 **1.5 Exabytes**，且持续增长，标志着 Ceph 在超大规模存储领域的主导地位进一步巩固。

## 三、核心组件年度进展

### RGW（RADOS Gateway）

RGW 是 2024 年代码活动最密集的组件，全年持续举行重构会议。主要进展包括：

**多站点（Multisite）架构重构**：全年多次会议（[2024-09-25](/posts/2024/Ceph_RGW_Refactoring_Meeting_2024-09-25))、[2024-10-02](/posts/2024/Ceph_RGW_Refactoring_Meeting_2024-10-02))、[2024-12-11](/posts/2024/Ceph_RGW_Refactoring_Meeting_2024-12-11))）深入讨论了多区域复制策略、元数据同步优化、Bucket 索引清理等问题，并探索了基于图形索引（graph-based indexes）替代哈希索引的方案。

**通知与主题系统重构**：[2024-01-03](/posts/2024/Ceph_RGW_Refactoring_Meeting_2024-01-03))、[2024-01-24](/posts/2024/Ceph_RGW_Refactoring_Meeting_2024-01-24))、[2024-01-31](/posts/2024/Ceph_RGW_Refactoring_Meeting_2024-01-31)) 等会议系统解决了 Topic 授权、持久化通知 TTL/Max Retry 配置、非持久化通知改进等问题。[2024-10-30](/posts/2024/Ceph_RGW_Refactoring_Meeting_2024-10-30)) 讨论了 V2 通知同步在多站点场景下的过滤机制。

**新功能**：S3 Bucket 日志（[2024-08-28](/posts/2024/Ceph_RGW_Refactoring_Meeting_2024-08-28))）、云对象恢复（cloud restore，[2024-09-11](/posts/2024/Ceph_RGW_Refactoring_Meeting_2024-09-11))）、对象完整性校验（[2024-02-14](/posts/2024/Ceph_RGW_Refactoring_Meeting_2024-02-14))）、数据去重工具 ddop（[2024-09-04](/posts/2024/Ceph_RGW_Refactoring_Meeting_2024-09-04))）等相继推进。

**IAM/STS 完善**：账户（Account）功能基本完成，IAM 策略限制、STS OIDC 签名验证等企业级特性持续推进（[2024-02-14](/posts/2024/Ceph_RGW_Refactoring_Meeting_2024-02-14))、[2024-12-18](/posts/2024/Ceph_RGW_Refactoring_Meeting_2024-12-18))）。

**Resharding 优化**：[2024-09-11](/posts/2024/Ceph_RGW_Refactoring_Meeting_2024-09-11)) 合并了非阻塞 Resharding 改进，[2024-10-09](/posts/2024/Ceph_RGW_Refactoring_Meeting_2024-10-9)) 和 [2024-11-13](/posts/2024/Ceph_RGW_Refactoring_Meeting_2024-11-13)) 深入讨论了基于 C++20 协程的并行 Resharding 设计。

**端到端追踪**：[2024-08-21](/posts/2024/Ceph_RGW_Refactoring_Meeting_2024-08-21)) 梳理了从 RGW 前端到 OSD 的完整追踪链路，并规划了向 OpenTelemetry 协议迁移的路线图。

### CephFS

[CDS Tentacle - CephFS](/posts/2024/CDS_Tentacle_-_CephFS)) 规划了多项重要特性：

- **大小写不敏感目录**（Case-insensitive directory）：通过客户端驱动的 alternate name 元数据实现，提升 Samba 等网关兼容性
- **Layout Transformation**：允许在线迁移目录中文件的存储布局
- **Subvolume 元数据迁移**：从文件存储迁移到 SQLite 数据库，提升可靠性和事务支持
- **加密功能**：在 libcephfs 和 cephfuse 中实现 fscrypt 加密
- **快照快速克隆**：解决硬链接文件快照的效率问题

[Designing a Multitenancy File System for Cloud Environment](/posts/2024/Designing_a_Multitenancy_File_System_for_Cloud_Environment_Ceph_Days_NYC_2024)) 展示了基于 CephFS RADOS 命名空间实现多租户隔离的生产实践，支持 NFS、SMB、快照和配额。

### BlueStore

[CDS Tentacle - BlueStore](/posts/2024/CDS_Tenctacle_-_BlueStore)) 记录了 BlueStore 团队的深度工作：

- **性能退化分析**：开发了 OSD 操作日志抓取和重放工具，用于分析真实工作负载下的性能退化
- **RBD 碎片化检查**：分析了 DigitalOcean 提供的 RBD 工作负载，发现非预期碎片化模式
- **KVS 线程优化**：减少写操作延迟，研究 RocksDB 管道功能
- **新压缩算法**：允许用户在压缩程度和 CPU 消耗之间灵活权衡
- **新分配器**：Igor 开发了改进内存组织和队列性能的新分配器

[Attempting to Improve Discard Performance](/posts/2024/Attempting_to_Improve_Discard_Performance_Ceph_Days_NYC_2024)) 深入分析了 NVMe 驱动器 discard 命令性能问题，探索了分配器选择对性能的影响。

### Crimson / SeaStore

Crimson 在 2024 年取得了显著进展。[Crimson Project Updates](/posts/2024/Crimson_Project_Updates_Ceph_Days_London_2024)) 宣布 Crimson 进入技术预览（Tech Preview）阶段，支持 RBD 工作负载在副本池中运行，具备多核 CPU 支持、快速部署、垃圾回收和快照功能。

[CDS Tentacle - Crimson](/posts/2024/CDS_Tentacle_-_Crimson)) 规划了 Tentacle 版本的目标：
- 推进多核性能，特别是异步消息传递的可扩展性
- SeaStore（CStore）核心功能完成，包括数据读写、元数据索引、事务支持
- 引入协程（coroutines），提升代码可维护性
- 扩展测试套件，包括 RBD 镜像测试

[Ceph Code Walkthroughs - Crimson](/posts/2024/Ceph_Code_Walkthroughs_-_Crimson)) 通过代码分析会议，系统介绍了 Crimson 与经典 OSD 的架构差异，特别是 Seastar 框架下 Futures/Continuation 编程模型的应用。

### Dashboard

[CDS Tentacle - Dashboard](/posts/2024/CDS_Tentacle_-_Dashboard)) 规划了 Dashboard 的重大升级：

- **多集群管理**：Tentacle 将是首个支持多集群管理的版本，目标支持 50-100 个集群
- **SE 管理网关**：为所有监控堆栈提供单一入口，提供单点登录和反向代理，提升安全性
- **Carbon 设计系统迁移**：全面迁移到 IBM Carbon Design System，提升 UI 一致性和性能
- **NVMe 管理**：引入 Gateway Group 管理界面
- **RGW 分析**：可视化 Bucket 和用户分析数据

[Ceph User + Dev Monthly Meeting2024-09-25](/posts/2024/Ceph_User_+_Dev_Monthly_Meeting_2024-09-25)) 展示了 Carbon 设计系统在导航栏和数据表中的实际应用效果。

### RADOS Core

[CDS Tentacle - Core RADOS](/posts/2024/CDS_Tentacle_-_Core_RADOS)) 涵盖了 RADOS 层的多项改进：

- **QoS 改进**：操作级别、回填操作、客户端 API 和 RBD 图像级别 QoS
- **Scrub 重构**：拆分浅层和深层错误存储，设计新的 Scrub 队列，改进 Deep Scrub 调度
- **Upmap 平衡器**：多线程改进，提升可扩展性
- **Monitor 配置 Profile**：简化配置管理
- **NVMe-oF 网关**：支持运行时服务选择

[Ceph Data Placement with Upmap - Introducing Chorus](/posts/2024/Ceph_Data_Placement_with_Upmap_Introducing_Chorus_Ceph_Days_NYC_2024)) 深入介绍了 CRUSH、PG、Upmap 的协同工作机制，并介绍了用于 S3 集群数据迁移的开源工具 Chorus。

### RBD

[CDS Tentacle - RBD](/posts/2024/CDS_Tentacle_-_RBD)) 规划了 RBD 的核心改进：

- **一致性组快照镜像**：实现基于快照的一致性组（Consistency Group）镜像功能
- **内置 LUKS 加密改进**：修复快照镜像过程中的数据一致性问题
- **实时迁移增强**：支持从其他子集群导入镜像，支持 NBD 格式迁移流

[Making RBD Snapshot-based Mirroring Robust for Disaster Recovery](/posts/2024/Making_RBD_Snapshot-based_Mirroring_Robust_for_Disaster_Recovery_Ceph_Days_NYC_2024)) 详细介绍了 RBD 快照镜像在灾难恢复场景下的健壮性改进，以及与 Kubernetes ramen 操作符的集成方案。

## 四、社区生态

### 线下活动

2024 年 Ceph 社区线下活动全面恢复并扩展：

- **Ceph Days London 2024**：举办了多场技术演讲，涵盖 Crimson、BlueStore、硬件选型、NVMe-oF 等主题（见 [Afternoon Lightning Talks](/posts/2024/Afternoon_Lightning_Talks_Ceph_Days_London_2024))、[Morning Lightning Talks](/posts/2024/Morning_Lightning_Talks_Ceph_Days_London_2024))）
- **Ceph Days NYC 2024**：规模最大的年度活动，涵盖性能极限、多租户文件系统、灾难恢复、大规模运营等主题（见 [Diving Deep with Squid](/posts/2024/Diving_Deep_with_Squid_Ceph_Days_NYC_2024))、[How we Operate Ceph at Scale](/posts/2024/How_we_Operate_Ceph_at_Scale_Ceph_Days_NYC_2024))）
- **Ceph Days Asia**：在韩国举办，吸引了三星 SDS、Samsung Electronics 等亚洲企业参与（见 [State of the Cephalopod](/posts/2024/Ceph_Days_Asia_-_State_of_the_Cephalopod_with_Josh_Durgin_IBM))）

### 用户委员会启动

2024 年的重要社区建设举措是 **Ceph 用户委员会**的正式启动。[Community Initiatives and Improving Ceph through User Feedback](/posts/2024/Community_Initiatives_and_Improving_Ceph_through_User_Feedback_Ceph_Days_NYC_2024)) 详细介绍了委员会的工作机制：围绕性能和编排部署两大支柱，通过调查问卷收集用户反馈，设立 Champion 角色引导讨论，将用户需求转化为具体行动项。

[Ceph Developer Monthly2024-04-17](/posts/2024/Ceph_Developer_Monthly_2024-04-17)) 披露了首次用户调查的结果：共收到 27 份回复，主要工作负载为备份归档和 Kubernetes 持久存储，用户对 mclock 调度器、网络配置、错误状态下的性能等方面提出了具体反馈。

### 基金会成员动态

[Ceph Days Asia - State of the Cephalopod](/posts/2024/Ceph_Days_Asia_-_State_of_the_Cephalopod_with_Josh_Durgin_IBM)) 披露，Ceph 基金会引入了新的会员结构，Bloomberg、IBM 和 45Drives 成为新的钻石会员，进一步强化了社区的企业支持基础。

### 大规模生产实践分享

[How we Operate Ceph at Scale](/posts/2024/How_we_Operate_Ceph_at_Scale_Ceph_Days_NYC_2024)) 来自 DigitalOcean，披露了其 58 个集群、超过 200PB 原始存储、28,000 个 OSD 的运营规模，分享了基于 Chef + Ansible + AWX 的自动化运维体系。

[All things in Moderation](/posts/2024/All_things_in_Moderation_Ceph_Days_London_2024)) 来自 Bloomberg，分享了在 S3 对象存储上构建集群级 QoS 堆栈的实践经验，包括基于 HAProxy + Redis 的速率限制架构。

### 文档与可用性改进

[CDS Tentacle - Documentation](/posts/2024/CDS_Tentacle_-_Documentation)) 和 [Ceph User + Dev Monthly Meeting 2024-08-21](/posts/2024/Ceph_User_+_Dev_Monthly_Meeting_2024-08-21)) 推动了"冰镐倡议"（Ice Pick Initiative），旨在系统改进 Ceph 命令的帮助输出，降低使用门槛。文档团队还规划了新手指南、测试驱动指南和硬件推荐列表。

## 五、下一年展望

基于 2024 年的技术讨论和社区动向，2025 年（Tentacle 版本周期）的技术路线和社区方向可以做出以下推断：

### 技术路线

**Crimson 走向生产**：Crimson 在 2024 年完成技术预览，Tentacle 版本的目标是进一步提升稳定性和功能完整性，特别是多核扩展性能和 SeaStore 后端的成熟度。NVMe 时代的 CPU 效率优化将是核心驱动力。

**NVMe-oF 生产就绪**：NVMe over TCP Gateway 将从技术预览走向生产就绪，引入快照复制、xcopy 支持、更完善的安全认证机制。与 VMware 的集成也将进一步深化。

**RGW 多站点架构重构完成**：基于 2024 年大量的设计讨论，Tentacle 版本预计将完成多站点复制架构的重大重构，包括并行 Resharding、改进的元数据同步、更清晰的全量同步与增量同步语义。

**EC 性能突破**：部分读取、直接读取、Parity Delta 写入等优化将在 Tentacle 中落地，有望使 EC 池在块存储场景下具备实用价值。

**Dashboard 多集群管理**：多集群管理功能将是 Tentacle Dashboard 的标志性特性，配合 SE 管理网关提供企业级安全和高可用性。

**AI/ML 存储集成**：[Ceph RGW Refactoring Meeting 2024-11-20](/posts/2024/Ceph_RGW_Refactoring_Meeting_2024-11-20)) 展示了 RGW 与向量数据库（Milvus）集成的原型，通过 Knative + Kafka 实现对象上传自动触发向量化。这一方向预计将在 2025 年获得更多关注。

### 社区方向

**用户委员会深化运作**：用户委员会将扩展到更多支柱（质量、可扩展性等），通过持续调查和 Champion 机制，建立更直接的用户-开发者反馈闭环。

**S3 用户工作组**：[Ceph User + Dev Monthly Meeting -10/16/24](/posts/2024/Ceph_User_+_Dev_Monthly_Meeting_-_10_16_24)) 提出建立专注于 S3 RGW 的用户开发小组，预计 2025 年将正式落地，提升 S3 功能需求的透明度和优先级管理。

**用户案例收集**：[Ceph User + Developer Monthly Meeting 2024-11-20](/posts/2024/Ceph_User_+_Developer_Monthly_Meeting_2024-11-20)) 启动了系统性的用户案例收集计划，预计 2025 年将在官网展示更多大规模生产实践，增强社区影响力。

**EL10 /新发行版支持**：[Ceph User + Developer Meeting 2024-11-06](/posts/2024/Ceph_User_+_Developer_Meeting_2024_-11-06)) 讨论了 CentOS Stream 10 和 SELinux 集成，预计 2025 年将完成对新一代 Linux 发行版的支持，解决 CentOS Stream 生命周期结束带来的挑战。
