# Ceph 社区 2018 Q1 季度进展报告

## 1. 本季度重点议题

2018年第一季度，Ceph 社区围绕以下几个核心方向持续深入讨论：

**BlueStore 性能与稳定性**
BlueStore 是本季度最高频的讨论主题。从异步读取支持、缓存策略重构，到与 RocksDB 的缓存协调，几乎每周的性能例会都有相关议题。详见 [2018-JAN-04 性能周会](2018-JAN-04_-_-Ceph_Performance_Weekly) 和 [2018-FEB-22 性能周会](2018-FEB-22_-_Ceph_Performance_Weekly)。

**OSD 性能优化与异步化改造**
OSD 的同步基础设施被多次指出存在冗余开销，社区持续推进对象存储接口（OST）的异步化改造，并讨论了执行上下文分析和调用图构建。详见 [2018-FEB-01 性能周会](2018-FEB-01_-_Ceph_Performance_Weekly)。

**RocksDB 缓存与元数据管理**
RocksDB 的 Bloom filter 内存占用、索引/过滤器缓存分配、以及 BlueStore 与 RocksDB 之间的缓存再平衡机制，在 3 月份的会议中成为焦点。详见 [2018-MAR-01 性能周会](2018-MAR-01_-_Ceph_Performance_Weekly)。

**Dashboard v2 与管理工具现代化**
社区启动了基于 Angular 2 + CheryPy 的 Dashboard v2 开发，并在 Ceph Day Germany 上展示了 openATIC 等管理工具的进展。

**Kubernetes/容器化部署**
Rook 项目成为 Kubernetes 上部署 Ceph 的首选方案，并计划与 Ceph Mimic 版本同步发布。详见 [2018-JAN-03 开发者月会](/posts/2018/2018-JAN-03_-_-_Ceph_Developer_Monthly))。

## 2. 技术亮点

### BlueStore 异步读取
社区提交了为 BlueStore 添加异步读取支持的大型 PR，但发现存在性能回归问题，需要在特定场景下回退到同步路径。该工作持续贯穿整个季度。详见 [2018-JAN-04 性能周会](/posts/2018/2018-JAN-04_-_-_Ceph_Performance_Weekly))。

### CRC 缓存补丁
一个简洁有效的 CRC 缓存补丁在 1 月完成并进入 QA 测试阶段，被认为是低风险高收益的优化。

### QAT（Quick Assist Technology）支持
新增了对 Intel QAT 硬件加速的支持，涵盖压缩和加密加速，但集成过程中遇到若干问题需要解决。详见 [2018-JAN-11 性能周会](2018-JAN-11_-_Ceph_Performance_Weekly)。

### VP 网络集成探索
1 月的性能周会中，社区探讨了将 VPP（Virtual Packet Processing）集成到 Ceph 的可能性，讨论了通过 VPP 通信库在用户空间处理网络操作，以及作为 RGW 插件的方案。详见 [2018-JAN-18 性能周会](2018-JAN-18_-_Ceph_Performance_Weekly)。

### Messenger v2
Messenger v2 的开发持续推进，重点在于身份验证和传输加密，计划集成 GSSAPI 以支持 Kerberos 等认证协议。详见 [2018-FEB-07 开发者月会](/posts/2018/2018-FEB-07_-_-_Ceph_Developer_Monthly))。

### 集群级别复制（Multi-site Replication）
2 月开发者月会讨论了集群级别复制的架构细节，引入了新模块处理复制工作，并设计了日志条目和操作缓存机制来管理复制操作。

### RGW 对象变更日志
3 月开发者月会讨论了为 RGW 添加对象变更日志功能，以便备份系统等外部工具可以追踪对象变化，并考虑兼容 S3 日志接口。详见 [2018-MAR-07 开发者月会](2018-MAR-07_-_Ceph_Developer_Monthly)。

### BlueStore/RocksDB 缓存自动调优
3 月的性能周会中，社区开始研究在 BlueStore 和 RocksDB 之间动态调整缓存分配的机制，目标是根据实际工作负载自动优化缓存比例。详见 [2018-Mar-15 性能周会](/posts/2018/2018-Mar-15_-_-_Ceph_Performance_Weekly))。

### Seastar/SPDK 新存储后端（C Store）
1 月开发者月会讨论了基于 Seastar 框架和 SPDK 库的新存储后端，提供日志结构化存储格式，专为高速 NVMe 设备设计，命名讨论中出现了"C Store"或"C18 Store"等候选名称。

## 3. 重要决策与里程碑

**Ceph Luminous 回顾与 Mimic 规划**
Ceph Day Germany 上对 Luminous 版本进行了全面回顾，介绍了 BlueStore 正式成为默认后端、Ceph Manager 引入等重要变化。同时，Rook 项目计划与即将发布的 Mimic 版本同步。详见 [Ceph Day Germany - Ceph Luminous is out](/posts/2018/Ceph_Day_Germany_-_Ceph_Luminous_is_out_what_s_in_it_for_you))。

**BlueStore 缓存策略讨论**
社区认真讨论了是否移除 BlueStore 自身的缓存层、仅依赖 RocksDB 缓存管理元数据的方案，但决定在收集更多 Bloom filter 内存占用数据后再做决定，暂时维持默认的 50/50 缓存分配策略。

**Specter 漏洞影响评估**
1 月会议中，社区评估了 Spectre 漏洞对 Intel 处理器性能的潜在影响，Red Hat 性能团队介入研究解决方案。详见 [2018-JAN-18 性能周会](2018-JAN-18_-_Ceph_Performance_Weekly)。

**新配置管理系统（mod）**
1 月开发者月会确认了新配置管理系统的方向，支持配置存储、解析、验证和展示，但身份验证功能尚未完成，列为后续工作项。

## 4. 社区动态

### Ceph Day Germany
本季度举办了 Ceph Day Germany，涵盖多个主题演讲：

- **openATTIC 管理工具**：展示了基于 openATTIC 的自动化部署和集群管理能力。详见 [Ceph Day Germany - Management and Monitoring with openATTIC](/posts/2018/Ceph_Day_German_-_Ceph_Management_and_Monitoring_with_openATTIC))。
- **CERN 大科学应用**：CERN 分享了在两个数据中心运行 Ceph 集群（最大 5.5PB）的经验，涵盖物理实验数据、S3 存储和 HPC 场景。详见 [Ceph Day Germany - Ceph for Big Science](/posts/2018/Ceph_Day_Germany_-_Ceph_for_Big_Science))。
- **SAP 企业云实践**：SAP 分享了基于 Ceph 构建"cattle cloud"的实践，使用 Saltstack 进行自动化部署。详见 [Ceph Day Germany - Ceph at SAP](/posts/2018/Ceph_Day_Germany_-_Ceph_at_SAP_-_How_to_build_a_cattle_cloud))。
- **Intel 平台与 SD 性能**：讨论了 Ceph 在新型 Intel 平台和 SSD 上的性能表现。详见 [Ceph Day Germany - Ceph Performance on New Intel Platforms and SSDs](/posts/2018/Ceph_Day_Germany_-_Ceph_Performance_on_New_Intel_Platforms_and_SSDs))。
- **SD-only 性能方案**：探讨了全 SSD 存储介质下的 Ceph 性能优化策略。详见 [Ceph Day Germany - SD only Performance with Ceph](Ceph_Day_Germany_-_SD_only_Performance_with_Ceph)。
- **Ceph mgr 与 Kubernetes集成**：介绍了 CephCO 容器编排工具和 Rook 项目的进展。详见 [Ceph Day Germany - Development update Ceph mgr and Kubernetes](/posts/2018/Ceph_Day_Germany_-_Development_update_Ceph_mgr_and_Kubernetes))。
- **croit 管理方案**：一家基于 Rust 开发 Ceph 管理工具的初创公司分享了其产品。详见 [Ceph Day Germany - Everyone can Build and Maintain a Ceph Cluster with croit](/posts/2018/Ceph_Day_Germany_-_Everyone_can_Build_and_Maintain_a_Ceph_Cluster_with_croit))。

### 开发者月会
- 1 月月会（[2018-JAN-03](/posts/2018/2018-JAN-03_-_-_Ceph_Developer_Monthly))）：讨论了配置管理、Rook、Easy Clones、OSD 性能优化和新存储后端等多个方向。
- 2 月月会（[2018-FEB-07](/posts/2018/2018-FEB-07_-_-_Ceph_Developer_Monthly))）：重点讨论 Dashboard v2、Messenger v2 和集群级别复制。
- 3 月月会（[2018-MAR-07](/posts/2018/2018-MAR-07_-_-_Ceph_Developer_Monthly))）：讨论 RGW 对象变更日志、多区域同步模块改进和配置历史记录功能。

### 性能周会
本季度共举办 9 次性能周会，参与者包括来自 Red Hat 等公司的核心开发者，持续跟踪性能相关 PR 的进展，形成了稳定的周期性协作机制。

## 5. 下季度展望

基于本季度的讨论内容，预计 2018 Q2 将重点推进以下方向：

1. **BlueStore 异步读取落地**：解决性能回归问题后，异步读取 PR 有望合并，进一步提升 BlueStore 的 I/O 性能。

2. **BlueStore/RocksDB 缓存自动调优**：缓存再平衡机制的代码开发将继续，目标是在 Mimic 版本中提供更智能的缓存管理。

3. **Dashboard v2 发布**：Angular 2 前端开发接近完成，预计 Q2 可提交可审查版本，并逐步集成监控功能。

4. **Messenger v2 身份验证**：Kerberos/GSSAPI 集成工作将继续推进，为集群通信提供加密和认证能力。

5. **Rook 与 Mimic 同步发布**：Rook 项目将与 Ceph Mimic 版本协调发布节奏，推动 Kubernetes 上的 Ceph 部署标准化。

6. **Seastar/SPDK 新存储后端原型**：C Store（基于 Seastar + SPDK）的早期原型开发将继续，为下一代高速存储设备做准备。

7. **RGW 对象变更日志**：该功能将继续开发，为备份和数据同步场景提供基础能力。
