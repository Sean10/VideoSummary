# Ceph 社区 2020Q3 季度进展报告

---

## 一、本季度重点议题

### 1. Crimson/SeaStar 新一代 OSD 开发

本季度最核心的持续议题是 Crimson OSD 与 SeaStar 存储引擎的开发推进。从 7月到 9 月，团队每周召开专项会议，覆盖了回填（backfill）与恢复（recovery）功能实现、可中断 future（interuptible future）机制设计、垃圾回收（GC）与空间管理、缓存驱逐（cache eviction）等多个核心子系统。详见 [Ceph_Crimson_SeaStor_OSD_Weekly_2020-07-01](/posts/2020/Ceph_Crimson_SeaStor_OSD_Weekly_2020-07-01))、[Ceph_Crimson_SeaStor_OSD_2020-09-02](/posts/2020/Ceph_Crimson_SeaStor_OSD_2020-09-02))。

### 2. BlueStore 性能优化

BlueStore 的性能调优贯穿整个季度，重点包括 RocksDB 写放大问题、删除操作性能瓶颈、缓存策略改进以及 buffer list 重建开销优化。详见 [Ceph_Performance_Meeting_2020-09-10](/posts/2020/Ceph_Performance_Meeting_2020-09-10))、[Ceph_Performance_Meeting_2020-08-06](/posts/2020/Ceph_Performance_Meeting_2020-08-06))。

### 3. Orchestrator 与 cephadm 部署体验

Orchestrator 会议持续讨论 cephadm 的功能完善、文档整合、NFS 集成冲突、OSD 移除设计以及容器化部署体验改进。详见 [Ceph_Orchestrator_Meeting_2020-08-31](/posts/2020/Ceph_Orchestrator_Meeting_2020-08-31))、[Ceph_Orchestrator_Meeting_2020-09-14](/posts/2020/Ceph_Orchestrator_Meeting_2020-09-14))。

### 4. 文档质量改进（DocuBetter）

DocuBetter 工作组本季度持续推进入门指南、开发者指南、安装指南的重构与整合，并探索视频教程制作。详见 [Ceph_DocuBetter_Meeting_2020-08-12](/posts/2020/Ceph_DocuBetter_Meeting_2020-08-12))、[Ceph_Docubetter_Meeting_2020-09-05](/posts/2020/Ceph_Docubetter_Meeting_2020-09-05))。

## 二、技术亮点

### Crimson OSD 与 SeaStar 存储引擎

- **可中断 future 机制**：本季度重点攻关 interuptible future wrapper，解决了 PG interval 变化时请求需要重新排队的问题，引入 tri-mutex 的暂停/恢复语义。详见 [Ceph_Crimson_SeaStor_OSD_Weekly_2020-09-23](/posts/2020/Ceph_Crimson_SeaStor_OSD_Weekly_2020-09-23))。
- **垃圾回收与空间管理**：实现了基于内存计数器的段活跃字节追踪，设计了目标空闲空间和使用率两个可调参数。详见 [Ceph_Crimson_SeaStor_OSD_2020-08-26](/posts/2020/Ceph_Crimson_SeaStor_OSD_2020-08-26))。
- **SeaStar 存储引擎 OMAP 树**：完成了字符串键布局操作，推进了 LBA 树与 OMAP 树的节点布局设计。详见 [Ceph_Crimson_SeaStor_OSD_2020-07-22](/posts/2020/Ceph_Crimson_SeaStor_OSD_2020-07-22))。
- **Hybrid Bar 里程碑**：成功重现并修复了 Hybrid Bar 问题，并集成到 Ceph OSD 实现中，被视为重要里程碑。详见 [Ceph_Crimson_SeaStor_OSD_2020-09-02](/posts/2020/Ceph_Crimson_SeaStor_OSD_2020-09-02))。
- **容器化支持**：完成了 Crimson 的 Docker 容器镜像准备，解决了 Crimson 与 Seastar 命名差异问题。详见 [Ceph_Developer_Monthly_2020-07-02](/posts/2020/Ceph_Developer_Monthly_2020-07-02))。

### BlueStore 性能

- **删除流程重设计**：Igor 提出并测试了新的删除流程——先回收空间再删除数据库记录，显著提升了大量对象删除场景下的性能。详见 [Ceph_Performance_Meeting_2020-09-10](/posts/2020/Ceph_Performance_Meeting_2020-09-10))。
- **RocksDB 优化**：讨论了为每个列族（column family）提供独立块缓存的 PR，以及动态 level 实现。详见 [Ceph_Performance_Meeting_2020-09-24](/posts/2020/Ceph_Performance_Meeting_2020-09-24))。
- **Buffer list 优化**：Radek 推进了减少 buffer list 重建的工作，通过动态调整 append buffer 长度降低内存分配开销。详见 [Ceph_Performance_Meeting_2020-08-13](/posts/2020/Ceph_Performance_Meeting_2020-08-13))。

### CRUSH 算法研究

本季度多次讨论了一篇关于 CRUSH 算法扩展的论文（FAST 2020），该论文通过引入时间维度映射解决集群扩展时的数据迁移问题。团队评估后认为该方案复杂度较高，倾向于改进现有 PG 临时（PG temp）机制或引入多 CRUSH 规则方法。详见 [Ceph_Performance_Meeting_2020-08-13](/posts/2020/Ceph_Performance_Meeting_2020-08-13))、[Ceph_Performance_Meeting_2020-08-20](/posts/2020/Ceph_Performance_Meeting_2020-08-20))。

### dmclock QoS 算法

7 月举行了专项代码讲解会议，深入介绍了 dmclock 分布式 QoS 算法的实现，包括客户端/服务端交互模型和间接侵入式堆数据结构。详见 [Ceph_Code_Walkthrough_2020-07-14_-_Dmclock](/posts/2020/Ceph_Code_Walkthrough_2020-07-14_-_Dmclock))。

### 内核 RBD I/O 流程

8 月代码讲解会议系统介绍了内核 RBD 驱动的映射/解映射流程、对象映射（object map）查询、父镜像（parent image）处理以及写入状态机设计。详见 [Ceph_Code_Walkthrough_2020-08-25_-_kRBD_I_O_Flow](/posts/2020/Ceph_Code_Walkthrough_2020-08-25_-_kRBD_I_O_Flow))。

### 边缘计算应用

Red Hat 实习生展示了基于 Ceph RGW S3 API 和 GStreamer 的多视频源边缘流式传输项目，利用 Knative 函数触发器和 OpenCV 实现视频拼接与分析。详见 [Ceph_Tech_Talk_2020-08-20_-_Edge_Application_-_Streaming_Multiple_Video_Sources](/posts/2020/Ceph_Tech_Talk_2020-08-20_-_Edge_Application_-_Streaming_Multiple_Video_Sources))。

## 三、重要决策与里程碑

### 版本发布

- **Ceph 15.2.5 发布**：解决了从旧版本升级时 OSD 支持模块导致的健康警告问题。详见 [Ceph_Orchestrator_Meeting_2020-09-08](/posts/2020/Ceph_Orchestrator_Meeting_2020-09-08))。
- **Rook 1.4 发布**：本季度完成发布，等待 CSI 3.0 后如期推出。详见 [Ceph_Orchestrator_Meeting_2020-08-10](/posts/2020/Ceph_Orchestrator_Meeting_2020-08-10))。

### 重大设计决定

- **移除 cephadm 包模式（package mode）**：由于升级路径复杂、文档缺失，决定暂时移除该模式。详见 [Ceph_Orchestrator_Meeting_2020-07-20](/posts/2020/Ceph_Orchestrator_Meeting_2020-07-20))。
- **不再支持 CentOS 7**：由于 Python 2 已停止维护，团队多数意见倾向于放弃 CentOS 7 支持。详见 [Ceph_Orchestrator_Meeting_2020-08-24](/posts/2020/Ceph_Orchestrator_Meeting_2020-08-24))。
- **NFS 集成冲突问题**：确认 Dashboard 与Volumes NFS 模块存在两套不兼容实现，需要制定迁移方案。详见 [Ceph_Orchestrator_Meeting_2020-08-31](/posts/2020/Ceph_Orchestrator_Meeting_2020-08-31))。
- **cephadm 二进制重构**：决定逐步将 cephadm 重构为规范的 Python 包，从简化 bootstrap 命令开始。详见 [Ceph_Orchestrator_Meeting_2020-08-17](/posts/2020/Ceph_Orchestrator_Meeting_2020-08-17))。
- **Crimson 中断处理架构**：决定采用装饰器/构建器方式处理中断检查，而非将中断逻辑直接嵌入 aerator，优先保证代码可维护性。详见 [Ceph_Crimson_SeaStor_OSD_2020-09-02](/posts/2020/Ceph_Crimson_SeaStor_OSD_2020-09-02))。

## 四、社区动态

### 会议与活动

- **代码讲解系列（Code Walkthrough）**：本季度举办了三场，分别覆盖 dmclock 算法（7 月）、内核 RBD I/O 流程（8 月）和 CephFS MDS 代码结构（9 月），由 Patrick Donnelly 主讲 MDS 部分。详见 [Ceph_Code_Walkthrough_-_Patrick_Donnelly_-_Metadata_Servers2020-09-29](/posts/2020/Ceph_Code_Walkthrough_-_Patrick_Donnelly_-_Metadata_Servers_2020-09-29))。
- **Tech Talk 系列**：7 月讨论了多数据中心小型 Ceph 集群实践，8 月展示了边缘视频流应用。详见 [Ceph_Tech_Talk_-_A_Different_Scale_Running_Small_Ceph_Clusters_in_Multiple_Data_Centers_20200723](/posts/2020/Ceph_Tech_Talk_-_A_Different_Scale_Running_Small_Ceph_Clusters_in_Multiple_Data_Centers_20200723))。
- **Science Working Group**：7 月和 9 月各举行一次，分享了集群满容量处理、Octopus 升级踩坑（RGW 统计问题、性能下降）、Ceph-CSI 使用经验等。详见 [Ceph_Science_Working_Group_2020-07-23](/posts/2020/Ceph_Science_Working_Group_2020-07-23))、[Ceph_Science_Working_Group_2020-09-23](/posts/2020/Ceph_Science_Working_Group_2020-09-23))。
- **Developer Monthly**：7 月和 9 月各举行一次，分别聚焦 Crimson 集成进展和故障诊断工具改进。

### 贡献者动态

- Crimson 团队迎来新成员 Gaby（20 年存储行业经验）。详见 [Ceph_Crimson_SeaStor_OSD_Weekly_2020-07-01](/posts/2020/Ceph_Crimson_SeaStor_OSD_Weekly_2020-07-01))。
- Orchestrator 团队新增文档贡献者 Karen Norma，专注于 cephadm 和安装程序文档。详见 [Ceph_Orchestrator_Meeting_2020-07-13](/posts/2020/Ceph_Orchestrator_Meeting_2020-07-13))。
- DocuBetter 工作组讨论了引入专职文档改进人员的需求，并探索视频教程制作。
- PR 审查周期过长问题在 Orchestrator 会议中被正式提出，讨论了改进团队参与度的机制。详见 [Ceph_Orchestrator_Meeting_2020-09-28](/posts/2020/Ceph_Orchestrator_Meeting_2020-09-28))。

### 用户反馈

- 多个用户报告 Octopus（15.2.x）升级后遇到 RGW 统计不准确、性能下降等问题，部分用户选择回滚到 Nautilus。详见 [Ceph_Science_Working_Group_2020-07-23](/posts/2020/Ceph_Science_Working_Group_2020-07-23))。
- 小型多数据中心 Ceph 集群部署模式获得社区关注，被认为在管理简便性和故障隔离方面具有优势。

## 五、下季度展望

基于本季度讨论，预计 2020Q4 将重点推进以下方向：

1. **Crimson OSD 功能完整性**：可中断 future 机制趋于稳定后，预计将推进更完整的 backfill/recovery 测试，并向 teuthology 集成测试迈进。
2. **BlueStore 删除性能**：Igor 的新删除流程设计已有初步测试结果，预计将提交正式 PR 并进入审查合并流程。
3. **cephadm 成熟度提升**：包括 gather facts硬件信息收集命令、NFS 集成冲突解决方案、以及 cephadm 二进制重构的持续推进。
4. **性能 CI 建设**：本季度末已提出构建基于 CBT 和 Jenkins 的自动化性能回归测试体系，预计下季度开始落地。详见 [Ceph_Performance_Meeting_2020-08-28](/posts/2020/Ceph_Performance_Meeting_2020-08-28))。
5. **RocksDB 深度优化**：Gabi 正在研究可丢弃内存表（discardable memtable）的可行性，以解决 PG 日志与对象节点同步的性能问题。详见 [Ceph_Performance_Meeting_2020-09-24](/posts/2020/Ceph_Performance_Meeting_2020-09-24))。
6. **文档体系完善**：入门指南、安装指南整合 PR 预计在 Q4 完成合并，视频教程制作计划也将推进。
