# Ceph 2020 年度社区进展报告

## 一、全年技术演进概述

2020年是Ceph历史上承上启下的关键一年。上半年以 **Octopus（15.x）** 版本的发布为核心里程碑，下半年则全面转入 **Pacific** 版本的规划与开发。全年技术演进呈现出三条主线：

1. **可操作性（Operability）的系统性提升**：以 `cephadm` 为核心的新一代部署工具链逐步成熟，Orchestrator API 走向统一，Dashboard 持续增强。
2. **下一代存储引擎的探索**：Crimson/SeaStor OSD 项目进入密集开发期，每周例会贯穿全年，B+树、事务管理器、LBA 管理器等核心子系统从设计走向实现。
3. **性能工程的体系化**：BlueStore 混合分配器、延迟大写、RocksDB 升级等优化落地，同时建立了基于 Jenkins + CBT 的性能 CI 框架。

新冠疫情（COVID-19）对全年工作产生了显著影响：Cephalocon 等线下活动被取消或转为线上，开发者峰会（CDS）改为虚拟形式，但这也客观上推动了社区在线协作能力的提升。

---

## 二、重大里程碑

### 2.1 Ceph Octopus（15.2.x）正式发布

Octopus 于 **2020年3月** 正式发布，是本年度最重要的版本里程碑。如 [2020-05-28 Tech Talk](2020-05-28_-Ceph_Tech_Talk_-_What_s_New_In_Octopus) 所详细介绍，Octopus 的核心亮点包括：

- **Orchestrator API 统一**：实现了跨 `cephadm`、Rook 等后端的统一部署管理接口，支持容器化部署。
- **Dashboard 增强**：界面布局调整，增强用户管理功能，改进 OSD 部署流程。
- **BlueStore 优化**：改进预取和压缩机制，优化内存使用和 TRIM 行为。
- **RBD 镜像改进**：基于快照的灾难恢复，减少 I/O 开销。
- **健康监控增强**：新增网络监控健康警报，改进内部健康警报处理。

Octopus 支持从 Luminous、Mimic 和 Nautilus 直接升级，但 Luminous 需先升级到 Mimic 或 Nautilus。发布后，15.2.2 版本随即跟进，包含大量针对用户实际问题的 bug 修复和文档改进。

### 2.2 Pacific版本规划启动

2020年4月，Ceph 开发者峰会（CDS Pacific）以虚拟形式召开，为 Pacific 版本（预计2021年3月发布）确立了技术方向。各组件的 Pacific 规划详见后续章节。

## 三、核心组件年度进展

### 3.1 Crimson/SeaStor OSD

Crimson/SeaStor 是2020年技术投入最密集的方向，全年保持每周例会节奏（[1月](/posts/2020/2020-01-07_-_-_Crimson_SeaStor_OSD_Weekly_Meeting))至[10月](/posts/2020/2020-10-21_-_-_Crimson_SeaStor_OSD_Weekly_Meeting))持续记录）。

**核心子系统进展：**

- **SeaStor B+树（Onode Tree / LBA Tree）**：全年从设计走向实现。1月讨论了异步版本的架构，确定采用自顶向下的分裂合并策略；5月 [Crimson 会议](/posts/2020/2020-05-05_-_-_Ceph_Crimson_Meeting)) 中LBA 树的逻辑地址到物理地址映射设计趋于成熟；到5月底，节点分裂单元测试已通过。
- **事务管理器（Transaction Manager）**：2月 [会议](/posts/2020/2020-02-18_-_-_Ceph_Crimson_Meeting)) 确立了避免显式锁定、依赖事务层处理并发的设计原则；4月讨论了模板类型系统以控制代码复杂度。
- **PG log based recovery**：3月开始实现，Josh Anderson 在3月底 [会议](/posts/2020/2020-03-31_-_-_Ceph_Crimson_Meeting)) 中报告手动测试已通过，正在补充测试用例。
- **对象类（CLS）支持**：4月 [会议](/posts/2020/2020-04-14_-_-_Ceph_Crimson_Meeting)) 讨论了在 PG 后端实现对象类的几何操作支持。
- **Scrubing 引擎重构**：4月讨论了将 Scrubbing 代码重构为更可测试的结构。
- **优雅关机（Graceful Shutdown）**：5月 [会议](/posts/2020/2020-05-27_-_-_Crimson_SeaStor_OSD_Weekly_Meeting)) 讨论了通过停止标志或从 messenger 注销调度器来实现优雅关机。

**Pacific 目标**：[4月会议](/posts/2020/2020-04-07_-_-_Ceph_Crimson_Meeting)) 明确了 Crimson 在 Pacific 版本中的核心目标——速度和质量的提升，快照功能作为扩展目标而非核心需求。

### 3.2 BlueStore

BlueStore 在2020年经历了多项重要优化，主要体现在分配器和写路径上：

**混合分配器（Hybrid Allocator）**：Igor全年持续推进，基于 AVL 树和位图的混合分配器在 [2月性能会议](/posts/2020/2020-02-20_-_-_Ceph_Performance_Meeting)) 中展示了性能数据，最终在4月 [性能会议](/posts/2020/2020-04-16_-_-_Ceph_Performance_Meeting)) 中合并到主分支。

**延迟大写（Deferred Big Writes）**：与混合分配器配合，针对 HDD 场景下 4K 最小分配单元的写放大问题，在 [4月性能会议](/posts/2020/2020-04-16_-_-_Ceph_Performance_Meeting)) 中合并。

**BlueFS 缓冲 I/O 默认禁用**：[3月性能会议](/posts/2020/2020-03-26_-_-_Ceph_Performance_Meeting)) 发现 OSD 在缓存达到限制后会触发内核交换，严重影响性能，决定禁用 BlueFS 缓冲 I/O。

**Pacific 规划**（[CDS Pacific 性能专题](/posts/2020/CDS_Pacific_-_Performance))）：
- Adam 的 Column Family Sharding（改善写放大和空间放大）
- 基于缓存年龄的竞价机制（Cache Age Based Biding）
- O 节点数据结构瘦身（预计带来10-20%改进）

### 3.3 RGW（RADOS Gateway）

**Octopus 中的 RGW 改进**：
- 动态分片（Dynamic Resharding）优化
- 多站点同步流程改进
- 垃圾回收使用简单块，减少 RocksDB 瓶颈

**Pacific 规划**（[CDS Pacific RGW 专题](/posts/2020/CDS_Pacific_-_RGW))）：
- **动态分片**确认为优先开发项目，文档和设计已就绪
- **OMAP 卸载**：减少 RocksDB 压力
- **类 FIFO 实现**：用于数据日志，[5月性能会议](/posts/2020/2020-05-07_-_-_Ceph_Performance_Meeting)) 中 Adam 提交了相关 PR
- **多站点监控增强**：Dashboard 集成多站点同步状态
- **对象模型重构**：数据库后端集成和策略层构建
- **RBD 与 RGW 集成**：通过 RGW 暴露 RBD 快照

### 3.4 CephFS

**Octopus 中的 CephFS 改进**：
- 多文件系统（Multi FS）支持增强
- 快照调度和统计功能

**Pacific 规划**（[CDS Pacific CephFS 专题](CDS_Pacific_-_CephFS)）：
- **快照复制（Snapshot Replication）**：采用 arsenic 作为初始方案，创建新守护进程处理同步
- **多 MDS 前向扫描（Multi MDS Forward Scrub）**：采用冻结所有导出的方式实现
- **FS top功能**：CLI 包装器编写
- **Ganesha 集成**：PR 清理和合并

**IO 500 基准测试**：全年持续进行，[3月性能会议](/posts/2020/2020-03-12_-_-_Ceph_Performance_Meeting)) 报告排名第9，接近第8，主要瓶颈在 MDS 锁争用和内核客户端性能。

### 3.5 RBD

**Pacific 规划**（[CDS Pacific RBD 专题](/posts/2020/CDS_Pacific_-_RBD))）：
- **异步重构**：exclusive lock 代码的异步化，对性能至关重要
- **librbd 缓存机制**：对象 ID 哈希映射缓存，减少 CPU 使用
- **客户端加密**：在 librbd 中实现客户端侧加密
- **RBD NBD 守护进程**：适应 Kubernetes 和容器环境
- **即时恢复功能**：从 S3/Swift 备份进行即时恢复

**LibRBD I/O 流分析**：[10月 Code Walkthrough](/posts/2020/Ceph_Code_Walkthrough_-_LibRBD_I_O_Flow_Pt._1_2020-10-27)) 由 RBD Tech Lead Jason Dillman 主讲，系统梳理了从 librbd API 到 OSD 的完整 I/O 路径，包括 I/O 分发层的各子组件（排队层、QoS 层、独占锁层、缓存层、加密层、日志层等）。

### 3.6 Orchestrator / cephadm

Orchestrator 是2020年工程投入最大的运维方向，全年保持每周例会。

**主要进展：**

- **cephadm 成为主推部署工具**：[CDS Pacific Orchestrator 专题](CDS_Pacific_-_Orchestratorcephadm_rook) 确认 cephadm 将成为 Ceph 的统一部署工具，支持容器化部署，提供统一 CLI，并集成到 Dashboard。
- **OSD 生命周期管理**：全年持续讨论 OSD 移除、替换、排空（drain）流程的简化，[1月](/posts/2020/2020-01-08_-_-_Ceph_Orchestration_Meeting)) 提出两阶段操作方案，[4月](/posts/2020/2020-04-20_-_-_Ceph_Orchestration_Meeting)) 讨论了调度器行为调整。
- **CLI 重构**：[5月会议](/posts/2020/2020-05-18_-_-_Ceph_Orchestration_Meeting)) 讨论了统一 `apply` 和 `daemon add` 命令，简化 CLI 设计。
- **Prometheus 高可用**：[4月会议](/posts/2020/2020-04-20_-_-_Ceph_Orchestration_Meeting)) 讨论了在多节点部署 Prometheus 的高可用方案。
- **Rook 集成**：Python 客户端库迁移到独立仓库，建立夜间自动化测试，[4月](/posts/2020/2020-04-27_-_-_Ceph_Orchestration_Meeting)) 讨论了 CI 集成策略。
- **Drive Group 管理**：[2月](/posts/2020/2020_02_03_-_-_Ceph_Orchestration_Meeting)) 深入讨论了 Drive Group 的持久性、幂等性和版本控制设计。

**Pacific 目标**（[CDS Pacific Orchestrator 专题](/posts/2020/CDS_Pacific_-_Orchestrator_cephadm_rook))）：重点在于修复 Octopus 中的粗糙边缘，改善开发者体验，完善文档，增强 OSD 管理和升级流程。

### 3.7 Dashboard

Dashboard 在Octopus 中完成了界面重构和用户管理增强。全年与 Orchestrator 深度集成，[5月会议](/posts/2020/2020-05-04_-_-_Ceph_Orchestration_Meeting)) 讨论了将 Dashboard 集成到 cephadm 测试套件中。

### 3.8 RADOS

**Pacific 规划**（[CDS Pacific RADOS 专题](/posts/2020/CDS_Pacific_-_RADOS))）：
- **数据复制优化**：新哈希函数提高数据放置效率
- **分布式追踪（Distributed Tracing）**：基于 Jaeger 的 OSD 追踪
- **自动化恢复设置（Simple Adaptive Recovery Settings）**：重新评估并计划实现
- **管理器模块优化**：减少 CPU 周期和冗余信息处理
- **平衡器改进**：考虑主 OSD 数量的性能优化
- **Python 子解释器**：解决管理器模块中的全局状态冲突

### 3.9 性能工程

2020年建立了系统化的性能工程体系：

- **性能 CI 框架**：[4月](/posts/2020/2020-04-_23_-_-_Ceph_Performance_Meeting)) 和 [5月](/posts/2020/2020-05-07_-_-_Ceph_Performance_Meeting)) 会议讨论了 Jenkins + CBT 集成，支持 FIO 和 Rados bench 测试，建立长期性能基线。
- **RocksDB 升级**：[5月](/posts/2020/2020-05-14_-_-_Ceph_Performance_Meeting)) 讨论升级到 6.5.1，包含数据损坏修复和迭代器速度改进，但同期也发现了升级引入的数据损坏问题，需谨慎处理。
- **AVX2 编码优化**：[5月](/posts/2020/2020-05-21_-_-_Ceph_Performance_Meeting)) 两个 PR 针对缓冲列表编码解码，预计部分场景速度提升2倍。
- **PG 自动缩放**：默认 PG 数量增加到32，[1月](/posts/2020/2020-01-23_-_-_Ceph_Performance_Meeting)) 和 [1月底](/posts/2020/2020-01-30_-_-_Ceph_Performance_Meeting)) 会议讨论了相关调整。

## 四、社区生态

### 4.1 线上活动转型

受 COVID-19 影响，2020年 Ceph 社区活动全面转向线上：

- **Ceph Tech Talk 系列**：[1月 MeerKAT 射电望远镜数据存储](/posts/2020/2020-Jan-23_-_-_Ceph_Tech_Talk_-_Ceph_for_Storing_MeerKAT_Radio_Telescope_Data)) 和 [5月 Octopus 新特性介绍](/posts/2020/2020-05-28_-_-_Ceph_Tech_Talk_-_What_s_New_In_Octopus)) 是两场重要的线上技术分享。
- **CDS Pacific 虚拟峰会**：2020年4月以虚拟形式召开，覆盖 CephFS、Orchestrator/cephadm/Rook、性能、RADOS、RBD、RGW 等所有核心组件的 Pacific 规划。
- **Ceph Science User Group**：[1月](/posts/2020/2020-01-22_-_-_Ceph_Science_User_Group_Meeting))、[3月](/posts/2020/2020-03-25_-_-_Ceph_Science_User_Group_Meeting))、[5月](/posts/2020/2020-05-27_-_-_Ceph_Science_User_Group_Meeting)) 持续举办，聚焦科学计算场景下的 Ceph 应用。

### 4.2 科学计算用户群体

科学计算是2020年 Ceph 社区的重要用户群体：

- **MeerKAT 射电望远镜**（[Tech Talk](/posts/2020/2020-Jan-23_-_-_Ceph_Tech_Talk_-_Ceph_for_Storing_MeerKAT_Radio_Telescope_Data))）：南非 SKA 项目自2018年使用 Ceph 生产集群，存储数亿个天文观测对象，通过 S3 接口提供数据服务。
- **Sanger Institute**：维护大规模 Ceph 集群用于基因组学数据存储。
- **Diamond Light Source**：同步辐射光源设施使用 Ceph 存储实验数据。
- **马里兰大学**：[5月科学用户组会议](/posts/2020/2020-05-27_-_-_Ceph_Science_User_Group_Meeting)) 分享了 NVMe 驱动器上的数据库日志问题和 MDS 崩溃处理经验。

### 4.3 文档社区（DocUBetter）

文档工作在2020年持续推进，全年保持双周例会：

- **Google Season of Docs**：[4月](2020-04-22_-_-_CephDocubetter_Meeting) 和 [5月](/posts/2020/2020-05-13_-_-_Ceph_DocUBetter_Meeting)) 讨论了申请参与，最终未能入选，但推动了新手引导文档的编写。
- **文档基础设施**：讨论了将文档迁移到 readthedocs，修复 ceph.com 的 403/404 错误，改进网站搜索功能。
- **封装定义倡议**：[5月](/posts/2020/2020-05-13_-_-_Ceph_DocUBetter_Meeting)) 提出为每个概念提供简洁定义，帮助新手理解。
- **PG 修复文档**：[1月](/posts/2020/2020-01-22_-_-_Ceph_DocUBetter_Meeting)) 和 [2月](2020-02-12_-_-_CephDocubetter_Meeting) 持续完善 PG 不一致性处理文档。

### 4.4 测试基础设施

[测试会议](/posts/2020/2020-01-21_-_-_Ceph_Testing_Meeting)) 全年持续推进测试体系建设：

- CentOS 7 向 CentOS 8 的测试环境迁移
- openSUSE 15.1 支持
- Luminous 版本维护状态讨论
- [3月](/posts/2020/2020-03-24_-_-_Ceph_Testing_Meeting)) 讨论了 CI 改进提案，包括自动触发集成测试和基于文件变更的测试范围调整

### 4.5 合作伙伴动态

- **Red Hat**：主要贡献者，主导 cephadm、BlueStore、RBD 等核心组件开发
- **SUSE**：参与 Orchestrator 和 Dashboard 开发
- **Rook 社区**：与 Ceph Orchestrator 深度集成，全年持续推进 Kubernetes 上的 Ceph 部署
- **SKA/SARAO**：MeerKAT 项目的重要用户，推动对象存储在科学计算场景的应用

## 五、下一年（2021年）展望

基于2020年的讨论和规划，2021年 Ceph 社区的技术路线和方向可以预判如下：

### 5.1 Pacific 版本发布（预计2021年3月）

Pacific 将是继 Octopus 之后的下一个主要版本，核心目标：
- **cephadm 成熟化**：成为生产级统一部署工具，完善 OSD 生命周期管理
- **BlueStore 性能提升**：Column Family Sharding、缓存优化、节点数据结构瘦身
- **RGW 动态分片 GA**：解决大规模 bucket 的性能瓶颈
- **CephFS 快照复制**：多站点 CephFS 数据保护能力
- **Crimson 里程碑**：达到可测试的基本功能完整性

### 5.2 Crimson/SeaStor 进入关键阶段

2020年奠定了 SeaStor 核心子系统的基础，2021年预计：
- LBA 树、事务管理器、段管理器达到功能完整
- 垃圾回收和段恢复机制实现
- 与经典 OSD 的性能对比测试
- 面向社区的早期预览

### 5.3 SMR 磁盘支持

[Octopus Tech Talk](/posts/2020/2020-05-28_-_-_Ceph_Tech_Talk_-_What_s_New_In_Octopus)) 明确提到 Pacific 版本将引入新的后端存储以支持 SMR（叠瓦式磁记录）磁盘，这将是存储硬件适配的重要方向。

### 5.4 性能 CI 体系化

基于2020年建立的 Jenkins + CBT 框架，2021年将进一步完善长期性能基线，实现性能回归的自动检测。

### 5.5 容器化生态深化

Kubernetes 上的 Ceph 部署（通过 Rook 和 cephadm）将继续成为社区重点，预计在 Pacific 中达到生产就绪状态。
