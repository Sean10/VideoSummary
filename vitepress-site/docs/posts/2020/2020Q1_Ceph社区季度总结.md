# Ceph 社区 2020Q1 季度进展报告

## 1. 本季度重点议题

本季度 Ceph 社区围绕以下几个核心方向持续深入讨论：

**Crimson/SeaStar OSD 新架构**
Crimson 项目是本季度最活跃的研发方向之一。[2020-01-07 会议](/posts/2020/2020-01-07_-_-_Crimson_SeaStor_OSD_Weekly_Meeting))和[2020-01-14 会议](/posts/2020/2020-01-14_-_-_Crimson_SeaStor_OSD_Weekly_Meeting))持续推进 B+树异步实现、事务处理机制、以及如何减少写放大问题。团队在 SeaStar 网络栈集成、内存零拷贝优化等方面投入了大量精力。

**Orchestrator 与部署自动化**
Orchestrator 相关会议贯穿整个季度（[1月8日](2020-01-08_-_Ceph_Orchestration_Meeting)、[1月13日](/posts/2020/2020-01-13_-_-_Ceph_Orchestration_Meeting))、[1月20日](/posts/2020/2020-01-20_-_-_Ceph_Orchestration_Meeting))、[1月27日](/posts/2020/2020-01-27_-_-_Ceph_Orchestration_Meeting))），重点讨论 OSD 生命周期管理（移除、替换、排空）、cephadm 与 Rook 的协作边界，以及 Python 客户端库的独立化。

**PG 自动缩放与性能调优**
[1月16日](/posts/2020/2020-01-16_-_-_Ceph_Performance_Meeting))、[1月23日](/posts/2020/2020-01-23_-_-_Ceph_Performance_Meeting))、[1月30日](2020-01-30_-_Ceph_Performance_Meeting)的性能会议持续关注 PG autoscaler 的默认参数调整、BlueStore 空间放大问题，以及 buffer list 优化。

---

## 2. 技术亮点

### Crimson/SeaStar OSD
- 正在从零开始实现 B+树，高度定制化以适配 Ceph 的事务语义，不依赖外部库。需要同时支持物理地址和逻辑地址两个版本，以应对不同存储后端。
- 探索混合逻辑时钟（HLC）实现轻量级快照的可行性。
- 讨论了 TCP/IP 栈中套接字在多核环境下的放置优化策略，目标是实现真正的零拷贝 I/O。
- 详见 [2020-01-14Crimson 会议](/posts/2020/2020-01-14_-_-_Crimson_SeaStor_OSD_Weekly_Meeting))。

### BlueStore 性能优化
- 针对 blob 空间放大问题，讨论了将最小分配大小从 64k 调整为 4k 的方案，但需权衡 HDD 场景下的性能回退风险。Octopus 版本计划若无法及时解决分配器问题，HDD 将回退到 64k。
- Igor 提交了通过改变数据结构减少缓存 PG 内存占用的 PR，以及简化 pin/unpin 逻辑的 PR（解决了之前修复引入的竞态条件）。
- 详见 [1月23日性能会议](/posts/2020/2020-01-23_-_-_Ceph_Performance_Meeting))。

### PG Autoscaler
- 将默认 PG 数量从原有值提升至 32 的PR 已合并，目标是改善初始数据分布和 OSD 响应性。
- 在 OpenShift 环境中测试发现数据分布不均问题，通过调整目标比率并启用 PG balancer 得到改善。
- 讨论了根据 PG 数量自动选择 PG log 长度以优化内存使用。
- 详见 [1月16日](2020-01-16_-_Ceph_Performance_Meeting)和[1月30日性能会议](/posts/2020/2020-01-30_-_-_Ceph_Performance_Meeting))。

### Orchestrator / cephadm
- 提出新的 OSD 排空管理模块，可被 Rook 和 cephadm 直接消费，也可供 Dashboard 独立调用。排空流程包括设置权重为零、等待 OSD 清空等步骤，并引入 safe command API。
- Ceph Python 客户端库决定独立为单独仓库（置于 Rook 组织下），通过 pip 安装，并使用 GitHub Actions 保持与 CRD 变更同步。
- 停用旧的 trailer bots，统一迁移到新 Orchestrator 项目。
- 详见 [1月13日](/posts/2020/2020-01-13_-_-_Ceph_Orchestration_Meeting))和[1月27日 Orchestrator 会议](2020-01-27_-_Ceph_Orchestration_Meeting)。

### RGW
- Erica 添加的 RGW 过滤逻辑通过 QA 测试，但需进一步调整。
- 讨论了允许 zone 配置 index charts（增加 bucket shards 数量）的 PR。

## 3. 重要决策与里程碑

- **Rook 1.2 发布**：[1月8日 Orchestrator 会议](/posts/2020/2020-01-08_-_-_Ceph_Orchestration_Meeting))提到 Rook 1.2 已发布，并计划进行第一次补丁发布。安全审查发现的敏感信息日志记录问题已有 PR 处理。
- **Luminous 版本维护决策**：[测试会议](/posts/2020/2020-01-21_-_-_Ceph_Testing_Meeting))讨论了 Luminous 版本的维护状态，决定尽快完成其测试和发布，并讨论了是否继续长期支持的问题。
- **Nautilus CVE 热修复**：即将发布两个 CVE 的安全更新，热修复流程已明确。
- **取消每日 Orchestrator 站立会议**：改为每周一次，减少会议开销。
- **Pacific 版本方向确定**：[CDS Pacific Orchestrator 会议](/posts/2020/CDS_Pacific_-_Orchestrator_cephadm_rook))明确 Pacific 将以修复 Octopus 遗留问题为主，而非增加新功能，重点包括 OSD 管理、升级流程和开发者体验改善。

## 4. 社区动态

### 科学用户组
[1月22日科学用户组会议](/posts/2020/2020-01-22_-_-_Ceph_Science_User_Group_Meeting))汇聚了多个大型科学计算用户：
- Liam Monahan 分享了 3.5PB 集群在机器学习场景的运维经验。
- Tom Bennett 介绍了南非 MeerKAT 射电望远镜的 Ceph 存储方案（数亿个对象），详细内容见 [Tech Talk 专题演讲](/posts/2020/2020-Jan-23_-_-_Ceph_Tech_Talk_-_Ceph_for_Storing_MeerKAT_Radio_Telescope_Data))。MeerKAT 自 2018 年起使用 Ceph 生产集群，当前运行 Luminous，计划升级至 Nautilus，并测试 EC 池。
- 下次科学用户组会议计划三月举行，时间将参考 Cephalocon 安排。

### 文档工作
[DocUBetter 会议](/posts/2020/2020-01-08_-_-_Ceph_DocUBetter_Meeting))和[1月22日文档会议](/posts/2020/2020-01-22_-_-_Ceph_DocUBetter_Meeting))持续推进：
- 完成 Ceph 入门指南 PR。
- 完善 PG 不一致性修复文档，补充 "stat mismatch" 场景的处理步骤。
- 计划建立文档请求热线，并研究自动分配文档相关 bug 的机制。
- 计划与 Brad合作编写 RADOS 速查表。

### 测试基础设施
[测试会议](/posts/2020/2020-01-21_-_-_Ceph_Testing_Meeting))讨论了：
- CentOS 7 → CentOS 8 测试环境迁移进展及遇到的失败问题。
- openSUSE 15.1 在 Sepia 测试环境中的支持推进。
- Jenkins 发布流程改进，包括分支和发布管理的优化。

## 5. 下季度展望

基于本季度讨论，预计 2020Q 将重点推进以下方向：

1. **Crimson OSD 持续演进**：B+树异步实现将进入更完整的测试阶段，恢复机制（日志处理、回填）的实现将是重点，参见 [10月 Crimson 会议](/posts/2020/2020-10-21_-_-_Crimson_SeaStor_OSD_Weekly_Meeting))中对恢复机制的前瞻讨论。

2. **Octopus 版本发布准备**：BlueStore 最小分配大小的最终决策、PG autoscaler 的进一步稳定化，以及 Nautilus CVE 热修复的跟进。

3. **cephadm 成熟化**：OSD 排空/替换 API 的完整实现，Python 客户端库独立仓库的建立和 CI 集成，以及 cephadm 在 Pacific 中作为主要部署工具的地位确立。

4. **Cephalocon 2020**：社区活动将为各子项目提供集中讨论和路线图对齐的机会，科学用户组计划在此期间组织 Birds of a Feather 会议。

5. **测试环境现代化**：完成 CentOS 8 迁移，推进 openSUSE 15.1 支持，持续改进 CI 基础设施。
