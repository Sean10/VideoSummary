# Ceph 2023 年度社区进展报告

## 一、全年技术演进概览

2023年是Ceph社区在架构演进和生态建设上极为关键的一年。这一年的核心主题可以概括为：**Reef版本的正式发布、Squid版本的规划启动、Crimson/SeaStore的持续推进，以及IBM收购Red Hat Ceph团队后的社区整合**。

### 1.1 治理模式变革

2023年初，Ceph项目完成了从单一领导模型向**理事会（Council）模型**的转变。新的治理结构由各组件负责人选举产生，负责项目的技术治理和社区管理。这一变化标志着Ceph社区走向更加开放和分布式的协作模式。详见 [Ceph Days NYC 2023 - State of the Cephalopod](/posts/2023/Ceph_Days_NYC_-_State_of_the_Cephalopod))。

### 1.2 IBM 整合与开源承诺

2023年1月1日，IBM正式将Ceph团队纳入其存储部门。IBM明确承诺：
- 坚持**开源优先**战略，保证Ceph 100%开源和上游开发
- 成为Ceph基金会的**Premium Member**
- 安全修复将持续回溯到上游，确保所有版本保持同等安全水平

IBM存储部门CTO Vincent Shu在 [Ceph Days NYC 2023 - Ceph Crossing the Chasm](/posts/2023/Ceph_Days_NYC_2023_-_Ceph_Crossing_the_Chasm)) 中详细阐述了IBM的存储愿景：构建可编程、统一、API驱动的软件定义存储平台，支持混合云环境，并引入AI Ops等技术加速价值实现。

## 二、重大里程碑

### 2.1 Reef 版本发布

Reef是2023年最重要的版本里程碑。原计划3月发布，因实验室故障推迟至**2023年6月**正式发布。Reef版本的主要特性包括：

- **m-clock调度器**正式引入，改进QoS（服务质量）
- **NVMe-oF Gateway**初始版本（实验性）
- Dashboard重大改进，包括新登录页面、自动化管理、服务器端加密
- RGW多站点功能增强
- BlueStore弹性共享Blob（Elastic Shared Blobs）特性，已回溯到Quincy和Reef版本

详见 [CDS Squid - Dashboard](/posts/2023/CDS_Squid_-_Dashboard)) 和 [Ceph Days NYC - State of the Cephalopod](/posts/2023/Ceph_Days_NYC_-_State_of_the_Cephalopod))。

### 2.2 Squid 版本规划启动

2023年下半年，社区启动了下一个主要版本**Squid**的规划工作（CDS = Ceph Developer Summit）。各组件团队分别召开了专项规划会议，确定了Squid周期的开发重点：

- **Cephadm**：SMB支持、NVMe-oF集成、升级历史记录
- **RADOS**：读取均衡器自动化、可用性跟踪、Erasure编码简化
- **RGW**：D4N数据缓存、异步重构、多站点增强
- **RBD**：镜像一致性组、性能改进
- **BlueStore**：碎片整理原语、自定义写前锁

详见 [CDS Squid - RADOS](/posts/2023/CDS_Squid_-_RADOS))、[CDS Squid - RGW](/posts/2023/CDS_Squid_-_RGW))、[CDS Squid - BlueStore](/posts/2023/CDS_Squid_-_BlueStore))。

## 三、核心组件年度进展

### 3.1 BlueStore

BlueStore在2023年进入了"V2演进"阶段，由Adam Kupczyk（IBM）和Mark Nelson（Clyso）主导。主要工作包括：

**已完成/进行中的改进：**
- **弹性共享Blob（Elastic Shared Blobs）**：优化克隆对象时的效率，已回溯到Quincy和Reef
- **分配器模拟器**：通过GSoC合作项目开发，用于预测分配器更改对已部署OSD的影响
- **碎片整理原语**：在BlueStore中引入对象碎片整理的基本机制，创建空闲周期队列
- **Codel算法**：平衡延迟和吞吐量，通过批处理事务提高性能
- **自定义写前锁（Write-Ahead Lock）**：在BlueStore级别实现，减少写操作延迟

**重要Bug修复：**
- 修复了长期存在的内存泄漏问题（自2017年存在于代码中），该问题在Octopus版本因auto-scaler默认设置更改而加剧。详见 [Bug of the Year - A Memory Leak Reboot Could Not Help With](/posts/2023/Bug_of_the_Year_-_A_Memory_Leak_Reboot_Could_Not_Help_with_-_Radoslaw_Zarzynski_IBM))。

**性能优化：**
- RocksDB升级至7.8.3，改进range delete操作
- 有界迭代器（Bounded Iterators）优化，解决RocksDB性能下降问题
- BlueFS增量日志更新优化

详见 [BlueStore V2 - An Evolutionary Step Forward](/posts/2023/BlueStore_V2_-_an_Evolutionary_Step_Forward_-_Adam_Kupczyk_IBM_Mark_Nelson_Clyso_GmbH)) 和 [CDS Squid - BlueStore](/posts/2023/CDS_Squid_-_BlueStore))。

### 3.2 Crimson / SeaStore

Crimson（新一代OSD实现）和SeaStore（为Crimson设计的对象存储后端）在2023年持续推进，但仍处于**实验阶段**。

**架构特点：**
- 采用无共享（Shared-Nothing）架构，基于SeaStar框架
- SeaStore（c-store）设计目标：支持QLC/ZNS闪存、HDD及高性能NVMe设备
- 内部元数据结构：LBA B树和back-ref B树，支持透明数据块移动

**2023年主要进展：**
- 多核Messenger（Multi-core Messenger）开发，支持多OSD并发
- 内存泄漏问题修复（与CPU核心间内存管理相关）
- Arch64（ARM）平台验证，华为团队贡献了ARM架构上的优化，禁用LSE指令后小包性能提升50%
- 热数据缓存（Hot Data Cache）设计讨论
- 克隆（Clone）机制原型开发
- 下游CI框架开始支持Crimson构建

**挑战：**
- 与经典BlueStore相比，多节点集群测试中性能仍有差距
- 构建基础设施问题（OS 8构建失败、Java绑定问题）影响了测试进度

详见 [Ceph Code Walkthroughs - SeaStore](/posts/2023/Ceph_Code_Walkthroughs_-_SeaStore))、[Ceph Crimson Verification on Arch64](/posts/2023/Ceph_Crimson_Verification_on_AArch64_-_Rixin_Luo_Huawei)) 以及系列 [Crimson/SeaStore 周会记录](/posts/2023/Ceph_Crimson_SeaStore_Meeting_2023-01-11))。

### 3.3 RGW（RADOS Gateway）

RGW在2023年的工作重点是**多站点增强、性能优化和新协议支持**。

**多站点（Multi-site）：**
- Bloomberg完成了跨数据中心灾难恢复部署，65PB集群跨四个数据中心，详见 [Ceph Multi-Site at Scale - Bloomberg's Disaster Recovery Journey](/posts/2023/Ceph_Multi-Site_at_Scale_-_Bloomberg_s_Disaster_Recovery_Journey))
- 计划将桶索引日志从omap迁移，产品化归档区域同步模块
- 多站点复制性能优化，引入并行同步

**新特性：**
- **NVMe-oF Gateway**：初始版本在Reef中发布，支持TCP/RDMA/Fiber Channel，实验室测试性能达原生性能的92%，详见 [Ceph Days NYC 2023 - NVMe-over-Fabrics support for Ceph](/posts/2023/Ceph_Days_NYC_2023_-_NVMe-over-Fabrics_support_for_Ceph))
- **D4N数据缓存**：开发中，计划在Squid版本中增加灵活性
- **S3 Select扩展**：计划支持Parquet和JSON格式
- **OpenTelemetry/Jaeger集成**：端到端分布式追踪
- **Lua脚本支持**：动态调整存储类别，优化混合介质存储管理，详见 [Ceph Days NYC - Optimizing RGW Object Storage Mixed Media through Storage Classes and Lua Scripting](/posts/2023/Ceph_Days_NYC_-_Optimizing_RGW_Object_Storage_Mixed_Media_through_Storage_Classes_and_Lua_Scripting))
- **Arrow Flight前端**：低延迟数据传输RPC框架（实验性）

**异步重构：**
- 持续进行异步模型转换，减少RGW线程池大小
- 探索基于C++20协程的多站点原型

详见 [Ceph Object Storage Overview Capabilities and Future Plans](Ceph_Object_Storage_Overview_Capabilities_and_Future_Plans_-_Matt_BenjaminIBM) 和 [CDS Squid - RGW](/posts/2023/CDS_Squid_-_RGW))。

### 3.4 CephFS

CephFS在2023年的工作重点是**管理工具完善和稳定性提升**。

**Dashboard集成：**
- 卷管理、子卷管理、快照管理功能开发
- CephFS管理功能持续完善

**SQL on Ceph：**
- 通过libcephsqlite库将SQLite数据库分布式存储在RADOS上
- Ceph Manager已开始使用libcephsqlite进行数据持久化（设备健康模块）
- 详见 [Ceph Days NYC 2023 - SQL on Ceph](/posts/2023/Ceph_Days_NYC_2023_-_SQL_on_Ceph))

**审计日志：**
- 讨论了在RADOS中持久化存储审计日志的需求，开发新的RADOS管理模块

### 3.5 Dashboard

Dashboard在2023年进行了大量改进，重点是**用户体验和功能完整性**：

- 新登录页面和UI重设计
- RGW概览仪表盘（展示RGW实体数量、多站点指标）
- 集群升级管理界面
- CephFS管理功能
- 性能优化（特别是处理大量OSD时）
- 端到端（E2E）测试覆盖率提升

详见 [CDS Squid - Dashboard](/posts/2023/CDS_Squid_-_Dashboard))。

### 3.6 Cephadm（编排器）

Cephadm在2023年的主要工作：

- **SMB支持**：计划使用Samba替代NFS，在Squid周期完成
- **NVMe-oF集成**：计划在Squid发布周期完成开发测试
- **升级历史记录**：跟踪集群升级路径和失败记录
- **证书管理**：讨论引入统一Secret Store管理证书、SSH密钥和码
- **代码重构**：Python Black格式化工具集成，目录结构优化
- **IPv6支持**：持续改进，但受限于测试环境

详见 [CDS Squid - Cephadm](/posts/2023/CDS_Squid_-_Cephadm))。

### 3.7 RBD

RBD在2023年重点解决**镜像可靠性问题**并推进新特性：

**高优先级Bug修复：**
- 同步克隆图像时的数据损坏风险
- 丢弃操作同步问题（空间未被正确释放）
- 块列表错误传播问题
- 强制提升操作的无限等待问题

**新特性：**
- 快照镜像一致性组
- 流式快照增量（性能改进）
- 从非Ceph源进行实时迁移支持
- Windows NBD驱动改进（持久保留和多路复用）

详见 [CDS Squid - RBD](/posts/2023/CDS_Squid_-_RBD))。

### 3.8 Telemetry

Telemetry模块在2023年持续扩展，约**2500个集群**参与，报告了近**1 Exabyte**的存储容量。

主要进展：
- 崩溃报告自动同步到Redmine问题跟踪系统
- 集群内容分析工具开发（对象大小分布、BlueStore碎片化信息）
- Dashboard使用数据分析
- 崩溃报告分组算法优化

详见 [Ceph Crash Telemetry - Observability in Action](/posts/2023/Ceph_Crash_Telemetry_-_Observability_in_Action_-_Yaarit_Hatuka_IBM)) 和 [CDS Squid - Telemetry](/posts/2023/CDS_Squid_-_Telemetry))。

## 七、2024年展望

基于2023年的讨论和规划，可以推断2024年（Squid版本周期）的主要方向：

### 7.1 Squid版本特性落地
- **SMB支持**正式进入Ceph，通过Cephadm管理Samba服务
- **NVMe-oF Gateway**从实验性走向生产就绪，引入Discovery Service和身份验证
- **读取均衡器**自动化集成到平衡器管理模块
- **BlueStore碎片整理**基本原语完成

### 7.2 Crimson/SeaStore成熟化
- 多核Messenger完成，支持真正的无共享架构
- 与经典OSD的性能差距持续缩小
- 更多工作负载类型支持（RBD随机读写）

### 7.3 AI存储场景深化
- 随着AI训练数据需求爆发，Ceph在AI/ML存储场景的优化将成为重要方向
- GPU Direct Storage、高吞吐对象存储等特性受到关注

### 7.4 运维自动化提升
- Cephadm继续向"零接触"运维演进
- Telemetry数据驱动的智能配置建议
- 证书管理和安全自动化

### 7.5 社区持续扩展
- IBM主导下的企业级功能增强
- 与Kubernetes生态（Rook、CSI）的深度集成
- 亚太地区（中国、日本、韩国）社区活跃度提升

---

## 总结

2023年是Ceph社区在**组织架构、技术演进和生态建设**三个维度同步推进的重要一年。IBM的加入带来了企业级资源和安全管理经验；Reef版本的发布标志着多年积累的技术改进正式落地；Crimson/SeaStore虽仍在实验阶段，但已展现出下一代OSD架构的清晰轮廓；而Bloomberg、CERN等大型用户的实践案例，则为社区提供了宝贵的生产经验反馈。

进入2024年，随着Squid版本规划的全面展开，Ceph将在NVMe-oF、SMB支持、AI存储等新兴领域持续发力，同时在可用性、文档和用户体验方面持续改善，以吸引更广泛的用户群体。
