# Ceph 社区季度进展报告 — 2015 Q4

---

## 1. 本季度重点议题

本季度材料集中在以下几个反复出现的技术方向：

**存储性能优化**是本季度最突出的主题。从网络层（10GbE 已不足够）到存储介质层（全闪存），再到 Ceph 内核的数据路径优化，多个演讲都在探讨如何突破性能瓶颈。详见 [Sudarshan_Ramachandran_--_When_10GbE_is_Not_Enough](/VideoSummary/2015/11/13/Sudarshan_Ramachandran_--_When_10GbE_is_Not_Enough/) 和 [Venkat_Kolli_--_Ceph_on_All-Flash_Storage](/VideoSummary/2015/11/13/Venkat_Kolli_--_Ceph_on_All-Flash_Storage/)。

**Erasure Coding 与缓存分层**是另一个核心议题，涉及纠删码的配置选择、缓存池与分层存储的性能权衡，以及与 RBD 的兼容性问题。详见 [Samual_Just_--_Recovery_erasure_coding_cache_tiering](/VideoSummary/2015/11/10/Samual_Just_--_Recovery_erasure_coding_cache_tiering/)。

**Ceph 在科研与企业场景的落地**也是本季度的重要方向，包括 Monash 大学的备份存储部署、软件定义一切（Software-Defined Everything）的 PoC 实践，以及科研 ICT 对规模和渗透性的特殊需求。

**社区建设与治理**方面，本季度有明确的社区更新报告，涵盖治理结构、活动规划和开发者生态。

---

## 2. 技术亮点

### 全闪存存储优化

[Venkat_Kolli_--_Ceph_on_All-Flash_Storage](/VideoSummary/2015/11/13/Venkat_Kolli_--_Ceph_on_All-Flash_Storage/) 展示了 Sandisk 针对无限闪存系统（InfiniFlash）对 Ceph 进行的深度优化成果：

- 优化方向：数据路径、锁优化、队列优化
- 性能结果：读取约 250 万 IOPS，写入约 100 万 IOPS，延迟约 2ms，相比优化前提升 10 倍以上
- 计划开源新开发的 Key-Value 存储引擎并集成到 Ceph 中（这是 BlueStore 方向的早期探索信号）
- 与 Mellanox 合作优化网络层性能

### 高速网络与 RDMA 集成

[Sudarshan_Ramachandran_--_When_10GbE_is_Not_Enough](/VideoSummary/2015/11/13/Sudarshan_Ramachandran_--_When_10GbE_is_Not_Enough/) 指出 10GbE 已成为高性能 Ceph 集群的瓶颈，Melanox 提出的方案包括：

- 支持 25G/40G/50G 网络适配器和交换机
- RDMA 和 RoCE 技术将网络延迟降至微秒级
- 通过网络卸载技术释放 CPU 资源，提升整体 IOPS 和吞吐量

### Erasure Coding 与缓存分层

[Samual_Just_--_Recovery_erasure_coding_cache_tiering](/VideoSummary/2015/11/10/Samual_Just_--_Recovery_erasure_coding_cache_tiering/) 详细介绍了 RADOS 层的关键特性：

- CRUSH 算法支持多种数据放置策略（按数据类型、性能需求、访问频率）
- 缓存池支持将热点数据缓存到 SD，提升系统性能
- 纠删码（Erasure Coding）提高数据冗余和恢复效率
- 缓存分层（Cache Tiering）根据访问频率进行分层存储
- 快照和克隆功能的性能优化

### 软件定义一切 PoC

[Tomohiko_Kimura_--_Walk_Through_a_Software-Defined_Everything_PoC](/VideoSummary/2015/11/13/Tomohiko_Kimura_--_Walk_Through_a_Software-Defined_Everything_PoC/) 展示了 Ceph + OpenStack + MidoNet（SDN）的完整集成方案，用于欧洲某大型学术研究实验室，实现了计算、存储、网络资源的统一抽象管理。

### 调试工具体系

[Brad_Hubbard_--_Troubleshooting_Ceph](/VideoSummary/2015/11/13/Brad_Hubbard_--_Troubleshooting_Ceph/) 系统梳理了 Ceph 调试方法论，涵盖 `rados bench`、`perf dump`、`strace`、`gdb` 等工具链，为社区提供了完整的故障排查框架。

## 3. 重要决策与里程碑

**社区治理结构确立**：[Patrick_McGary_--_Ceph_Community_Update](/VideoSummary/2015/11/13/Patrick_McGarry_--_Ceph_Community_Update/) 宣布 Ceph 社区成立正式董事会，由 10 名成员组成，包含非商业成员代表（用户、学术界），Sage 担任项目领导，标志着 Ceph 社区治理走向正规化。

**用户委员会成立**：社区成员自发组织用户委员会，负责社区基础设施、Meetup、Swag 等事务，体现了社区自治能力的提升。

**Ceph Day Melbourne 举办**：[Ceph_Day_Melbourne_Promo](/VideoSummary/2015/11/17/Ceph_Day_Melbourne_Promo/) 和 [Ceph_Day_Melbourne_Roundtable_Q_A](/VideoSummary/2015/11/13/Ceph_Day_Melbourne_Roundtable_Q_A/) 记录了在 Monash 大学举办的 Ceph Day 活动，这是 Ceph 社区在亚太地区影响力扩展的重要里程碑。

**对象类（Object Class）功能推广**：社区明确将对象类作为重要特性推广，支持在存储节点上执行代码（如图像缩略图处理、日志清理），拓展了 Ceph 的应用边界。

**Key-Value 存储引擎开源计划**：Sandisk 宣布将开源其为全闪存优化开发的 KV 存储引擎，并计划集成到 Ceph 中，这是后续 BlueStore 发展的重要前置工作。

## 4. 社区动态

### Ceph Day Melbourne

本季度最重要的社区活动是在澳大利亚墨尔本 Monash 大学举办的 Ceph Day。活动吸引了来自 Red Hat、Monash 大学研究部门等机构的参与者，内容涵盖技术演讲、圆桌讨论和 Q&A 环节。详见 [Ceph_Day_Melbourne_Roundtable_Q_A](/VideoSummary/2015/11/13/Ceph_Day_Melbourne_Roundtable_Q_A/)，圆桌讨论涉及 Erasure Coding 配置、地理复制（Geo Replication）、多租户（Multi-tenancy）、监控工具选型（Calamari、Roma、USM）等实际部署问题。

### 社区生态扩展

根据 [Patrick_McGarry_--_Ceph_Community_Update](/VideoSummary/2015/11/13/Patrick_McGarry_--_Ceph_Community_Update/)：

- 社区连续两年参与 **Google Summer of Code**，持续培养新贡献者
- 参与 **Outreach Program**，承接 wiki迁移等社区基础设施任务
- 提供公用测试集群，降低社区成员的参与门槛
- 部署和编排工具生态持续完善，支持 Ansible、Chef、Puppet 及 Docker 容器化部署

### 科研机构参与

[Steve_Quenette_BlairBethwaite_--_Servicing_the_Fabric_and_the_Workshop](/VideoSummary/2015/11/13/Steve_Quenette_Blair_Bethwaite_--_Servicing_the_Fabric_and_the_Workshop/) 展示了科研机构对 Ceph 的深度使用，强调了科研 ICT 对自服务、多租户、质量服务（QoS）的特殊需求，以及 Ceph 与 OpenStack 结合构建科研基础设施的实践价值。

### 地理分布与国际化

[Ceph_Day_Melbourne_Roundtable_Q_A](/VideoSummary/2015/11/13/Ceph_Day_Melbourne_Roundtable_Q_A/) 提到马来西亚政府正在尝试 Ceph 地理复制方案，表明 Ceph 的用户群体已扩展至东南亚政府机构。

## 5. 下季度展望

基于本季度讨论内容，可以推断以下方向将在 2016 Q1 持续推进：

**BlueStore 方向加速**：Sandisk 开源 KV 存储引擎的计划，以及全闪存优化的持续投入，预示着 Ceph 将加快推进新一代本地存储后端的开发，以替代 FileStore 解决全闪存场景下的性能瓶颈。

**RDMA/RoCE 网络支持**：Mellanox 与 Ceph 社区的合作将深化，预计会有更多关于 Ceph 消息层支持 RDMA 的技术讨论和 PR 提交。

**Erasure Coding 成熟度提升**：缓存分层与纠删码的结合使用仍存在性能和兼容性问题，下季度预计会有针对性的优化工作，特别是与 RBD 的兼容性改进。

**监控与管理工具整合**：圆桌讨论中暴露了 Calamari、Roma、USM 等工具并存导致的选择困难，社区可能会推动监控工具的整合或明确推荐方案。

**亚太地区社区活动**：Ceph Day Melbourne 的成功举办预示着亚太地区将有更多社区活动，Ceph 在科研机构和政府机构的部署案例也将持续增加。

**自动化部署标准化**：多个演讲提及 Ansible、Puppet、Chef 等工具，社区可能会在下季度推动 ceph-ansible 等官方部署工具的标准化工作。
