# Ceph 社区季度进展报告：2015 Q3（7月–9月）

---

## 1. 本季度重点议题

本季度 Ceph 社区的技术讨论呈现出以下几条主线：

**性能优化**是贯穿全季度的核心主题。从 RADOS 层的尾延迟改进、OSD Pering 加速，到存储引擎选型（LevelDB vs RocksDB），再到内存分配器（Jemalloc vs TCMalloc）的对比测试，性能问题在多个会议中反复出现。详见 [2015-AUG-27 Ceph Tech Talks - Ceph Performance](/VideoSummary/2015/08/27/2015-AUG-27_--_Ceph_Tech_Talks_-_Ceph_Performance/) 和 [CDS Jewel -- RADOS Tail Latency Improvements](/VideoSummary/2015/08/03/CDS_Jewel_--_RADOS_Tail_Latency_Improvements/)。

**新存储后端探索**是另一条重要主线。NewStore（后演化为 BlueStore）的小对象存储优化、PMStore 实验性后端，以及 metadata-only journal mode 的算法设计，均在本季度密集讨论。

**RGW 多站点与多租户**成为对象存储方向的重点，涵盖多站点配置模型重构、数据同步机制改进、多租户命名空间隔离等议题。

**CephFS 稳定化**持续推进，包括 fsck/修复工具开发、IO hint 框架设计、starter tasks梳理等。

**安全与 QoS** 也在本季度进入议程，CephX 暴力破解防护和 RADOS QoS 策略均有专项讨论。

---

## 2. 技术亮点

### 2.1 存储引擎与后端

**NewStore 小对象优化**：[CDS Jewel -- Optimize newstore for massive small object storage](/VideoSummary/2015/08/04/CDS_Jewel_--_Optimize_newstore_for_massive_small_object_storage/) 讨论了将多个小对象合并为 64MB 大文件（类似 TFS 实现）的方案，以减少随机 I/O，并探讨了引用计数和 PG 锁的配合机制。

**PMStore 实验性后端**：[CDS Jewel -- PMStore](/VideoSummary/2015/08/03/CDS_Jewel_--_PMStore/) 介绍了基于非易失性存储（NVM）的实验性 OSD 后端，使用内存映射文件存储对象，对象索引在内存中维护并在启动时从块元数据重建，计划开源。

**Metadata-only Journal Mode**：[CDS Jewel -- RADOS metadata-only journal mode](/VideoSummary/2015/08/04/CDS_Jewel_--_RADOS_metadata-only_journal_mode/) 提出两种算法方案，核心权衡是"先写数据后提交元数据日志"与"先提交元数据日志后写数据"之间的一致性与性能取舍，计划通过仿真测试选型。

**存储引擎迁移**：[CDS Jewel -- RADOS Tail Latency Improvements](/VideoSummary/2015/08/03/CDS_Jewel_--_RADOS_Tail_Latency_Improvements/) 中讨论了用 RocksDB 替代 LevelDB，以解决压缩过程中的性能抖动问题。

### 2.2 RADOS 层改进

**Peering 加速**：[CDS Jewel -- Pering Speed Improvements](/VideoSummary/2015/08/03/CDS_Jewel_--_Peering_Speed_Improvements/) 分析了 Peering 过程中多轮往返（get-info、get-log、get-missing）的开销，提出利用历史信息预测上一次 interval 正确性、缓存信息避免重复获取等优化方向。

**RADOS QoS**：[CDS Jewel -- RADOS QoS](/VideoSummary/2015/08/03/CDS_Jewel_--_RADOS_QoS/) 讨论了基于 dmClock（EM 算法）的 I/O 调度器改进，支持为客户端配置最小/最大 IOPS，并探讨了 OSD 性能自动检测和网络 QoS 联动。

**多对象事务**：[CDS Jewel -- RADOS multi-object transaction support](/VideoSummary/2015/08/04/CDS_Jewel_--_RADOS_multi-object_transaction_support/) 提出基于两阶段提交协议的多对象事务机制，支持客户端定义事务主体和对象操作列表，并讨论了死锁检测和超时机制。

**Slopy Reads**：[CDS Jewel -- Sloppy Reads](/VideoSummary/2015/08/03/CDS_Jewel_--_Sloppy_Reads/) 探讨了允许客户端从非活动 OSD 读取数据以降低延迟的可能性，讨论了引入新存储池类型或参数来支持多种一致性级别。

**Scrub Repair智能化**：[CDS Jewel -- Scrub Repair](/VideoSummary/2015/08/04/CDS_Jewel_--_Scrub_Repair/) 提出重构修复流程，支持对单个对象执行有针对性的修复，并使用 JSON 格式持久化不一致对象信息。

### 2.3 RGW 方向

**多站点配置模型重构**：[CDS Jewel -- RGW Multisite Configuration](/VideoSummary/2015/08/03/CDS_Jewel_--_RGW_Multisite_Configuration/) 引入了 Zone、Zone Group、Realm、Period 四层配置模型，支持运行时动态配置变更，无需重启网关。

**多站点同步改进**：[CDS Jewel -- RGW Multisite Sync](/VideoSummary/2015/08/03/CDS_Jewel_--_RGW_Multisite_Sync/) 讨论了元数据同步和据同步的改进方案，引入 Active-Active 复制、推送通知机制，并计划移除独立的网关代理进程，将代理功能内嵌到网关中。

**多租户支持**：[CDS Jewel -- RGW Multitenancy](/VideoSummary/2015/08/03/CDS_Jewel_--_RGW_Multitenancy/) 讨论了为 RGW 引入独立租户命名空间，修改存储桶和用户标识符数据结构，并探讨了与 Keystone 租户的映射集成方案。

**Hadoop over RGW**：[CDS Jewel -- Hadoop over Ceph RGW](/VideoSummary/2015/08/04/CDS_Jewel_--_Hadoop_over_Ceph_RGW/) 介绍了 Rgw Skidaway FS（Hadoop 兼容文件系统插件）的进展，已完成约 70% 代码开发，添加了块级位置信息以提升读取性能，与 HDFS 基准对比中 Swift 读取性能约低 20%。

### 2.4 CephFS 方向

**fsck 工具进展**：[CDS Jewel -- CephFS fsck progress](/VideoSummary/2015/08/04/CDS_Jewel_--_CephFS_fsck_progress/) 介绍了数据扫描工具的两阶段设计：第一阶段扫描数据池对象并记录元数据，第二阶段利用元数据修复元数据树，并讨论了目录碎片、快照处理等边界情况。

**IO Hints 框架**：[CDS Jewel -- add IOHints in CephFS](/VideoSummary/2015/08/04/CDS_Jewel_--_add_IOHints_in_CephFS/) 讨论了通用 IO hint 框架，用于实现数据生命周期控制、数据重要性标识和分配策略，探讨了缓存数据/可用数据/非可用数据的标识体系。

**Starter Tasks 梳理**：[CDS Jewel -- CephFS starter tasks](/VideoSummary/2015/08/04/CDS_Jewel_--_CephFS_starter_tasks/) 整理了适合新贡献者入手的任务，包括缓存状态导出、目录碎片对象检查工具、异步接口集成、MDS 类型拆分等。

### 2.5 RBD 方向

**RBD Journal Blueprint**：[CDS Jewel -- RBD Journal](/VideoSummary/2015/08/03/CDS_Jewel_--_RBD_Journal/) 设计了基于 librados API 的通用日志机制，使用 RNG 算法将日志条目分散到多个对象，引入软最大小限制，支持多读者，为 RBD 跨数据中心镜像复制奠定基础。

### 2.6 安全

**CephX 暴力破解防护**：[CDS Jewel -- CephX brute-force protection](/VideoSummary/2015/08/03/CDS_Jewel_--_CephX_brute-force_protection/) 讨论了自动黑名单机制，针对频繁错误认证的客户端进行封禁，并探讨了 OSD map 签名以增强安全性。

### 2.7 基础设施与运维

**参考架构**：[2015-SEP-24 Ceph Tech Talks - Reference Architectures](/VideoSummary/2015/09/24/2015-SEP-24_--_Ceph_Tech_Talks_-_Reference_Architectures/) 发布了与 Supermicro、Cisco、Scalable Informatics 合作的性能与尺寸指南，提出 4×3 矩阵用于识别不同工作负载（IOPS 优化、吞吐量优化、成本容量优化）的候选架构。

**Calamari 硬件 API**：[CDS Jewel -- Calamari API Storage Hardware](/VideoSummary/2015/08/03/CDS_Jewel_--_Calamari_API_Storage_Hardware/) 规划了硬件 API，使 Calamari 能感知底层存储硬件状态（SMART 数据、设备序列号等），支持 SUSE、Ubuntu、CentOS，并计划扩展 Fedora 支持。

**Ceph on Mesos**：[CDS Jewel -- Ceph Mesos](/VideoSummary/2015/08/04/CDS_Jewel_--_Ceph_Mesos/) 介绍了 Intel 上海团队开发的 Seth Mesos 框架，支持在 Apache Mesos 上部署和扩展 Ceph 集群（OSD、Mon、Gateway），动态伸缩和故障转移功能仍在开发中。

**非功能性测试框架**：[CDS Jewel -- Non-Functional Tests](/VideoSummary/2015/08/03/CDS_Jewel_--_Non-Functional_Tests/) 提出将可扩展性、性能等非功能性测试纳入 Ceph 开发流程，使用 cgroup 资源限制控制测试环境，开发 maestro/rattles/averte 等任务组件。

**性能回归检测**：[CDS Jewel -- Ceph 0 day for performance regression](/VideoSummary/2015/08/04/CDS_Jewel_--_Ceph_0_day_for_performance_regression/) 讨论了建立自动化性能回归测试框架，使用 fio 等工具进行基准测试，并将结果集成到日常 CI 流程中。

**消息优先级**：[CDS Jewel -- Messenger Priorities for Client](/VideoSummary/2015/08/04/CDS_Jewel_--_Messenger_Priorities_for_Client/) 讨论了通过 Token Bucket 算法实现客户端消息优先级队列，解决负载不均衡问题。

**缓存层优化**：[CDS Jewel -- Cache Tiering](/VideoSummary/2015/08/04/CDS_Jewel_--_Cache_Tiering/) 讨论了缓存穿透问题的实验方案、基于重用距离算法的驱逐策略改进，以及 Sandisk 提出的策略引擎（支持用户自定义缓存策略）。

**被动 Monitor**：[CDS Jewel -- Passive Monitors](/VideoSummary/2015/08/03/CDS_Jewel_--_Passive_Monitors/) 讨论了不参与 Quorum 但接收所有提案的被动 Monitor 设计，用于增强灾难恢复能力，并分析了脑裂（Split Brain）防护机制。

## 3. 重要决策与里程碑

- **Jewel 版本规划启动**：本季度大量 CDS（Ceph Developer Summit）Jewel 专项会议密集召开，涵盖存储引擎、RGW、CephFS、RADOS、安全等几乎所有子系统，标志着 Jewel 版本的特性规划进入实质阶段。

- **RGW 多站点架构重构决策**：确定引入 Zone/Zone Group/Realm/Period 四层模型，这是 RGW 多站点功能的重大架构升级，详见 [CDS Jewel -- RGW Multisite Configuration](/VideoSummary/2015/08/03/CDS_Jewel_--_RGW_Multisite_Configuration/) 和 [CDS Jewel -- RGW Multisite Sync](/VideoSummary/2015/08/03/CDS_Jewel_--_RGW_Multisite_Sync/)。

- **RBD Journal 设计确定**：RBD Journal Blueprint 完成设计评审，为后续 RBD 镜像（rbd-mirror）功能奠定基础，详见 [CDS Jewel -- RBD Journal](/VideoSummary/2015/08/03/CDS_Jewel_--_RBD_Journal/)。

- **NewStore 小对象优化方向确定**：决定在 NewStore 中实现小对象合并存储方案，详见 [CDS Jewel -- Optimize newstore for massive small object storage](/VideoSummary/2015/08/04/CDS_Jewel_--_Optimize_newstore_for_massive_small_object_storage/)。

- **CephFS 进入稳定化阶段**：[2015-JUL-30 Ceph Tech Talks - CephFS](/VideoSummary/2015/08/03/2015-JUL-30_--_Ceph_Tech_Talks_-_CephFS/) 显示 CephFS 已具备高可用性、访问控制、故障恢复工具等生产级特性，社区正在推进稳定化和 QA 工作。

- **Jemalloc 性能优势确认**：[2015-AUG-27 Ceph Tech Talks - Ceph Performance](/VideoSummary/2015/08/27/2015-AUG-27_--_Ceph_Tech_Talks_-_Ceph_Performance/) 中 Red Hat 测试确认 Jemalloc 在小 I/O 场景下性能显著优于 TCMalloc，但内存占用更高，需进一步权衡。

## 4. 社区动态

**Tech Talks 系列**：本季度举办了三场面向社区的 Ceph Tech Talks，分别聚焦性能调优（8月）、CephFS（7月）和参考架构（9月），覆盖了从底层性能到上层部署的完整技术栈。

**CDS Jewel 开发者峰会**：本季度召开了大规模的 Ceph Developer Summit，针对 Jewel 版本进行了系统性的特性规划，涉及议题超过 20 个，参与者来自 Red Hat、Intel、Sandisk、UC Santa Cruz 等机构。

**Intel 上海团队贡献**：Intel 上海研发团队在本季度贡献了 Ceph Mesos 框架（Seth Mesos），展示了 Ceph 在容器编排平台上的集成能力，详见 [CDS Jewel -- Ceph Mesos](/VideoSummary/2015/08/04/CDS_Jewel_--_Ceph_Mesos/)。

**学术界参与**：UC Santa Cruz 博士生（Red Hat 实习生）主导了非功能性测试框架项目，体现了学术界与工业界在 Ceph 社区的协作，详见 [CDS Jewel -- Non-Functional Tests](/VideoSummary/2015/08/03/CDS_Jewel_--_Non-Functional_Tests/)。

**参考架构生态建设**：Red Hat 与 Supermicro、Cisco、Scalable Informatics 合作发布了多份性能与尺寸指南，并建立了社区性能基准测试库，详见 [2015-SEP-24 Ceph Tech Talks - Reference Architectures](/VideoSummary/2015/09/24/2015-SEP-24_--_Ceph_Tech_Talks_-_Reference_Architectures/)。

**Calamari 正式发布**：Calamari 最新稳定版本在本季度发布，可通过 download.com/calamari 下载，支持 SUSE、Ubuntu、CentOS，详见 [CDS Jewel -- Calamari API Storage Hardware](/VideoSummary/2015/08/03/CDS_Jewel_--_Calamari_API_Storage_Hardware/)。

## 5. 下季度展望

基于本季度的讨论内容，预计 2015 Q4 将重点推进以下方向：

1. **BlueStore/NewStore 实现落地**：小对象合并存储、metadata-only journal mode 的仿真测试选型完成后，将进入编码实现阶段。

2. **RBD Mirror 功能开发**：RBD Journal Blueprint 设计已确定，下季度将进入代码实现，推进跨数据中心 RBD 镜像复制功能。

3. **RGW 多站点新架构上线**：Zone/Zone Group/Realm/Period 模型的代码实现将是 RGW 方向的核心工作，Active-Active 复制和推送通知功能也将跟进开发。

4. **CephFS fsck 工具完善**：数据扫描工具的两阶段实现将继续推进，目录碎片和快照处理等边界情况需要解决。

5. **RADOS QoS 原型验证**：基于 dmClock 的 I/O 调度器改进方案将进入原型开发和测试阶段。

6. **性能回归 CI 集成**：自动化性能回归测试框架将逐步集成到 Ceph 日常 CI 流程中，以防止性能退化。

7. **CephX 安全加固**：自动黑名单机制和 OSD map 签名功能将进入实现阶段。

8. **Hadoop over RGW 开源**：Rgw Skidaway FS 代码开发接近完成，预计下季度完成基准测试并开源。
