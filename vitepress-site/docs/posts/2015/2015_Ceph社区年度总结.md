# 2015 年 Ceph 社区年度进展报告

---

## 1. 年度概述

2015 年是 Ceph 项目从"可用"走向"生产就绪"的关键一年。这一年，社区围绕两个主要版本（Infernalis 和 Jewel 的规划）展开了密集的技术讨论与工程实践，核心议题集中在：存储后端现代化（NewStore/BlueStore）、多站点高可用（RGW Active-Active）、文件系统稳定化（CephFS）、以及管理平台成熟化（Calamari/Romana）。

与此同时，社区治理结构在这一年正式成型——董事会、技术委员会和用户委员会相继建立，Ceph Days 在全球多个城市举办，合作伙伴生态持续扩大。从 [Ceph Community Update](/VideoSummary/2015/11/13/Patrick_McGarry_--_Ceph_Community_Update/) 的社区更新可以看出，2015 年的 Ceph 社区在规模和组织成熟度上都迈上了新台阶。

---

## 2. 全年技术演进

### 2.1 存储后端的根本性变革

2015 年最具战略意义的技术方向是对 OSD 存储后端的彻底重构。现有的 FileStore 后端依赖文件系统（XFS/ext4）加日志（journal）的双写架构，带来了严重的写放大问题。社区在 Infernalis CDS 和 Jewel CDS 上密集讨论了多条路线：

- **NewStore**：使用 RocksDB 管理元数据和事务，使用 POSIX 文件系统（XFS）管理数据块，消除双写开销。详见 [CDS Infernalis - OSD NewStore](/VideoSummary/2015/03/06/CDS_Infernalis_Day_2.2_--_OSD_-_Newstore/)。
- **PMStore**：面向非易失性存储（NVM/SD）的实验性后端，使用内存映射文件，以固定大小块处理碎片化。详见 [CDS Jewel - PMStore](/VideoSummary/2015/08/03/CDS_Jewel_--_PMStore/)。
- **LMDB 后端**：探索将 Lightning Memory-Mapped Database 作为键值存储后端的可行性。详见 [CDS Infernalis - LMDB backend](/VideoSummary/2015/03/06/CDS_Infernalis_Day_2.2_--_LMDB_backend_for_Ceph/)。

这一系列探索最终汇聚成 BlueStore 的设计方向，为 Jewel 之后的版本奠定基础。

### 2.2 高可用与多站点架构

RGW 的 Active-Active 多站点架构是 2015 年另一条重要技术主线。传统的主从（Active-Passive）模式无法满足跨数据中心读写需求，社区在 Infernalis CDS 上提出了区域组（Zone Group）概念，并在 Jewel CDS 上进一步引入了 Realm 和 Period 的配置模型，实现了真正的主动-主动复制。详见 [CDS Infernalis - RGW Active-Active Arch](/VideoSummary/2015/03/06/CDS_Infernalis_Day_1_--_RGW_-_Active_Active_Arch/) 和 [CDS Jewel - RGW Multisite Sync](/VideoSummary/2015/08/03/CDS_Jewel_--_RGW_Multisite_Sync/)。

### 2.3 性能工程的系统化

2015 年，Ceph 性能工程从"经验调优"走向"系统化测量"。Red Hat 首席性能工程师 Mark Nelson 在 [Ceph Tech Talks - Ceph Performance](/VideoSummary/2015/08/27/2015-AUG-27_--_Ceph_Tech_Talks_-_Ceph_Performance/) 中分享了使用 CBT、CollectL、Perf 等工具链的完整方法论，发现 Jemalloc 替代 TCMalloc 可显著提升小 I/O 性能。Jewel CDS 上进一步讨论了性能回归自动检测框架，详见 [CDS Jewel - Ceph 0-day Performance Regression](/VideoSummary/2015/08/04/CDS_Jewel_--_Ceph_0_day_for_performance_regression/)。

Sandisk 在全闪存场景下的优化实践（[Ceph on All-Flash Storage](/VideoSummary/2015/11/13/Venkat_Kolli_--_Ceph_on_All-Flash_Storage/)）展示了 Ceph 在 NVMe/SSD 介质上的潜力：读取约 250 万 IOPS，写入约 100 万 IOPS，延迟约 2 毫秒。

### 2.4 容器化与云原生集成

Ceph 与容器生态的融合在 2015 年正式提上日程。社区讨论了官方 Docker 镜像（Monitor、OSD、MDS、RGW 各组件独立容器化），使用 etcd 进行分布式配置，并探索了 Ceph 作为 Kubernetes 存储提供商的集成路径。详见 [CDS Infernalis - Ceph Containers](/VideoSummary/2015/03/06/CDS_Infernalis_Day_1_--_Ceph_Containers/)。Intel 上海团队还开发了 Ceph Mesos 框架，实现在 Apache Mesos 上动态扩展 Ceph 集群，详见 [CDS Jewel - Ceph Mesos](/VideoSummary/2015/08/04/CDS_Jewel_--_Ceph_Mesos/)。

### 2.5 QoS 与服务质量

随着 Ceph 在多租户环境中的广泛部署，QoS 成为迫切需求。Jewel CDS 讨论了基于 EM 算法的 RADOS QoS 方案，支持为客户端配置最小/最大 IOPS，引入资源预留机制，详见 [CDS Jewel - RADOS QoS](/VideoSummary/2015/08/03/CDS_Jewel_--_RADOS_QoS/)。消息优先级问题也在 [CDS Jewel - Messenger Priorities for Client](/VideoSummary/2015/08/04/CDS_Jewel_--_Messenger_Priorities_for_Client/) 中通过 Token Bucket 算法得到了初步解决方案。

## 3. 重大里程碑（版本发布）

### 3.1 Hammer（v0.94）

Hammer 是 2015 年上半年的稳定版本，作为长期支持（LTS）版本被广泛部署于生产环境。其核心特性包括 Cache Tiering 的成熟化、Erasure Coding 的基础支持，以及 RGW 的 S3/Swift 兼容性改进。[Recovery, Erasure Coding, Cache Tiering](/VideoSummary/2015/11/10/Samual_Just_--_Recovery_erasure_coding_cache_tiering/) 中对 Hammer 时代的 Erasure Coding 缓存分层架构有详细阐述。

### 3.2 Infernalis（v9.x）

Infernalis 是 2015 年下半年发布的主要版本，对应的 CDS（Ceph Developer Summit）在年中举行，讨论内容涵盖：

- OSD scrub 优化，减少对业务 I/O 的干扰，详见 [CDS Infernalis - OSD Less Intrusive Scrub](/VideoSummary/2015/03/06/CDS_Infernalis_Day_1_--_OSD_-_Less_Intrusive_Scrub/)
- Erasure Coding 池覆盖写支持的方案论证，详见 [CDS Infernalis - EC Pool Overwrite Support](/VideoSummary/2015/03/06/CDS_Infernalis_Day_1_--_OSD_-_Erasure_Coding_Pool_Overwrite_Support/)
- RBD 异步镜像（Async Mirroring）设计，详见 [CDS Infernalis - RBD Async Mirroring](/VideoSummary/2015/03/06/CDS_Infernalis_Day_1_--_RBD_-_Async_Mirroring/)
- Cache Tier 读写优化，引入 Bloom 过滤器跟踪冷数据，详见 [CDS Infernalis - Cache Tier Improvements](/VideoSummary/2015/03/06/CDS_Infernalis_Day_2.2_--_Cache_Tier_Improvements/)
- Calamari 客户端更名为 Rana，采用 MIT 许可证开源，详见 [CDS Infernalis - Calamari Discussion](/VideoSummary/2015/03/06/CDS_Infernalis_Day_1_--_Calamari_Discussion/)

### 3.3 Jewel（v10.x，规划中）

Jewel 的 CDS 在 2015 年底举行，规划了下一个 LTS 版本的核心特性：

- RBD Journal 与跨数据中心镜像，详见 [CDS Jewel - RBD Journal](/VideoSummary/2015/08/03/CDS_Jewel_--_RBD_Journal/)
- RGW 多站点同步的完整实现，详见 [CDS Jewel - RGW Multisite Configuration](/VideoSummary/2015/08/03/CDS_Jewel_--_RGW_Multisite_Configuration/)
- CephFS 稳定化与 fsck 工具，详见 [CDS Jewel - CephFS fsck progress](/VideoSummary/2015/08/04/CDS_Jewel_--_CephFS_fsck_progress/)
- NewStore/BlueStore 后端的进一步成熟

## 4. 核心组件进展

### 4.1 RADOS

RADOS 作为 Ceph 的核心存储层，2015 年在多个维度取得进展。

**Pering 性能优化**：Pering 延迟是影响集群恢复速度的关键因素。Infernalis CDS 和 Jewel CDS 均专题讨论了优化方案，包括基于历史间隔预判权威 OSD、跳过冗余步骤、客户端驱动读取等。详见 [CDS Infernalis - OSD Peering Latency](/VideoSummary/2015/03/06/CDS_Infernalis_Day_2.2_--_OSD_-_Peering_Latency/) 和 [CDS Jewel - Peering Speed Improvements](/VideoSummary/2015/08/03/CDS_Jewel_--_Peering_Speed_Improvements/)。

**尾部延迟（Tail Latency）改进**：通过心跳优化（主动声明自身死亡）、慢 OSD 自动检测、并行读取多个副本等手段降低 P99 延迟，详见 [CDS Jewel - RADOS Tail Latency Improvements](/VideoSummary/2015/08/03/CDS_Jewel_--_RADOS_Tail_Latency_Improvements/)。

**多对象事务**：基于两阶段提交协议实现跨对象原子操作，支持客户端定义事务主体，详见 [CDS Jewel - RADOS Multi-object Transaction Support](/VideoSummary/2015/08/04/CDS_Jewel_--_RADOS_multi-object_transaction_support/)。

**元数据仅日志模式**：通过减少日志写入范围降低写放大，详见 [CDS Jewel - RADOS Metadata-only Journal Mode](/VideoSummary/2015/08/04/CDS_Jewel_--_RADOS_metadata-only_journal_mode/)。

**Placement Groups基础**：Tech Talk 系列对 PG 机制进行了系统性科普，阐明了 CRUSH 算法如何通过 PG 实现均匀数据分布和可扩展性，详见 [Ceph Tech Talks - Placement Groups](/VideoSummary/2015/05/27/2015-MAY-27_--_Ceph_Tech_Talks_-_Placement_Groups/)。

### 4.2 RBD（Rados Block Device）

RBD 在 2015 年的核心进展集中在**跨数据中心镜像**和**性能优化**两条线。

**异步镜像（Async Mirroring）**：这是 2015 年 RBD 最重要的新特性设计。基于完整的 RBD Journal 日志，支持 write-back 和 write-through 两种模式，为灾难恢复提供了基础。详见 [CDS Infernalis - RBD Async Mirroring](/VideoSummary/2015/03/06/CDS_Infernalis_Day_1_--_RBD_-_Async_Mirroring/) 和 [CDS Jewel - RBD Journal](/VideoSummary/2015/08/03/CDS_Jewel_--_RBD_Journal/)。

**元数据机制**：为 LibRBD 添加了键值对形式的元数据存储，允许为每个 RBD 镜像配置独立的配置视图，详见 [CDS Infernalis - RBD Add Metadata Mechanism to LibRBD](/VideoSummary/2015/03/06/CDS_Infernalis_Day_2.2_--_RBD_-_Add_metadata_mechanism_to_LibRBD/)。

**差异导出与对象映射**：改进了克隆与父卷之间的差异导出功能，使用哈希表优化对象映射，引入 AIO 异步操作，详见 [CDS Infernalis - RBD Kernel Client Copy-on-read](/VideoSummary/2015/03/06/CDS_Infernalis_Day_2.2_--_RBD_-_Kernel_RBD_client_supports_copy-on-read/)。

**SCSI Target 集成**：推进了使用 RBD 作为 LIO SCSI 目标的工作，支持持久组和预留，详见 [CDS Infernalis - Clustered SCSI Target using RBD](/VideoSummary/2015/03/06/CDS_Infernalis_Day_1_--_Clustered_SCSI_Target_using_RBD/)。

Tech Talk 系列也对 RBD 基础架构进行了系统梳理，详见 [Ceph Tech Talks - RBD](/VideoSummary/2015/02/27/2015-FEB-26_--_Ceph_Tech_Talks_-_RBD/)。

### 4.3 RGW（RADOS Gateway）

RGW 在 2015 年经历了架构层面的重大演进，多站点和多租户是两条并行的主线。

**多站点架构（Multisite）**：从 Infernalis 的区域组（Zone Group）概念，到 Jewel 规划中的 Realm/Period 模型，RGW 逐步建立起支持动态配置、无需重启的多站点同步体系。Active-Active 复制移除了网关代理，添加了推送通知功能，详见 [CDS Jewel - RGW Multisite Sync](/VideoSummary/2015/08/03/CDS_Jewel_--_RGW_Multisite_Sync/) 和 [CDS Jewel - RGW Multisite Configuration](/VideoSummary/2015/08/03/CDS_Jewel_--_RGW_Multisite_Configuration/)。

**多租户（Multitenancy）**：从全局命名空间迁移到租户隔离模型，引入租户实体，支持独立配置和权限控制，与 Keystone 租户映射集成，详见 [CDS Infernalis - RGW Multitenancy](/VideoSummary/2015/03/06/CDS_Infernalis_Day_1_--_RGW_-_Multitenancy/) 和 [CDS Jewel - RGW Multitenancy](/VideoSummary/2015/08/03/CDS_Jewel_--_RGW_Multitenancy/)。

**NFS 导出**：探索通过 librgw 库连接 NFS Ganesha，将 RGW 对象以 NFS 协议导出，详见 [CDS Infernalis - RGW NFS](/VideoSummary/2015/03/06/CDS_Infernalis_Day_1_--_RGW_-_NFS/)。

**Hadoop 集成**：开发了 Rgw FS（Hadoop 兼容文件系统插件）和 SD 缓存后端，详见 [CDS Jewel - Hadoop over Ceph RGW](/VideoSummary/2015/08/04/CDS_Jewel_--_Hadoop_over_Ceph_RGW/)。

Tech Talk 系列对 RGW 基础架构进行了完整介绍，详见 [Ceph Tech Talks - RGW](/VideoSummary/2015/03/30/2015-MAR-26_--_Ceph_Tech_Talks_-_RGW/)。

### 4.4 CephFS

2015 年 CephFS 的核心任务是**稳定化**和**生产就绪**，而非追加新特性。

**故障恢复工具**：开发了数据扫描工具（data scan），分两阶段扫描数据池对象并尝试恢复元数据树，详见 [CDS Jewel - CephFS fsck progress](/VideoSummary/2015/08/04/CDS_Jewel_--_CephFS_fsck_progress/)。

**健康检查与性能优化**：改进了缓存机制、锁机制，以及基于路径的访问控制（path-based access control）和 root squash，详见 [Ceph Tech Talks - CephFS](/VideoSummary/2015/08/03/2015-JUL-30_--_Ceph_Tech_Talks_-_CephFS/)。

**OpenStack Manila 集成**：讨论了三种将 CephFS 与 Manila 集成的方案，以及多租户安全特性（命名空间隔离、数据路径安全），详见 [CDS Infernalis - CephFS OpenStack](/VideoSummary/2015/03/06/CDS_Infernalis_Day_1_--_CephFS_OpenStack/)。

**IO Hints**：基于通用框架实现数据生命周期控制和分配策略，详见 [CDS Jewel - Add IOHints in CephFS](/VideoSummary/2015/08/04/CDS_Jewel_--_add_IOHints_in_CephFS/)。

**开发任务规划**：Jewel CDS 梳理了 CephFS 的待办事项，包括缓存状态导出、目录碎片检查工具、Samba 异步接口集成等，详见 [CDS Jewel - CephFS Starter Tasks](/VideoSummary/2015/08/04/CDS_Jewel_--_CephFS_starter_tasks/)。

### 4.5 Dashboard / Calamari

Calamari 在 2015 年完成了从内部工具到开源项目的转型。

**架构成熟**：后端采用 Django REST框架，通过 Salt 和 ZeroMQ 消息总线与集群代理通信，使用 Graphite 存储时序数据，详见 [Ceph Tech Talks - Calamari](/VideoSummary/2015/05/04/2015-APR-23_--_Ceph_Tech_Talks_-_Calamari/)。

**品牌重塑**：Infernalis CDS 上，Calamari 客户端更名为 Rana，作为上游参考实现以 MIT 许可证开源，详见 [CDS Infernalis - Calamari Discussion](/VideoSummary/2015/03/06/CDS_Infernalis_Day_1_--_Calamari_Discussion/)。

**硬件 API**：Jewel CDS 规划了硬件监控 API，提供设备 ID、SMART 数据、驱动器信息等，支持 SUSE、Ubuntu 和 CentOS，详见 [CDS Jewel - Calamari API Storage Hardware](/VideoSummary/2015/08/03/CDS_Jewel_--_Calamari_API_Storage_Hardware/)。

### 4.6 存储后端（NewStore / BlueStore）

存储后端的现代化是 2015 年技术讨论最密集的领域之一。

**NewStore 设计**：核心思路是将元数据/事务管理（RocksDB）与数据块管理（POSIX 文件系统）分离，彻底消除 FileStore 的双写开销，详见 [CDS Infernalis - OSD NewStore](/VideoSummary/2015/03/06/CDS_Infernalis_Day_2.2_--_OSD_-_Newstore/)。

**小对象优化**：针对海量小对象场景，讨论了将多个小对象合并为大文件的方案（类似 TFS），改进 X-attr 存储结构，详见 [CDS Jewel - Optimize NewStore for Massive Small Object Storage](/VideoSummary/2015/08/04/CDS_Jewel_--_Optimize_newstore_for_massive_small_object_storage/)。

**Cache Tier 演进**：引入近似计数 Bloom 过滤器区分冷热数据，支持基于 I/O 类型的提升决策，Sandisk 提出了用户定义缓存策略的策略引擎，详见 [CDS Jewel - Cache Tiering](/VideoSummary/2015/08/04/CDS_Jewel_--_Cache_Tiering/)。

## 5. 社区生态

### 5.1 治理结构正式化

2015 年是 Ceph 社区治理走向正式化的里程碑年。根据 [CDS Infernalis - Community Governance](/VideoSummary/2015/03/06/CDS_Infernalis_Day_1_--_Community_Governance/) 的讨论，治理结构确立了三层架构：董事会（Board）、技术委员会（Technical Committee）和用户委员会（User Committee），强调所有决策在公开场合进行并记录在案。[Ceph Community Update](/VideoSummary/2015/11/13/Patrick_McGarry_--_Ceph_Community_Update/) 进一步确认，董事会由 10 名成员组成，用户委员会由社区成员自发组织。

### 5.2 Ceph Days 全球扩展

2015 年 Ceph Days 在全球多个城市举办，覆盖范围持续扩大：

- **Ceph Day Melbourne**：在 Monash University 举办，讨论了 Ceph 在科研存储整合中的应用，详见 [Ceph Day Melbourne Promo](/VideoSummary/2015/11/17/Ceph_Day_Melbourne_Promo/) 和 [Ceph Day Melbourne Roundtable Q&A](/VideoSummary/2015/11/13/Ceph_Day_Melbourne_Roundtable_Q_A/)。
- **Ceph Day London**：IBM 研究部门分享了基于 Ceph 的软件定义存储（SDFS）实践，Wido 分享了生产部署经验，详见 [IBM @ Ceph Day London](/VideoSummary/2015/01/14/IBM_@_Ceph_Day_London/) 和 [Wido @ Ceph Day London](/VideoSummary/2015/01/14/Wido_@_Ceph_Day_London/)。

### 5.3 合作伙伴生态

2015 年，多家硬件和软件厂商深度参与 Ceph 生态：

- **Red Hat**：作为主要贡献者，主导了性能工程、存储后端重构等核心工作。
- **Sandisk**：在全闪存场景下对 Ceph 进行深度优化，并提出了缓存策略引擎方案，详见 [Ceph on All-Flash Storage](/VideoSummary/2015/11/13/Venkat_Kolli_--_Ceph_on_All-Flash_Storage/)。

- **Supermicro、Cisco、Scalable Informatics**：与社区合作发布针对不同工作负载的参考架构和性能指南，详见 [Ceph Tech Talks - Reference Architectures](/VideoSummary/2015/09/24/2015-SEP-24_--_Ceph_Tech_Talks_-_Reference_Architectures/)。
- **IBM**：通过 SoftLayer 提供基于 Ceph 的托管私有云存储服务，详见 [IBM @ Ceph Day London](/VideoSummary/2015/01/14/IBM_@_Ceph_Day_London/)。

## 6. 2016 年展望

基于 2015 年 Jewel CDS 的讨论内容，可以推断 2016 年 Ceph 社区的技术路线和重点方向：

### 6.1 Jewel 正式发布与 BlueStore 落地

Jewel 作为下一个 LTS 版本，预计在 2016 年上半年发布。其核心交付物包括：RBD 跨数据中心镜像（基于 Journal）、RGW 多站点 Active-Active 同步、CephFS 稳定化（单 MDS 生产就绪）。NewStore/BlueStore 后端有望在 Jewel 中以实验性特性形式出现，为后续版本的全面切换做准备。

### 6.2 存储后端的全面现代化

2015 年对NewStore、PMStore、LMDB 等多种方案的探索，预示着 2016 年将在 BlueStore 方向上集中投入。消除双写开销、原生支持 NVMe/SD、降低写放大，是这一方向的核心目标。

### 6.3 容器化与云原生深化

随着 Kubernetes 和 Docker 生态的快速成熟，Ceph 的容器化部署（ceph-docker）和动态存储供给（Dynamic Provisioning）将成为重要方向。Ceph Mesos 框架的探索也预示着 Ceph 在大数据平台上的部署将更加便捷。

### 6.4 QoS 与多租户成熟化

RADOS QoS、RGW 多租户、CephFS 多租户安全特性将在 2016 年进入实现阶段，满足公有云和私有云场景下的服务质量保障需求。

### 6.5 管理平台的智能化

Calamari/Rana 将向更智能的管理方向演进，包括硬件健康监控（SMART 数据）、自动化运维（PG 扩容不中断 I/O）、以及更完善的 REST API，为第三方管理平台集成提供基础。

### 6.6 安全性加固

CephX 暴力破解保护、OSD 映射签名、dm-crypt 密钥管理等安全特性将在 2016 年逐步落地，详见 [CDS Jewel - CephX Brute-force Protection](/VideoSummary/2015/08/03/CDS_Jewel_--_CephX_brute-force_protection/) 和 [CDS Infernalis - dm-crypt Key Management](/VideoSummary/2015/03/06/CDS_Infernalis_Day_1_--_Simple_ceph-mon_dm-crypt_key_management/)。

---

**总结**：2015 年的 Ceph 社区在技术深度和社区广度上都取得了显著进展。存储后端重构、多站点高可用、文件系统稳定化三条主线并行推进，容器化和全闪存两个新兴场景开始受到重视。社区治理的正式化和 Ceph Days 的全球扩展，标志着 Ceph 已从一个技术项目成长为一个成熟的开源生态。
