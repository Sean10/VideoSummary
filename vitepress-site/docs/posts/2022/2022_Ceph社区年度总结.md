# Ceph 社区 2022 年度进展报告

## 概述

2022年是Ceph项目承上启下的关键一年。上半年完成了 **Quincy（17.x）** 版本的发布，下半年全力投入 **Reef 版本的规划与开发。社区在性能优化、新一代存储引擎、可观测性、编排管理等多个维度均取得了显著进展，同时在治理结构和社区生态建设上也进行了深入讨论。

---

## 一、全年技术演进

### 1.1 从 Quincy 到 Reef 的技术跨越

2022年的技术主线是完成 Quincy 版本的收尾与稳定，同时为 Reef 版本奠定架构基础。Quincy 版本在年初进入特性冻结阶段，重点工作集中在稳定性、部署支持（Rook、cephadm）和性能回归修复上。详见 [CDS Reef -RADOS](/posts/2022/CDS_Reef_-_RADOS)) 和 [CDS Reef - Crimson](/posts/2022/CDS_Reef_-_Crimson)) 中对两个版本的系统性规划。

Reef 版本的规划贯穿全年，各组件均在年中的 CDS（Ceph Developer Summit）会议上确立了开发方向，涵盖 RADOS、RGW、RBD、CephFS、Dashboard、Orchestrator、Crimson/SeaStore 等所有核心子系统。

### 1.2 性能优化成为核心主题

全年性能会议（Ceph Performance Meeting）持续追踪多条优化线索：

- **AVL 分配器**：发现并修复了 AVL 分配器在 Quincy 版本中引入的写性能回归，涉及 First Fit 与 Best Fit 模式切换阈值的调整。详见 [Ceph Performance Meeting 2022-03-31](/posts/2022/Ceph_Performance_Meeting_2022-03-31)) 和 [Ceph Performance Meeting 2022-04-07](/posts/2022/Ceph_Performance_Meeting_2022-04-07))。
- **RocksDB 调优**：深入研究了 RocksDB 的 Tombstone 积累问题、TTL 压缩策略、写放大优化，并讨论了针对不同列族的差异化配置。详见 [Ceph Performance Meeting 2022-07-28](/posts/2022/Ceph_Performance_Meeting_2022-07-28)) 和 [Ceph Performance Meeting 2022-06-30](/posts/2022/Ceph_Performance_Meeting_2022-06-30))。
- **PG Log 优化**：提出将 PG Log 写入循环缓冲区（Cyclic Buffer）以减少对 RocksDB 的依赖，降低写放大。详见 [CDS Reef - Performance](/posts/2022/CDS_Reef_-_Performance))。
- **Snap Mapper重构**：Gaby 主导了 Snap Mapper 的全面重写，将数据结构从 Red-Black 树改为哈希表，并探索全内存存储方案，以解决 RBD 镜像场景下的性能瓶颈。详见 [Ceph Performance Meeting 2022-06-23](/posts/2022/Ceph_Performance_Meeting_2022-06-23)) 和 [Ceph Performance Meeting 2022-06-09](/posts/2022/Ceph_Performance_Meeting_2022-06-09))。

### 1.3 可观测性体系建设

2022年社区在可观测性方向投入显著增加：

- **Telemetry（遥测）** 功能持续完善，新增 Crash Telemetry 通道，支持自动收集崩溃回溯并映射到 Redmine 问题，实现了从崩溃发现到 bug 修复的闭环。详见 [Ceph Crash Telemetry - Observability in Action](/posts/2022/Ceph_Crash_Telemetry_-_Observability_in_Action))。
- **分布式追踪**：Jaeger 集成持续推进，讨论了基于 Lua 的条件追踪方案，以降低追踪开销。
- **指标收集架构重构**：针对大规模集群（150节点以上）中 Ceph Manager 成为指标收集瓶颈的问题，提出了 per-node exporter 方案，将指标直接从各守护进程暴露给 Prometheus，绕过 Manager 的 Python GIL 限制。详见 [Ceph Developer Monthly 2022-02](/posts/2022/Ceph_Developer_Monthly_2022-02-02)) 和 [Ceph Developer Monthly 2022-10-05](/posts/2022/Ceph_Developer_Monthly_2022-10-05))。

## 二、重大里程碑

### 2.1 Quincy（17.x）版本发布

Quincy 是2022年上半年最重要的里程碑。主要特性包括：

- **mclock QoS 配置文件**：提供高客户端 IO、高恢复、平衡三种预设配置文件，简化 QoS 调优。
- **PG autoscaler 改进**：新增 `bulk` 标志和全局关闭选项，解决自动扩缩影响集群性能的问题。
- **BlueStore 零块检测**：优化厚置备 RBD 镜像的存储效率（后因性能问题在 17.21 中默认关闭，引发后续讨论）。
- **cephadm 部署增强**：支持 Rook、cephadm 等多种部署方式，Orchestrator 模块持续完善。

详见 [CDS Reef - RADOS](/posts/2022/CDS_Reef_-_RADOS)) 中对 Quincy 特性的回顾。

### 2.2 Reef 版本规划确立

年中的 CDS Reef 系列会议（涵盖 RADOS、RGW、RBD、CephFS、Dashboard、Orchestrator、CrimsonPerformance、Governance 等专题）系统性地确立了 Reef 版本的开发路线图。这是2022年社区治理层面的重要里程碑，为2023年的 Reef 发布奠定了基础。

### 2.3 cephadm 二进制重构完成

cephadm 的二进制重构（将单一大型二进制拆分为模块化结构）在2022年完成主体工作，并通过了单元测试和集成测试验证。详见 [Ceph Orchestrator Meeting 2022-09-20](/posts/2022/Ceph_Orchestrator_Meeting_2022-09-20)) 和 [Ceph Orchestrator Meeting 2022-09-27](/posts/2022/Ceph_Orchestrator_Meeting_2022-09-27))。

### 2.4 新Ceph Exporter 上线

开发了新的 per-node Ceph Exporter，作为每个节点的独立守护进程，直接从各 OSD/MDS/RGW 守护进程收集性能计数器并通过 HTTP 暴露给 Prometheus，显著改善了大规模集群的监控可扩展性。详见 [Ceph Developer Monthly 2022-10-05](/posts/2022/Ceph_Developer_Monthly_2022-10-05))。

## 三、核心组件年度进展

### 3.1 RADOS / OSD

RADOS 层在2022年的主要工作集中在稳定性、性能和新特性三个方向：

- **均衡器改进**：重构了容量均衡器代码，新增基于工作负载的主 PG 均衡，支持按池工作负载平衡读请求。
- **OSD Map 修剪**：发现并修复了数百万 OSD Map 未被修剪的问题。
- **部分条带读取（Partial Stripe Read）**：实现了对大对象中小范围数据的高效读取，无需访问所有 OSD，显著降低 CPU 负载。
- **自动密钥轮换**：Quincy 版本实现，Reef 版本接近完成。
- **QoS 改进**：持续完善 mclock 调度器，讨论了客户端视角的 QoS 配置文件管理。

详见 [CDS Reef - RADOS](/posts/2022/CDS_Reef_-_RADOS))。

### 3.2 RGW（RADOS Gateway）

RGW 在2022年是技术创新最活跃的组件之一：

- **Zipper 架构**：引入动态加载存储后端的插件化架构，支持独立模式运行（无需 Ceph 集群），并实现了数据缓存过滤层。这是 RGW 架构的重大演进。
- **S3 Select 增强**：新增 JSON 格式对象查询支持，并探索与 Apache Arrow Flight 的集成。
- **异步重构**：减少线程数量，提升并发性能。
- **多站点（Multi-Site）改进**：动态重分片支持、同步公平性优化，并讨论了用 Go 重写多站点测试套件。
- **HTTP/3 支持**：开始初步研究在 RGW 中引入 HTTP/3（QUIC）支持。
- **可观测性**：集成 Jaeger 追踪，构建追踪原语。

详见 [CDS Reef -Rados Gateway](/posts/2022/CDS_Reef_-_Rados_Gateway))。

### 3.3 RBD（块存储）

RBD 在2022年的重点工作包括：

- **NVMe-oF 网关**：开发新的 NVMe over Fabrics 网关，作为 iSCSI 网关的现代化替代方案。
- **加密克隆**：支持使用不同密码和加密格式的克隆操作。
- **镜像（Mirroring）改进**：优化快照和镜像计划以减少性能影响，改善状态机文档，处理脑裂条件。
- **持久化写回缓存**：改进 pmem 模式下的持久化宽背缓存。
- **日志和监控**：提供一致的镜像级别指标，通过 admin socket 暴露给性能监控工具。

详见 [CDS Reef - RBD](/posts/2022/CDS_Reef_-_RBD))。

### 3.4 CephFS

CephFS 在2022年的主要进展：

- **内核客户端代码解析**：社区举办了 CephFS 内核客户端代码 Walkthrough，系统介绍了 VFS 驱动、超级块、iNode 结构、路径名解析、原子打开等核心机制，以及新的 `netfs` 网络请求处理层。详见 [CephFS Code Walkthrough - Kernel Client Overview](/posts/2022/CephFS_Code_Walkthrough_-_Kernel_Client_Overview))。
- **MDS 高可用性**：在 Orchestrator 层面讨论了 MDS 的调度策略和故障转移优化。

### 3.5 BlueStore

BlueStore 在2022年的主要工作：

- **PMEM 硬件卸载**：探索利用 Intel DSA（数据流加速器）卸载 CPU 在持久内存操作中的负担，已在 BlueStore 中实现同步模式的 DSA 支持。详见 [Accelerating PMEM Device operations in bluestore with hardware based memory offloading technique](/posts/2022/Accelerating_PMEM_Device_operations_in_bluestore_with_hardware_based_memory_offloading_technique))。
- **分配器优化**：修复 AVL 分配器性能回归，引入基于时间的搜索阈值，改善碎片化问题。
- **BlueStore WAL**：Igor 实现了 BlueStore 自定义 Write-Ahead Log，作为 RocksDB WAL 的替代方案。
- **零块检测**：深入讨论了零块检测与加密用例的语义冲突，提出引入逻辑范围与物理范围区分的改进方案。详见 [Ceph Developer Monthly 2022-06-01](/posts/2022/Ceph_Developer_Monthly_2022-06-01))。

### 3.6 Crimson / SeaStore

Crimson 和 SeaStore 在2022年从实验阶段向可测试阶段迈进，是全年进展最为密集的方向之一：

**Quincy 阶段成果：**
- 支持通过 Rook 和 cephadm 部署
- 开发了 Crimson RADOS 技术测试套件，支持故障注入测试
- 修复了大量排序和 watch/notify API 问题
- 改进了 BlueStore 后端支持

**SeaStore（C-Store）核心进展：**
- **垃圾回收（GC）**：引入基于代数（generation-based）的 GC 策略，将相似特性和年龄的 extent 存储在同一 segment，减少写放大和冲突。详见 [Ceph Crimson SeaStore Meeting 2022-06-22](/posts/2022/Ceph_Crimson_SeaStore_Meeting_2022-06-22))。
- **ZNS 设备支持**：开发了 ZNS（Zoned Namespace SD）驱动，在真实 ZNS 设备上完成测试，解决了 segment 关闭后无法重新打开的问题。详见 [Ceph Crimson SeaStore Meeting 2022-08-16](/posts/2022/Ceph_Crimson_SeaStore_Meeting_2022-08-16))。
- **多核支持**：多核快照和清理是 Reef 版本的重点，实现了跨核心反应器通信的 IO Handler 类。详见 [Ceph Crimson SeaStore Meeting 2022-12-07](/posts/2022/Ceph_Crimson_SeaStore_Meeting_2022-12-07))。
- **LBA 树优化**：简化 LBA 树结构，添加 LBA 叶子节点与逻辑 extent 之间的指针。
- **Messenger V2**：推进 Crimson 中 Messenger V2 协议的实现，将握手阶段与就绪阶段分离以支持多核。

**Reef 版本 Crimson 目标：**
- 多核快照和清理
- C-Store 多设备和分层支持
- 通过 Random Block Manager 快速访问 NVMe 设备
- 引入 OSD Map 标志和 pool 标志，防止用户意外在生产集群启用 Crimson

详见 [CDS Reef - Crimson](/posts/2022/CDS_Reef_-_Crimson)) 和 [Ceph Developer Monthly 2022-11-02](/posts/2022/Ceph_Developer_Monthly_2022-11-02))。

### 3.7 Dashboard

Dashboard 在2022年持续改善用户体验：

- **可访问性（Accessibility）**：改进颜色对比度、屏幕阅读器兼容性，实现暗模式主题。详见 [Ceph Developer Monthly 2022-10-05](/posts/2022/Ceph_Developer_Monthly_2022-10-05))。
- **多集群支持**：讨论并规划了多集群监控和管理功能，以及集中式日志系统（基于 Loki + Promtail）。
- **规模测试反馈**：在150节点集群上发现了监控指标传递给 Prometheus 的性能问题，推动了架构改进。
- **主页重设计**：规划展示更有意义数据的新主页。
- **后端驱动 UI**：探索使用 JSON 生成表单的后端驱动 UI 方案，降低前端开发成本。

详见 [CDS Reef - Dashboard](/posts/2022/CDS_Reef_-_Dashboard))。

### 3.8 Orchestrator / cephadm

Orchestrator 在2022年是迭代最频繁的组件，全年持续举行周会：

- **cephadm 二进制重构**：将单一大型二进制拆分为模块化结构，提升可维护性。
- **Agent 稳定化**：完善 per-host agent 的稳定性，实现守护进程部署和信息收集的异步化。
- **RGW Multi-Site 配置支持**：引入新的 spec 层级结构，通过 `kind` 关键字区分不同规范类型，简化多站点配置流程。详见 [Ceph Orchestrator Meeting 2022-08-16](/posts/2022/Ceph_Orchestrator_Meeting_2022-08-16))。
- **HA NFS**：实现了基于虚拟 IP 的 NFS 高可用方案，支持 Ganesha 守护进程在节点故障后自动重调度。
- **升级改进**：支持按主机和按守护进程类型的细粒度升级控制，改善大规模集群的升级体验。
- **服务发现**：新增 Prometheus 服务发现端点，支持外部 Prometheus 实例动态获取集群配置。
- **离线环境支持**：增强对断网（air-gapped）环境的部署支持。

详见 [CDS Reef - Orchestrator](/posts/2022/CDS_Reef_-_Orchestrator))。

## 四、社区生态

### 4.1 开发者月度会议

2022年全年坚持举办 Ceph Developer Monthly 会议，覆盖了指标收集架构、集中式日志、可访问性改进、Manager 架构重构、Crimson 保护措施、Scrub 调度改进等多个跨组件议题，是社区技术决策的重要平台。

### 4.2 Orchestrator 周会

Orchestrator 团队全年坚持每周例会，详细记录了从 Quincy 特性冻结到 Reef 规划的完整过程，体现了社区在工程管理上的成熟度。

### 4.3 Crimson/SeaStore 双周会

Crimson 团队全年坚持双周技术会议，系统追踪了 SeaStore、ZNS 支持、多核架构等前沿方向的进展，展现了社区在下一代存储引擎上的持续投入。

### 4.4 Grace Hopper Open Source Day

社区积极参与 Grace Hopper Open Source Day 活动，专门整理了适合新贡献者的低难度问题（low hanging fruit issues），推动多元化贡献者加入。详见 [Ceph Developer Monthly 2022-08-03](/posts/2022/Ceph_Developer_Monthly_2022-08-03))。

### 4.5 Teuthology 本地化

社区推进了 Teuthology 测试框架的本地化部署，通过 Docker 容器化自动化安装过程，降低了外部贡献者的参与门槛。详见 [2022-03-24 Ceph Tech Talk - Running Teuthology Locally](2022-03-24_-_Ceph_Tech_Talk_-_Running_Teuthology_Locally)。

### 4.6 治理讨论

CDS Reef Governance 会议深入讨论了 Ceph 项目的治理结构（TSC/PMC）、代码审查流程、测试与发布流程、API 稳定性保证等议题，并提出了多项改进措施，包括发布前升级长期运行集群、增加性能测试覆盖、改善发布说明编写流程等。详见 [CDS Reef - Governance](/posts/2022/CDS_Reef_-_Governance))。

### 4.7 合作伙伴动态

- **Intel**：推进 DSA 硬件卸载在 BlueStore 中的应用，以及 Optane PMEM 的深度集成。
- **IBM/Seagate**：IBM 开发了基于插件系统的在线压缩块设备支持；Seagate 与社区合作探索 Motor 对象存储后端的集成。详见 [Ceph Developer Monthly 2022-05-04](/posts/2022/Ceph_Developer_Monthly_2022-05-04)) 和 [Ceph Orchestrator Meeting 2022-10-18](/posts/2022/Ceph_Orchestrator_Meeting_2022-10-18))。
- **OpenStack/Manila**：与 OpenStack Manila 团队合作，推进 HA NFS 方案的测试和集成。
- **Rook**：持续完善 Rook Orchestrator 模块，讨论了 Kubernetes 环境下的差异化 API 设计需求。

## 五、下一年展望

基于2022年的讨论和规划，2023年的技术路线和社区方向可以预判如下：

### 5.1 Reef 版本发布（预计2023年）

Reef 版本将是2023年最重要的里程碑，预计包含：
- **Crimson OSD** 达到可供有经验用户在实际场景测试的成熟度
- **RGW Zipper** 架构正式落地，支持多种可插拔存储后端
- **Dashboard** 多集群管理和集中式日志功能
- **cephadm** 模块化二进制正式发布
- **NVMe-oF 网关** 替代 iSCSI 网关

### 5.2 Crimson/SeaStore 走向生产就绪

2022年 Crimson 完成了多核架构的基础设施建设，2023年将重点推进：
- 多核快照和清理的完整实现
- SeaStore 在真实 ZNS 设备上的稳定运行
- 性能测试体系的完善，为与 Classic OSD 的性能对比提供数据支撑

### 5.3 可观测性体系成熟

- per-node Ceph Exporter 全面替代 Manager 中的指标收集
- Jaeger 追踪集成达到生产可用状态
- Telemetry 数据分析能力增强，引入 AI 工具改善崩溃去重

### 5.4 性能持续优化

- RocksDB 调优方案（TTL 压缩、删除跟踪）落地验证
- Snap Mapper 重构完成，解决 RBD 镜像场景的性能瓶颈
- PG Log 循环缓冲区方案推进，减少写放大

### 5.5 社区生态扩展

- Cephalocon 等线下活动有望恢复，推动社区面对面交流
- 持续降低新贡献者门槛，扩大多元化贡献者群体
- 与 OpenStack、Kubernetes/Rook 生态的集成持续深化

---

## 总结

2022年，Ceph 社区在技术深度和广度上均取得了显著进展。Quincy 版本的成功发布标志着社区在稳定性和部署体验上的成熟；Reef 版本的系统性规划展现了社区的前瞻性；Crimson/SeaStore 的持续演进代表着下一代存储引擎的希望；而可观测性、性能优化、编排管理等方向的全面推进，则体现了社区对生产环境实际需求的深刻理解。

这一年，Ceph 不仅是一个技术项目，更是一个运转成熟、协作高效的开源社区——从每周的 Orchestrator 例会到每月的开发者月会，从 Crimson 双周技术深潜到 Grace Hopper 的多元化招募，社区的每一个细节都在诠释着开源协作的价值。
