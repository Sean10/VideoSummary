# Ceph 社区 2016 年度进展报告

## 概述

2016 年是 Ceph 项目承上启下的关键一年。社区在这一年完成了 Jewel 版本的发布，并全力推进 Kraken 和 Luminous 的开发准备工作。BlueStore 从实验性功能走向候选默认后端，Messenger v2 协议设计成型，Manager 守护进程架构初现雏形——这些技术方向共同构成了 Ceph 下一阶段演进的基础。

---

## 一、全年技术演进

### 存储后端革新：FileStore → BlueStore

2016 年最重要的技术方向是彻底替换 OSD 存储后端。传统 FileStore 依赖 POSIX 文件系统，存在双重日志开销、原子性不足等固有缺陷。[2016-JUN-21 的 Tech Talk](2016-JUN-21_--_Ceph_TechTalks_-_Bluestore) 系统介绍了 BlueStore 的设计哲学：绕过文件系统，直接管理裸块设备，以 RocksDB 存储元数据，对象数据直写块设备，从而获得原子性事务、高效对象枚举、内联压缩和 checksum 等能力。

[2016-JUN-01 的开发者月度会议](/posts/2016/2016-JUN-01_--_Ceph_Developer_Monthly)) 进一步确定了 BlueStore 缓存的关键设计决策：采用分片缓存结构（Sharded Cache）和 MultiQ 缓存替换算法，以提升多核并发性能并减少锁竞争。[2016-AUG-03 的开发者月度会议](/posts/2016/2016-AUG-03_-_-_Ceph_Developer_Monthly)) 则展示了 BlueStore onode 序列化的持续优化，通过引入标志位和优化物理扩展引用来降低 CPU 开销。

### 网络层重构：Messenger v2

网络协议的现代化是 2016 年另一条主线。[2016-MAR-02 的开发者月度会议](/posts/2016/2016-MAR-02_-_-_Ceph_Developer_Monthly)) 讨论了新的同步消息协议设计，重点关注与 DPDK、liburing 的集成以实现高性能网络通信，以及多 OSD 宿主机场景下的锁竞争优化。[2016-JUN-01 的会议](/posts/2016/2016-JUN-01_--_Ceph_Developer_Monthly)) 进一步讨论了 Messenger v2 的安全设计，包括防降级攻击、消息头签名、客户端与服务端协议版本协商机制。网络加密需求也在 [3 月的会议](/posts/2016/2016-MAR-02_-_-_Ceph_Developer_Monthly)) 中被提出，建议利用处理器硬件加速降低加密开销。

### Manager 守护进程架构

[2016-AUG-03 的会议](/posts/2016/2016-AUG-03_-_-_Ceph_Developer_Monthly)) 明确了 Manager（ceph-mgr）的定位：作为可选组件承接 Monitor 的部分职责，首要任务是将 PG 状态和统计信息从 Monitor 迁移至 Manager，计划在 Luminous 版本完成，Kraken 版本提供实验性支持。这一架构变化对于解决 Monitor 在大规模集群下的性能瓶颈具有重要意义。

## 二、重大里程碑

### Jewel 版本发布

Jewel（v10.2.x）是 2016 年上半年的核心交付目标。[2016-FEB-25 的 CephFS Tech Talk](/posts/2016/2016-FEB-25_--_Ceph_Tech_Talks_-_CephFS)) 明确指出该次分享是"Jewel 最后一个重要更新前的介绍"，说明 Jewel 在 2016 年上半年已进入收尾阶段。Jewel 是 Ceph 历史上第一个将 CephFS 标记为生产就绪的版本，具有里程碑意义。

### Kraken 与 Luminous 的开发准备

[2016-AUG-03 的会议](/posts/2016/2016-AUG-03_-_-_Ceph_Developer_Monthly)) 多次提及"Kraken 版本"和"Luminous 版本"的规划，包括 Manager 实验性支持进入 Kraken、PG 状态迁移在 Luminous 完成、BlueStore 成为 Kraken 默认后端等目标，显示社区已在年中开始为后续两个版本做系统性准备。

### CI/CD 基础设施统一化

[2016-AUG-25 的 Tech Talk](/posts/2016/2016-AUG-25_--_Ceph_Tech_Talk_-_Unified_CI)) 专题讨论了构建和发布流程的现代化改造，引入 Docker 容器化构建环境、Kubernetes 弹性扩展、Nexus/Artifactory 依赖管理等方案，标志着 Ceph 社区工程基础设施进入系统性升级阶段。

## 三、核心组件进展

### BlueStore

全年进展最为显著的组件。从 [6 月的架构介绍](/posts/2016/2016-JUN-21_--_Ceph_Tech_Talks_-_Bluestore)) 到 [8 月的序列化优化](/posts/2016/2016-AUG-03_-_-_Ceph_Developer_Monthly))，再到 [6 月开发者会议](/posts/2016/2016-JUN-01_--_Ceph_Developer_Monthly)) 确定的缓存架构，BlueStore 在 2016 年完成了从概念验证到工程落地的关键跨越。年底规划中已明确将其作为 Kraken 的候选默认后端，并列出了后续路线：支持 SPDK 优化 NVMe 性能、SMR 硬盘支持、ZetaScale 作为 RocksDB 替代方案等。

### CephFS

[2016-FEB-25 的 Tech Talk](/posts/2016/2016-FEB-25_--_Ceph_Tech_Talks_-_CephFS)) 展示了 Jewel 周期内 CephFS 的主要新特性：文件系统 scrub 和修复工具（用于检测元数据损坏）、改进的细粒度授权控制、支持将文件指向特定 RADOS 命名空间的文件布局改进、以及多文件系统支持（单集群内创建多个独立文件系统）。与 OpenStack Manila 的集成也在持续推进。

[2016-AUG-03 的会议](2016-AUG-03_-_Ceph_Developer_Monthly) 介绍了 MDS 元数据负载均衡器 Mantle 的设计，通过 Lua 脚本注入实现策略与机制分离，允许灵活调整负载均衡策略，但彼时仍处于实验阶段。

### RBD

RBD 在 2016 年有两个重要方向：

- **镜像横向扩展**：[2016-AUG-03 的会议](2016-AUG-03_-_Ceph_Developer_Monthly) 介绍了三阶段方案，从活动/被动故障转移，到每镜像横向扩展（RPC 消息分配），再到基于指标的热点能力扩展。
- **客户端持久缓存**：同次会议介绍了将读写负载从集群卸载到本地缓存的设计，支持克隆镜像的共享读缓存，使用稀疏文件或 BlueStore 实例存储缓存数据。

[2016-SEP-07 的开发者月度会议](2016-SEP-07_-_Ceph_Developer_Monthly) 讨论了 RBD 快照和一致性组的设计，包括快照类型字段区分用户快照与一致性组快照、并行创建快照的内部机制等。

### RGW

2016 年的会议材料中 RGW 专项讨论相对较少，但 [Ceph 宣传视频](/posts/2016/Ceph_Promo_Video)) 中强调了对象存储作为 Ceph 三大接口之一的核心地位，CRUSH 算法和无单点故障架构是 RGW 可靠性的基础。

### QoS 与内存管理

[2016-OCT-05 的开发者月度会议](2016-OCT-05_-_Ceph_Developer_Monthly) 讨论了两个底层基础设施改进：一是基于 DM Block算法的 QoS 实现，重点区分背景 I/O（恢复、scrub）与客户端 I/O；二是新的内存池分配器，通过宏定义实现对象在正确内存池中的分配，解决内存碎片化问题，并支持编译时调试模式追踪对象分配。

### 安全性

[2016-SEP-07 的会议](/posts/2016/2016-SEP-07_-_-_Ceph_Developer_Monthly)) 讨论了 Kerberos 认证集成方案，定义新认证类型直接与 libkrb5 交互，并探讨了"混合令牌"机制将用户身份与 Ceph 身份结合。同次会议还讨论了 EC 库中 SIMD 指令集检测的实现，以支持不同处理器架构的性能优化。

### Dashboard /管理工具

[2016-JUN-23 的 Tech Talk](2016-JUN-23_--_Ceph_Tech_Talks_-_OpenATIC) 介绍了 OpenATIC 与 Ceph 的深度集成进展，包括基于 Librados 和 LibRBD API 的集群管理、Nagios+RDtool 监控、Saltstack 远程节点管理，以及新的 Ceph 管理仪表板开发计划。OpenATTIC 每月发布新版本，是当时 Ceph 管理界面的重要社区方案。

## 四、社区生态

### 工程基础设施建设

2016 年社区在工程效率上投入显著。[统一 CI 的 Tech Talk](/posts/2016/2016-AUG-25_--_Ceph_Tech_Talk_-_Unified_CI)) 反映了随着贡献者数量增长，原有 Jenkins 构建系统已难以支撑，社区开始系统性地引入容器化和云原生工具链来提升 CI/CD 能力。[3 月的开发者会议](/posts/2016/2016-MAR-02_-_-_Ceph_Developer_Monthly)) 也讨论了 Teuthology（Paddle/Pulpito）测试基础设施的改进，包括为测试结果添加问题追踪字段、支持按 SHA 和作业描述查询等。

### 基准测试工具

[2016-MAY-26 的 Tech Talk](/posts/2016/2016-MAY-26_--_Ceph_Tech_Talks_-_Ceph_Benchmarking_Tool)) 专题介绍了 CBT（Ceph Benchmarking Tool），这一由 Mark Nelson 开发的 Python 框架已成为社区标准基准测试工具，支持 RBD、文件系统、对象存储的全面测试，并提供自动化集群配置和结果收集能力。

### 企业用户实践

[2016-JAN-26 的 Tech Talk](2016-JAN-26_--_Ceph_Tech_Talks_-_High-Performance_Production_Databaseson_Ceph) 展示了 Medalia 公司将 Ceph 用于高性能生产数据库的实践，结合 Docker 容器化和 OpenStack 编排，实现了单流 I/O 550 MB/s、多流接近 4 GB/s 的性能指标，为社区提供了企业级落地的参考案例。

### Hackathon 与社区活动

[2016-MAR-02 的会议](/posts/2016/2016-MAR-02_-_-_Ceph_Developer_Monthly)) 提及了 Ceph Hackathon 的筹备，Sage 负责收集主题建议，显示社区在线下协作活动上保持活跃。Google Summer of Code 也被提及作为网络加密等新特性的孵化渠道。

## 五、下一年展望

基于 2016 年的技术讨论和规划，可以推断 2017 年社区将重点推进以下方向：

**BlueStore 成为默认后端**：Kraken 版本将 BlueStore 作为候选默认后端，2017 年的 Luminous 版本预计完成这一切换，同时推进 SPDK 支持以充分发挥 NVMe 设备性能。

**Manager 守护进程正式化**：PG 状态从 Monitor 迁移至 Manager 是 Luminous 的核心目标，这将显著改善大规模集群的 Monitor 压力，并为后续的模块化管理能力（如 Dashboard、Prometheus 导出）奠定基础。

**Messenger v2 落地**：网络协议现代化工作将在 2017 年进入实现阶段，带来加密支持、更好的多连接管理和性能提升。

**CephFS 生产化深化**：多文件系统、Mantle 负载均衡器、与 Manila 集成等特性将持续完善，推动 CephFS 在更多生产场景落地。

**QoS 与性能隔离**：DM Block 算法的 QoS 实现将为混合负载场景（客户端 I/O 与后台恢复并存）提供更好的服务质量保障。

**管理工具整合**：OpenATTIC 与 Ceph 的深度集成，以及 Manager 模块化架构，预示着 Ceph 原生 Dashboard 将在 Luminous 周期内成为重要交付目标。
