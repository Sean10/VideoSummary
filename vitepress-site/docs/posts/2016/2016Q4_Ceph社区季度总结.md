# Ceph 社区 2016Q4 季度进展报告

---

## 1. 本季度重点议题

本季度 Ceph 开发者月度会议围绕以下核心技术方向展开深入讨论：

- **内存管理优化**：内存池分配器（Memory Pool Allocator）是本季度最突出的议题，重点解决 OSD 进程的内存碎片化问题
- **服务质量（QoS）**：基于 DM Block 算法的 QoS 实现，聚焦于区分背景 I/O 与客户端 I/O
- **BlueStore 持续推进**：会议明确将 BlueStore 开发进展列为持续关注项
- **RBD 设备接口扩展**：为 RBD 添加设备唯一 ID 查询能力

详见 [2016-OCT-05_-_-_Ceph_Developer_Monthly](2016-OCT-05_-_Ceph_Developer_Monthly)。

---

## 2. 技术亮点

### 内存池分配器（Memory Pool Allocator）

Sage 主导设计了新的内存池分配器，核心特性包括：

- 通过**宏定义**实现对象在正确内存池中的自动分配
- 支持编译时开启**调试模式**，可追踪对象分配情况
- 目标是解决 OSD 内存碎片化，并通过统计内存分配实现**内存压力管理**
- 已完成部分类型的迁移，待性能分析验证无额外开销

### Boost Pool 与 Slop Containers

与内存池分配器采用相同底层技术，本季度已基本具备合并条件。合并后的重点工作是确定在代码库中的最优使用场景。

### RBD 设备查询接口

Nitin 推进了 RBD 设备唯一 ID 查询接口的设计，涉及改动范围包括：

- `libceph` 库层
- RBD 类方法层
- OSD 层

该接口为上层应用提供设备标识能力，是 RBD 功能完善的重要一步。

### QoS — DM Block 算法

Josh 与 Erika 合作推进基于 **DM Block 算法**的 QoS 实现：

- 核心目标：为不同客户端提供差异化服务质量保证
- 当前阶段重点：区分**背景 I/O**（如 recovery、scrub）与**客户端 I/O**
- Erika 负责性能测试，结果待分享

详见 [2016-OCT-05_-_-_Ceph_Developer_Monthly](2016-OCT-05_-_Ceph_Developer_Monthly)。

## 5. 下季度展望

基于本季度讨论内容，预计后续工作重点方向如下：

1. **内存池分配器落地**：完成性能基准测试，推广到更多核心数据结构，正式合并 Boost Pool / Slop Containers
2. **QoS 性能数据公开**：Erika 的测试结果将指导 DM Block 算法的调优方向，预计进入更广泛的评审阶段
3. **BlueStore 成熟度提升**：作为持续关注项，预计在后续季度进入更多稳定性和性能验证工作
4. **RBD 接口完善**：设备查询接口涉及多层改动，预计在下季度完成跨层联调并提交 PR
5. **蓝图驱动开发**：社区推动提前在 Wiki 讨论蓝图的机制，预计后续季度的月度会议议题质量将进一步提升
