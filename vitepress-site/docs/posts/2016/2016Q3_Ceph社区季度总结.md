# Ceph 社区季度进展报告 — 2016 Q3

---

## 1. 本季度重点议题

本季度开发者讨论高度集中在以下几个反复出现的技术方向：

**存储引擎与序列化优化**
BlueStore 的 onode 序列化改进是本季度的核心议题之一，详见 [2016-AUG-03_-_-Ceph_Developer_Monthly](/VideoSummary/2016/08/03/2016-AUG-03_-_-_Ceph_Developer_Monthly/)。编码/解码框架的 CPU 开销优化贯穿整个季度讨论。

**RBD 功能扩展**
RBD 镜像横向扩展、客户端持久缓存、快照与一致性组三个方向同步推进，是本季度 RBD 子系统的主要投入方向，详见 [2016-AUG-03_-_-_Ceph_Developer_Monthly](2016-AUG-03_-_Ceph_Developer_Monthly) 和 [2016-SEP-07_-_-_Ceph_Developer_Monthly](/VideoSummary/2016/09/08/2016-SEP-07_-_-_Ceph_Developer_Monthly/)。

**Kraken / Luminous 版本准备**
多个议题（Manager、PG 状态迁移、EC 覆写）均以 Kraken 和 Luminous 版本为交付目标，版本规划压力明显。

**CI/CD 基础设施现代化**
构建和发布流程的统一化改造是本季度基础设施层面的重点，详见 [2016-AUG-25_--_Ceph_Tech_Talk_-_Unified_CI](/VideoSummary/2016/09/01/2016-AUG-25_--_Ceph_Tech_Talk_-_Unified_CI/)。

## 2. 技术亮点

### BlueStore — onode 序列化改进
Alan Samuels 在 [8月开发者月会](/VideoSummary/2016/08/03/2016-AUG-03_-_-_Ceph_Developer_Monthly/) 中介绍了新的编码/解码框架：
- 通过优化缓冲区操作和迭代器减少代码层级
- 引入标志位标识常见优化路径（如无空洞、单物理扩展）
- 减少物理扩展引用的序列化冗余，降低存储空间占用

### CephFS — Mantle 元数据负载均衡器
Michael Silla 提出 Mantle 设计，通过 Lua 脚本注入控制 MDS 负载均衡策略，将策略与机制解耦。目前处于实验阶段，设计文档已发布至 Etherpad 供社区讨论。

### RBD 镜像横向扩展（三阶段方案）
Jason 提出分阶段实现路径：
1. 活动/被动故障转移（锁机制）
2. 每图像横向扩展（RPC 消息分配）
3. 热点能力扩展（指标驱动负载均衡）

### RBD 客户端持久缓存
支持读写数据本地缓存，克隆镜像可共享读缓存，底层使用稀疏文件或 BlueStore 实例，由缓存管理器负责槽位分配与垃圾回收。

### RBD 快照与一致性组
[9月开发者月会](2016-SEP-07_-_Ceph_Developer_Monthly) 中 Sage 提出在快照设计中引入"快照类型"字段，支持用户快照与一致性组快照并行创建，并新增 `get_snapshot_id`、`get_image_id` 等辅助接口。

### EC 覆写（Erasure Code Overwrites）
持久化缺失集合、缓存和哈希基础设施的改造工作持续推进，代码重构同步进行以提升可维护性。

### DDO（数据去重）
Python 原型已完成，计划重写为 C++，支持内容地址对象存储与去重功能。

### SIMD 指令集检测
Basam 提出在 EC 库中实现运行时 SIMD 指令集检测，以支持不同处理器架构的性能优化，详见 [2016-SEP-07_-_-_Ceph_Developer_Monthly](2016-SEP-07_-_Ceph_Developer_Monthly)。

### Scrub 接口改进
通过逐分片对象信息比对提升损坏检测精度，新增 JSON 输出格式，便于自动化脚本处理。

### Kerberos 认证
讨论了定义新认证类型 `Kerberos 5`、直接对接 libkrb5、在 Monitor 中实现身份映射的方案，以及"混合令牌"机制。

### OpenATTIC 与 Ceph 集成
[6月 Tech Talk](/VideoSummary/2016/07/22/2016-JUN-23_--_Ceph_Tech_Talks_-_OpenATTIC/) 中介绍了 OpenATTIC 通过 Librados 和 LibRBD API 管理 Ceph 集群，集成 Nagios + RDtool 监控，并使用 Saltstack 实现远程节点自动化管理。

## 3. 重要决策与里程碑

**Manager 组件引入**
PG 状态和统计信息将从 Monitor迁移至 Manager 组件：
- Kraken 版本：提供实验性 Manager 支持
- Luminous 版本：完成正式迁移

这是 Ceph 监控架构的重要分层决策，将 Monitor 从繁重的统计聚合职责中解放出来。

**统一 CI 系统建设**
[Unified CI Tech Talk](/VideoSummary/2016/09/01/2016-AUG-25_--_Ceph_Tech_Talk_-_Unified_CI/) 确立了基于 Jenkins + Docker + Kubernetes 的新构建体系，引入 Nexus/Artifactory 做依赖管理，Ansible 做资源管理，解决原有构建耗时数天、可扩展性差的问题。

**Messenger 2 计划启动**
9月月会中提及 Messenger 2 计划，标志着网络层的下一代重构正式进入议程。

**AutoMake 升级**
构建系统层面完成 AutoMake 升级，属于工程基础设施改善。

## 5. 下季度展望

基于本季度讨论内容，预计 2016 Q4 将重点推进：

1. **Kraken 版本发布准备** — Manager 实验性支持、EC 覆写、BlueStore 序列化优化需在 Kraken 窗口内落地
2. **RBD 功能完善** — 镜像横向扩展第一阶段（活动/被动故障转移）和客户端持久缓存进入可用状态
3. **Mantle 生产化评估** — 社区反馈收集后决定是否推进 MDS 负载均衡器的生产就绪工作
4. **DDO C++ 重写** — Python 原型验证后的工程化实现
5. **Messenger 2 详细设计** — 网络层重构方案细化
6. **Kerberos 认证实现** — Dan 负责的认证模块开发
7. **统一 CI 系统上线** — 新构建体系完成部署并与各团队对接
8. **OpenATTIC Ceph 仪表板** — Hack Week 成果转化为正式功能迭代
