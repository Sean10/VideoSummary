### Ceph 性能评估与 CBT 工具改进会议纪要

#### 会议概述
- **主讲人**：Lee Sanders（IBM UK）
- **主题**：Ceph 存储系统性能评估的常见陷阱及 CBT（Ceph Benchmarking Tool）工具的优化
- **目标**：分享性能测试经验，推动 CBT 成为社区标准化的 Ceph 性能评估工具

#### 关键讨论内容

1. **性能评估的核心关注点**
   - **响应曲线**：通过绘制吞吐量与延迟曲线，分析系统在不同负载下的表现，关注性能一致性。
   - **真实场景模拟**：考虑峰值与波动，避免测试数据被缓存误导。

2. **性能测试的常见陷阱**
   - **预填充**：确保读取已写入的数据，避免测试未分配空间。
   - **预调节**：模拟真实场景的垃圾回收和碎片化。
   - **配置一致性**：关闭 scrubbing/deep scrub/balancer 以获取可重复结果，但需在真实测试中启用。
   - **PG 配置**：合理分配 Placement Groups (PGs)，避免 OSD 争用。
   - **CPU 调优**：禁用 CPU 频率调节，避免空闲状态影响性能。

3. **CBT 工具的改进**
   - **标准化测试流程**：支持单次点击生成 Object/Block/File 存储的性能报告。
   - **多数据对比**：新增中间数据格式，支持不同测试工具的结果统一分析。
   - **报告增强**：生成 PDF/Markdown 格式报告，包含吞吐量-延迟曲线和摘要表格。
   - **YAML 配置优化**：支持细粒度控制 IO Depth 和 Total IO Depth，支持动态卷管理。

4. **未来计划**
   - **故障注入**：测量节点故障、OSD 重启等事件对性能的影响。
   - **高级监控**：集成 CPU/网络/后端磁盘利用率数据，定位性能瓶颈。
   - **社区协作**：建立公共 GitHub 仓库收集社区性能数据，支持更多协议和工具。

#### 行动项
- **社区推广**：发布 CBT 使用指南博客，鼓励社区贡献性能数据。
- **工具开发**：完善 Cephadm 集成，量化性能一致性。
- **反馈收集**：通过 Slack/Ceph 性能周会讨论需求。

#### 问答环节摘要
- **小容量卷问题**：需避免测试范围完全命中缓存，建议使用合理容量模拟真实负载。
- **CBT 与外部系统集成**：目前不支持，但欢迎贡献代码。
- **预调节实现**：通过 YAML 配置自动化，未来将提供示例模板。

#### 结论
CBT 工具的目标是成为 Ceph 性能评估的黄金标准，通过标准化测试和社区协作，帮助用户更高效地验证和优化存储集群。
