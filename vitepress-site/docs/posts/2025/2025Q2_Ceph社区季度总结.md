# Ceph 社区季度进展报告：2025 Q2

> 报告周期：2025年4月 — 2025年6月
> 数据来源：42篇社区会议与技术分享总结

---

## 一、本季度重点议题

本季度 Ceph 社区围绕以下几个核心方向持续深入讨论：

**1. Tentacle 版本发布准备**

Tentacle 是本季度最高频出现的关键词。多个 RGW 重构会议、EC 优化分享、NVMe 网关更新均以"Tentacle 能否合入"作为决策基准。版本进入代码冻结阶段，RC 测试同步推进，详见 [Ceph RGW Refactoring Meeting 2025-05-21](/VideoSummary/2025/05/24/Ceph_RGW_Refactoring_Meeting_2025-05-21/) 和 [Ceph RGW Refactoring Meeting 2025-06-11](/VideoSummary/2025/06/23/Ceph_RGW_Refactoring_Meeting_2025-06-11/)。

**2. Erasure Coding 全面优化**

EC 性能优化、测试工具开发、数据一致性检测是本季度技术讨论密度最高的方向，贯穿多场会议，详见 [Erasure Coding Enhancements for Tentacle](/VideoSummary/2025/06/24/Erasure_Coding_Enhancements_for_Tentacle/)、[Optimism Erasure Coding - The Testing That Makes Us Confident](/VideoSummary/2025/06/24/Optimism_Erasure_Coding_-_The_Testing_That_Makes_Us_Confident/)、[Cephalautopsy - When Erasure Coding Goes Wrong](/VideoSummary/2025/06/24/Cephalautopsy_-_When_Erasure_Coding_Goes_Wrong/)。

**3. RGW 重构与功能扩展**

RGW 重构会议本季度连续召开（4月至6月），议题涵盖 Bucket Logging、加密复制、生命周期管理、多站点同步、KMS 缓存等，是本季度讨论最活跃的子系统。

**4. 大规模集群运维与性能**

来自 Walmart、DigitalOcean、STFC（110PB 集群）、Sony 等用户的实战分享，集中反映了超大规模 Ceph 集群在运维自动化、硬件选型、性能调优方面的共性挑战。

**5. 新兴存储协议与接入层**

SMB 集成、NVMe-oF 网关、Zero Trust Lakehouse 等议题显示社区正在积极拓展 Ceph 的协议覆盖面和应用场景边界。

## 二、技术亮点

### 2.1 Erasure Coding 性能大幅提升

[Erasure Coding Enhancements for Tentacle](/VideoSummary/2025/06/24/Erasure_Coding_Enhancements_for_Tentacle/) 详细介绍了 IBM 团队在 Tentacle 中实现的 EC 优化：

- **部分读写**：旧版需读取完整条带，新版仅读取所需块，大幅减少冗余 IO
- **Parity Delta Writes**：减少数据读取和写入量
- **空间效率**：小对象写入时避免零填充，实际存储空间占用显著降低
- **Deep Scrub 增强**：新增对 EC 池的 CRC 校验支持
- **配置建议**：推荐 16K 条带，通过 `allow_ec_optimizations` 标志启用
- **向后兼容**：升级后默认禁用，不影响现有集群

配套的测试工具 `ceph IO sequence exerciser` 同步开发，支持错误注入、跨分片写入验证、并发边界测试，计划集成至 Teuthology，详见 [Optimism Erasure Coding - The Testing That Makes Us Confident](/VideoSummary/2025/06/24/Optimism_Erasure_Coding_-_The_Testing_That_Makes_Us_Confident/)。

针对 EC 数据不一致性问题，IBM UK 团队开发了离线和在线两种 EC 一致性检测工具，详见 [Cephalautopsy - When Erasure Coding Goes Wrong](/VideoSummary/2025/06/24/Cephalautopsy_-_When_Erasure_Coding_Goes_Wrong/)。

### 2.2 Crimson OSD 架构进展

[56 Weeks Later - Becoming a Jack of All Trades](/VideoSummary/2025/06/24/56_Weeks_Later_-_Becoming_a_Jack_of_All_Trades/) 展示了 Crimson OSD 的最新性能测试结果：

- 随机读性能显著优于 Classic OSD
- 基于 `seastar` 框架的单 `reactor` 绑定单 CPU 核心策略，16 核心为性能拐点
- 开发了 CPU 核心绑定工具、I/O 成本评估工具和自动化回归测试生成器
- Crimson 将直接使用 Fast EC 路径，与 EC 优化方向协同

### 2.3 RGW 功能扩展

本季度 RGW 重构会议密集推进多项功能：

- **Bucket Index Snapshots**：[Ceph RGW Refactoring Meeting 2025-04-23](/VideoSummary/2025/04/25/Ceph_RGW_Refactoring_Meeting_2025-04-23/) 确定在 Tentacle 中引入基础数据结构，作为实验性功能发布
- **Bucket Logging 优化**：[Ceph RGW Refactoring Meeting 2025-05-21](/VideoSummary/2025/05/24/Ceph_RGW_Refactoring_Meeting_2025-05-21/) 解决了 EC 池不支持 append 操作的问题，采用 manifest 跨池方案；[Ceph RGW Refactoring Meeting 2025-06-18](/VideoSummary/2025/06/23/Ceph_RGW_Refactoring_Meeting_2025-06-18/) 进一步推进日志池配置化
- **加密对象复制**：[Ceph RGW Refactoring Meeting 2025-06-11](/VideoSummary/2025/06/23/Ceph_RGW_Refactoring_Meeting_2025-06-11/) 确定优先合并 Marcus PR，Cena 后续优化代码结构
- **KMS 缓存**：[Ceph RGW Refactoring Meeting 2025-05-07](/VideoSummary/2025/05/24/Ceph_RGW_Refactoring_Meeting_2025-05-07/) 讨论了为 KMS 添加缓存机制以提升性能的 PR
- **生命周期管理（LC）锁机制改进**：[Ceph RGW Refactoring Meeting 2025-06-18](/VideoSummary/2025/06/23/Ceph_RGW_Refactoring_Meeting_2025-06-18/) 针对 Rados 锁超时问题提出修复方案，并探讨基于 CLS 的原子化设计
- **版本控制分片改进**：提出 in-order sharding 方案，解决当前约 200,000 个版本化对象的数量限制

### 2.4 NVMe-oF 网关新特性

[NVMeoF in Ceph - What's New and What's Next](NVMeoF_in_Ceph_-_Whats_New_and_What_s_Next) 介绍了 Tentacle 中即将发布的 NVMe over TCP 网关新特性：

- Cluster Context 优化，提升低命名空间数量时的并行性
- 自动负载均衡，动态调整命名空间分布
- 命名空间掩码，精细化控制主机访问权限
- In-band 认证，子系统与主机双向认证
- 故障恢复目标优化至 6-8 秒
- Grafana 监控看板和 CLI 集成

### 2.5 CephFS 新特性

[CephFS Basics What's New](/VideoSummary/2025/05/08/CephFS_Basics_What_s_New._Greg_Farnum_from_IBM/) 介绍了 CephFS 的最新进展：

- 快照功能增强，支持目录级别快照，创建速度快、成本低
- 递归统计支持
- 客户端加密（数据在发送到服务器前加密）
- Samba VFS 插件优化，通过代理守护进程提升集成性能
- 即将推出：快照一致性改进、硬链接支持改进、元数据日志优化

### 2.6 SMB 集成模块

[Ceph SMB - Opening Windows to the Ceph World](/VideoSummary/2025/06/24/Ceph_SMB_Opening_Windows_to_the_Ceph_World/) 展示了通过新 SMB Manager Module 管理 CephFS 的 SMB 导出：

- 声明式（YAML/JSON）或命令式（CLI）管理集群和共享
- 已实现 Case Insensitivity、快照支持、多通道传输
- 未来计划：QoS 限制、离线域加入、多协议支持

### 2.7 MSR CRUSH 规则

[MSR Multi-Step Retry](/VideoSummary/2025/05/08/MSR_Multi-Step_Retry_-_A_generalization_of_CRUSH_allowing_multiple_OSDs_per_failure_domain/) 介绍了 CRUSH 算法的新扩展，允许在每个故障域中放置多个 OSD，专门解决小型 EC 集群中 OSD 故障时数据分布不均的问题，计划在未来版本中推广。

### 2.8 Stretch Cluster 三可用区支持

[Supporting a3 Availability Zones Stretch Cluster](Supporting_a_3_Availability_Zones_Stretch_Cluster._Kamoltat_JuniorSirivadhna_from_IBM) 介绍了将 Stretch Cluster 从两数据中心扩展到三可用区的工作，包括新的配对规则（`pool stretch set` 命令）和网络分区检测功能，计划在 T 版本中发布。

### 2.9 Dashboard 多集群与多协议支持

[Multi-Cluster and Protocol Visibility with the New Ceph Dashboard](/VideoSummary/2025/06/24/Multi-Cluster_and_Protocol_Visibility_with_the_New_Ceph_Dashboard/) 展示了 Tentacle 中 Dashboard 的重大升级：

- 多集群统一监控（Grafana Federation）
- 对象存储跨集群复制、云分层、S3 账户管理
- Management Gateway 统一认证（OAuth2/OIDC）
- SMB 协议管理、NFS UX 优化
- NVMe 监控面板

### 2.10 ARM 架构支持

[Ceph on ARM - The Next Tentacle](/VideoSummary/2025/06/24/Ceph_on_ARM_-_The_Next_Tentacle/) 宣布 Ceph 将正式支持 ARM 64 架构：

- ARM 客户端 GA 于 2025 年 6 月内发布
- Ampere One 在 4KB 随机写入中达到 400K IOPS，能效比显著优于 x86
- 社区实验室从 Red Hat 北卡罗来纳迁移至 IBM亚利桑那，重新开放 ARM硬件
- 目标 2024 年底前完成完整 ARM 集群支持

## 三、重要决策与里程碑

### 3.1 Tentacle 版本进入 RC 阶段

本季度最重要的里程碑是 Tentacle 版本进入 RC 测试阶段。[Keynote - State of Ceph](/VideoSummary/2025/06/24/Keynote_-_State_of_Ceph/) 和 [Keynote Speech - State of Ceph](/VideoSummary/2025/05/08/Keynote_Speech_-_State_of_Ceph/) 均确认 Tentacle 预计 2025 年下半年正式发布，核心技术亮点包括：

- EC 性能优化（减少网络带宽消耗）
- RGW 桶列表性能提升 5 倍
- Crimson 后端稳定化（C Store 作为默认后端）
- RBD 一致性组支持、实时迁移功能
- Stretch Cluster 支持"解伸缩"操作
- LUKS 加密迁移支持

### 3.2 单元测试框架引入 Catch2

[Ceph RGW Refactoring Meeting 2025-04-16](/VideoSummary/2025/04/25/Ceph_RGW_Refactoring_Meeting_2025-04-16/) 决定引入 `Catch2` 作为新的单元测试框架，以替代现有的 `GTest`，提供更友好的测试体验和协程测试支持。

### 3.3 Boost Spirit迁移至 Boost JSON

[Ceph Developer Monthly2025-02-12](/VideoSummary/2025/04/02/Ceph_Developer_Monthly_2025-02-12/) 决定将 Seth Jason 中的 Boost Spirit 替换为 Boost JSON，提高性能和代码可维护性。

### 3.4 CI 测试优化方向确定

[Ceph Developer Monthly 2025-04-02 Part 1](/VideoSummary/2025/04/02/Ceph_Developer_Monthly_2025-04-02_Part_1/) 和 [Part 2](/VideoSummary/2025/04/02/Ceph_Developer_Monthly_2025-04-02_Part_2/) 讨论了 `make check` 优化方向：Draft PR 默认不触发测试、按组件拆分测试、引入 Clang-Tidy 静态分析（先作为非必选检查）。

### 3.5 审计日志系统设计启动

[Ceph Developer Meetup June 4th 2025](/VideoSummary/2025/06/04/Ceph_Developer_Meetup_June_4th_2025/) 启动了集中化审计日志系统的设计讨论，优先评估 OpenTelemetry 的适用性，覆盖所有 Ceph 子系统的关键命令。

### 3.6 AI 生成代码政策讨论

[AI-generated Code Policy for Ceph](/VideoSummary/2025/06/24/AI-generated_Code_Policy_for_Ceph/) 启动了社区对 AI 生成代码政策的讨论，参考 Linux 基金会政策框架，计划组建工作组起草 Ceph 的 AI 使用初步指南。

## 五、下季度展望

基于本季度讨论内容，预计 2025 Q3 将重点推进以下方向：

**1. Tentacle 正式发布**
RC 测试完成后，Tentacle 将正式发布，这是下季度最确定的里程碑。EC 优化、RGW 功能扩展、NVMe-oF 增强、Dashboard 多集群支持等将随版本落地。

**2. RGW 跨区域组复制设计落地**
[Ceph RGW Refactoring Meeting 2025-06-11](/VideoSummary/2025/06/23/Ceph_RGW_Refactoring_Meeting_2025-06-11/) 中 Cena 已提交初步设计草案，下季度将完成详细设计文档并拆分实现任务。

**3. Crimson OSD 功能完善**
Crimson 将继续推进 PG 支持扩展、QoS 初始支持，以及与 Fast EC 路径的深度整合。

**4. ARM 集群支持完整化**
ARM 客户端 GA 发布后，社区实验室重启，将推进 ARM 集群的 CI/CD 测试完善和参考架构文档。

**5. 审计日志系统实现**
OpenTelemetry 适用性评估完成后，将推进原生审计日志方案的实现，覆盖 Monitor、Manager 等核心组件。

**6. PG Autoscaler 算法改进**
[Ceph User + Dev Monthly Meetup June](/VideoSummary/2025/06/18/Ceph_User_+_Dev_Monthly_Meetup_June/) 中提出的元数据池独立启发式、`ceph pg-autoscaler explain` 命令等改进，计划在 RADOS 周会深入讨论后推进实现。

**7. CephFS 灾难恢复工具化**
[Disaster Recovery User Story](/VideoSummary/2025/06/24/Disaster_Recovery_User_Story/) 中 LMB 的真实故障案例推动了社区对 CephFS DR 自动化工具的需求，下季度将推进相关文档和工具改进。

**8. Zero Trust Lakehouse 深化**
[Zero Trust Data Lakehouse](/VideoSummary/2025/06/24/Zero_Trust_Data_Lakehouse/) 和 [Zero trust data lakehouse - Kyle Bader from IBM](/VideoSummary/2025/05/08/Zero_trust_data_lakehouse._Kyle_Bader_from_IBM/) 展示的 Ceph RGW 与 Polaris Catalog 集成方向，将推进 RGW Flight Server 开发和 Ceph Lakehouse 红皮书发布。
