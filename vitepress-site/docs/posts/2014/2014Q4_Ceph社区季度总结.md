# Ceph 社区季度进展报告：2014 Q4

---

## 1. 本季度重点议题

本季度 Ceph 社区围绕以下几个核心方向展开了密集讨论：

**数据完整性与校验和**
OSD 层的数据完整性是本季度最高频的议题。从机会主义全对象校验和（[CDS_Hammer_Day_1-_OSD_-_Opportunistic_Whole-Object_Checksums](/posts/2014/CDS_Hammer_Day_1_-_OSD_-_Opportunistic_Whole-Object_Checksums))）到 librados 层的校验和暴露（[CDS_Hammer_Day_1_-_librados_-_Expose_Checksums](/posts/2014/CDS_Hammer_Day_1_-_librados_-_Expose_Checksums))），社区在多个层次推进数据完整性保障机制。

**OSD 分层（Tiering）优化**
Cache Tier 的读写延迟优化（[CDS_Hammer_Day_2_-_OSD_Tiering_-_Reduce_R_W_Latencieson_Cache_Tier_Miss](/posts/2014/CDS_Hammer_Day_2_-_OSD_Tiering_-_Reduce_R_W_Latencies_on_Cache_Tier_Miss))）和细粒度提升单元（[CDS_Hammer_Day_2_-_OSD_Tiering_-_Fine-Grained_Promotion_Unit](/posts/2014/CDS_Hammer_Day_2_-_OSD_Tiering_-_Fine-Grained_Promotion_Unit))）是本季度 OSD 方向的两大重点，反映出社区对混合存储场景性能的持续关注。

**CephFS 稳定性与功能完善**
CephFS 的 forward scrub（[CDS_G_H_Day_2_-_CephFS_-_forward_scrub](/posts/2014/CDS_G_H_Day_2_-_CephFS_-_forward_scrub))）、配额支持（[CDS_Hammer_Day_2_-_Quota_Discussion](/posts/2014/CDS_Hammer_Day_2_-_Quota_Discussion))）以及 Hadoop 集成（[CDS_Hammer_Day_2_-_CephFS_-_Hadoop_Support](/posts/2014/CDS_Hammer_Day_2_-_CephFS_-_Hadoop_Support))）贯穿整个季度，表明 CephFS 正在从实验性功能向生产就绪迈进。

**RGW 可扩展性**
Bucket Index 分片扩展（[CDS_Hammer_Day_1_-_RGW_-_Bucket_Index_Scalability](/posts/2014/CDS_Hammer_Day_1_-_RGW_-_Bucket_Index_Scalability))）和对象版本化（[CDS_Hammer_Day_1_-_RGW_-_Object_Versioning_Object_Snapshots](/posts/2014/CDS_Hammer_Day_1_-_RGW_-_Object_Versioning_Object_Snapshots))）是 RGW 方向的核心议题，S3 兼容性持续增强。

**性能与网络层优化**
消息编码（[CDS_Hammer_Day_1_-_Buffer_Encoding](/posts/2014/CDS_Hammer_Day_1_-_Buffer_Encoding))）、RDMA Messenger（[CDS_Hammer_Day_1_-_Acelio_RDMA_Messenger](/posts/2014/CDS_Hammer_Day_1_-_Accelio_RDMA_Messenger))）以及固定内存布局消息传递（[CDS_Hammer_Day_2_-_Fixed_Memory_Layout_for_Message_OpPassing](/posts/2014/CDS_Hammer_Day_2_-_Fixed_Memory_Layout_for_Message_Op_Passing))）反映出社区对底层通信性能的系统性改进意图。

## 2. 技术亮点

### 2.1 OSD 层改进

**机会主义全对象校验和**
在 [CDS_Hammer_Day_1_-_OSD_-_Opportunistic_Whole-Object_Checksums](/posts/2014/CDS_Hammer_Day_1_-_OSD_-_Opportunistic_Whole-Object_Checksums)) 中，社区讨论了在 scrub 时记录每个对象的完整 CRC32 校验和，并存储于 object info 结构中。后续读取时自动比对，不一致则触发告警。该方案与现有 scrub/repair 流程兼容，性能影响可控。

**OSD Scrub 与 Repair 智能化**
[CDS_Hammer_Day_2_-_OSD_-_Scrub_and_Repair](/posts/2014/CDS_Hammer_Day_2_-_OSD_-_Scrub_and_Repair)) 讨论了通过 librados 接口暴露不一致副本信息，允许用户通过 Calamari 或 JSON 接口查询并指定修复方式，同时推进异步读取在复制副本中的实现。

**Scrub/Snap Trim IO 优先级**
[CDS_Hammer_Day_2_-_OSD_-_Scrub_SnapTrim_IO_Prioritization](/posts/2014/CDS_Hammer_Day_2_-_OSD_-_Scrub_SnapTrim_IO_Prioritization)) 提出将所有 IO 操作整合到统一队列并引入优先级标记，解决 scrub、snap trim 与客户端 IO 之间的资源竞争问题。

**灵活缓存控制**
[CDS_Hammer_Day_2_-_OSD_-_Add_Flexible_Cache_Control_of_Object_Data](/posts/2014/CDS_Hammer_Day_2_-_OSD_-_Add_Flexible_Cache_Control_of_Object_Data)) 提出通过客户端 IO 指示（fadvise 语义）传递至 OSD，实现对 page cache 行为的精细控制，有助于减少 RBD 大对象对缓存的污染。

**OSD 事务编码重构**
[CDS_Hammer_Day_2_-_OSD_-_Update_Transaction_Encoding](/posts/2014/CDS_Hammer_Day_2_-_OSD_-_Update_Transaction_Encoding)) 讨论了使用固定大小结构体和缓冲区 ID 简化事务编解码，同时保持向后兼容性，为 FileStore 和未来后端存储的优化奠定基础。

### 2.2 RBD 改进

**Copy-on-Read for Clones**
[CDS_G_H_Day_2_-_RBD_-_Copy-on-read_for_clones_in_kernelRBD_client](/posts/2014/CDS_G_H_Day_2_-_RBD_-_Copy-on-read_for_clones_in_kernel_RBD_client)) 和 [CDS_Hammer_Day_2_-_RBD_-_Copy-on-Read_for_Clones_in_Kernel_RBD_Clients](/posts/2014/CDS_Hammer_Day_2_-_RBD_-_Copy-on-Read_for_Clones_in_Kernel_RBD_Clients)) 讨论了在内核 RBD 客户端实现克隆的 copy-on-read，减少对父对象的重复读取，提升克隆镜像的读取性能。

**独占锁与对象映射（Object Map）**
[CDS_Hammer_Day_2_-_librbd_-_Shared_Flag_Object_Map](/posts/2014/CDS_Hammer_Day_2_-_librbd_-_Shared_Flag_Object_Map)) 详细讨论了 RBD 独占锁特性和三态对象映射（不存在/可能存在/待删除），通过 watch-notify 机制协调多客户端访问，并优化读请求路径。

**集群化 SCSI Target**
[CDS_Hammer_Day_1_-_Clustered_SCSI_Target_Using_RBD](/posts/2014/CDS_Hammer_Day_1_-_Clustered_SCSI_Target_Using_RBD)) 探讨了基于 RBD 实现主动/主动 iSCSI target 的方案，涉及分布式持久保留（Persistent Reservation）和任务管理的实现路径。

### 2.3 RGW 改进

**Bucket Index 分片**
[CDS_Hammer_Day_1_-_RGW_-_Bucket_Index_Scalability](/posts/2014/CDS_Hammer_Day_1_-_RGW_-_Bucket_Index_Scalability)) 讨论了 bucket index 的水平分片方案，以及与多区域（multi-zone）功能的集成问题，并提出了有序和无序两种 list 命令的设计。

**对象版本化**
[CDS_Hammer_Day_1_-_RGW_-_Object_Versioning_Object_Snapshots](/posts/2014/CDS_Hammer_Day_1_-_RGW_-_Object_Versioning_Object_Snapshots)) 讨论了 S3 兼容的对象版本化实现，包括版本列表、特定版本读取/删除，以及 bucket 生命周期管理（对象过期、低冗余存储类）。

### 2.4 CephFS 改进

**Forward Scrub**
[CDS_Hammer_Day_2_-_CephFS_-_Forward_Scrub](/posts/2014/CDS_Hammer_Day_2_-_CephFS_-_Forward_Scrub)) 报告了 forward scrub（从根节点递归检查元数据一致性）和 backward scrub（从 RADOS pool 反向验证对象归属）的双向推进，并讨论了使用健康检查系统和结构化日志记录 scrub 错误。

**Hadoop 集成**
[CDS_Hammer_Day_2_-_CephFS_-_Hadoop_Support](/posts/2014/CDS_Hammer_Day_2_-_CephFS_-_Hadoop_Support)) 讨论了 CephFS 作为 HDFS 替代方案的适配工作，包括 HDFS 语义对齐、Bigtop 自动化测试集成以及文件重命名语义修复。

**配额支持**
[CDS_Hammer_Day_2_-_Quota_Discussion](/posts/2014/CDS_Hammer_Day_2_-_Quota_Discussion)) 讨论了 CephFS 配额与子树（subtree）、子卷（sub volume）的结合方案，利用现有 snap realm 数据结构跟踪 inode 成员资格，并计划添加测试用例验证配额强制执行。

### 2.5 网络与消息层

**Accelio RDMA Messenger**
[CDS_Hammer_Day_1_-_Accelio_RDMA_Messenger](/posts/2014/CDS_Hammer_Day_1_-_Accelio_RDMA_Messenger)) 报告了 Melanox 团队在 Accelio 中增加多传输支持、新的显式流控制接口，以及 Ceph 团队对 XIO Messenger 的重大重构，新的内存缓冲区模型和流控制机制已基本就绪。

**Buffer Encoding 优化**
[CDS_Hammer_Day_1_-_Buffer_Encoding](/posts/2014/CDS_Hammer_Day_1_-_Buffer_Encoding)) 讨论了通过内联代码、减少函数调用开销等微优化手段改善编解码性能，并探讨了 flat bufers 等序列化方案的可行性。

### 2.6 新型纠删码

**Shingled Erasure Code (SHEC)**
[CDS_Hammer_Day_2_-_Shingled_Erasure_Code_SHEC](/posts/2014/CDS_Hammer_Day_2_-_Shingled_Erasure_Code_SHEC)) 介绍了富士通开发的 SHEC 纠删码，其校验块具有局部性（locality），在多磁盘故障场景下恢复效率优于传统方案，计划集成到 Ceph 并提供源代码。

### 2.7 冷存储支持

[CDS_Hammer_Day_1_-_Towards_Ceph_Cold_Storage](/posts/2014/CDS_Hammer_Day_1_-_Towards_Ceph_Cold_Storage)) 探讨了能量感知的数据放置策略、冷热数据分层存储以及对象重定向功能，为 Ceph 进入冷存储场景提供了初步方案框架。

## 3. 重要决策与里程碑

**Firefly 版本发布**
根据 [Ross_Turk_@_Ceph_Day_London](/posts/2014/Ross_Turk_@_Ceph_Day_London)) 的社区更新，Ceph Firefly 版本在本季度正式发布，引入了 Erasure Code 池和 Cache Pool 等重要特性，标志着 Ceph 在存储效率和分层存储方面迈出关键一步。

**Giant 版本功能冻结**
[Patrick_McGary_@_Ceph_Day_Paris](/posts/2014/Patrick_McGarry_@_Ceph_Day_Paris)) 报告 Giant 版本已进入功能冻结阶段，即将发布 0.85 版本，包含 RDMA 支持、SD 改进、CivetWeb 前端等特性，RBD 将默认开启客户端缓存。

**Hammer 版本规划启动**
本季度的 CDS Hammer 开发者峰会（Day 1 & Day 2）标志着 Hammer 版本的正式规划启动，涵盖上述几乎所有技术方向的蓝图讨论，为下一个主要版本奠定了路线图基础。

**Red Hat 收购后的社区治理**
[Patrick_McGarry_@_Ceph_Day_Paris](/posts/2014/Patrick_McGarry_@_Ceph_Day_Paris)) 明确了 Red Hat 收购 Inktank 后的社区策略：继续支持 Ubuntu 和 SUSE，专注 CentOS/Fedora，同时保持 Ceph 和 Gluster 双线并行，用户委员会负责社区治理。

**Calamari API 重新定位**
[CDS_Hammer_Day_1_-_Calamari_API_Roadmap](/posts/2014/CDS_Hammer_Day_1_-_Calamari_API_Roadmap)) 决定将 Calamari 重新定位为纯后端 API 服务层，去除 GUI 依赖，目标是与 rados、RBD、RGW 命令行工具功能对等，并支持异步操作。

**Erasure Code 本地恢复（Local Recovery）**
[Loic_Dachary_@_Ceph_Day_Paris](/posts/2014/Loic_Dachary_@_Ceph_Day_Paris)) 宣布 Hammer 版本将支持 Erasure Code 的本地恢复功能和 ARM 处理器优化，进一步降低纠删码的恢复开销。

## 4. 社区动态

### 4.1 开发者峰会

本季度举办了两场重要的线下开发者活动：

- **CDS G/H（Giant/Hammer）峰会 Day 2**：聚焦 CephFS forward scrub、RBD copy-on-read 等议题
- **CDS Hammer 峰会 Day 1 & Day 2**：规模更大，覆盖 OSD、RGW、CephFS、BD、网络层等几乎所有子系统，是本季度技术讨论最密集的活动

### 4.2 Ceph Day 活动

- **Ceph Day London**：[Ross_Turk_@_Ceph_Day_London](/posts/2014/Ross_Turk_@_Ceph_Day_London)) 主持，Dell（[Dell_@_Ceph_Day_London](/posts/2014/Dell_@_Ceph_Day_London))）、Melanox（[Mellanox_@_Ceph_Day_London](/posts/2014/Mellanox_@_Ceph_Day_London))）等合作伙伴参与，重点讨论企业级部署和高性能网络互连
- **Ceph Day Paris**：[Patrick_McGarry_@_Ceph_Day_Paris](/posts/2014/Patrick_McGarry_@_Ceph_Day_Paris))、[Loic_Dachary_@_Ceph_Day_Paris](/posts/2014/Loic_Dachary_@_Ceph_Day_Paris))、[Sebastian_Han_@_Ceph_Day_Paris](/posts/2014/Sebastian_Han_@_Ceph_Day_Paris)) 等分享了社区进展、Erasure Code 技术深度解析以及 Ceph+OpenStack 集成状态

### 4.3 生态合作

- **Dell**：积极推广 Ceph 作为 OpenStack 存储解决方案，提供硬件参考架构（Intel Xeon E5 系列、近线 SAS、10G/40G 网络）
- **Mellanox**：推进 RDMA 在 Ceph 中的应用，提供 40G 互连方案，并与 Ceph 团队合作开发 Acelio RDMA Messenger
- **富士通**：贡献 SHEC 纠删码实现，展示了社区在日本企业参与方面的扩展
- **法国 University of Nantes**：[Yann_Dupont_@_Ceph_Day_Paris](/posts/2014/Yann_Dupont_@_Ceph_Day_Paris)) 分享了高校生产环境中 5 个独立 Ceph 集群的运维实践，包括 LXC 容器化 OSD、Bcache 缓存加速等经验

### 4.4 部署工具

[Sebastian_Han_@_Ceph_Day_Paris](/posts/2014/Sebastian_Han_@_Ceph_Day_Paris)) 报告了 Ansible 部署工具的完善进展，支持 Monitor、OSD、MDS、RGW 全组件部署，支持滚动升级和多种 OSD 部署场景，并已集成到 DevStack 中简化 OpenStack+Ceph 的开发测试环境搭建。

### 4.5 测试基础设施

[CDS_Hammer_Day_1_-_Tuethology](/posts/2014/CDS_Hammer_Day_1_-_Tuethology)) 讨论了 Teuthology 测试框架的改进，包括文档完善、发布流程建立、容器化测试（Docker）可行性研究以及插件架构设计，以支持不同的资源分配后端。

## 5. 下季度展望

基于本季度讨论内容，预计 2015 Q1（Hammer 版本开发期）将重点推进以下方向：

**OSD 层**
- 机会主义全对象校验和功能落地，与 scrub 流程深度集成
- Cache Tier 读写延迟优化补丁合并，异步读取策略实装
- IO 优先级统一队列机制实现
- OSD 事务编码重构完成并通过兼容性测试

**RBD**
- 内核 RBD 客户端 copy-on-read 功能：等待用户空间实现合并后推进内核侧
- 独占锁与 Object Map 功能稳定化，向生产环境推广
- 集群化 SCSI Target 持久保留支持原型验证

**RGW**
- Bucket Index 分片与多区域功能集成完成
- 对象版本化 bug 修复并进入测试阶段
- Bucket 生命周期管理（对象过期）初步实现

**CephFS**
- Forward scrub 代码审查通过并合并
- 配额功能测试用例完善，子卷概念引入
- Hadoop/HDFS 集成测试通过 Bigtop 自动化验证

**网络与性能**
- Accelio RDMA Messenger 代码提交，进入集成测试
- Buffer Encoding 微优化补丁合并
- 消息结构重构方案（flat bufers 或固定布局）原型验证

**新特性**
- SHEC 纠删码集成到 Ceph 主线，提供文档和单元测试
- Erasure Code 本地恢复功能在 Hammer 版本中发布
- Calamari 1.3 版本发布，完善 Crush 管理和基于角色的授权

**冷存储**
- 对象重定向功能原型开发，为冷热数据分层存储提供基础支撑
