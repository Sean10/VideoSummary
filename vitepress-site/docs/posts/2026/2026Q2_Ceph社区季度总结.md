# Ceph 2026Q2 社区季度进展报告

---

## 一、本季度重点议题

本季度社区讨论高度集中在以下几个反复出现的技术方向：

### 1. Fast EC（快速纠删码）性能优化

Fast EC 是本季度最受关注的技术议题，贯穿多场会议与演讲。[FastEC_in_Ceph_Tentacle_A_Technical_Deep_Dive_into_Next_Gen_Erasure_Coding_Performance](/VideoSummary/2026/04/20/FastEC_in_Ceph_Tentacle_A_Technical_Deep_Dive_into_Next_Gen_Erasure_Coding_Performance/) 对Tentacle 版本中 partial reads、partial writes、arity delta writes 等核心优化进行了深度解析。[Ceph_EC_Performance_Journey_-_Classic_vs._Fast_EC](/VideoSummary/2026/04/20/Ceph_EC_Performance_Journey_-_Classic_vs._Fast_EC/) 则通过 IBM 团队的实测数据，揭示了 Fast EC 中存在的内存泄漏问题并完成修复，修复后 IOPS 提升约 33%。

### 2. RGW 重构与功能完善

RGW Refactoring Meeting 本季度共召开 10 余次，覆盖 lifecycle policy、multipart upload 安全性、小对象存储效率、cloud transition、加密（GCM/SSE）、OIDC、list 请求限速等多个方向，是本季度讨论最密集的子系统。

### 3. 小对象存储效率

多个会议从不同角度讨论了小对象在 erasure coding 场景下的低效问题，包括 object packing、write coalescing、内联存储（inline xattr）等方案，尚处于设计探讨阶段。

### 4. Umbrella 版本升级测试稳定性

[Ceph_Developer_Monthly_Meetup_EMEA_-_April_2026](/VideoSummary/2026/04/08/Ceph_Developer_Monthly_Meetup_EMEA_-_April_2026/) 专门讨论了 Umbrella 升级测试大量失败的问题，主要原因是 health warning 触发测试框架误判，而非升级流程本身存在根本性问题。

### 5. CephFS 新特性交付

[CephFS_News](/VideoSummary/2026/04/02/CephFS_News/) 系统梳理了 Tentacle 已交付特性和 Umbrella 规划特性，涵盖 sub volume metrics、用户空间加密、MDS QoS、mirror daemon 增强等多个方向。

## 二、技术亮点

### Fast EC 内存泄漏修复与性能验证

[Ceph_EC_Performance_Journey_-_Classic_vs._Fast_EC](/VideoSummary/2026/04/20/Ceph_EC_Performance_Journey_-_Classic_vs._Fast_EC/) 记录了一个关键发现：Fast EC 在 PG 进入 idle 状态时，EC dummy ops 创建的约 1KB 对象未被正确释放，导致内存持续泄漏，OSD 实际内存消耗远低于 target（16GB target 实际仅 1GB）。修复后：
- CPU 使用率从约 780% 降至 600%
- 16K block size 下 IOPS 从约 1.2M 提升至 1.6M
- 12 节点集群验证了线性扩展能力

### RGW 小对象内联存储方案

[Ceph_RGW_Refactoring_Meeting_2026-03-11](/VideoSummary/2026/05/13/Ceph_RGW_Refactoring_Meeting_2026-03-11/) 提出将小于 320~512 字节的对象数据直接存储在 xattr（BlueStore RocksDB Omap）中，省去 manifest，实现零额外 block 开销。在 erasure coding 4+2 场景下，一个 256 字节对象当前消耗约 24KB 存储空间，该方案可将其降至字节级别。

### RGW Lifecycle性能优化

[Ceph_RGW_Refactoring_Meeting_2026-04-29](/VideoSummary/2026/05/13/Ceph_RGW_Refactoring_Meeting_2026-04-29/) 和 [Ceph_RGW_Refactoring_Meeting_2026-05-06](/VideoSummary/2026/05/13/Ceph_RGW_Refactoring_Meeting_2026-05-06/) 讨论了两个方向：
- **版本对象批量删除**：将相同 key 下多版本对象归组，使用 multi-delete 批量处理，实测版本化 bucket lifecycle 处理速度提升 50%~60%
- **多线程处理**：提出 intra-RGW（单 daemon 内部 fan-out）和 cross-RGW（跨 daemon 协同）两种方案，前者 PoC 已验证 2~3 倍提升

### CephFS 用户空间加密

[CephFS_News](/VideoSummary/2026/04/02/CephFS_News/) 介绍了 Umbrella 版本将内核客户端加密（Linux 6.6+）移植至用户空间客户端，支持目录项名称加密和文件数据加密，无密钥者只能看到密文。

### CephFS Sub Volume Quarantine（隔离）

作为安全特性引入，主要应对勒索软件攻击场景。通过 manager volumes 接口对指定 sub volume 执行隔离：已挂载客户端被驱逐，新挂载请求被拒绝。

### S3 Vector Search（近邻搜索）

[Closer_than_you_think_-_Ceph_sjourney_to_nearest_neighbor_search](/VideoSummary/2026/04/21/Closer_than_you_think_-_Ceph_s_journey_to_nearest_neighbor_search/) 介绍了 Ceph RGW 兼容 Amazon S3 Vectors API 的工作进展，选用 LanceDB（Rust 实现，IVFPQ 索引）作为向量库，目标是在 Ceph 集群中原生支持 vector embedding存储与近邻检索，无需额外部署 PGVector、Milvus 等独立系统。

### BXC：RBD 懒加载镜像架构

[BXC_-_An_Architecture_for_Lazy_RBD_Imaging_and_Snapshot_Exports](/VideoSummary/2026/04/20/BXC_-_An_Architecture_for_Lazy_RBD_Imaging_and_Snapshot_Exports/) 介绍了 Digital Ocean 基于 RBD import-only live migration 特性设计的 Block Exchange 架构，实现 VM 启动盘的即时启动（instant boot）——OS 按需拉取 block，后台异步完成完整镜像写入，同时通过 edge cache 实现 deduplication。

### PG Autoscaler 均匀分配改进

[Ceph_User_+_Dev_Monthly_-_April_2026](/VideoSummary/2026/04/15/Ceph_User_+_Dev_Monthly_-_April_2026/) 介绍了将 autoscaler 分配问题建模为背包问题（Knapsack Problem）的动态规划优化，修复了多个 pool 设置相同 `target_sizeratio` 时分配不均的 bug，时间复杂度 O(n log m)，升级后自动生效。

### 3AZ Stretch Cluster 的 Net Split 处理

[Detect_Decide_Fence_Resolving_Netsplits_in_3_AZ_Stretch_Cluster](/VideoSummary/2026/04/20/Detect_Decide_Fence_Resolving_Netsplits_in_3_AZ_Stretch_Cluster/) 提出了 Detect → Decide → Fence 三步方案：使用 Bron-Kerbosch 最大团算法选出胜出分区，支持用户配置 zone preference 或自动启发式决策，并通过 fencing 机制隔离落败分区，防止 split-brain。

### Dashboard 性能大幅提升

[Ceph_Dashboard_Roadmap](/VideoSummary/2026/04/02/Ceph_Dashboard_Roadmap/) 报告了 Tentacle 版本 dashboard 的重要里程碑：LCP（Largest Contentful Paint）从 9.82 秒降至 2.11 秒，达到 2.5 秒以内的性能基准。

### RGW Lua 动态数据放置

[Ceph_S3_Dynamic_Placement_and_Optimized_Retention](/VideoSummary/2026/04/02/Ceph_S3_Dynamic_Placement_and_Optimized_Retention/) 展示了通过 Lua 脚本在 pre-request 阶段动态分配 storage class 的实践，延迟开销在微秒级别，支持按对象大小、扩展名、bucket 名等维度路由，实现小对象走 replicated pool、大对象走 erasure coding pool 的自动分层。

## 三、重要决策与里程碑

### Tentacle 版本发布

本季度 Tentacle（Ceph 30.x）已正式发布，多个会议以 Tentacle 为基准讨论新特性和 backport 工作。[Ceph_RGW_Refactoring_Meeting_2026-02-25](/VideoSummary/2026/05/13/Ceph_RGW_Refactoring_Meeting_2026-02-25/) 提到 lifecycle policy 删除 bug 的 backport 已合并至 Squid 分支，将随 19.2.4 发布。

### Umbrella 版本 Feature Freeze

[Ceph_RGW_Refactoring_Meeting_2026-05-06](/VideoSummary/2026/05/13/Ceph_RGW_Refactoring_Meeting_2026-05-06/) 明确宣布 Umbrella 版本的 feature freeze 将于 2026 年 5 月底到来，有意合入新功能的开发者需在月底前完成相关工作。

### Umbrella 升级 Kickoff PR 合并

[Ceph_Developer_Monthly_Meetup_EMEA_-_April_2026](/VideoSummary/2026/04/08/Ceph_Developer_Monthly_Meetup_EMEA_-_April_2026/) 记录了 Umbrella 升级 kickoff PR 已合并，尽管升级测试存在大量失败，团队决定先合并再跟进修复，并建立 baseline 调度机制。

### MDS QoS Tech Preview

[CephFS_News](/VideoSummary/2026/04/02/CephFS_News/) 宣布基于 DM-Clock 算法的 MDS QoS 将在 Umbrella 版本以 Tech Preview 形式发布，计划在 Vampire 版本达到 GA。

### Ceph 配置变更可追踪机制上线

[Don_t_Get_Conf_d_Making_Ceph_Configuration_Changes_Obvious](/VideoSummary/2026/04/02/Don_t_Get_Conf_d_Making_Ceph_Configuration_Changes_Obvious/) 介绍了 CI 中新增的 **ceph-config-diff** 检查，在每个 PR 提交时自动检测配置项变更并提示开发者更新 release notes，相关脚本已合入上游仓库。

### Ceph 作为 NAS 平台的架构就绪声明

[Ceph_as_a_NAS_Platform_Are_We_Architecturally_Ready](/VideoSummary/2026/04/02/Ceph_as_a_NAS_Platform_Are_We_Architecturally_Ready/) 系统梳理了 Ceph 从 NFS/Samba 存储后端演进为原生 NAS 平台的历程：Reef 版本引入 NFS 原生编排，Squid 版本引入 SMB 原生编排，配置统一存储于 RADOS 层，标志着 Ceph 在架构层面已具备完整 NAS 平台能力。

## 四、社区动态

### 大规模生产用户经验分享

### 支持工程师与开发者之间的协作障碍

### KCLI 容器化开发环境推广

## 五、下季度展望

基于本季度讨论，预计 2026Q3 将重点推进以下方向：

### 1. Umbrella 版本发布与稳定化

Feature freeze 已于 5 月底到来，Q3 将进入 Umbrella 版本的QA 测试、bug 修复和发布准备阶段。升级测试 baseline 的建立和 health warning 误判问题的修复是近期优先项。

### 2. Fast EC 生产化推广

内存泄漏修复后，Fast EC 的性能优势已得到验证。预计 Q3 将有更多用户开始评估从 Classic EC迁移，社区也将持续完善 `allow_ec_optimizations` 相关文档和最佳实践。

### 3. RGW 小对象存储效率落地

小对象内联存储（xattr inline）和 object packing 方案本季度完成了设计讨论，Q3 预计进入原型实现和 PR 提交阶段，重点需要解决向后兼容性（zone feature flag保护）问题。

### 4. RGW Lifecycle 多线程处理

intra-RGW fan-out 方案 PoC 已验证 2~3 倍提升，Q3 预计提交正式 PR。针对单桶百亿对象的极端场景，cross-RGW 协同方案的设计讨论也将继续推进。

### 5. CephFS MDS QoS GA

MDS QoS 在 Umbrella 以 Tech Preview 发布后，社区将收集用户反馈，为 Vampire 版本的 GA 做准备。

### 6. 3 AZ Stretch Cluster 正式支持

Detect → Decide → Fence 方案的实现工作预计在 Q3 继续推进，MON 连通性评分功能已在 Squid 合并，决策与 fencing 逻辑是下一步重点。

### 7. S3 Vector Search 功能完善

[Closer_than_you_think_-_Ceph_s_journey_to_nearest_neighbor_search](/VideoSummary/2026/04/21/Closer_than_you_think_-_Ceph_s_journey_to_nearest_neighbor_search/) 中的 LanceDB 集成工作预计在 Q3 进入更成熟的实现阶段，目标是达到 sub-millisecond 查询延迟。

### 8. RGW 加密体系完善

GCM 加密 PR 的安全审查（计划引入 Cloudflare 团队）、SSE 对象 copy 修复、lifecycle transition 中的 recompression/re-encryption 支持，预计在 Q3 陆续完成并合入。

### 9. Ceph CI 实验室迁移完成

上游实验室迁至 Poughkeepsie 后仍有约四分之三设备处于网络接入待完成状态，Q3 预计完成基础设施恢复，升级测试的定期 baseline 调度也将随之恢复。
