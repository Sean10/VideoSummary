# Ceph 社区 2026Q1 季度进展报告

---

## 一、本季度重点议题

本季度社区讨论高度集中在以下几个反复出现的技术方向：

**1. RGW 存储效率优化**
bucket ID 与对象 prefix 字符串过长问题贯穿多次 RGW 重构会议，是本季度 RGW 方向最核心的持续性议题。详见 [Ceph RGW Refactoring Meeting 2026-01-14](/posts/2026/Ceph_RGW_Refactoring_Meeting_2026-01-14))。

**2. RGW Server-Side Encryption 演进**
GCM 加密模式支持、DUP 与加密结合的设计问题，在多次会议中被深入讨论，反映出社区对数据安全与存储效率协同优化的持续关注。详见 [Ceph RGW Refactoring Meeting 2026-02-11](/posts/2026/Ceph_RGW_Refactoring_Meeting_2026-02-11))。

**3. 大容量 HDD 场景下的运维挑战**
随着 HDD 单盘容量突破 26TB 乃至 44TB，deep scrub 性能、PG 数量调优等运维问题在社区中引发广泛讨论。详见 [Ceph Use + Dev Meetup March 2026](/posts/2026/Ceph_Use_+_Dev_Meetup_March_2026))。

**4. 测试基础设施扩展**
Teuthology 在 Sepia 实验室外的 OpenStack 环境中运行，是本季度测试工程方向的重要推进。详见 [Running Teuthology Outside of the Sepia lab](/posts/2026/Running_Teuthology_Outside_of_the_Sepia_lab_With_Deepshikha_Singh))。

## 二、技术亮点

### RGW：bucket ID 缩短方案

[Ceph RGW Refactoring Meeting 2026-01-14](/posts/2026/Ceph_RGW_Refactoring_Meeting_2026-01-14)) 中，社区确定了使用 **zone short ID**（32-bit 整数，hex 后仅 8 字节）替代当前 40+ 字节 zone UUID 的方案。该方案可显著降低每个 RADOS 对象名称的长度，减少 OSD OMAP 中的元数据开销，在大规模小对象场景下收益尤为明显。同时讨论了通过 CLS 范围分配机制缩短 prefix 的方案，但因收益相对有限，决定优先推进 bucket ID 缩短。

### RGW：S3 Vectors API — Vector Bucket实现

[Ceph RGW Refactoring Meeting 2026-01-21](/posts/2026/Ceph_RGW_Refactoring_Meeting_2026-01-21)) 详细介绍了 vector bucket 的架构设计：
- 在 driver 层新增 `load_vector_bucket` / `list_vector_buckets` 接口
- 复用现有 `bucket_info` 对象，避免大规模代码改动
- 新增独立 pool 与独立 metadata sync section（`vector_bucket`）
- 通过继承 `RGWSI_Bucket_SObj` 实现 `RGWSI_VectorBucket_SObj`，差异通过 virtual 函数隔离

### RGW：AES-256GCM 加密模式支持

[Ceph RGW Refactoring Meeting 2026-02-11](/posts/2026/Ceph_RGW_Refactoring_Meeting_2026-02-11)) 中，Matthew 介绍了 AES-256-GCM 支持 PR。GCM 作为 size-changing cipher，需修复大量假设加密前后数据大小不变的代码路径，新增三个 head object 属性记录明文大小。GCM 的核心优势是任何数据损坏或密钥错误均可立即被检测。

### RGW：DUP 与 Server-Side Encryption 结合设计

同一会议中，DDUP 与加密的结合方案取得重要进展：
- SSE-S3 / SSE-KMS 模式下 E tag 为明文 MD5，可作为去重判断依据
- 当前阶段限定为**同 bucket 内**加密对象去重，跨 bucket 因 per-bucket key 问题暂不支持
- 计划在 E tag 之外额外存储强 hash（SHA 或 BLAKE），供未来 multi-site sync 优化使用

### RGW：Object History 索引条目泄漏问题

[Ceph RGW Refactoring Meeting 2026-01-28](/posts/2026/Ceph_RGW_Refactoring_Meeting_2026-01-28)) 中，Bloomberg 团队报告了 OH 索引条目在所有版本删除后存在泄漏的问题，根因为清理流程中的竞态条件（race condition），影响 squid 及更早版本。社区正在编写 multi-site 测试用例以复现该问题。

### RGW：Admin CLI帮助文档自动生成

同次会议讨论了将命令描述集中定义于代码中、自动生成 man page 与 help 输出的方案，参考了 Ceph 配置选项的 YAML 元数据驱动做法，并将部分任务列为 GSoC 候选项目。

### RGW：Lua 脚本包管理

[Ceph Tech Talk - RGW Lua Scripting Code Walkthrough](/posts/2026/Ceph_Tech_Talk_-_RGW_Lua_Scripting_Code_Walkthrough_-_Clip)) 介绍了 RGW Lua 脚本中基于 LuaRocks 的外部包管理机制，支持引入 `socket`、`json` 等第三方包，扩展脚本实用性。

### BlueStore：Elastic Shared Blobs Bug 告警机制讨论

[Ceph User + Dev Meetup January 2026](/posts/2026/Ceph_User_+_Dev_Meetup_January_2026)) 中，社区围绕 bluestore elastic shared blobs 数据损坏 bug 的通知机制展开深入讨论。该 bug 在 Tentacle 版本已修复，Squid 修复已合并待发布，但代码修复无法恢复已损坏元数据。社区就是否引入 health warning 存在分歧，最终共识是需要更主动的通知渠道，具体方案待后续讨论。

### Teuthology：OpenStack 环境支持

[Running Teuthology Outside of the Sepia lab](/posts/2026/Running_Teuthology_Outside_of_the_Sepia_lab_With_Deepshikha_Singh)) 介绍了在自有 OpenStack 环境中运行 Teuthology 的完整方案，支持与 Sepia 实验室相同的测试套件，Mass 模式执行已于本季度合并。当前限制为不支持 power cycle 及基于真实磁盘的 BlueStore 测试。

## 三、重要决策与里程碑

| 事项 | 决策内容 |
|------|------|
| bucket ID 缩短方案 | 采用 zone short ID（8 字节 hex），优先于 prefix 缩短 |
|加密 DDUP 范围 | 当前阶段限定同 bucket 内，跨 bucket 暂不支持 |
| Vector Bucket 架构 | 复用 `bucket_info`，新增独立 pool 与 metadata sync section |
| BlueStore bug 通知 | 需要更主动通知机制，具体方案待邮件列表讨论 |
| Teuthology Mass 模式 | 已合并，OpenStack 环境支持正式可用 |
| RBD namespace quota | 技术可行性已分析，底层依赖 RADOS namespace 机制，待后续推进 |

**版本状态：**
- BlueStore elastic shared blobs bug：Tentacle 已修复发布，Squid 修复已合并待发布
- RBD clone flatten读零 bug：已由 Nikola 完成初步调查，尚无 PR，需 code review

## 四、社区动态

### Ceph Ambassador Program2026 年计划

- **Ceph Day London**：CFP 已开放，活动定于 6 月 17 日，征稿截止 4 月 24 日

## 五、下季度展望

基于本季度讨论，预计 2026Q2 将在以下方向持续推进：

1. **RGW bucket ID 缩短落地**：zone short ID 方案已达成共识，预计进入实现与测试阶段，相关 tail tag、bucket index shard 命名将同步受益。

2. **AES-256-GCM 加密 PR 合并**：GCM 支持 PR 已进入审查阶段，预计本季度完成合并，为后续 DDUP 与加密结合奠定基础。

3. **DDUP 功能推进**：依赖 split head 功能完成后方可完整实现，SSE-KMS 模式支持及跨 bucket 加密 DDUP 的 key pining 方案将在同 bucket DDUP 验证后评估。

4. **S3 Vectors API 完善**：vector bucket 基础架构已设计完成，预计推进 vector 数据操作接口的实现与集成测试覆盖。

5. **BlueStore bug 通知机制**：社区已达成需要更主动通知渠道的共识，预计在邮件列表形成具体方案（health warning 分级、cluster error log 等）。

6. **RBD namespace quota**：技术可行性已明确，预计进入详细设计与实现阶段。

7. **Teuthology OpenStack 覆盖扩展**：持续增加 job 数量、提升稳定性，Shaman 自建实例支持待确认。

8. **Ceph Day London**：6 月 17 日举办，预计带来更多用户案例与性能优化实践分享。
