# Ceph 社区 2026 年度进展报告

---

## 一、全年技术演进

2026 年，Ceph 社区的技术演进呈现出几条清晰的主线：**存储效率提升**、**协议层原生化**、**可观测性增强**，以及**AI 时代的新存储范式探索**。

### 1.1 存储效率：EC 优化与小对象处理

Erasure Coding 的性能改进是本年度最受关注的技术方向之一。Tentacle 版本引入的 Fast EC 通过 partial reads、partial writes 和 parity delta writes 三项机制，从根本上解决了传统 EC 在 block 工作负载下的 read-modify-write 放大问题。详见 [FastEC in Ceph Tentacle: A Technical Deep Dive](/VideoSummary/2026/04/20/FastEC_in_Ceph_Tentacle_A_Technical_Deep_Dive_into_Next_Gen_Erasure_Coding_Performance/) 和 [Ceph EC Performance Journey](/VideoSummary/2026/04/20/Ceph_EC_Performance_Journey_-_Classic_vs._Fast_EC/)。

与此同时，社区在 RGW 层面也持续探索小对象存储效率问题，包括：
- 将小于 512 字节的对象数据内联存储于 xattr，省去 manifest 开销
- 针对 EC 场景的 write coalescing（写合并）方案，通过延迟 ACK 聚合多个小写入
- 两层缓存架构（前端 replication + 后端 EC）的设计讨论

详见 [Ceph RGW Refactoring Meeting 2026-03-04](/VideoSummary/2026/05/13/Ceph_RGW_Refactoring_Meeting_2026-03-04/) 和 [Ceph RGW Refactoring Meeting 2026-03-11](/VideoSummary/2026/05/13/Ceph_RGW_Refactoring_Meeting_2026-03-11/)。

### 1.2 协议层原生化：NAS 平台化进程

Ceph 正在从"存储后端"向"完整 NAS 平台"演进。Reef 版本引入 NFS 原生编排，Squid 版本引入 SMB 原生编排，使 NFS 和Samba 服务成为 Ceph 内部的一等公民组件，由 cephadm 统一管理生命周期。详见 [Ceph as a NAS Platform: Are We Architecturally Ready](/VideoSummary/2026/04/02/Ceph_as_a_NAS_Platform_Are_We_Architecturally_Ready/)。

### 1.3 AI 时代的新存储范式：S3 Vectors

2025 年底AWS 发布 S3 Vectors API后，Ceph 社区迅速跟进，启动了 RGW 兼容 S3 Vectors API 的实现工作。目标是让用户无需额外部署 PGVector、Milvus 等独立向量数据库，即可在 Ceph 集群中存储和检索 vector embedings，实现 unstructured data 与对应 embedings 的同平台存储。详见 [Closer than you think: Ceph's journey to nearest neighbor search](/VideoSummary/2026/04/21/Closer_than_you_think_-_Ceph_s_journey_to_nearest_neighbor_search/)。

### 1.4 可观测性与配置管理

本年度社区在可观测性方面投入显著增加：
- CephFS 新增 MDS tracing framework，为 OpenTelemetry 集成奠定基础
- Dashboard LCP 从 9.82 秒降至 2.11 秒，性能大幅提升
- 新增 ceph-config-diff CI工具，自动检测配置项变更并提示更新 release notes
- 沃尔玛等大规模用户的实践表明，外部端到端延迟监控不可替代

详见 [Ceph Dashboard Roadmap](/VideoSummary/2026/04/02/Ceph_Dashboard_Roadmap/) 和 [Don't Get Conf'd: Making Ceph Configuration Changes Obvious](/VideoSummary/2026/04/02/Don_t_Get_Conf_d_Making_Ceph_Configuration_Changes_Obvious/)。

## 二、重大里程碑

### 2.1 Tentacle 版本发布

Tentacle（版本 30.x）是本年度最重要的版本里程碑，主要交付包括：

**RGW 方向：**
- Fast EC 正式可用，支持 partial reads/writes 和 parity delta writes
- SMB 管理功能引入 Dashboard
- RGW multi-site 自动化向导
- NVMe-oF TCP 管理界面重构

**CephFS 方向：**
- 大小写不敏感目录树（Case-Insensitive Directory Trees），提升 Samba 互操作性
- Block Diff RPC，支持快速增量镜像同步
- MDS log replay 和 sub volume 删除操作的预计完成时间（ETC）显示

**基础设施：**
- BlueStore elastic shared blobs bug 修复（Tentacle 已修复，Squid 修复合并待发布）

详见 [CephFS News](/VideoSummary/2026/04/02/CephFS_News/) 和 [Ceph Dashboard Roadmap](/VideoSummary/2026/04/02/Ceph_Dashboard_Roadmap/)。

### 2.2 Umbrella 版本开发启动

Umbrella 版本（Reef 的下一个版本）在本年度进入活跃开发阶段，feature freeze 预计于 2026 年 5 月底。主要规划特性包括：

- CephFS sub volume metrics（per sub volume 的读写吞吐量指标）
- CephFS snapshot 可见性控制
- CephFS sub volume 隔离（Quarantine）安全特性
- CephFS 用户空间加密支持
- MDS QoS（基于 DM-Clock 算法，Tech Preview）
- Dashboard multicluster 管理视图
- RGW lifecycle metrics 作为 perf counters

详见 [CephFS News](/VideoSummary/2026/04/02/CephFS_News/)、[Ceph Developer Monthly Meetup EMEA - April 2026](/VideoSummary/2026/04/08/Ceph_Developer_Monthly_Meetup_EMEA_-_April_2026/) 和 [Ceph RGW Refactoring Meeting 2026-04-29](/VideoSummary/2026/05/13/Ceph_RGW_Refactoring_Meeting_2026-04-29/)。

### 2.3 Fast EC 内存泄漏修复

IBM 团队在 Tentacle Fast EC 的性能测试中发现了一个关键内存泄漏：EC dummy ops 在 PG 进入 idle 状态时未被正确释放，导致 OSD 内存消耗远低于 target，CPU 使用率异常偏高。修复后 IOPS 提升约 33%（从 1.2M 提升至 1.6M），这是本年度最重要的 bug fix 之一。详见 [Ceph EC Performance Journey](/VideoSummary/2026/04/20/Ceph_EC_Performance_Journey_-_Classic_vs._Fast_EC/)。

## 三、核心组件进展

### 3.1 RGW（RADOS Gateway）

RGW 是本年度代码活动最活跃的组件，重构会议几乎每周举行。主要进展：

**新特性：**
- **S3 Vectors API 实现**：新增 vector bucket抽象，复用现有 bucket_info 结构，独立 pool 和 metadata sync section。详见 [Ceph RGW Refactoring Meeting 2026-01-21](/VideoSummary/2026/01/25/Ceph_RGW_Refactoring_Meeting_2026-01-21/)
- **AES-256-GCM 加密支持**：替代现有 CBC 模式，引入认证加密能力，正在进行密码学安全审查。详见 [Ceph RGW Refactoring Meeting 2026-02-11](/VideoSummary/2026/02/18/Ceph_RGW_Refactoring_Meeting_2026-02-11/)
- **DUP（数据去重）**：支持 SSE-S3 和 SSE-KMS 加密对象的同 bucket 内去重，依赖 split head 功能完成后落地
- **Cloud transition异步删除**：通过 FIFO Queue 支持云端对象的异步删除，opt-in 特性。详见 [Ceph RGW Refactoring Meeting 2026-05-06](/VideoSummary/2026/05/13/Ceph_RGW_Refactoring_Meeting_2026-05-06/)
- **Lifecycle 多线程优化**：两种方案（intra-RGW 和 cross-RGW）正在评估，初步 PoC 显示 2-3 倍性能提升

**Bug 修复：**
- Lifecycle policy 删除 bug（backport 至 Squid 19.2.4）
- Multipart upload 数据丢失问题（CLS lock 续约方案）
- Object history 索引条目泄漏问题

**架构改进：**
- Bucket ID缩短方案（使用 zone short ID 替代完整 UUID，节省 OMAP 存储开销）
- RGW objector introspection 修复（为每个 librados 实例设置独立 socket 名称）
- List 请求基于时间的 rate limiting

详见 [Ceph RGW Refactoring Meeting 2026-01-14](/VideoSummary/2026/01/25/Ceph_RGW_Refactoring_Meeting_2026-01-14/)、[Ceph RGW Refactoring Meeting 2026-02-18](Ceph_RGW_Refactoring_Meeting_2026-02-18) 和 [Ceph RGW Refactoring Meeting 2026-03-25](/VideoSummary/2026/05/13/Ceph_RGW_Refactoring_Meeting_2026-03-25/)。

**Lua 脚本能力增强：**
RGW Lua 脚本支持动态 storage class 分配，可根据对象大小、扩展名、bucket 名称等维度自动路由，字节码缓存优化已合并。详见 [Ceph S3 Dynamic Placement and Optimized Retention](/VideoSummary/2026/04/02/Ceph_S3_Dynamic_Placement_and_Optimized_Retention/) 和 [Ceph Tech Talk - RGW Lua Scripting Code Walkthrough](/VideoSummary/2026/03/06/Ceph_Tech_Talk_-_RGW_Lua_Scripting_Code_Walkthrough_-_Clip/)。

### 3.2 CephFS

**Tentacle 已交付：**
- 大小写不敏感目录树
- Block Diff RPC（与 mirror daemon 集成）
- 操作预计完成时间（ETC）显示

**Umbrella 规划中：**
- Sub volume metrics（per client 粒度）
- Snapshot 可见性控制（面向 NFS 场景）
- Sub volume 隔离（Quarantine，应对勒索软件）
- Mirror daemon 多线程支持（已合并主线）
- 用户空间加密支持（移植自内核客户端 Linux 6.6 实现）
- 命令审计日志（Command Audit Logging）
- MDS Tracing Framework（OpenTelemetry 集成基础设施）
- MDS QoS（DM-Clock 算法，Tech Preview）

**Vampire 版本规划：**
- MDS QoS GA
- 快速灾难恢复工具

详见 [CephFS News](/VideoSummary/2026/04/02/CephFS_News/)。

**实际部署案例：**
乔治梅森大学将约 16,000 个用户主目录从 NFS 迁移至 CephFS，解决了期末高并发 IO 导致的 NFS 服务器过载问题。详见 [Implementing Ceph at GMU's College of Engineering and Computing](/VideoSummary/2026/04/21/Implementing_Ceph_at_GMU_s_College_of_Engineering_and_Computing/)。

### 3.3 BlueStore

本年度 BlueStore 的主要关注点集中在两个方面：

**Elastic Shared Blobs Bug：**
该 bug 在 Tentacle 已修复，Squid 修复合并待发布。核心问题是写入时触发断言失败导致 OSD 崩溃，且损坏的元数据无法通过 fsck 检测。社区围绕是否应添加 health warning 展开了深入讨论，最终共识是需要更主动的通知机制，但具体形式仍在讨论中。详见 [Ceph User + Dev Meetup January 2026](/VideoSummary/2026/01/28/Ceph_User_+_Dev_Meetup_January_2026/)。

**大容量 HDD 的 deep scrub 问题：**
随着 HDD 容量持续增大（Seagate 已有 44TB 产品），默认 1 周的 deep scrub 间隔在大容量 HDD 上已无法完成一次完整扫描。建议将每 OSD PG 数调整至 150-200，并正确配置 MCLOCK 调度器。详见 [Ceph Use + Dev Meetup March 2026](/VideoSummary/2026/03/20/Ceph_Use_+_Dev_Meetup_March_2026/)。

### 3.4 Crimson/SeaStore

Crimson OSD 在本年度进入更广泛的测试阶段。社区开发了基于 KCLI 的容器化部署工具，支持一键部署 Crimson 集群，显著降低了开发者的测试门槛。KCLI 支持指定 OS 镜像版本、挂载本地源码目录、配置 Crimson 专属参数（如 `crimson_cpu_num`），并通过 `--osd-type crimson` 参数部署 Crimson OSD。详见 [Containerized deployment of Ceph with KCLI](/VideoSummary/2026/05/12/Containerized_deployment_of_Ceph_with_KCLI/)。

### 3.5 Dashboard

本年度 Dashboard 完成了多项重要改进：

- **性能大幅提升**：LCP 从 9.82 秒降至 2.11 秒，达到 2.5 秒以内的 performance 基准
- **Carbon Design System 迁移**：持续从 Bootstrap 迁移至 Carbon Design System
- **Multicluster 管理视图**：支持跨集群添加、删除、编辑，统一查看 capacity 和 alerts
- **OAuth2 SSO**：基于 OIDC 协议，支持 MFA
- **SMB 管理**：新增 SMB cluster 创建与管理界面
- **RGW 增强**：Multi-site 自动化向导、Notification Destination、Storage Class 管理、用户账户管理
- **NVMe-oF TCP 管理**：按Carbon Design System 规范完整重构
- **全新 onboarding 页面**：引导用户完成初始集群配置

详见 [Ceph Dashboard Roadmap](/VideoSummary/2026/04/02/Ceph_Dashboard_Roadmap/) 和 [Ceph User + Dev Monthly Meetup - May 2026](/VideoSummary/2026/05/27/Ceph_User_+_Dev_Monthly_Meetup_-_May_2026/)。

### 3.6 RADOS 与 PG 管理

**PG Autoscaler 均匀分配改进：**
修复了多个 pool 设置相同 `target_size_ratio` 时分配不均的 bug，采用类背包问题的动态规划算法，确保同组 pool 公平分配 PG。详见 [Ceph User + Dev Monthly - April 2026](/VideoSummary/2026/04/15/Ceph_User_+_Dev_Monthly_-_April_2026/)。

**3 AZ Stretch Cluster：**
社区正在将 stretch 模式从 2 AZ 扩展到 3 AZ，核心挑战是在没有 tiebreaker monitor 的情况下处理 split-brain。解决方案采用 Detect → Decide → Fence 三步流程，使用 Bron-Kerbosch 最大团算法选出胜出分区，并通过 fencing 隔离落败分区。详见 [Detect, Decide, Fence: Resolving Netsplits in 3 AZ Stretch Cluster](/VideoSummary/2026/04/20/Detect_Decide_Fence_Resolving_Netsplits_in_3_AZ_Stretch_Cluster/)。

## 四、社区生态

### 4.1 重要活动

**Cephalocon 2025 温哥华峰会：**
本年度最重要的社区活动，是迄今为止规模最大的 Ceph 社区年度盛会之一，汇聚了全球开发者、用户和架构师。峰会围绕 OSD、MDS、RGW、RADOS 等核心组件的演进路线，以及 BlueStore 性能优化、EC 改进、容器化与 Kubernetes 集成等议题展开深入讨论。详见 [Cephalocon 2025 Highlights: Vancouver's Biggest Ceph Community Gathering](/VideoSummary/2026/01/12/Cephalocon_2025_Highlights_Vancouver_s_Biggest_Ceph_Community_Gathering/)。

**Ceph Days 系列：**
- Ceph Days Raleigh（2026 年 3 月）
- Ceph Day London（2026 年 6 月 17 日，CFP 截止 4 月 24 日）

**月度例会：**
Ceph User + Dev Monthly Meetup 和 Ceph Developer Monthly Meetup EMEA 持续举行，覆盖用户案例分享、bug 讨论和技术方向规划。

### 4.2 Ambassador Program

Ceph Foundation Ambassador Program 在本年度进入系统化运营阶段，Anthony Middleton 担任社区经理。四大核心目标：建设地区社区、放大用户声音、提升 Ceph 知名度、支持上游参与。Ceph Foundation 已连续近 10 年参与 Google Summer of Code，2026 年再次获批。详见 [Get Involved with the Ceph Ambassador Program](/VideoSummary/2026/02/26/Get_Involved_with_the_Ceph_Ambassador_Program_featuring_Anthony_Middleton_Ceph_Community_Manager/)。

### 4.3 大规模用户实践

**沃尔玛（10 年 Ceph 实践）：**
沃尔玛分享了从 2015 年 Hammer 版本到 2024-2025 年 Reef 版本的完整演进历程，硬件从 SATA HDD 演进至全 NVMe，网络从 10GbE 升级至 100GbE，存储节点从借用硬件扩展至数十个生产集群。核心经验：外部端到端延迟监控不可替代，Ceph 原生 dashboard 的延迟数据在大版本升级期间完全失真。详见 [10 Years of Ceph at Walmart](/VideoSummary/2026/04/20/10_years_of_Ceph_at_Walmart/)。

**Digital Ocean（BXC 架构）：**
Digital Ocean 设计了 Block Exchange（BXC）架构，利用 RBD import-only live migration 特性实现 lazy imaging，解决了大规模 VM 启动盘创建时的写流量爆炸问题，实现即时启动和后台异步镜像写入。详见 [BXC - An Architecture for Lazy RBD Imaging and Snapshot Exports](/VideoSummary/2026/04/20/BXC_-_An_Architecture_for_Lazy_RBD_Imaging_and_Snapshot_Exports/)。

**Hetzner（RGW Auto Tiering）：**
Hetzner 发现约 13% 的 S3 对象小于 4 KB，通过 lifecycle policy 将小对象路由至 replicated pool，大对象路由至 EC pool，实现自动分层。详见 [Ceph User + Dev Monthly - April 2026](/VideoSummary/2026/04/15/Ceph_User_+_Dev_Monthly_-_April_2026/)。

### 4.4 CI/CD 基础设施

Ceph CI 团队分享了从 GitBuilders 时代到现 Jenkins Pipeline 的完整演进历程。当前每天运行约 2,000-3,000 个集成测试任务，支持 x86、arm64 多架构，覆盖 CentOS、Ubuntu、Rocky Linux 等多个发行版。近期重大改进：已实现在容器内构建 Ceph，Ubuntu 宿主机可构建 RPM。详见 [Ceph CI and Developer Tooling - Past, Present and Future](/VideoSummary/2026/04/20/Ceph_CI_and_Developer_Tooling_-_Past_Present_and_Futur/)。

Teuthology 新增 MAS（Metal as a Service）裸金属 provisioning 后端支持，提供类云体验的裸金属管理能力。详见 [MAAS as a Backend - Provisioning Infrastructure for Teuthology Suites](/VideoSummary/2026/04/22/MAAS_as_a_Backend_-_Provisioning_Infrastructure_for_Teuthology_Suites_With_Vaibhav_Mahajan/)。

### 4.5 开发者与支持生态

Croyd 公司的支持工程师指出了容器化部署时代开发者与支持团队之间的协作障碍：从本地 patch 到可部署容器镜像的流程过于繁琐，尤其在 air-gapped 环境中。社区正在推进一条命令完成本地 patch 构建和容器镜像生成的工具链改进。详见 [Barriers between Ceph Development and Ceph Support](/VideoSummary/2026/04/02/Barriers_between_Ceph_Development_and_Ceph_Support/)。

## 五、下一年展望

基于本年度的技术讨论和社区动态，可以推断以下方向将在 2027 年持续推进：

### 5.1 Umbrella 版本 GA 与 Vampire 版本规划

Umbrella 版本将在 2026 年底至 2027 年初正式发布，带来 CephFS sub volume metrics、MDS QoS Tech Preview、用户空间加密等特性。Vampire 版本的规划重点预计包括 MDS QoS GA、快速灾难恢复工具，以及 CephFS mirror daemon 的进一步增强。

### 5.2 Fast EC 生产化与 Object Packing

Fast EC 在 Tentacle 中完成了核心机制的实现，2027 年预计将进入更广泛的生产验证阶段。与此同时，RADOS 层的 object packing 方案（针对 EC 场景下小对象的合并存储）将与 Gaby 的两层缓存架构方案协同推进，最终在 RADOS 层统一落地。

### 5.3 S3 Vectors 与 AI 存储

S3 Vectors API 的RGW 实现将在 2027 年进入可用阶段，Ceph 有望成为 AI 工作负载中 unstructured data 与 vector embedings 的统一存储平台，直接竞争 PGVector、Milvus 等专用向量数据库的市场空间。

### 5.4 RGW 架构现代化

RGW 重构工作将持续推进，主要方向包括：
- Bucket ID 缩短（减少 OMAP 存储开销）
- GCM 加密完成安全审查并正式 GA
- DUP 功能在 split head 完成后落地
- Lifecycle 多线程处理方案选型落地
- Admin CLI帮助文档自动生成机制

### 5.5 3 AZ Stretch Cluster GA

3 AZ stretch 模式的 Detect → Decide → Fence 方案已完成设计，2027 年预计完成实现并进入 Tech Preview 或 GA 阶段，为需要更高可用性的企业用户提供原生支持。

### 5.6 NVMe-oF 与 VMware 集成

NVMe-oF TCP 的 vSphere full clone offload 功能正在开发中，预计在未来几个月内完成，将显著改善 VMware 环境下 Ceph block storage 的使用体验。

### 5.7 可观测性与运维工具链

ceph-config-diff 工具将逐步从非强制性检查演进为 CI 强制检查，配置变更的可追踪性将进一步提升。Dashboard 的 Carbon Design System 迁移将在 2027 年基本完成，整体 UX 一致性将达到新的水平。
