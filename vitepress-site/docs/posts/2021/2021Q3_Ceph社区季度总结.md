# Ceph 社区季度进展报告 — 2021 Q3

## 1. 本季度重点议题

本季度社区讨论高度集中在以下几个技术方向：

**Crimson/SeaStore 新一代存储引擎**
Crimson 和 SeaStore 是本季度最活跃的开发主线，贯穿整个季度的周会。核心议题包括 LBA 树重写与合并、Extent Placement Manager 优化、多设备支持、性能分析与写放大问题，以及 Segment Cleaner 的稳定性修复。详见 [Ceph_Crimson_SeaStore_2021-09-01](/VideoSummary/2021/09/01/Ceph_Crimson_SeaStore_2021-09-01/)、[Ceph_Crimson_SeaStore_2021-09-08](/VideoSummary/2021/09/11/Ceph_Crimson_SeaStore_2021-09-08/)。

**BlueStore 性能优化**
BlueStore 的写放大问题在本季度引发了持续讨论，涉及延迟 IO 路径改进、BlueFS 日志增量更新模式、omap 命名方案限制等多个方向。详见 [Ceph_Performance_Meeting_2021-08-05](/VideoSummary/2021/08/21/Ceph_Performance_Meeting_2021-08-05/)、[Ceph_Performance_Meeting_2021-09-11](/VideoSummary/2021/09/11/Ceph_Performance_Meeting_2021-09-11/)。

**Orchestrator 与部署体验**
Cephadm Agent 架构、本地存储运营商（LSO）集成、Rook 与 Kubernetes 的协同，以及 SSH 库替换等议题在 Orchestrator 会议中反复出现。

**CephFS MDS 代码质量与性能**
MDS Locker 代码走读系列、路径遍历机制、R-Stats 实现，以及 MDS 锁切换为公平互斥锁等工作，体现了社区对 CephFS 元数据层的持续投入。

---

## 2. 技术亮点

### Crimson/SeaStore

- **LBA 树重写合并**：LBA 管理器完成重写并合并，引入二分查找优化 LBA 树遍历，显著减少 CPU 周期浪费。合并后发现断言失败问题，团队持续跟进修复。详见 [Ceph_Crimson_SeaStore_2021-09-01](/VideoSummary/2021/09/01/Ceph_Crimson_SeaStore_2021-09-01/)。
- **多设备支持**：Extent Placement Manager 完成多设备支持的主要开发工作，Segment Cleaner 行为相应调整。详见 [Ceph_Crimson_SeaStore_2021-09-15](/VideoSummary/2021/09/15/Ceph_Crimson_SeaStore_2021-09-15/)。
- **性能分析基础设施**：开发了 systole 性能指标输出工具，引入 OProfile 进行 CPU 热点分析，并开发了对比 Ceph 与 Crimson 性能的专用工具。详见 [Ceph_Crimson_SeaStore_2021-08-04](/VideoSummary/2021/08/23/Ceph_Crimson_SeaStore_2021-08-04/)、[Ceph_Crimson_SeaStore_2021-07-28](/VideoSummary/2021/08/23/Ceph_Crimson_SeaStore_2021-07-28/)。
- **Multi-reactor 支持**：通过在多个 OSD 上模拟多 reactor 环境，验证了随机读取的良好扩展性，Greg Farnham 负责正式实现。详见 [Ceph_Performance_Meeting_2021-09-02](/VideoSummary/2021/09/02/Ceph_Performance_Meeting_2021-09-02/)。
- **构建工具链迁移**：将编译器从 GCC 切换至 Clang，解决了 Sealant 构建失败问题，并通过启用 Cache 改善编译速度。详见 [Ceph_Crimson_SeaStore_2021-08-11](/VideoSummary/2021/08/20/Ceph_Crimson_SeaStore_2021-08-11/)。

### BlueStore

- **写放大问题定位**：发现 mclock QoS 更改和 BlueStore 缓冲 IO 默认启用是性能回归的主要来源。Gaby 提交的移除 RocksDB 中分配数据的 PR 显著提升了 4K 随机写性能。详见 [Ceph_Performance_Meeting_2021-09-11](/VideoSummary/2021/09/11/Ceph_Performance_Meeting_2021-09-11/)。
- **延迟 IO 路径优化**：Igor 提交的优化 HDD 延迟 IO 路径 PR 已应用于 master 和 Pacific 版本。详见 [Ceph_Performance_Meeting_2021-08-12](/VideoSummary/2021/08/20/Ceph_Performance_Meeting_2021-08-12/)。
- **BlueFS 日志增量更新**：提出减少 BlueFS 日志增长速度的增量更新模式，但尚未通过 QA 测试。
- **SMR 驱动器支持**：讨论了针对 HSM（Host-Managed SMR）驱动器的 Zoned Allocator 和 Zone Frelist Manager 实现，决定保留 ZBD 库以维持旧内核兼容性。详见 [Ceph_Code_Walkthroughs_-_BlueStore_SMR](/VideoSummary/2021/08/21/Ceph_Code_Walkthroughs_-_BlueStore_SMR/)。

### CephFS

- **MDS Locker 代码走读**：启动三部分系列讲解，系统梳理 MDS 锁机制、数据结构与分布式锁实现。详见 [CephFS_Code_Walkthrough_-_MDS_Locker_Part_1](/VideoSummary/2021/08/23/CephFS_Code_Walkthrough_-_MDS_Locker_Part_1/)。
- **MDS 锁公平性改进**：将 MDS 锁切换为公平互斥锁，避免长等待请求的资源饥饿问题，已合并。详见 [Ceph_Performance_Meeting_2021-09-11](/VideoSummary/2021/09/11/Ceph_Performance_Meeting_2021-09-11/)。
- **R-Stats 机制梳理**：深入讨论了递归树统计的传播机制、锁定挑战及快照目录 RC 时间更新 bug。详见 [CephFS_Code_Walkthrough_-_rstats](/VideoSummary/2021/08/20/CephFS_Code_Walkthrough_-_rstats/)。

### RGW

- **Lua 脚本集成 NATS**：通过 Lua 脚本机制，无需修改源代码即可将 NATS 客户端集成到存储桶通知流程，展示了 Lua 脚本扩展点的灵活性。详见 [Ceph_Tech_Talk_-_Going_NATS](/VideoSummary/2021/08/26/Ceph_Tech_Talk_-_Going_NATS/)。
- **RGW 跟踪（Jaeger）**：RGW 分布式跟踪实现完成初步合并，后续将扩展跟踪细节。详见 [Ceph_Performance_Meeting_2021-08-26](/VideoSummary/2021/08/26/Ceph_Performance_Meeting_2021-08-26/)。
- **OSD 压缩绕过 RGW 压缩**：相关 PR 进入测试分支，避免双重压缩开销。

### Orchestrator

- **Cephadm Agent 架构**：提出使用 HTTP 端点和 systemd 单元替代 SSH 通信的 Agent 方案，通过 HTTPS 和自签名证书保障安全，可显著提升大规模集群的管理响应速度。详见 [Ceph_Orchestrator_Meeting_2021-09-07](/VideoSummary/2021/09/11/Ceph_Orchestrator_Meeting_2021-09-07/)。
- **Async SSH 库替换**：Outreach 实习生项目，用 Python Async SSH 库替换 Zeknet 和 Remoto，改善 Cephadm 远程命令执行的错误处理和调试能力。详见 [Ceph_Orchestrator_Meeting_2021-08-24](/VideoSummary/2021/08/24/Ceph_Orchestrator_Meeting_2021-08-24/)。
- **集成测试框架**：基于 Behave 框架开发新的集成测试方案，使用自然语言定义测试场景，降低测试编写门槛。详见 [Ceph_Orchestrator_Meeting_2021-08-24](/VideoSummary/2021/08/24/Ceph_Orchestrator_Meeting_2021-08-24/)。
- **OSD Repaving**：提出 `ceph osd repave` 命令概念，用于自动化 OSD 重铺过程（如更改最小分配大小或 db/wal 配置）。详见 [Ceph_Orchestrator_Meeting_2021-09-07](/VideoSummary/2021/09/11/Ceph_Orchestrator_Meeting_2021-09-07/)。

### Dashboard 与可观测性

- **问题报告功能**：GSoC 实习生开发从 Dashboard 和 CLI 直接向 Ceph 问题跟踪器提交 bug 的功能。
- **视觉回归测试**：使用 Amplitude 工具为 Dashboard 建立视觉回归测试体系。
- **崩溃报告仪表板**：新增崩溃报告仪表板和崩溃报告机器人，用于跟踪和关联崩溃事件。详见 [Ceph_Developer_Monthly_2021-08-04](/VideoSummary/2021/08/23/Ceph_Developer_Monthly_2021-08-04/)。

## 3. 重要决策与里程碑

- **Ceph 配置 Profile 提案**：Developer Monthly 会议提出引入"边缘资源受限"和"高性能"两类配置 Profile，自动调整 CPU 和内存参数，以支持家庭集群、边缘部署等资源受限场景。详见 [Ceph_Developer_Monthly_2021-09-01](/VideoSummary/2021/09/02/Ceph_Developer_Monthly_2021-09-01/)。
- **无复制池 EIO 处理**：提出引入池级别 EIO 标志，客户端检测到后立即返回 EIO 错误，防止底层存储失败时文件系统损坏。详见 [Ceph_Developer_Monthly_2021-09-01](/VideoSummary/2021/09/02/Ceph_Developer_Monthly_2021-09-01/)。
- **大规模集群测试方案**：提出使用内存 backed OSD 和模拟数据存储来测试超大规模集群行为，无需实际部署大量物理硬件。
- **LSO 集成路径确定**：经过多轮讨论，确定短期内在 Manager Rook 中实现基本 PV/OSD 支持，长期探索与 TopoLVM 合作或开发新的 Rook 本地存储运营商。详见 [Ceph_Orchestrator_Meeting_2021-08-31](/VideoSummary/2021/09/02/Ceph_Orchestrator_Meeting_2021-08-31/)、[Ceph_Orchestrator_Meeting_2021-09-14](/VideoSummary/2021/09/14/Ceph_Orchestrator_Meeting_2021-09-14/)。
- **Omap 命名方案限制**：Igor 提交的 PR 解决了 omap 列表过大时的内存消耗问题，已合并。详见 [Ceph_Performance_Meeting_2021-09-11](/VideoSummary/2021/09/11/Ceph_Performance_Meeting_2021-09-11/)。
- **OSD 客户端消息容量调整**：将 `osd client message cap` 默认值调整为 256，解决生产环境心跳超时问题，已合并。详见 [Ceph_Performance_Meeting_2021-07-29](/VideoSummary/2021/08/23/Ceph_Performance_Meeting_2021-07-29/)。

## 5. 下季度展望

基于本季度的讨论内容，预计 2021 Q4 将重点推进以下方向：

1. **Crimson 稳定性与性能**：LBA 重写合并后的断言失败问题需要彻底解决；随机写入和顺序写入性能优化将持续推进；multi-reactor 正式实现预计进入开发阶段。

2. **BlueStore 写放大根治**：Adam 的直接 IO 写入PR 需完成一致性审查；BlueFS 日志增量更新模式需通过 QA 测试；IOU Ring 在 BlueStore 中的应用将重新评估。

3. **Cephadm Agent 落地**：Agent 架构已完成设计，下季度将进入开发和测试阶段，预计显著改善大规模集群的管理性能。

4. **本地存储运营商**：Manager Rook 基本 PV/OSD 支持将率先实现；与 TopoLVM 的合作方向将进一步明确，raw 设备动态配置原型将完成验证。

5. **Ceph 配置 Profile**：边缘资源受限和高性能两类 Profile 的具体参数将通过实验确定，并推进社区讨论。

6. **CephFS MDS 代码走读系列**：MDS Locker 第二、三部分讲解将继续，深入分布式锁实现和锁类状态机。

7. **SMR 驱动器支持完善**：Zoned Allocator 和 Zone Freelist Manager 将继续迭代，多区域清理逻辑将进一步简化。
