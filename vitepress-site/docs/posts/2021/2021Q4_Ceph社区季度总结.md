# Ceph 社区季度进展报告：2021 Q4

---

## 一、本季度重点议题

本季度社区讨论高度集中在以下几个技术方向：

**1. Crimson/SeaStore 稳定化与功能完善**

Crimson 和 SeaStore 是本季度最活跃的开发主线。从 [Ceph_Crimson_SeaStore_2021-09-22](/posts/2021/Ceph_Crimson_SeaStore_2021-09-22)) 到 [Ceph_Crimson_SeaStore_2021-12-08](/posts/2021/Ceph_Crimson_SeaStore_2021-12-08))，每周例会持续跟进 SeaStore 的 journal batching、cache LRU、segment cleaner、ZNS 支持等核心子系统，并推进 Crimson 与Rook/Kubernetes 的集成。

**2. BlueStore 性能优化**

BlueStore 的细粒度锁定（fine-grained locking）、增量更新模式（incremental update mode）、CoDel 准入控制算法等多个优化方向在性能会议中反复出现，贯穿整个季度。

**3. Orchestrator 与大规模集群管理**

Cephadm Agent 机制、Topo LVM Operator、NFS 高可用、大规模集群压力测试等议题在 Orchestrator 周会中持续讨论，反映出社区对生产级部署能力的强烈需求。

**4. CephFS MDS 内部机制深度解析**

本季度举办了多场 CephFS 代码走读，系统性地梳理了 MDS Journal、MDS Locker、内核客户端（kclient）等核心模块，为后续优化奠定文档基础。

---

## 二、技术亮点

### 2.1 SeaStore / Crimson

- **Journal Batching**：经过多轮讨论（详见 [Ceph_Crimson_SeaStore_2021-09-29](/posts/2021/Ceph_Crimson_SeaStore_2021-09-29))），确定了不使用定时器、在无写入时立即刷盘的批处理策略，并于 11月成功合并两个 Journal PR。
- **多设备支持（Multi-device PR）**：在 [Ceph_Crimson_SeaStore_2021-10-13](/posts/2021/Ceph_Crimson_SeaStore_2021-10-13)) 完成合并，支持 PC 和 distance 放置策略。
- **Random Block Manager（RBM）**：首个 RBM PR 在 [Ceph_Crimson_SeaStore_2021-10-27](/posts/2021/Ceph_Crimson_SeaStore_2021-10-27)) 成功合并，标志着 SeaStore 随机访问设备支持的里程碑。
- **ZNS Segment Manager**：[Ceph_Crimson_SeaStore_2021-11-10](/posts/2021/Ceph_Crimson_SeaStore_2021-11-10)) 报告 ZNS 段管理器已实现大部分功能，实验室中已有真实 ZNS 设备进行测试。
- **Extent Placement Manager**：Schwehn 的 extent placement manager 已合并，支持 SeaStore 内部分层存储，详见 [Ceph_Developer_Monthly_2021-11-03](/posts/2021/Ceph_Developer_Monthly_2021-11-03))。
- **PRT 结构泛化**：[Ceph_Crimson_SeaStore_2021-11-10](/posts/2021/Ceph_Crimson_SeaStore_2021-11-10)) 中推进 PRT 结构泛化，使随机访问设备地址可在 Transaction Manager 中无缝使用。
- **Crimson 配置简化**：移除 Rook 中 Crimson 特定配置需求，简化 Kubernetes 集群部署，详见 [Ceph_Crimson_SeaStore_2021-11-10](/posts/2021/Ceph_Crimson_SeaStore_2021-11-10))。

### 2.2 BlueStore 性能

- **CoDel 算法引入**：[Ceph_Code_Walkthroughs_-_CoDel_for_BlueStore](/posts/2021/Ceph_Code_Walkthroughs_-_CoDel_for_BlueStore)) 详细介绍了通过 CoDel 准入控制平衡前端可调度性与后端吞吐量的方案，实验证有效控制目标延迟。
- **BlueStore 细粒度锁定**：Adam 的 fine-grained locking PR 在 [Ceph_Performance_Meeting_2021-11-04](/posts/2021/Ceph_Performance_Meeting_2021-11-04)) 重新提交，持续推进中。
- **BlueStore 增量更新模式**：已通过测试，处于代码审查阶段，详见 [Ceph_Performance_Meeting_2021-12-09](/posts/2021/Ceph_Performance_Meeting_2021-12-09))。
- **Blob fsck 内存优化**：Igor 的 PR 将 fsck 内存使用从 12GB 降至 0.5GB，详见 [Ceph_Performance_Meeting_2021-10-28](/posts/2021/Ceph_Performance_Meeting_2021-10-28))。
- **SMR 驱动器支持**：[Ceph_Developer_Monthly_2021-10-06](/posts/2021/Ceph_Developer_Monthly_2021-10-06)) 报告 BlueStore 已可在 SMR 硬盘上成功运行，内部元数据跟踪和简单清理器已实现。

### 2.3 OSD 与 RADOS

- **OSD Read Lease机制**：[Ceph_Code_Walkthroughs_-_OSD_Read_Lease](/posts/2021/Ceph_Code_Walkthroughs_-_OSD_Read_Lease)) 深入讲解了 Octopus 版本中引入的租约机制，通过 Lagy 和 Wait 两种新PG 状态解决了网络分区下的读一致性问题。
- **Backfill/Recovery 性能优化**：[Ceph_Performance_Meeting_2021-10-21](/posts/2021/Ceph_Performance_Meeting_2021-10-21)) 讨论了通过 PG 日志进行恢复比传统 recovery 更快的新 PR。
- **PG 移除优化**：Igor 的 PG removal 优化 PR 持续推进，详见 [Ceph_Performance_Meeting_2021-10-07](/posts/2021/Ceph_Performance_Meeting_2021-10-07))。

### 2.4 CephFS

- **MDS Journal 优化**：[CephFS_Code_Walkthrough_-_MDS_Journal_Machinery](/posts/2021/CephFS_Code_Walkthrough_-_MDS_Journal_Machinery)) 讨论了将打开文件表移出 MDS 日志的优化，以及将子树映射移出日志的 PR（Jung 的 PR），可显著减少日志大小并提升故障转移速度。
- **MDS Locker 文档化**：[CephFS_Code_Walkthrough_-_MDS_Locker_Part_2](/posts/2021/CephFS_Code_Walkthrough_-_MDS_Locker_Part_2)) 系统梳理了 Simple Lock、Scatter Lock、File Lock 等锁类型和状态机，并计划提交文档 PR。
- **内核客户端（kclient）概述**：[CephFS_Code_Walkthrough_-_kclient_overview](/posts/2021/CephFS_Code_Walkthrough_-_kclient_overview)) 全面介绍了 libsep、rbd 驱动、cephfs 内核模块的代码结构和 I/O 流程。

### 2.5 RGW 与对象存储

- **分布式追踪（Tracing）**：[Ceph_Developer_Monthly_2021-11-30](/posts/2021/Ceph_Developer_Monthly_2021-11-30)) 介绍了从 OpenTracing 迁移到 OpenTelemetry + Jaeger 的追踪方案，已在 RGW 和 OSD 中实现，支持运行时启用/禁用，并规划条件追踪和多站点追踪。
- **RGW OSD 压缩绕过**：性能会议中持续推进，接近合并状态，详见 [Ceph_Performance_Meeting_2021-09-23](/posts/2021/Ceph_Performance_Meeting_2021-09-23))。
- **RBD 镜像复制监控集成**：[Ceph_Developer_Monthly_2021-10-06](/posts/2021/Ceph_Developer_Monthly_2021-10-06)) 讨论了通过 Prometheus HTTP 端点暴露跨集群复制指标的方案。

### 2.6 Orchestrator / Cephadm

- **Cephadm Agent 机制**：[Ceph_Orchestrator_Meeting_2021-11-02](/posts/2021/Ceph_Orchestrator_Meeting_2021-11-02)) 报告 Agent 关键 PR 已通过 QA 测试，包括端点支持和响应性改进，并讨论回溯到 Pacific 版本的计划。
- **NFS 高可用**：[Ceph_Orchestrator_Meeting_2021-11-23](/posts/2021/Ceph_Orchestrator_Meeting_2021-11-23)) 发现主机宕机时 NFS 服务未能自动重新部署，创建跟踪票持续跟进。
- **Topo LVM Operator**：[Ceph_Orchestrator_Meeting_2021-11-30](/posts/2021/Ceph_Orchestrator_Meeting_2021-11-30)) 决定创建全新的 Topo LVM Operator 以支持原始设备动态配置，原有方案停滞。
- **存储类（Storage Classes）支持**：[Ceph_Orchestrator_Meeting_2021-09-28](/posts/2021/Ceph_Orchestrator_Meeting_2021-09-28)) 讨论了新 Orchestrator API 以列出可用存储类，并在驱动组属性中添加存储类支持。

### 2.7 遥测与可观测性

- **遥测性能通道**：[Ceph_Developer_Monthly_2021-10-06](/posts/2021/Ceph_Developer_Monthly_2021-10-06)) 讨论了从按池收集改为按 PG 级别收集统计总和，并计划添加 mempool 和 RocksDB 压缩统计。
- **关键问题通知机制**：[Ceph_Developer_Monthly_2021-11-03](/posts/2021/Ceph_Developer_Monthly_2021-11-03)) 提出通过 releases.yaml 标记有问题版本，在集群中发出健康警告，帮助用户做出升级决策。
- **Prometheus 模块性能**：[Ceph_Orchestrator_Meeting_2021-11-23](/posts/2021/Ceph_Orchestrator_Meeting_2021-11-23)) 发现 Prometheus 模块在处理大量 OSD 数据时存在性能问题，需优化。

## 五、下季度展望

基于本季度的讨论和进展，预计 2022 Q1 将重点推进以下方向：

1. **SeaStore 进入 Teuthology 测试**：本季度多次提及将 Crimson OSD 引入 Teuthology 测试套件，预计下季度将有实质性进展，推动 SeaStore 走向更广泛的集成测试。

2. **ZNS 设备支持完善**：ZNS Segment Manager 已有真实设备测试，下季度有望完成并合并，推动 Ceph 对新型存储介质的原生支持。

3. **BlueStore 细粒度锁定合并**：Adam 的 fine-grained locking PR 经过多次迭代，预计下季度有望完成审查并合并，带来显著的并发性能提升。

4. **Cephadm Agent 回溯到 Pacific**：Agent 功能已通过 QA 测试，下季度将推进 backport 工作，提升 Pacific 版本的大规模集群管理能力。

5. **分布式追踪端到端集成**：RGW 和 OSD 的追踪已实现，下季度将推进条件追踪、多站点追踪以及 Jaeger 与 Cephadm 的集成部署。

6. **Topo LVM Operator 新设计落地**：新 Operator 设计方案预计在下季度提交，推动 Kubernetes 环境下动态本地存储配置能力。

7. **MDS Locker 文档与第三部分代码走读**：MDS Locker 系列计划继续，Scatter Lock 和 File Lock 的深度解析将为 CephFS 性能优化提供理论基础。

8. **Cephalocon 2022 准备**：随着征稿截止，下季度将进入演讲准备和社区活动组织阶段。
