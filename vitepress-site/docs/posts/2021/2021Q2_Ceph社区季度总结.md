# Ceph 社区季度进展报告 — 2021 Q2

---

## 1. 本季度重点议题

本季度（2021年4月—6月）社区讨论高度集中在以下几个技术方向：

**Crimson OSD 与 SeaStore（C-Store）**
Crimson/SeaStore 是本季度最活跃的开发线。每周例会持续推进，涵盖事务管理器重构、interrupted future 转换、ZNS 设备支持、垃圾回收机制、多核支持设计等核心议题。详见 [Ceph_Crimson_SeaStore_2021-04-14](/VideoSummary/2021/04/16/Ceph_Crimson_SeaStore_2021-04-14/)、[Ceph_Crimson_SeaStore_2021-05-05](/VideoSummary/2021/05/05/Ceph_Crimson_SeaStore_2021-05-05/)、[Ceph_Crimson_SeaStore_2021-06-16](/VideoSummary/2021/06/16/Ceph_Crimson_SeaStore_2021-06-16/) 等系列会议。

**Quincy 版本规划**
Ceph Developer Summit Quincy 系列会议覆盖了 CephFS、RADOS、RBD、RGW、Dashboard、Orchestrator、Crimson、CI、Rook 等所有主要子系统，集中讨论下一个主要版本的路线图和优先级。

**CephFS 功能演进**
CephFS 镜像（Snapshot Mirroring）、fscrypt 加密、MDS 监控、NFS 支持、异步操作等方向在本季度均有深入讨论和代码走读。

**Pacific 版本发布后的社区推广**
Ceph Month 2021 系列活动贯穿本季度，涵盖 Pacific 版本特性介绍、性能评测、用户案例分享等内容。

---

## 2. 技术亮点

### 2.1 Crimson OSD / SeaStore

**事务管理器 interrupted future 重构**
本季度最重要的架构工作之一。[Ceph_Crimson_SeaStore_2021-06-16](/VideoSummary/2021/06/16/Ceph_Crimson_SeaStore_2021-06-16/) 记录了事务管理器向 interrupted future 模型的全面转换，目标是让所有消费者统一使用该模型，为后续多核支持奠定基础。

**ZNS 设备支持**
[Ceph_Crimson_SeaStore_2021-06-16](/VideoSummary/2021/06/16/Ceph_Crimson_SeaStore_2021-06-16/) 和 [Ceph_Crimson_SeaStore_2021-06-23](/VideoSummary/2021/06/24/Ceph_Crimson_SeaStore_2021-06-23/) 讨论了 ZNS（Zoned Namespace）设备的集成方案，包括通过 nvme pass-through ioctl 管理 Zone 设备，以及异步 ioctl 的潜在优势。

**多核支持设计**
[Ceph_Developer_Summit_Quincy_-_Crimson](/VideoSummary/2021/04/08/Ceph_Developer_Summit_Quincy_-_Crimson/) 确定了多核支持的实现路径：先实现 PG 在多核上的分布，再逐步扩展到 Messenger 和 C-Store，并需要开发跨核服务管理 PG 到核心的映射。

**mclock 移植**
[Ceph_Crimson_SeaStore_2021-05-26](/VideoSummary/2021/05/26/Ceph_Crimson_SeaStore_2021-05-26/) 讨论了将 mclock 调度器移植到 Crimson OSD 的方案，涉及与线程模型的解耦和 pthread锁处理。

**性能指标体系**
[Ceph_Crimson_SeaStore_2021-05-26](/VideoSummary/2021/05/26/Ceph_Crimson_SeaStore_2021-05-26/) 决定在 Crimson 中使用 seastar metrics 作为性能计数器方案，替代传统的 Ceph 性能计数器。

### 2.2 CephFS

**C Snapshot Mirroring 代码走读**
[CephFS_Code_Walkthrough_-_CephFS_Mirroring_Part_1](/VideoSummary/2021/04/19/CephFS_Code_Walkthrough_-_CephFS_Mirroring_Part_1/) 和 [CephFS_Code_Walkthrough_-_CephFS_Mirroring_Part_2](/VideoSummary/2021/04/27/CephFS_Code_Walkthrough_-_CephFS_Mirroring_Part_2/) 对 Pacific 版本新引入的目录快照异步同步功能进行了深入代码走读，涵盖 FS Map 持久化、镜像守护进程架构、状态机设计、增量同步机制等。

**fscrypt 文件系统加密**
[Ceph_Month_2021_-_CephFS_+_fscrypt_-_filename_and_contentencryption](/VideoSummary/2021/06/24/Ceph_Month_2021_-_CephFS_+_fscrypt_-_filename_and_content_encryption/) 详细介绍了 CephFS fscrypt 集成进展：文件名加密已基本实现，内容加密仍在开发中，主要挑战在于截断操作与加密块完整性的协调。

**MDS Monitor 深度解析**
[CephFS_Code_Walkthrough_-_MDSMonitoring](/VideoSummary/2021/05/03/CephFS_Code_Walkthrough_-_MDSMonitoring/) 对 MDS Monitor 的 Paxos 服务机制、FS Map 管理、Beacon 消息处理进行了系统性代码走读。

**Quincy CephFS 路线图**
[Ceph_Developer_Summit_Quincy_-_CephFS](/VideoSummary/2021/04/12/Ceph_Developer_Summit_Quincy_-_CephFS/) 确定了 Quincy 版本 CephFS 的重点方向：MDS 内存目标优化、递归删除 RPC、MDS 滚动升级简化、文件系统镜像指标对齐、客户端隔离（fencing）方案等。

### 2.3 RGW

**Bucket Notifications 代码走读**
[Ceph_Code_Walkthrough_-_RGW_Bucket_Notifications_with_AMQA_Kafka](/VideoSummary/2021/04/28/Ceph_Code_Walkthrough_-_RGW_Bucket_Notifications_with_AMQA_Kafka/) 深入讲解了 RGW Bucket Notifications 与 AMQP/Kafka 的集成实现，包括 Push/Pull 两种模式、过滤器类型、同步/异步通知处理流程。

**Zipper 项目**
[Ceph_Developer_Summit_Quincy_-_RGW](/VideoSummary/2021/04/09/Ceph_Developer_Summit_Quincy_-_RGW/) 讨论了 Zipper 项目（RGW 存储后端抽象层）的当前状态，重点关注 API 稳定性和外部实现兼容性。

**SQLite Bucket 索引**
同一会议讨论了使用 SQLite 替代现有 Bucket 索引方案的可行性，以解决索引性能瓶颈。

**Lua 脚本扩展**
[Ceph_Month_2021_-_From_Open_Source_to_OpenEnded_in_Ceph_with_Lua](/VideoSummary/2021/06/15/Ceph_Month_2021_-_From_Open_Source_to_Open_Ended_in_Ceph_with_Lua/) 介绍了在 RGW 中集成 Lua 脚本层的方案，允许用户在不修改核心代码的情况下实现自定义业务逻辑。

### 2.4 RBD

**librbd 图像加密**
[Ceph_Developer_Summit_Quincy_-_RBD](/VideoSummary/2021/04/12/Ceph_Developer_Summit_Quincy_-_RBD/) 介绍了基于 LUKS 格式在 librbd 层实现透明加密的工作，并讨论了支持不同密钥克隆的未来方向。

**NVMe over Fabrics**
同一会议讨论了 NVMe-oF 网关的进展，包括通过 SPDK 设置网关和实现发现服务的计划。

**RBD 镜像监控改进**
讨论了统一不同镜像方案（日志模式、快照模式）的 Prometheus 指标，计划为每个镜像守护进程提供独立的 Prometheus 端点。

**librbd vs krbd 性能对比**
[Ceph_Month_2021_-_Qemu_-_librbd_vs_krbd_performance](/VideoSummary/2021/06/21/Ceph_Month_2021_-_Qemu_-_librbd_vs_krbd_performance/) 通过系统性测试揭示了 librbd 在特定配置下存在约 20,000 IOPS 的性能上限，物理主机上 krbd 性能显著优于 librbd。

### 2.5 RADOS

**RADOS Snapshots 技术解析**
[Ceph_Code_Walkthroughs_-_RADOS_Snapshots](/VideoSummary/2021/04/01/Ceph_Code_Walkthroughs_-_RADOS_Snapshots/) 系统讲解了 RADOS 快照机制，涵盖 RBD 和 CephFS 的快照工作原理、OSD 端快照状态映射、回滚和删除的实现细节。

**OSD Map 优化**
[Ceph_Developer_Monthly_2021-05-05](/VideoSummary/2021/05/06/Ceph_Developer_Monthly_2021-05-05/) 讨论了客户端 OSD Map 请求优化，目标是减少监控器负担，探索仅包含客户端所需信息的轻量级 OSD Map 版本。

**Manager 模块扩展性**
[Ceph_Developer_Monthly_2021-06-02](/VideoSummary/2021/06/02/Ceph_Developer_Monthly_2021-06-02/) 讨论了将 Manager 模块分离到不同进程、创建共享池的方案，以解决 Python 多进程通信开销问题。

### 2.6 Dashboard

**Pacific 版本 Dashboard 亮点**
[Ceph_Month_2021_-_Dashboard_Update](/VideoSummary/2021/06/15/Ceph_Month_2021_-_Dashboard_Update/) 总结了 Pacific 版本 Dashboard 的主要改进：Cephadm 集成、RGW 多站点监控、RESTful API 正式化、账户锁定等安全性改进。

**Quincy Dashboard 规划**
[Ceph_Developer_Summit_Quincy_-_Dashboard](/VideoSummary/2021/04/12/Ceph_Developer_Summit_Quincy_-_Dashboard/) 确定了 Quincy 版本的方向转变：从功能复制转向用户体验优化，引入安装向导和升级向导，并探索前端逻辑后端化。

### 2.7 Orchestrator / Cephadm

**自管理代（Self-Management Agent）设计**
[Ceph_Crimson_SeaStore_2021-05-19](/VideoSummary/2021/05/19/Ceph_Crimson_SeaStore_2021-05-19/) 深入讨论了 cephadm 自管理代理的架构设计，倾向于采用推模型（push model）——在每个主机上运行代理将信息推送到 Manager 模块，以解决当前通过 SSH 执行任务的扩展性问题。

**Quincy Orchestrator 路线图**
[Ceph_Developer_Summit_Quincy_-_Orchestrator](/VideoSummary/2021/04/09/Ceph_Developer_Summit_Quincy_-_Orchestrator/) 讨论了维护模式改进、服务管理高可用配置（HAProxy + Keepalived）、开发环境优化等议题。

### 2.8 硬件与性能

**Intel QLC SD 成本效益分析**
[Ceph_Month_2021_-_Intel_QLC_SSD_-_Cost-Effective_Ceph_Deployments](/VideoSummary/2021/06/11/Ceph_Month_2021_-_Intel_QLC_SSD_-_Cost-Effective_Ceph_Deployments/) 分析了 QLC SSD 在 Ceph 部署中的成本优势，讨论了 BlueStore 针对 QLC 特性的自动配置优化方向。

**ARM64 性能优化**
[Ceph_Month_2021_-_Optimizing_Ceph_on_Arm64](/VideoSummary/2021/06/23/Ceph_Month_2021_-_Optimizing_Ceph_on_Arm64/) 和 [Ceph_Month_2021_-_Performance_Optimization_for_All_Flash_based_on_arch64](/VideoSummary/2021/06/11/Ceph_Month_2021_-_Performance_Optimization_for_All_Flash_based_on_aarch64/) 分别介绍了 ARM64 平台上 CRC32、AES-GCM 等算法的优化（性能提升 3-8 倍），以及 64KB 内核页面带来的 3-11% 性能提升。

## 3. 重要决策与里程碑

### 3.1 Ceph Pacific 正式发布

本季度初 Ceph Pacific 版本正式发布，[Ceph_Month_2021_-_CephFS_update](/VideoSummary/2021/06/23/Ceph_Month_2021_-_CephFS_update/) 和 [Ceph_Month_2021_-_Ceph_Project_Update](/VideoSummary/2021/06/01/Ceph_Month_2021_-_Ceph_Project_Update/) 对 Pacific 版本的主要特性进行了系统性总结，包括：
- CephFS 多文件系统支持稳定化、MDS 自动扩展器
- CephFS Top 工具、快照计划管理模块
- NFS 网关支持（通过 NFS Manager 模块）
- Cephadm 成为默认部署工具

### 3.2 Quincy 版本路线图确立

Ceph Developer Summit Quincy 系列会议（共 10+ 场）完成了 Quincy 版本各子系统的路线图规划，主要决策包括：
- **CephFS**：不再支持 NFS v3；递归删除 RPC 列入 Quincy；MDS 滚动升级简化列入 Quincy
- **RADOS**：MClock 调度器作为默认调度器；集群日志消息重定向到 Manager 日志
- **Crimson**：多核支持作为核心目标；C-Store 继续推进 ZNS 和持久内存支持
- **Dashboard**：从功能复制转向用户体验，引入安装/升级向导

详见 [Ceph_Developer_Summit_Quincy_-_CephFS_Follow-up](/VideoSummary/2021/04/28/Ceph_Developer_Summit_Quincy_-_CephFS_Follow-up/) 和 [Ceph_Developer_Summit_Quincy_-_RADOS_Follow-up](/VideoSummary/2021/04/20/Ceph_Developer_Summit_Quincy_-_RADOS_Follow-up/)。

### 3.3 FileStore 弃用讨论

[Ceph_Month_2021_-_Open_Discussion](/VideoSummary/2021/06/01/Ceph_Month_2021_-_Open_Discussion/) 中，遥测数据显示仍有约 1500 个 FileStore OSD（占总数 4%）在运行。会议决定向仍使用 FileStore 的 OSD 发出警告，并确认 Crimson 将不再支持 FileStore，推动社区向 BlueStore 迁移。

### 3.4 Cephadm 成为主流部署方式

[Ceph_Month_2021_-_Cephadm_Update](/VideoSummary/2021/06/23/Ceph_Month_2021_-_Cephadm_Update/) 确认了 Cephadm 容器化部署的主流地位，并讨论了自动升级策略和监控集成。

### 3.5 CI基础设施改进计划

[Ceph_Developer_Summit_Quincy_-_CI](/VideoSummary/2021/04/12/Ceph_Developer_Summit_Quincy_-_CI/) 制定了详细的 CI 改进计划，包括：设置预生产环境、改进 Jenkins 日志可调试性、自动重新运行已知竞争条件的作业、创建降级测试套件、将 Dockerfile 移入 Ceph 代码树。

## 4. 社区动态

### 4.1 Ceph Month 2021

本季度最重要的社区活动。Ceph Month 2021 采用分散式格式（每次几小时，分布在数周内），避免了长时间 Zoom 会议，包含计划演讲和非结构化讨论时间。活动涵盖：
- 技术更新（CephFS、Dashboard、Crimson、Cephadm、RGW 等）
- 用户案例分享（CERN 的 CephFS 性能评估、RBD 复制评估）
- 硬件优化（ARM64、Intel QLC SSD）
- 社区建设（大使计划、市场发展工作组）

## 5. 下季度展望

基于本季度的讨论和决策，预计 2021 Q3 将重点推进以下方向：

**Crimson/SeaStore 稳定化**
interrupted future 重构完成后，预计将进入更大规模的稳定性测试阶段，多核支持的初步实现也将提上日程。ZNS 设备集成和垃圾回收机制优化将持续推进。

**Quincy 版本功能开发**
各子系统将按照峰会确定的路线图开始实质性开发：CephFS 递归删除 RPC、MDS 滚动升级、RBD librbd 加密、RGW Zipper API 稳定化、Dashboard 安装向导等。

**Cephadm 自管理代理**
推模型架构设计已基本确定，预计将进入原型开发和测试阶段，这将是 Quincy 版本 Orchestrator 的核心改进。

**FileStore 弃用推进**
随着 Pacific 版本的普及和 Crimson 不支持 FileStore 的确定，预计将正式发布 FileStore 弃用时间表。

**CephFS fscrypt 内容加密**
文件名加密已基本完成，内容加密的截断问题是下季度的主要攻关目标。

**CI 基础设施升级**
预生产环境搭建、降级测试套件创建等 CI 改进工作将陆续落地，提升整体测试可靠性。

**ARM64 和 QLC SSD 优化**
ARM64 平台的 SVE 指令集优化、BlueStore 针对 QLC SD 的自动配置优化预计将有具体 PR 提交。
