# Ceph 2021 年度社区进展报告

## 概述

2021 年是 Ceph 社区承上启下的关键一年。Pacific 版本（16.x）在年初正式发布，成为该年度的核心里程碑；与此同时，下一个长期支持版本 Quincy 的规划工作全面展开。这一年，Crimson/SeaStore 新一代 OSD 架构从概念验证走向功能完善，CephFS 在镜像、加密和多 MDS 管理方面取得重要进展，Dashboard 和 Orchestrator 持续提升运维体验，整个社区在技术深度和生态广度上均有显著扩展。

---

## 一、全年技术演进

### 1.1 新一代 OSD 架构：Crimson 与 SeaStore

2021 年最重要的技术方向是 Crimson OSD 和 SeaStore 存储后端的持续演进。全年共举行了超过 30 次专项周会，覆盖从底层存储引擎到上层 OSD 逻辑的完整技术栈。

**核心技术突破**：
- **Interuptible Future 框架**：全年最重要的架构重之一。团队将事务管理器（Transaction Manager）、LBA 管理器等核心组件全面迁移到 interuptible future 模型，为多核并发奠定基础。详见 [Ceph_Crimson_SeaStore_2021-06-16](/posts/2021/Ceph_Crimson_SeaStore_2021-06-16)) 和 [Ceph_Crimson_SeaStore_2021-07-28](/posts/2021/Ceph_Crimson_SeaStore_2021-07-28))。
- **LBA 树重写**：完成了 LBA（Logical Block Address）管理器的完整重写，引入二分查找优化，解决了地址分配中的逻辑问题，提升了代码可读性。详见 [Ceph_Crimson_SeaStore_2021-09-01](/posts/2021/Ceph_Crimson_SeaStore_2021-09-01))。
- **多设备支持**：Extent Placement Manager（EPM）完成合并，支持在 SeaStore 内部进行分层存储，为 ZNS（Zoned Namespace）设备和 SMR 硬盘的接入奠定基础。详见 [Ceph_Crimson_SeaStore_2021-10-13](/posts/2021/Ceph_Crimson_SeaStore_2021-10-13))。
- **日志批处理优化**：实现了 Journal Batching，将写回列表合并到更大的缓冲区，减少了约 70% 的写入操作。详见 [Ceph_Crimson_SeaStore_2021-09-29](/posts/2021/Ceph_Crimson_SeaStore_2021-09-29))。

**性能分析与优化**：年中开始系统性地引入性能计数器和 Seastar Metrics，使用 OProfile 等工具识别 CPU 热点。分析发现 LBA 分配交换占用约 20% 的 CPU 周期，成为后续优化的重点方向。详见 [Ceph_Crimson_SeaStore_2021-09-08](/posts/2021/Ceph_Crimson_SeaStore_2021-09-08))。

### 1.2 BlueStore 持续演进

BlueStore 在 2021 年重点推进了两个方向：

- **SMR 驱动器支持**：完成了针对 Host-Managed SMR（HSM）设备的内核设备支持，实现了 Zoned Allocator 和 Zone Frelist Manager，并引入清理线程。详见 [Ceph_Code_Walkthroughs_-_BlueStore_SMR](/posts/2021/Ceph_Code_Walkthroughs_-_BlueStore_SMR))。
- **CoDel 队列算法**：引入 CoDel（Controlled Delay）算法用于 BlueStore 的准入控制，通过高频和低频双循环平衡前端可调度性与后端吞吐量，实验表明能有效控制目标延迟。详见 [Ceph_Code_Walkthroughs_-_CoDel_for_BlueStore](/posts/2021/Ceph_Code_Walkthroughs_-_CoDel_for_BlueStore))。

### 1.3 分布式追踪（Tracing）体系建立

2021 年 Ceph 正式引入基于 OpenTelemetry + Jaeger 的分布式追踪体系，从 OpenTracing 迁移到 OpenTelemetry（因前者 C++ 库停止维护）。RGW 和 OSD 均实现了追踪功能，支持运行时动态启用/禁用，并规划了条件追踪和多站点追踪能力。详见 [Ceph_Developer_Monthly_2021-11-30](/posts/2021/Ceph_Developer_Monthly_2021-11-30))。

### 1.4 OSD 读一致性修复

Octopus 版本中引入的 OSD Read Lease 机制在 2021 年通过代码走读得到深入阐释。该机制通过租约消息在主副本和副本之间同步状态，解决了网络分区场景下的读一致性问题，并引入了 Lagy 和 Wait 两种新的 PG 状态。详见 [Ceph_Code_Walkthroughs_-_OSD_Read_Lease](/posts/2021/Ceph_Code_Walkthroughs_-_OSD_Read_Lease))。

## 二、重大里程碑

### 2.1 Pacific（16.x）正式发布

Pacific 是 2021 年最重要的版本里程碑，带来了多项重要特性：

- **CephFS Snapshot Mirroring**：支持将目录快照异步同步到远程 Ceph 文件系统，采用推送模型，支持增量同步。详见 [CephFS_Code_Walkthrough_-_CephFS_Mirroring_Part_1](/posts/2021/CephFS_Code_Walkthrough_-_CephFS_Mirroring_Part_1)) 和 [CephFS_Code_Walkthrough_-_CephFS_Mirroring_Part_2](/posts/2021/CephFS_Code_Walkthrough_-_CephFS_Mirroring_Part_2))。
- **RGW Bucket Notifications**：支持 AMQP 和 Kafka 端点，提供 Push 和 Pull 两种模式（Pull 模式计划弃用）。详见 [Ceph_Code_Walkthrough_-_RGW_Bucket_Notifications_with_AMQAKafka](/posts/2021/Ceph_Code_Walkthrough_-_RGW_Bucket_Notifications_with_AMQA_Kafka))。
- **MDS 亲和性设置**：允许 MDS 更灵活地服务于特定文件系统。
- **Cephadm 成熟**：基于容器的部署工具进入生产就绪状态。

### 2.2 Quincy 开发规划启动

2021 年举行了 Ceph Developer Summit Quincy，系统规划了下一个 LTS 版本的技术路线。各组件均召开了专项规划会议和跟进会议，形成了 Trello 看板驱动的任务管理体系。详见 [Ceph_Developer_Summit_Quincy_-_RADOS](/posts/2021/Ceph_Developer_Summit_Quincy_-_RADOS))、[Ceph_Developer_Summit_Quincy_-_CephFS](/posts/2021/Ceph_Developer_Summit_Quincy_-_CephFS)) 等系列会议。

### 2.3 RBD 镜像加密 GA

librbd 完成了基于 Luks 格式的图像加密功能，具备性能优势，并规划了支持不同密钥的克隆功能。详见 [Ceph_Developer_Summit_Quincy_-_RBD](/posts/2021/Ceph_Developer_Summit_Quincy_-_RBD))。

## 三、核心组件年度进展

### 3.1 CephFS

2021 年 CephFS 在多个维度取得重要进展：

**镜像功能**：Pacific 版本引入的Snapshot Mirroring 功能通过两部分代码走读得到深入解析。Mirror Daemon 使用 libcephfs 客户端库与本地和远程集群通信，支持多对等体，通过引导令牌机制简化配置。详见 [CephFS_Code_Walkthrough_-_CephFS_Mirroring_Part_1](/posts/2021/CephFS_Code_Walkthrough_-_CephFS_Mirroring_Part_1))。

**MDS 内部机制深度解析**：社区举办了系列代码走读，覆盖 MDS Locker（三部分）、MDS Journal Machinery、MDS Monitor、MDS 路径遍历、R-Stats 等核心机制，并同步推进文档化工作。详见 [CephFS_Code_Walkthrough_-_MDS_Locker_Part_1](/posts/2021/CephFS_Code_Walkthrough_-_MDS_Locker_Part_1))、[CephFS_Code_Walkthrough_-_MDS_Journal_Machinery](/posts/2021/CephFS_Code_Walkthrough_-_MDS_Journal_Machinery))。

**Quincy 规划重点**：
- 递归删除 RPC（Recursive Unlink RPC）
- MDS 内存目标动态调整（优先级缓存方案）
- 文件系统加密（fs-crypt）内容加密
- MDS 滚动升级简化
- 客户端隔离（fencing）机制
- 背景强制 Scrub 调度

详见 [Ceph_Developer_Summit_Quincy_-_CephFS](/posts/2021/Ceph_Developer_Summit_Quincy_-_CephFS)) 和 [Ceph_Developer_Summit_Quincy_-_CephFS_Follow-up](/posts/2021/Ceph_Developer_Summit_Quincy_-_CephFS_Follow-up))。

**内核客户端（kclient）**：举办了内核客户端代码概述走读，涵盖 libsep 传输层、挂载流程、文件打开和写操作的完整路径，以及 cap 消息处理机制。详见 [CephFS_Code_Walkthrough_-_kclient_overview](/posts/2021/CephFS_Code_Walkthrough_-_kclient_overview))。

### 3.2 RGW（RADOS Gateway）

**Bucket Notifications 成熟**：完成了与 AMQP 和 Kafka 的深度集成，支持同步和异步（持久化）两种通知处理模式，过滤器支持前缀、后缀、正则表达式、标签和元数据等多种类型。

**SSE-S3 加密**：开始实现 SSE-S3 服务端加密，支持 put bucket encryption API，计划集成 Vault 作为 KMS。详见 [Ceph_Developer_Monthly_2021-06-02](/posts/2021/Ceph_Developer_Monthly_2021-06-02))。

**分布式追踪**：RGW 成为 Ceph 中首批集成 OpenTelemetry 追踪的组件，支持跨 OSD 的端到端追踪。

**多站点监控**：规划了统一的跨集群复制指标体系，使用 Prometheus HTTP 端点暴露指标，解决 Manager 过载问题。详见 [Ceph_Developer_Summit_Quincy_-_RBD](/posts/2021/Ceph_Developer_Summit_Quincy_-_RBD))。

### 3.3 BlueStore

**SMR 支持**：完成了 Host-Managed SMR 设备的基础支持，包括通过 SMART 调用获取区域信息、Zoned Allocator 实现、Zone Freelist Manager 以及清理线程。下一步工作包括更智能的清理策略和 BlueFS 使用顺序区域。详见 [Ceph_Code_Walkthroughs_-_BlueStore_SMR](/posts/2021/Ceph_Code_Walkthroughs_-_BlueStore_SMR)) 和 [Ceph_Developer_Monthly_2021-10-06](/posts/2021/Ceph_Developer_Monthly_2021-10-06))。

**CoDel 队列**：引入 CoDel 算法改善 BlueStore 的 I/O 调度，通过智能准入控制提升前端可调度性。

**性能优化**：讨论了 BlueStore 与 Split Cache 的改进方向，计划在 Quincy 中进一步优化。

### 3.4 Crimson/SeaStore

这是 2021 年投入最多的组件，全年进展可分为三个阶段：

**上半年（Q1-Q2）**：基础架构建设
- 完成客户端请求序列化器
- 实现 watch/notify 功能
- 引入 Interuptible Future 框架
- 完成 Extent Placement Manager 初版

详见 [Ceph_Crimson_SeaStore_2021-03-10](/posts/2021/Ceph_Crimson_SeaStore_2021-03-10))、[Ceph_Crimson_SeaStore_2021-04-14](/posts/2021/Ceph_Crimson_SeaStore_2021-04-14))。

**中期（Q3）**：性能分析与优化
- LBA 树完整重写并合并
- 引入系统性能指标（Seastar Metrics）
- 使用 OProfile 进行 CPU 热点分析
- 实现 Random Block Manager（RBM）首个 PR 合并

详见 [Ceph_Crimson_SeaStore_2021-09-01](/posts/2021/Ceph_Crimson_SeaStore_2021-09-01))、[Ceph_Crimson_SeaStore_2021-09-08](/posts/2021/Ceph_Crimson_SeaStore_2021-09-08))。

**下半年（Q4）**：功能完善与集成
- 多设备支持合并
- ZNS 段管理器开发（Joseph 实现，实验室已有实际 ZNS 设备）
- 日志批处理优化（减少 70% 写入操作）
- 与 Rook 集成推进
- 开始 Tothology 集成测试

详见 [Ceph_Crimson_SeaStore_2021-11-10](/posts/2021/Ceph_Crimson_SeaStore_2021-11-10))、[Ceph_Crimson_SeaStore_2021-12-08](/posts/2021/Ceph_Crimson_SeaStore_2021-12-08))。

**Quincy 规划**：确定了多核支持（M2N 映射）、Boost ASIO 适配、Replica Daemon 设计等方向。详见 [Ceph_Developer_Summit_Quincy_-_Crimson](/posts/2021/Ceph_Developer_Summit_Quincy_-_Crimson))。

### 3.5 Dashboard

2021 年 Dashboard 团队经历了人员变动（SUSE 成员流失），并据此调整了工作重心：

**功能进展**：
- 完成 RBD 镜像管理界面
- 实现 Orchestrator 主机维护模式 UI
- 服务管理界面（创建、删除、高可用配置）
- 视觉回归测试框架（GSoC 项目，使用 Amplitude 工具）
- 问题报告功能（从 Dashboard/CLI 直接提交 Issue）
- 崩溃报告仪表板和崩溃报告机器人

详见 [Ceph_Developer_Monthly_2021-08-04](/posts/2021/Ceph_Developer_Monthly_2021-08-04))、[Ceph_Developer_Summit_Quincy_-_Dashboard](/posts/2021/Ceph_Developer_Summit_Quincy_-_Dashboard))。

**Quincy 规划重点**：
- 安装向导和升级向导
- 嵌入式 CLI 工具（UI Toolbox）
- 多集群管理
- Manager API缓存（解决性能瓶颈）
- 监控堆栈高可用性

详见 [Ceph_Developer_Summit_Quincy_-_Dashboard_Follow-up](/posts/2021/Ceph_Developer_Summit_Quincy_-_Dashboard_Follow-up))。

### 3.6 Orchestrator（Cephadm）

**Self-Adm Agent 架构讨论**：2021 年重要的架构讨论之一是引入推模型（Push Model）的 Self-Adm Agent，在每个主机上运行代理将信息推送到 Manager 模块，解决当前通过 SSH 执行任务的扩展性问题。详见 [Ceph_Crimson_SeaStore_2021-05-19](/posts/2021/Ceph_Crimson_SeaStore_2021-05-19))。

**Rook 集成**：持续推进 Crimson 与 Rook 的集成，简化 Kubernetes 集群中的 Crimson 配置需求。

**Quincy 规划**：确定了 NFS-HA、Managed Clienturing、Host Maintenance Mode 等高优先级任务。详见 [Ceph_Developer_Summit_Quincy_-_Orchestrator](/posts/2021/Ceph_Developer_Summit_Quincy_-_Orchestrator)) 和 [Ceph_Developer_Summit_Quincy_-_Orchestrator_Follow-up](/posts/2021/Ceph_Developer_Summit_Quincy_-_Orchestrator_Follow-up))。

### 3.7 RADOS

**OSD Map 优化**：讨论了客户端 OSD Map 请求优化，减少监控器负担，探索更轻量级的 OSD Map 版本。详见 [Ceph_Developer_Monthly_2021-05](/posts/2021/Ceph_Developer_Monthly_2021-05-05))。

**配置文件（Config Profiles）**：提出引入性能配置文件（"边缘资源受限"和"高性能"），自动调整 CPU 和内存使用参数，解决资源受限环境的部署问题。详见 [Ceph_Developer_Monthly_2021-09-01](/posts/2021/Ceph_Developer_Monthly_2021-09-01))。

**遥测（Telemetry）增强**：
- 新增性能通道，收集 OSD 性能直方图、I/O 速率、每个池的统计总和
- 从按池收集改为按 PG 级别收集
- 讨论了用户重新选择机制和数据透明度
- 规划了 mempool 和 RocksDB 压缩统计等新指标

详见 [Ceph_Developer_Monthly_2021-10-06](/posts/2021/Ceph_Developer_Monthly_2021-10-06)) 和 [Ceph_Developer_Monthly_2021-11-03](/posts/2021/Ceph_Developer_Monthly_2021-11-03))。

**MClock 调度器**：讨论了将 MClock 移植到 Crimson OSD，并确定 MClock 作为 Quincy 的默认调度器。详见 [Ceph_Crimson_SeaStore_2021-05-26](/posts/2021/Ceph_Crimson_SeaStore_2021-05-26))。

**CRUSH 代码走读**：Sage Weil 主持了 CRUSH 算法深度走读，涵盖影子树（Shadow Trees）、选择参数（Choose Args）等高级特性，以及调试和优化技巧。详见 [Ceph_Code_Walkthroughs_-_CRUSH](/posts/2021/Ceph_Code_Walkthroughs_-_CRUSH))。

## 五、下一年展望（2022 年 Quincy 方向）

基于 2021 年的讨论和规划，2022 年 Quincy 版本预计在以下方向取得重要进展：

### 5.1 Crimson/SeaStore 走向生产就绪

- 多核支持（M2N 映射）实现，PG 在多个 Seastar 核心上分布
- ZNS 设备正式支持
- 与 Tothology 集成测试体系完善
- 性能达到与 BlueStore 可比的水平

### 5.2 CephFS 功能完善

- 递归删除 RPC 实现，简化子卷管理
- MDS 内存目标动态调整（优先级缓存方案）
- 文件系统加密（fs-crypt）内容加密完成
- MDS 滚动升级流程简化
- 客户端隔离（fencing）机制落地

### 5.3 运维体验大幅提升

- Dashboard 安装向导和升级向导上线
- Orchestrator Self-Adm Agent 推模型实现
- NFS 高可用（NFS-HA）支持
- 多集群管理能力

### 5.4 存储性能与新硬件

- MClock 成为默认 OSD 调度器
- BlueStore SMR 支持完善（更智能的清理策略）
- Config Profiles 引入，简化资源受限环境部署
- NVMe over Fabrics 发现服务实现

### 5.5 可观测性体系完善

- 分布式追踪（Jaeger/OpenTelemetry）全面铺开
- 遥测性能通道正式启用
- RBD 镜像独立 Prometheus 端点
- 崩溃报告与健康警告机制完善

## 总结

2021 年 Ceph 社区在技术深度和广度上均取得了显著进展。Pacific 版本的发布标志着 Ceph 在易用性（Cephadm）、CephFS 镜像、RGW 通知等方面达到新的成熟度；Crimson/SeaStore 从实验性项目走向功能完整的新一代存储引擎；Quincy 的系统性规划为 2022 年的发展奠定了坚实基础。社区通过大量代码走读活动有效传承了技术知识，GSoC 和新成员的加入也为社区注入了新的活力。
