# Ceph 社区 2025Q1 季度进展报告

---

## 一、本季度重点议题

本季度社区讨论呈现出以下几条主线：

**1. 性能优化与新硬件适配**

BlueStore 性能调优、Crimson/CStore 新存储引擎、NVMe-oF 网关、ARM 架构支持、Erasure Coding 插件优化等议题贯穿全季度，反映出社区对现代硬件（NVMe、ZNS、QLC SD）的持续适配需求。

**2. RGW 功能完善与企业化**

RGW 重构会议每周召开，本季度重点推进了 Bucket Logging、通知 V2（Notification V2）、D4N 缓存、多站点同步、对象删除一致性等企业级特性，同时修复了多个数据安全问题。

**3. CephFS 生态扩展**

异步 IO 接口、fscrypt 用户空间加密、CephFS 备份策略、NFS Ganesha 集成等议题集中出现，显示出 CephFS 在企业文件存储场景的持续深化。

**4. 可观测性与运维工具**

Telemetry 模块、多集群 Dashboard、条件跟踪（Conditional Tracing）、大规模集群监控架构等议题频繁出现，反映出运维复杂度上升后社区对可观测性的重视。

**5. AI/云原生存储需求**

多个演讲涉及 AI 原生应用的存储需求，Ceph 在高性能 GPU 集群存储、对象存储加速等场景的应用受到关注。

## 二、技术亮点

### 2.1 BlueStore 性能优化

[Advancing_BlueStore_with_Real-World_Insights-_Adam_Kupczyk_IBM](/posts/2025/Advancing_BlueStore_with_Real-World_Insights_-_Adam_Kupczyk_IBM)) 中，IBM 的 Adam Kupczyk 展示了通过真实客户工作负载（来自 DigitalOcean，包含 3亿次操作、73 小时 RBD 数据）分析 BlueStore 性能的方法。关键发现：

- 通过预取策略可减少 39% 的 IO 操作
- 开发了 scraper 工具抓取 OSD 历史操作数据，以及 replayer 工具用于回放测试
- 发现 RBD 客户端存在重复读取相同区域的模式，为缓存优化提供了方向

### 2.2 Crimson/CStore 新存储引擎

[Crimson_Project_Update_-_Matan_Breizman_Aishwarya_Mathuria_IBM](/posts/2025/Crimson_Project_Update_-_Matan_Breizman_Aishwarya_Mathuria_IBM)) 报告了重要进展：

- Crimson 在 3 OSD、每 OSD 10 核心配置下，性能比传统 OSD 提升 **40%-50%**
- 减少了 99% 的上下文切换，消除了 CPU 迁移
- CStore（Crimson 专用后端）已稳定，支持 Rados API，元数据使用 BitRI 替代 RocksDB
- 当前处于技术预览阶段，支持 RBD 和复制池基本功能

### 2.3 NVMe-oF Gateway路线图

[Ceph_NVMe-of_Road_Map_-_Orit_Wasserman_Aviv_Caro_IBM](/posts/2025/Ceph_NVMe-of_Road_Map_-_Orit_Wasserman_Aviv_Caro_IBM)) 明确了路线图：

- Ceph Tentacle 版本将达到生产就绪状态，代码已合并主分支
- 支持多 Gateway 高可用，使用 NVMe-oF ANAGRP 协议实现故障切换
- 计划在 Tentacle 中实现自动负载重平衡、CLI 集成和 Dashboard 支持
- 支持 VMware vSphere API，TLS 加密和 CHAP 认证

### 2.4 RGW 通知 V2 企业级特性

[Ceph_Notification_at_Scale_-_Notification_V2_an_Enterprise-Level_Feature_-_Krunal_Chheda_Bloomberg](/posts/2025/Ceph_Notification_at_Scale_-_Notification_V2_an_Enterprise-Level_Feature_-_Krunal_Chheda_Bloomberg)) 介绍了 Bloomberg 推动的 V2 增强：

- 引入 Topic 所有权与细粒度权限模型
- 支持多区域自动同步，用户只需在一个区域配置
- 新增 `rgw notification` 日志子系统
- 异步通知队列写入从 S3 请求路径中分离，提升性能
- Bloomberg 生产环境：10 个集群、4500 OSD、每日 20 亿次请求

### 2.5 CephFS 异步 IO 接口

[Async_IO_with_Libcephfs_-_Dhairya_Parmar_IBM](/posts/2025/Async_I_O_with_Libcephfs_-_Dhairya_Parmar_IBM)) 报告了 libcephfs 异步 IO 接口的开发进展：

- 解决了 NFS Ganesha 在高负载下线程争用和等待时间过长的问题
- 实现了回调机制，IO 完成后通知客户端，线程可立即释放
- 已与 NFS Ganesha 集成并测试，正在推进零拷贝技术实现
- 计划后续集成到 Samba

### 2.6 Erasure Coding 插件优化

[Erasure_Coding_-_5_Ways_to_Split_a_Squid_-_Jamie_Pryde_IBM](/posts/2025/Erasure_Coding_-_5_Ways_to_Split_a_Squid_-_Jamie_Pryde_IBM)) 的基准测试显示：

- ISA-L 插件在支持 AVX512 的 CPU 上，编解码性能比默认 Jerasure **高出 4-5 倍**
- 即使在仅支持 AVX2 的 AMD CPU 上，ISA-L 也比 Jerasure 快约 2 倍
- 已提交 PR 建议将 ISA-L 设为新建 Erasure Coding 池的默认插件
- Telemetry 数据显示约 1/4 到 1/3 的集群使用 Erasure Coding，大多数仍在使用 Jerasure

### 2.7 ARM 架构 CI 增强与 UADK 集成

[Arming_Ceph_-_CI_Enhancement_and_UADK_Integration_-_Rongqi_SunHUAWEI_TECHNOLOGIES_CO._LTD.](/posts/2025/Arming_Ceph_-_CI_Enhancement_and_UADK_Integration_-_Rongqi_Sun_HUAWEI_TECHNOLOGIES_CO._LTD.)) 报告了华为的贡献：

- 清理遗留代码，统一操作系统版本，解决了超过 20 个 MCI 相关问题
- MCI 现在要求代码合并前必须通过测试
- UADK（用户空间加速开发工具包）集成已合并到 main 分支，通过 RGW 和 RBD 测试显著减少 CPU 使用率

### 2.8 D4N 缓存功能

[D4N_in_RGW_-_Pritha_Srivastava_IBM](/posts/2025/D4N_in_RGW_-_Pritha_Srivastava_IBM)) 介绍了 RGW 新缓存架构：

- D4N 基于分布式目录，维护整个缓存的全局状态
- 已合并基于 SST 后端的读缓存实验版本
- 写回缓存已引入头块缓存，支持单部分对象
- 目录驱动已从 Redis 切换到 Valkyrie

### 2.9 fscrypt 用户空间加密

[Bringing_fscrypt_Encryption_to_CephFS_Userspace_-_Christopher_Hoffman_IBM](/posts/2025/Bringing_fscrypt_Encryption_to_CephFS_Userspace_-_Christopher_Hoffman_IBM)) 报告了 CephFS 用户空间加密进展：

- 核心功能已完成，包括加密/解密、FUSE 支持、CLI 工具、测试框架
- 已完成单客户端稳定性验证，正在进行多客户端互操作性测试
- 支持文件名和数据内容加密，每个文件有独立密钥

### 2.10 RocksDB Tombstone 问题分析

[Exploring_RocksDB_inGW_-_How_We_Manage_Tombstones_-_Sungjoon_Koh_Ilsoo_Byun_LINE_Plus_Corp](/posts/2025/Exploring_RocksDB_in_RGW_-_How_We_Manage_Tombstones_-_Sungjoon_Koh_Ilsoo_Byun_LINE_Plus_Corp)) 来自 LINE Plus Corp（管理 30+ 集群、700PB+ 存储）的深度分析：

- 发现 RocksDB Tombstone 积累会导致 OSD CPU 使用率达到 100% 并持续数小时
- 提出基于 Skip Count 的自动化压缩策略
- 提出前缀范围压缩（Prefix-based Compaction）方案，已计划提交社区

## 三、重要决策与里程碑

### 3.1 Tentacle 版本发布计划

多个 RGW 重构会议（[Ceph_RGW_Refactoring_Meeting_2025-02-26](/posts/2025/Ceph_RGW_Refactoring_Meeting_2025-02-26))、[Ceph_RGW_Refactoring_Meeting_2025-03-19](/posts/2025/Ceph_RGW_Refactoring_Meeting_2025-03-19))）明确了 Tentacle 版本计划：

- Seth Steering Committee 确认计划在未来一两个月内进行代码冻结
- NVMe-oF Gateway 将在 Tentacle 达到生产就绪
- 正在整理 Tentacle 目标功能列表文档

### 3.2 RGW 数据安全修复

[Ceph_RGW_Refactoring_Meeting_2025-01-08](/posts/2025/Ceph_RGW_Refactoring_Meeting_2025-01-08)) 讨论了一个重要的数据安全问题：

- 发现当 RGW 发起的 RADOS 操作超时可能导致数据丢失
- 该问题已在 Reef 版本修复，决定尽快 backport 到 Squid 版本
- 同时修复了 Last Modified Time Stamps 精度不一致问题（head object 返回秒级，list objects 返回毫秒级）

### 3.3 Ceph 20 周年

[Ceph_at_20_Years_Still_the_Best_for_Modern_Storage_-_Dan_van_derSter_CLYSO](/posts/2025/Ceph_at_20_Years_Still_the_Best_for_Modern_Storage_-_Dan_van_der_Ster_CLYSO)) 回顾了 Ceph 从 2004 年 Sage 博士项目到今天的历程，关键里程碑包括 CRUSH 算法（2006）、RBD（2010）、Inktank 成立与 Red Hat 收购（2012-2014）、BlueStore 迁移（2015-2016）、Ceph 基金会成立（2018）、Crimson 引入（2020）。

### 3.4 ISA-L 成为 Erasure Coding 默认插件

社区决定将 ISA-L 设为新建 Erasure Coding 池的默认插件，替代已停止维护的 Jerasure，这是一个影响所有新部署的重要默认值变更。

### 3.5 Ceph Dashboard 多集群管理

[Ceph_Made_Easy_-_One_Dashboard_for_Multiple_Ceph_Clusters_-_Nizamudeen_A_IBMIndia_Private_Ltd](/posts/2025/Ceph_Made_Easy_-_One_Dashboard_for_Multiple_Ceph_Clusters_-_Nizamudeen_A_IBM_India_Private_Ltd)) 展示了多集群管理功能的设计与实现，采用 Hub 集群 + Prometheus Federation 架构，已完成基本功能演示，计划支持 SSO 和 RBD 镜像自动化。

## 五、下季度展望

基于本季度的讨论内容，预计 2025Q2 将重点推进以下方向：

**1. Tentacle 版本发布**

代码冻结计划在 Q2 初执行，NVMe-oF Gateway 生产就绪、Crimson 功能扩展（纠删码池、RGW、QoS 支持）、CStore 替换 BlueStore 等将是核心交付目标。

**2. RGW 企业特性落地**

Bucket Logging 安全策略（Service Principal 方案）、账户暂停功能、Copy Object 加密、多区域 Broker 独立配置等功能将在 Q2 完成或进入 QA 阶段。

**3. Crimson 生产化路径**

随着 CStore 稳定性提升和功能扩展，社区将推动 Crimson 从技术预览向生产可用迈进，重点补齐纠删码池和 RGW 支持。

**4. CephFS 加密与备份完善**

fscrypt 用户空间实现将完成上游合并，CephFS 备份工具链（快照性能优化、递归 mtime 优化）将在 Tentacle 版本中得到改善。

**5. 可观测性基础设施升级**

条件跟踪系统迁移到 OpenTelemetry 最新架构，RGW 线程池阻塞问题跟踪，大规模集群监控的事件驱动架构将进入实验性部署阶段。

**6. ARM 生态持续扩展**

ARM CI 通道建设、更多开源操作系统支持、UADK 与 OpenSSL 3 provider 接口集成（包括 ChaCha20 加速）将持续推进。
