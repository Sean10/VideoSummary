# Ceph 社区 2025Q3 季度进展报告

---

## 一、本季度重点议题

2025Q3 季度，Ceph 社区围绕以下技术方向进行了密集讨论，呈现出明显的主线脉络：

**1. Umbrella 版本功能规划**

本季度大量会议以"Umbrella 版本"为核心议题，各子系统团队（BlueStore、RGW、CephFS、RBD、Crimson 等）均在 Ceph Developer Summit 上集中汇报了各自的功能规划与优先级排序。详见 [Ceph Developer Summit - RADOS CDS](/posts/2025/Ceph_Developer_Summit_-_RADOS_CDS))、[Ceph Developer Summit - RGW](/posts/2025/Ceph_Developer_Summit_-_RGW))。

**2. RGW 功能完善与稳定性**

RGW 重构会议贯穿整个季度（6月至9月），涵盖 DUP 去重、D4N 分布式缓存、加密对象处理、Bucket Logging、生命周期处理 Bug 等多个方向，是本季度讨论最为密集的子系统。

**3. BlueStore 性能与可靠性优化**

BlueStore 团队在 Developer Summit 上系统梳理了 RocksDB 缓存、快速恢复、分配映射持久化等多项改进，并讨论了 EC 优化和硬件压缩插件等前沿方向。

**4. Crimson/SeaStore 成熟度提升**

Crimson 在本季度完成了 PG 分裂功能合并，并开始定期发布性能基准数据，标志着其从实验性走向可评估阶段。

**5. 集群运维工具链改进**

Cephadm、Teuthology、Dashboard 等运维工具均有重要规划，PG Balancer 的改进也在用户月度会议中引发广泛讨论。

---

## 二、技术亮点

### BlueStore

- **RocksDB 缓存优化**：修复大缓存条目导致分片不平衡和持续驱逐的问题，已有 PR，计划 backport。详见 [Ceph Developer Summit - BlueStore Part 1](/posts/2025/Ceph_Developer_Summit_-_BlueStore_Part_1))。
- **快速 Onode 恢复（Fast Onode Recovery）**：多线程恢复显著缩短大容量 OSD 重启时间，避免被误判为下线。
- **BlueFS 分配映射持久化改进**：优化高碎片化磁盘场景下的恢复效率。
- **Scrub 期间对象优化**：Scrub 读取对象时同步执行重压缩和碎片整理。
- **VM Provisioning 插件**：探索硬件压缩支持，减轻 CPU 负载，需新增设备容量统计。详见 [Ceph Developer Summit - BlueStore Part 2](/posts/2025/Ceph_Developer_Summit_-_BlueStore_Part_2))。

### RGW

- **CLS Hash 优化**：在 OSD 端计算哈希（支持 MD5/SHA-256/Blake3），减少 RGW 数据传输负载，采用动态检查方案处理 Blake3 状态序列化问题。详见 [Ceph RGW Refactoring Meeting 2025-06-25](/posts/2025/Ceph_RGW_Refactoring_Meeting_2025-06-25))。
- **DDUP 去重**：Full DDUP PR 进入测试阶段，Rate Limiting 功能完成开发，Small Object DDUP 开发中。详见 [Ceph RGW Refactoring Meeting 2025-09-10](/posts/2025/Ceph_RGW_Refactoring_Meeting_2025-09-10))。
- **Bucket Logging EC Pool支持**：采用异步复制到 EC Pool 的最终方案，由 Nithia & Yuval 负责实现。详见 [Ceph RGW Refactoring Meeting 2025-08-13](/posts/2025/Ceph_RGW_Refactoring_Meeting_2025-08-13))。
- **持久化 Topic 队列分片**：引入分片方案提升并行写入性能，默认分片数初步定为 11，初始部署设为 1以保证兼容性。详见 [Ceph RGW Refactoring Meeting 2025-07-16](/posts/2025/Ceph_RGW_Refactoring_Meeting_2025-07-16))。
- **KMIP 后端支持 SSE-S3**：参考 Vault Transit 模式，采用 KEK/DEK 分离模型，计划在 Ceph 的 `libkmip` fork 中开发并推动上游合并。详见 [Ceph RGW Refactoring Meeting 2025-09-17](/posts/2025/Ceph_RGW_Refactoring_Meeting_2025-09-17))。
- **加密对象拷贝修复**：修复 multipart upload 加密属性传递问题，代码已 rebase 准备合并。详见 [Ceph RGW Refactoring Meeting 2025-09-24](/posts/2025/Ceph_RGW_Refactoring_Meeting_2025-09-24))。
- **RGW 生命周期处理 Bug 修复**：修复 `already_runtoday` 逻辑缺陷和 Shard 锁复用问题，导致 Bucket 处理被错误跳过。详见 [Ceph RGW Refactoring Meeting 2025-09-17](/posts/2025/Ceph_RGW_Refactoring_Meeting_2025-09-17))。

### CephFS

- **Mirror Daemon CLI 增强**：通过 `service daemon` 接口将状态推送至 `ceph-mgr`，支持 CLI 查询。
- **灾难恢复工具进度反馈**：利用 `ceph-mgr` 的 `progress module` 上报进度，支持多线程独立统计。
- **Subvolume Quarantine 功能**：应对勒索软件攻击场景，通过修改 CAP 协议支持隔离特定 Subvolume。
- **Subvolume V3**：修复 V1/V2 设计缺陷，支持自动升级，目标纳入 Umbrella 版本。详见 [Ceph Developer Summit - CephFS](/posts/2025/Ceph_Developer_Summit_-_CephFS))。

### Crimson/SeaStore

- **PG 分裂功能**：已合并至 `main` 分支，正在进行稳定性测试。
- **SeaStore 作为默认后端**：首次通过 `cephadm` 部署 SeaStore 的测试任务成功运行。
- **性能基准发布**：开始定期发布 IOPS、延迟等性能数据，4K 随机读场景优于 Classic OSD。详见 [Ceph Developer Summit - Crimson SeaStore](/posts/2025/Ceph_Developer_Summit_-_Crimson_SeaStore))。

### NVMe-oF 网关

- **故障转移时间优化**：通过优化 beacon 机制（仅发送状态差异），目标将故障转移时间从 12 秒缩短至 5-7 秒。
- **Active-Active 网关**：探索多网关同时写入支持，需解决 IO 顺序一致性问题。
- **自动监听器（Auto Listeners）**：根据网络掩码自动匹配节点 IP 创建监听器，降低运维复杂度。详见 [Ceph Developer Summit - NVMe-oF gateway](/posts/2025/Ceph_Developer_Summit_-_NVMe_oF_gateway))。

### RBD

- **快照镜像功能**：推进半动态组支持（Semi-dynamic groups）、镜像 API 处理程序重写、基于 RADOS watch 的通知机制。
- **数据同步正确性**：修复克隆镜像同步问题和 discard 操作传播问题。详见 [Ceph Developer Summit RBD](/posts/2025/Ceph_Developer_Summit_RBD))。

### Dashboard

- **Carbon 设计系统**：全面引入 Carbon Design System，对 Dashboard UI 进行现代化改造。
- **NVMe-oF Gateway Groups支持**：升级支持最新规范，支持批量创建 Namespace。
- **Multi-Cluster 支持**：新增跨集群 Metrics 查看能力。详见 [Ceph Developer Summit Dashboard](/posts/2025/Ceph_Developer_Summit_Dashboard))。

### PG Balancer

- **`ceph pg remap undo` 命令**：提案将社区广泛使用的 `upmap_remapper` 和 `pg_remapper` 脚本功能纳入官方支持，作为 Umbrella 版本短期目标。详见 [Ceph User + Dev Monthly - September 2025](/posts/2025/Ceph_User_+_Dev_Monthly_-_September_2025))。

## 三、重要决策与里程碑

**版本发布**

- **Tentacle RC1 发布**：本季度 Tentacle RC1 正式发布，正在收集用户反馈，可能需进一步修复后发布正式版。详见 [Ceph RGW Refactoring Meeting 2025-09-10](/posts/2025/Ceph_RGW_Refactoring_Meeting_2025-09-10))。
- **Quincy 17.2.9 紧急发布**：修复 BlueFS 的 LSN 问题导致的 OSD 崩溃，建议高风险集群尽快更新。详见 [Ceph Science User Group May 2025](/posts/2025/Ceph_Science_User_Group_May_2025))。

**重大设计决定**

- **DBStore 后端弃用方向确立**：社区达成共识，DBStore 已完成概念验证目标，开发重心转向 POSIX 后端，若无特殊需求可逐步弃用。详见 [Ceph RGW Refactoring Meeting 2025-09-17](/posts/2025/Ceph_RGW_Refactoring_Meeting_2025-09-17))。
- **OMAP Data Logs 标记弃用**：计划在 Umbrella 版本中标记为 deprecated，实际移除推迟至后续版本，为用户提供迁移时间。
- **S3 测试迁移策略**：Boto2 测试因 Python 版本升级无法运行，社区决定接受移除遗留测试的 PR，后续通过新测试补充覆盖率。详见 [Ceph RGW Refactoring Meeting 2025-09-24](/posts/2025/Ceph_RGW_Refactoring_Meeting_2025-09-24))。
- **旧版 Dashboard 弃用**：Umbrella 版本计划移除旧版 Dashboard（v2），仅保留 v3。
- **Crimson 构建类型分离**：将 Crimson 构建分为 `debug` 和 `release` 两种类型。
- **RGW Usage Log Triming 修复策略**：采用 config option 控制过渡逻辑，仅影响 `cls_rgw.cc`，对用户透明。详见 [Ceph RGW Refactoring Meeting 2025-08-27](/posts/2025/Ceph_RGW_Refactoring_Meeting_2025-08-27))。

## 四、社区动态

**Ceph Developer Summit（CDS）**

本季度举办了 Ceph Developer Summit，覆盖 BlueStore、CephFS、Cephadm、Crimson/SeaStore、NVMe-oF、RADOS、RGW、RBD、Dashboard、Telemetry/MGR、Teuthology 等几乎所有核心子系统，是本季度最重要的社区活动。

**Ceph Science User Group**

- 3 月会议：苏黎世科学 IT 服务的 Matia 分享了 CephFS 在可信研究环境（TRE）中的调优经验，规模达 500 名研究人员、3.2PB 数据。详见 [Ceph Science User Group - March 2025](/posts/2025/Ceph_Science_User_Group_-_March_2025))。
- 5 月会议：STFC 的 Tom 分享了超过 100PB 规模集群（Echo）中 RocksDB 从 HDD 迁移至 SSD 的性能分析。详见 [Ceph Science User Group May 2025](/posts/2025/Ceph_Science_User_Group_May_2025))。
- 7 月会议：Tom 分享了 HDD vs SSD 在 Ceph 集群中的电力与碳成本对比分析，闪存方案在小 IOPS 场景下单位性能碳效率更优。详见 [Ceph Science User Group Meetup - July 2025](/posts/2025/Ceph_Science_User_Group_Meetup_-_July_2025))。

**Ceph User + Dev Monthly**

- 7 月会议：讨论了 CephCon 2023（温哥华）注册与 CFP 征集，Anthony 推动用户故事收集计划，并讨论了容器化 Ceph 补丁构建问题和 RGW S3 API 兼容性回归问题。详见 [Ceph User + Dev Monthly - July 2025](/posts/2025/Ceph_User_+_Dev_Monthly_-_July_2025))。
- 9 月会议：深入讨论 PG Balancer 改进方案，社区成员 Dan Vanderster、Alexander 等积极参与，推动 `ceph pg remap undo` 命令提案。详见 [Ceph User + Dev Monthly - September 2025](/posts/2025/Ceph_User_+_Dev_Monthly_-_September_2025))。

**RGW 重构例会**

RGW 团队坚持每周举行重构会议，本季度共记录 8 次（6月至9月），涵盖加密、去重、Bucket Logging、生命周期、测试稳定性等多个专题，体现了 RGW 团队较强的工程纪律性。

**Teuthology 工具链**

- 推进 VM 环境测试（IBM Cloud VMs）、Podman 容器化 DevStack、日志压缩优化（`zstd-mt` 比 `gzip` 快 36%）、Metal-as-a-Service（MaaS）后端集成等。详见 [Ceph Developer Summit - Teuthology](/posts/2025/Ceph_Developer_Summit_-_Teuthology))。

## 五、下季度展望

基于本季度讨论内容，预计 2025Q4 将重点推进以下方向：

**1. Umbrella 版本冲刺**

各子系统将进入 Umbrella 版本的功能收敛阶段，预计 BlueStore 的 RocksDB 缓存优化、RGW 的 Full DDUP、D4N 性能优化、CephFS Subvolume V3、NVMe-oF 故障转移优化等将陆续完成合并。

**2. RGW 加密与安全增强**

KMIP 后端 SSE-S3 支持、加密对象拷贝修复、SSE-C 测试问题解决等将在下季度进入实质性开发阶段。

**3. Crimson 稳定性验证**

PG 合并功能开发、SeaStore 集成测试、EC Pool 通用代码合并将是 Crimson 团队的主要任务，随机写性能优化也是重点方向。

**4. PG Balancer 官方化**

`ceph pg remap undo` 命令的实现与测试将推进，长期目标是将 Balancer 模块改造为能自动处理 misplaced PG 的智能组件。

**5. 测试基础设施完善**

RGW 测试套件稳定性（Valgrind 内存泄漏、DBStore 测试标记、CLS 测试超时）、Teuthology MaaS 后端、Manager 测试覆盖率提升等将持续推进。

**6. 可持续性与绿色计算**

受 Science User Group 的碳成本分析研究影响，预计社区将进一步关注 QLC SD 在大规模集群中的应用，以及不同 EC 布局对功耗的影响。
