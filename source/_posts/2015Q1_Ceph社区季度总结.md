我将基于这31篇2015Q1季度的会议和视频总结，生成一份完整的社区季度进展报告。

# Ceph 社区季度进展报告 — 2015 Q1

---

## 一、本季度重点议题

本季度 Ceph 社区围绕以下几个核心方向展开了密集讨论：

**1. 新存储后端（NewStore / BlueStore 前身）**

OSD 存储后端的重构是本季度最受关注的议题之一。现有 FileStore 经过多年演进已趋于复杂，社区在 [CDS_Infernalis_Day_2.2_--_OSD_-_Newstore](/VideoSummary/2015/03/06/CDS_Infernalis_Day_2.2_--_OSD_-_Newstore/) 中深入讨论了以 RocksDB + POSIX 文件系统为基础的新存储后端方案，目标是消除双写开销、提升小写性能。

**2. RBD 异步镜像与灾难恢复**

RBD 跨集群异步复制是本季度 RBD 方向的核心议题，在 [CDS_Infernalis_Day_1--_RBD_-_Async_Mirroring](/VideoSummary/2015/03/06/CDS_Infernalis_Day_1_--_RBD_-_Async_Mirroring/) 中提出了基于完整日志的异步镜像设计方案，为灾难恢复能力奠定基础。

**3. RGW Active-Active 多区域架构**

RGW 的多区域主动架构改造在 [CDS_Infernalis_Day_1_--_RGW_-_Active_Active_Arch](/VideoSummary/2015/03/06/CDS_Infernalis_Day_1_--_RGW_-_Active_Active_Arch/) 中被重点讨论，涉及区域命名重构、同步代理改进、对象版本控制等多个子议题。

**4. Erasure Coding 覆盖写支持**

EC 池的覆盖写能力是制约 RBD 使用 EC 存储池的关键瓶颈，[CDS_Infernalis_Day_1_--_OSD_-_Erasure_Coding_Pool_Overwrite_Support](/VideoSummary/2015/03/06/CDS_Infernalis_Day_1_--_OSD_-_Erasure_Coding_Pool_Overwrite_Support/) 对两阶段提交、回滚日志等多种方案进行了系统性评估。

**5. OSD 性能与延迟优化**

包括 pering 延迟、scrub 侵入性、I/O hints、Cache Tier 改进等多个性能子议题在本季度均有专项讨论。

---

## 二、技术亮点

### 2.1 RBD

- **异步镜像机制设计**：[CDS_Infernalis_Day_1_--_RBD_-_Async_Mirroring](/VideoSummary/2015/03/06/CDS_Infernalis_Day_1_--_RBD_-_Async_Mirroring/) 提出基于 RBD journal 的完整数据日志方案，支持写回（writeback）和写透（writethrough）两种日志模式，可在单个镜像或整个存储池级别配置复制粒度，并支持一致性组（consistency group）。

- **LibRBD 元数据机制**：[CDS_Infernalis_Day_2.2_--_RBD_-_Add_metadatamechanism_to_LibRBD](/VideoSummary/2015/03/06/CDS_Infernalis_Day_2.2_--_RBD_-_Add_metadata_mechanism_to_LibRBD/) 讨论了为每个 RBD 镜像存储键值对元数据的方案，元数据存储于镜像头部，通过 `rbd meta put` / `rbd meta list` 等命令操作，解决不同场景下配置不一致的问题。

- **内核 RBD 客户端 Copy-on-Read**：[CDS_Infernalis_Day_2.2_--_RBD_-_Kernel_RBD_client_supports_copy-on-read](/VideoSummary/2015/03/06/CDS_Infernalis_Day_2.2_--_RBD_-_Kernel_RBD_client_supports_copy-on-read/) 讨论了使用状态机技术优化内核 RBD 的复制和写入操作，以及对象映射（object map）的哈希表优化方案。

- **克隆与父卷差异导出**：[CDS_Infernalis_Day_2.2_--_RBD_-_export_diff_between_clone_parent](/VideoSummary/2015/03/06/CDS_Infernalis_Day_2.2_--_RBD_-_export_diff_between_clone_parent/) 讨论了 RBD 克隆与父卷之间差异导出功能，以及多对象事务的两阶段提交实现方案。

- **Acelio XIO 传输协议集成**：[CDS_Infernalis_Day_1_--_Accelio_XIO_Integration_with_kernel_RBD](CDS_Infernalis_Day_1_--_Acelio_XIO_Integration_with_kernel_RBD) 介绍了将高性能 XIO 传输协议集成到内核 RBD 客户端的工作，支持动态加载传输协议，TCP 作为默认选项保持兼容。

- **集群化 SCSI Target**：[CDS_Infernalis_Day_1_--_Clustered_SCSI_Target_using_RBD](/VideoSummary/2015/03/06/CDS_Infernalis_Day_1_--_Clustered_SCSI_Target_using_RBD/) 讨论了使用 RBD 作为 iSCSI/SCSI target 后端的主动-主动集群方案，涉及 LIO 存储管理修改、持久预留、任务管理等。

### 2.2 RGW

- **Active-Active 多区域架构**：[CDS_Infernalis_Day_1_--_RGW_-_Active_Arch](/VideoSummary/2015/03/06/CDS_Infernalis_Day_1_--_RGW_-_Active_Active_Arch/) 提出将"zone"概念重命名为"zone group"以消除歧义，并设计了每个区域维护独立日志、由 Sync Agent 负责跨区域同步的新架构，支持多区域并发读写。

- **多租户支持**：[CDS_Infernalis_Day_1_--_RGW_-_Multitenancy](/VideoSummary/2015/03/06/CDS_Infernalis_Day_1_--_RGW_-_Multitenancy/) 讨论了为 RGW 用户和存储桶引入租户属性的方案，现有用户归入全局租户，新用户继承租户属性，并探讨了与 Keystone 集成及基于角色的认证方案。

- **NFS 导出**：[CDS_Infernalis_Day_1_--_RGW_-_NFS](/VideoSummary/2015/03/06/CDS_Infernalis_Day_1_--_RGW_-_NFS/) 讨论了通过创建高层次 librgw 库、对接 NFS-Ganesha 来实现 RGW 数据的 NFS 导出能力。

- **RGW 架构全面介绍**：[2015-MAR-26_--_Ceph_Tech_Talks_-_RGW](/VideoSummary/2015/03/30/2015-MAR-26_--_Ceph_Tech_Talks_-_RGW/) Tech Talk 系统介绍了 RGW 的前端、RESTful API、执行层、数据管理、多区域配置等模块，并宣布下一步计划包括主动架构、多租户、对象过期和 NFS 导出。

### 2.3 OSD /RADOS

- **NewStore 新存储后端**：[CDS_Infernalis_Day_2.2_--_OSD_-_Newstore](/VideoSummary/2015/03/06/CDS_Infernalis_Day_2.2_--_OSD_-_Newstore/) 提出以 RocksDB 管理事务和键值数据、以 XFS 管理数据块的新架构，通过避免双写消除 journal 开销，支持异步事务提交。

- **EC 池覆盖写**：[CDS_Infernalis_Day_1_--_OSD_-_Erasure_Coding_Pool_Overwrite_Support](/VideoSummary/2015/03/06/CDS_Infernalis_Day_1_--_OSD_-_Erasure_Coding_Pool_Overwrite_Support/) 评估了两阶段提交方案（确定性、可预测、类 RAID 行为）作为首选实现路径。

- **Peering 延迟优化**：[CDS_Infernalis_Day_2.2_--_OSD_-_Peering_Latency](/VideoSummary/2015/03/06/CDS_Infernalis_Day_2.2_--_OSD_-_Peering_Latency/) 分析了 pering 过程中多个往返延迟来源，提出基于历史区间预判权威 OSD、客户端驱动读取（client-driven read）等优化方案。

- **Scrub 侵入性降低**：[CDS_Infernalis_Day_1_--_OSD_-_Less_Intrusive_Scrub](/VideoSummary/2015/03/06/CDS_Infernalis_Day_1_--_OSD_-_Less_Intrusive_Scrub/) 讨论了随机化 scrub 调度时间、细粒度 scrub 窗口、统一工作队列（unified work queue）、scrub 限速等方案。

- **Scrub 与 Repair 接口**：[CDS_Infernalis_Day_1_--_OSD_-_Scrub_and_Repair](/VideoSummary/2015/03/06/CDS_Infernalis_Day_1_--_OSD_-_Scrub_and_Repair/) 讨论了开发 RADOS 接口查询 PG 修复状态、创建命令行工具处理不一致对象的方案。

- **I/O Hints**：[CDS_Infernalis_Day_2.2_--_OSD_-_RADOS_I_O_Hints](/VideoSummary/2015/03/06/CDS_Infernalis_Day_2.2_--_OSD_-_RADOS_I_O_Hints/) 讨论了在 RBD 和文件系统中传递 I/O 缓存行为提示（如 no-cache、proxy read）的框架，计划在 Hammer 版本中实现。

- **分层存储扩展**：[CDS_Infernalis_Day_2.2_--_OSD_-_Tiering](/VideoSummary/2015/03/06/CDS_Infernalis_Day_2.2_--_OSD_-_Tiering/) 讨论了将冷数据迁移到外部存储系统（其他 Ceph 集群、S3、Glacier）的插件接口设计，以及多级分层存储架构。

- **Cache Tier 改进**：[CDS_Infernalis_Day_2.2_--_Cache_Tier_Improvements](/VideoSummary/2015/03/06/CDS_Infernalis_Day_2.2_--_Cache_Tier_Improvements/) 讨论了基于 I/O 类型（读/写、顺序/随机）进行更精细的 promotion 决策，以及使用近似计数 Bloom 过滤器改进 Hit Set 的方案。

- **LMDB 键值后端**：[CDS_Infernalis_Day_2.2_--_LMDB_backendfor_Ceph](/VideoSummary/2015/03/06/CDS_Infernalis_Day_2.2_--_LMDB_backend_for_Ceph/) 讨论了将 LMDB 作为 OSD 键值存储后端的可行性，以解决 RocksDB 读写放大问题。

### 2.4 CephFS

- **OpenStack 集成与多租户**：[CDS_Infernalis_Day_1_--_CephFS_OpenStack](/VideoSummary/2015/03/06/CDS_Infernalis_Day_1_--_CephFS_OpenStack/) 讨论了 CephFS 与 Manila 集成的三种方案（默认驱动、Ganesha 驱动、原生驱动），倾向于 Ganesha 驱动以提供网络隔离和多租户支持，同时讨论了 Swift 兼容性差距。

### 2.5 基础设施与工具

- **Ceph 插件系统**：[CDS_Infernalis_Day_1_--_Ceph_Plugins](/VideoSummary/2015/03/06/CDS_Infernalis_Day_1_--_Ceph_Plugins/) 讨论了通用插件加载机制，包括插件版本与 OSD 版本严格匹配、以 C++ 虚拟类定义插件接口、以 OS 包形式分发插件等规范。

- **dm-crypt 密钥管理**：[CDS_Infernalis_Day_1_--_Simple_ceph-mon_dm-crypt_key_management](/VideoSummary/2015/03/06/CDS_Infernalis_Day_1_--_Simple_ceph-mon_dm-crypt_key_management/) 讨论了使用 LUKS 存储 OSD dm-crypt 密钥、设计可撤销密钥机制、实现 CLI 会话加密的方案。

- **容器化部署**：[CDS_Infernalis_Day_1_--_Ceph_Containers](/VideoSummary/2015/03/06/CDS_Infernalis_Day_1_--_Ceph_Containers/) 介绍了官方 Ceph Docker 镜像（包含 Monitor、OSD、MDS、RGW 组件）、基于 etcd 的分布式配置方案，以及 Ceph 作为 Kubernetes 存储提供商的集成探索。

- **性能分析框架**：[CDS_Infernalis_Day_2.2_--_Ceph_Performance](/VideoSummary/2015/03/06/CDS_Infernalis_Day_2.2_--_Ceph_Performance/) 讨论了将 COSBench 集成到 CBT（Ceph Benchmarking Tool）、引入语义化 Tracepoint 框架（基于 LTng）、使用 Zipkin 进行分布式追踪的标准化方案。

## 三、重要决策与里程碑

**版本规划**

- 本季度的 CDS（Ceph Developer Summit）以 **Infernalis** 版本为主题，多个议题均以 Infernalis 周期为交付目标。
- Hammer 版本即将发布，多项功能（如 I/O hints、Cache Tier 写代理改进）计划在 Hammer 中落地。

**重大设计决定**

| 决策 | 内容 |
|------|------|
| EC覆盖写方案 | 选择两阶段提交作为首选实现路径 |
| RGW 区域命名 | "zone" 重命名为 "zone group"，消除与数据中心概念的混淆 |
| NewStore 技术选型 | RocksDB（事务/KV）+ XFS（数据块）的混合架构 |
| RBD 异步镜像 | 基于完整 journal 的异步复制，支持池级别配置 |
| CephFS-Manila 集成 | 优先推进 Ganesha 驱动方案 |
| Calamari 重命名 | Calamari 客户端重命名为 **Rana**，采用 MIT 许可证，详见 [CDS_Infernalis_Day_1_--_Calamari_Discussion](/VideoSummary/2015/03/06/CDS_Infernalis_Day_1_--_Calamari_Discussion/) |

**治理里程碑**

[CDS_Infernalis_Day_1_--_Community_Governance](/VideoSummary/2015/03/06/CDS_Infernalis_Day_1_--_Community_Governance/) 讨论了 Ceph 项目向自我治理演进的路线图，计划建立包含董事会、技术委员会和用户委员会的三层治理结构，Red Hat 承诺提供更多社区资源（测试实验室、硬件等）。

- 1月：[2015-JAN-22_--_Ceph_Tech_Talk_-_RADOS](/VideoSummary/2015/01/23/2015-JAN-22_--_Ceph_Tech_Talk_-_RADOS/) — RADOS 内部架构，涵盖 librados、CRUSH、缓存分层、Erasure Coding
- 2月：[2015-FEB-26_--_Ceph_TechTalks_-_RBD](/VideoSummary/2015/02/27/2015-FEB-26_--_Ceph_Tech_Talks_-_RBD/) — RBD 技术深度解析，包括快照、克隆、I/O 路径
- 3月：[2015-MAR-26_--_Ceph_Tech_Talks_-_RGW](/VideoSummary/2015/03/30/2015-MAR-26_--_Ceph_Tech_Talks_-_RGW/) — RGW 架构与工作原理，宣布 4 月将举办 Calamari 专题

**Ceph Day London**

本季度举办了 Ceph Day London，来自 IBM 和荷兰社区的成员分享了实际部署经验：

- [IBM_@_Ceph_Day_London](/VideoSummary/2015/01/14/IBM_@_Ceph_Day_London/)：IBM 研究部门分享了在 OpenStack 环境和 SoftLayer 云平台上的 Ceph 部署实践，包括 SD/HDD 混合存储配置和跨数据中心管理规划。
- [Wido_@_Ceph_Day_London](/VideoSummary/2015/01/14/Wido_@_Ceph_Day_London/)：荷兰社区成员 Wido 分享了多年 Ceph 部署最佳实践，强调优先关注 I/O 性能而非容量、使用 SSD 作为 journal 盘、避免过多 PG 等实战经验。

**CDS Infernalis**

本季度举办了 CDS Infernalis（Ceph Developer Summit），分两天进行，涵盖 OSD、RBD、RGW、CephFS、容器、治理等多个专题，是本季度社区活动的核心。

## 五、下季度展望

基于本季度讨论内容，预计 2015 Q2 将重点推进以下方向：

1. **Hammer 版本发布**：I/O hints 框架、Cache Tier 写代理改进、scrub 优化等功能预计随 Hammer 发布落地。

2. **RBD 异步镜像原型实现**：journal 模块设计和异步复制功能的初步实现将是 RBD 方向的核心工作。

3. **RGW Active-Active 架构推进**：同步代理改进、对象版本控制重构、多租户初步实现预计进入开发阶段。

4. **NewStore 基准测试**：新存储后端完成 omap 实现和异步提交后，将进入性能基准测试阶段。

5. **Calamari → Rana 迁移**：Rana 首个版本预计在 Hammer 发布后约一个月推出。

6. **CephFS 稳定化与 Manila 集成**：Ganesha 驱动开发和 OpenStack 第三方测试环境搭建将持续推进。

7. **EC 覆盖写原型**：两阶段提交方案的原型实现预计启动。

8. **容器化部署完善**：官方 Docker 镜像多版本分支持和 Kubernetes 集成方案将进一步完善。
