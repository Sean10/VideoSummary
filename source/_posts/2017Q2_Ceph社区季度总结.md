# Ceph 社区 2017 Q2 季度进展报告

## 1. 本季度重点议题

本季度（2017年3月下旬至6月）Ceph 社区的讨论高度集中在以下几个方向：

**BlueStore 性能优化**是本季度最核心的主题，贯穿几乎所有 Performance Weekly 会议。涉及缓存管理、限流机制、内存使用、RocksDB 后端调优等多个子方向，详见 [2017-APR-05 Performance Weekly](2017-APR-05_-_Ceph_Performance_Weekly)、[2017-MAY-18 Performance Weekly](/VideoSummary/2017/05/26/2017-MAY-18_-_-_Ceph_Performance_Weekly/)。

**Luminous 版本收尾**是本季度的里程碑目标，多个会议中的 PR 合并和功能决策均以"是否纳入 Luminous"为判断标准，详见 [2017-APR-12 Developer Monthly](/VideoSummary/2017/05/17/2017-APR-12_-_-_Ceph_Developer_Monthly/)。

**ARM 平台支持**在本季度获得专题讨论，多家厂商（Cavium、SUSE、Deutsche Telekom）参与，详见 [2017-MAY-25 Ceph on ARM](/VideoSummary/2017/05/26/2017-MAY-25_--_Ceph_Tech_Talk_-_Ceph_on_ARM/)。

**Ceph Manager 功能扩展**，包括 REST API 和配置选项注释，作为 Luminous 的新增能力被重点讨论。

---

## 2. 技术亮点

### BlueStore 与 RocksDB

- **自适应限流（Adaptive Throttle）**：本季度持续迭代，目标是基于目标延迟动态调整限流参数，替代原有的静态配置。见 [2017-APR-12 Performance Weekly](/VideoSummary/2017/05/16/2017-APR-12_-_-_Ceph_Performance_Weekly/)、[2017-MAY-11 Performance Weekly](/VideoSummary/2017/05/17/2017-MAY-11_-_-_Ceph_Performance_Weekly/)。
- **RocksDB Compaction Read-Ahead**：Mark 验证了启用该功能后压缩期间读取时间从 95% 降至 18%，显著改善 BlueStore 在压缩期间的性能，见 [2017-MAY-04 Performance Weekly](/VideoSummary/2017/05/17/2017-MAY-04_-_-_Ceph_Performance_Weekly/)。
- **BlueFS 同步写（sync write）选项**：新增 BlueFS 同步提交功能，提高事务提交可靠性，见 [2017-JUN-01 Performance Weekly](2017-JUN-01_-_Ceph_Performance_Weekly)。
- **缓存池扩展**：BlueStore 新增 5 个缓存池，提高数据可见性和跟踪能力。
- **B-Tree 替代 STL map**：用于 PG temp mapping，提升元数据操作效率，见 [2017-MAY-25 Performance Weekly](2017-MAY-25_-_Ceph_Performance_Weekly)。
- **内存复制优化**：多个 PR 致力于在写路径上避免不必要的内存拷贝，见 [2017-MAY-18 Performance Weekly](/VideoSummary/2017/05/26/2017-MAY-18_-_-_Ceph_Performance_Weekly/)。

### OSD 与 RADOS

- **PG 重映射（PG Remapping）**：Sage 提出允许在 PG 已映射后重新映射的功能，解决长期存在的数据分布优化需求，见 [2017-MAR-22 Performance Weekly](/VideoSummary/2017/04/06/2017-MAR-22_-_-_Ceph_Performance_Weekly/)。
- **异步恢复（Async Recovery）**：Josh 推进异步恢复机制，阿里巴巴团队同步贡献了同步恢复和部分恢复的优化，见 [2017-MAY-04 Performance Weekly](/VideoSummary/2017/05/17/2017-MAY-04_-_-_Ceph_Performance_Weekly/)。
- **Commit Majority功能**：阿里巴巴团队实现了 commit majority，降低平均延迟和延迟抖动，见 [2017-MAY-11 Performance Weekly](/VideoSummary/2017/05/17/2017-MAY-11_-_-_Ceph_Performance_Weekly/)。
- **Scrub 作业优先级调整**：已合并，改善后台 scrub 对前台 IO 的影响，见 [2017-JUN-08 Performance Weekly](/VideoSummary/2017/06/21/2017-JUN-08_-_-_Ceph_Performance_Weekly/)。

### Async Messenger

- 持续优化锁机制，减少锁争用，在 Tesla 平台上验证了性能提升，见 [2017-MAY-25 Performance Weekly](2017-MAY-25_-_Ceph_Performance_Weekly)。

### Ceph Manager

- **REST API**：决定将 REST API 作为 Luminous 的实验性功能纳入，支持 OpenStack Swift 等上层应用集成，见 [2017-APR-12 Developer Monthly](/VideoSummary/2017/05/17/2017-APR-12_-_-_Ceph_Developer_Monthly/)。
- **配置选项注释（Config Option Annotations）**：为配置项添加描述、类型、默认值、影响范围、弃用标记等元数据，并通过文档生成工具自动输出文档。

### RBD

- **持久缓存（Persistent Cache）**：基于 Jason 草图的 RBD 持久缓存框架进入开发阶段，当前 IOPS 表现尚待优化，计划支持 unicast 和 scatter-gather，见 [2017-JUN-07 Developer Monthly](/VideoSummary/2017/06/22/2017-JUN-07_-_-_Ceph_Developer_Monthly/)。

### 可观测性

- **Zipkin 追踪框架集成**：Mark 持续推进将 Zipkin 集成到 Ceph 中，用于分布式追踪和性能监控，见 [2017-APR-05 Performance Weekly](/VideoSummary/2017/04/06/2017-APR-05_-_-_Ceph_Performance_Weekly/)。

### 语言绑定

- **Ceph Rust Bindings**：Chris Jones 展示了 Ceph 的 Rust 语言绑定，利用 Rust 内存安全特性封装 librados，见 [2017-MAR-23 Ceph Tech Talks](2017-MAR-23_--_Ceph_Tech_Talks_-_Ceph_at_ScaleWriting_Applications_with_Language_Bindings)。

## 3. 重要决策与里程碑

| 决策 | 内容 |
|------|------|
| REST API 纳入 Luminous | 以实验性功能状态发布，后续版本继续完善 |
| 配置选项注释纳入 Luminous | 统一配置文档生成机制 |
| 存储池应用标签（Pool Application Tags） | 添加 `application` 标签和元数据映射，不强制要求，提供健康警告，见 [2017-JUN-07 Developer Monthly](/VideoSummary/2017/06/22/2017-JUN-07_-_-_Ceph_Developer_Monthly/) |
| systemd 自定义集群名称支持移除 | 因兼容性问题决定移除，提供升级路径 |
| OSD 部署工具改用 LVM | 简化 OSD 部署流程，替代过于复杂的 ceph-disk 方案 |
| BlueStore 元数据后端探索 | 开始评估 LMDB 作为元数据存储后端的可行性 |
| ARM 平台 CI/CD 建设 | 决定将 ARM 构建纳入每个发布版本，并在 Jenkins 上建立 CI 流程，见 [2017-MAY-25 Ceph on ARM](/VideoSummary/2017/05/26/2017-MAY-25_--_Ceph_Tech_Talk_-_Ceph_on_ARM/) |
| Performance Weekly 会议时间调整 | 调整为周四 UTC 11:00，以兼顾不同时区参与者 |

## 4. 社区动态

**贡献者与厂商参与**

- **Red Hat**：Sage Weil、Josh、Greg 等核心开发者持续主导 BlueStore、OSD、恢复机制等方向。
- **阿里巴巴**：Mark、Jesse、Gem、CliffJohnson 等工程师深度参与性能优化，贡献了 commit majority、异步恢复等功能，并与社区建立了协作审查机制。
- **Cavium / ARM**：Pankaj Brijwasi 等推动 ARM 64 位平台支持，见 [2017-MAY-25 Ceph on ARM](/VideoSummary/2017/05/26/2017-MAY-25_--_Ceph_Tech_Talk_-_Ceph_on_ARM/)。
- **SUSE**：提供 ARM 64 位平台的 Ceph 企业存储产品支持。
- **Deutsche Telekom**：参与 ARM 平台性能测试和 Luminous 构建验证。
- **Canonical**：Chris Wholey 介绍了基于 Juju/Charm 的 Ceph 自动化部署方案，见 [2017-MAR-23 Ceph Tech Talks](/VideoSummary/2017/04/06/2017-MAR-23_--_Ceph_Tech_Talks_-_Ceph_at_Scale_Writing_Applications_with_Language_Bindings/)。

**大规模部署测试**

- CERN 部署了约 200 个主机的临时集群，用于验证新代码，见 [2017-MAY-25 Performance Weekly](/VideoSummary/2017/05/26/2017-MAY-25_-_-_Ceph_Performance_Weekly/)。

**会议与活动**

- 本季度持续举办 Ceph Performance Weekly（每周）、Ceph Developer Monthly（每月）和 Ceph Tech Talks 系列。
- Tech Talks 本季度涵盖"Ceph at Scale / Language Bindings"和"Ceph on ARM"两个专题。

## 5. 下季度展望

基于本季度讨论，预计 2017 Q3 的重点方向包括：

1. **Luminous 正式发布**：本季度大量功能已进入收尾阶段，Luminous 发布是 Q3 最重要的里程碑。
2. **BlueStore 稳定性与性能持续提升**：自适应限流、内存管理、LMDB 元数据后端等方向将进入验证阶段。
3. **Ceph Manager 生态完善**：REST API 和配置注释落地后，预计会有更多 Dashboard 和运维工具基于 Manager 构建。
4. **ARM 平台 CI 建设落地**：ARM 构建纳入正式发布流程，二进制包开始提供。
5. **RBD 持久缓存成熟**：当前 IOPS 性能问题待解决，预计 Q3 会有更完整的实现。
6. **阿里巴巴贡献合并**：commit majority、部分恢复等 PR 预计进入主线审查。
7. **OSD 部署工具 LVM 化**：ceph-volume 工具预计在 Q3 进一步完善并推广。
