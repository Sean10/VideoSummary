# Ceph 社区 2024Q1 季度进展报告

---

## 1. 本季度重点议题

本季度 Ceph 社区的讨论高度集中在以下几个技术方向：

**RGW 重构与通知系统改造**
RGW 重构会议贯穿整个季度（1月至3月），核心议题是 SNS/QS 风格的 Topic 和通知机制的重新设计。涉及 Topic 授权、持久化通知的 TTL/Max Retry 配置、多站点元数据同步一致性，以及通知迁移策略。详见 [Ceph RGW Refactoring Meeting 2024-01-03](/VideoSummary/2024/01/05/Ceph_RGW_Refactoring_Meeting_2024-01-03/)、[Ceph RGW Refactoring Meeting 2024-01-24](/VideoSummary/2024/01/24/Ceph_RGW_Refactoring_Meeting_2024-01-24/)、[Ceph RGW Refactoring Meeting 2024-01-31](/VideoSummary/2024/02/01/Ceph_RGW_Refactoring_Meeting_2024-01-31/)。

**Squid 版本发布准备**
代码冻结计划、功能卡点确认、分支管理策略是本季度反复出现的话题，多个功能（端到端追踪、IAM 账户、对象完整性）被列为 Squid 版本的阻塞项或目标特性。

**Crimson/Seastar 架构演进**
Crimson OSD 的代码结构、与经典 OSD 的差异、基于 Seastar 框架的异步编程模型是专项代码分析会议的核心内容。详见 [Ceph Code Walkthroughs - Crimson](/VideoSummary/2024/03/06/Ceph_Code_Walkthroughs_-_Crimson/)。

---

## 2. 技术亮点

### RGW 通知系统

- **持久化通知 TTL/Max Retry**：[Ceph RGW Refactoring Meeting 2024-01-31](/VideoSummary/2024/02/01/Ceph_RGW_Refactoring_Meeting_2024-01-31/) 中确定了通过配置选项支持用户和管理员分别设置事件生存时间与最大重试次数，解决消息代理宕机时队列无限增长的问题。
- **非持久化通知改进**：[Ceph RGW Refactoring Meeting 2024-01-03](/VideoSummary/2024/01/05/Ceph_RGW_Refactoring_Meeting_2024-01-03/) 讨论了消息代理不可用时应及时向客户端返回错误，而非静默失败。
- **Topic 授权机制**：[Ceph RGW Refactoring Meeting 2024-01-24](/VideoSummary/2024/01/24/Ceph_RGW_Refactoring_Meeting_2024-01-24/) 引入全局配置参数控制策略检查行为，解决任意用户可覆盖他人 Topic 的安全漏洞，同时保持向后兼容性。
- **Redis 作为消息队列**：[Ceph RGW Refactoring Meeting 2024-03-06](/VideoSummary/2024/03/06/Ceph_RGW_Refactoring_Meeting_2024-03-06/) 提出使用 Redis（基于 Boost Redis 客户端）替换现有持久化通知系统，处于技术探讨阶段。

### NVMe-oF TCP Gateway

[Ceph Developer Monthly 2024-02-07](/VideoSummary/2024/02/13/Ceph_Developer_Monthly_2024-02-07/) 中介绍了 NVMe-oF 在 Ceph 中的高可用性方案，包括 Gateway Group 概念和自动故障转移机制，目标是在未来版本中达到生产就绪状态。

### IAM/STS 账户功能

[Ceph RGW Refactoring Meeting 2024-02-14](/VideoSummary/2024/02/14/Ceph_RGW_Refactoring_Meeting_2024-02-14/) 中账户功能实现基本完成，进入代码审查阶段。同时讨论了 IAM 策略限制（策略长度、角色关联策略数量等），计划对齐 AWS 行为并建立相应约束。

### 对象完整性与多部分上传

RGW 对象完整性功能（Object Integrity）正在开发中，重点覆盖 multipart uploads 的 API 校验，计划在 Squid 代码冻结前完成。

### 端到端追踪（End-to-End Tracing）

[Ceph Developer Monthly 2024-02-07](/VideoSummary/2024/02/13/Ceph_Developer_Monthly_2024-02-07/) 中该功能被确认为 Squid 版本的阻塞项，需要完成测试结果审查后方可放行。

### Crimson OSD 异步架构

[Ceph Code Walkthroughs - Crimson](/VideoSummary/2024/03/06/Ceph_Code_Walkthroughs_-_Crimson/) 深入分析了 Crimson 与经典 OSD 的代码差异：Crimson 基于 Seastar 框架，使用 Futures + Continuation（C++ Lambda）替代同步阻塞模型，客户端请求管道包含地图等待、活动等待等多个阶段，错误处理通过 `erator` 机制处理非严重错误。

### 多站点复制头

[Ceph RGW Refactoring Meeting 2024-02-14](/VideoSummary/2024/02/14/Ceph_RGW_Refactoring_Meeting_2024-02-14/) 引入新的复制头 `X-Replicated-At`，用于多站点负载测试场景，计划作为 Squid 版本的一部分发布。

### S3 对象重复数据检测工具

[Ceph RGW Refactoring Meeting 2024-03-06](/VideoSummary/2024/03/06/Ceph_RGW_Refactoring_Meeting_2024-03-06/) 中 Gabriel 开发了一个检测 S3 对象级别重复数据（DDoP）的工具，部分集群中发现高达 25% 的重复率，社区鼓励广泛测试。

## 4. 社区动态

**月度开发者会议**
2 月 7 日的 [Ceph Developer Monthly](/VideoSummary/2024/02/13/Ceph_Developer_Monthly_2024-02-07/) 涵盖了 NVMe-oF 高可用方案介绍、端到端追踪 PR 审查请求、Monitor 统计输出变更等多个议题，体现了社区在多个技术方向的并行推进。

**用户与开发者联合会议**
[Ceph User + Dev Monthly 2024-01-18](/VideoSummary/2024/01/22/Ceph_User_+_Dev_Monthly_2024-01-18/) 中，国家太阳能天文台（DEIS 项目）的操作员 Joel Davido 提出了磁带存储集成需求，展示了科学计算场景对 Ceph 长期归档能力的实际诉求，推动了相关功能讨论进入社区视野。

**RGW 专项重构会议**
本季度 RGW 重构会议密度较高（1 月 3 日、1 月 24 日、1 月 31 日、2 月 14 日、3 月 6 日），产品团队（Nicholas 等）直接参与技术讨论，体现了 RGW 功能商业化落地的迫切需求。

**Google Summer of Code**
[Ceph RGW Refactoring Meeting 2024-03-06](/VideoSummary/2024/03/06/Ceph_RGW_Refactoring_Meeting_2024-03-06/) 中提及了 Zipper 相关的 GSoC 项目想法征集，鼓励社区成员参与。

**代码走查活动**
Crimson 代码走查会议面向社区开放，帮助开发者理解 Seastar 异步编程模型与经典 OSD 的差异，降低新贡献者的上手门槛。

## 5. 下季度展望

基于本季度讨论内容，预计 2024Q 将重点推进以下方向：

1. **Squid 版本发布**：代码冻结已执行，Q2 将进入 RC 测试和正式发布阶段，端到端追踪、IAM 账户、对象完整性等功能将随版本落地。

2. **RGW 通知系统完善**：Topic 授权、持久化通知 TTL/Max Retry、多站点元数据一致性等 PR 将陆续完成审查合并；Redis 消息队列方案可能进入原型验证阶段。

3. **NVMe-oF 高可用生产就绪**：Gateway Group 和自动故障转移机制将继续完善，目标是在后续版本中达到生产可用状态。

4. **IAM/STS 功能扩展**：账户功能代码审查完成后，IAM 策略限制对齐 AWS 行为的工作将提上日程。

5. **Crimson OSD 持续演进**：基于本季度代码走查的反馈，Crimson 的错误处理和依赖条件管理逻辑将继续优化。

6. **磁带存储集成探索**：功能 Tracker 已建立，Q2 可能开始分解子任务，探索 S3 生命周期管理与 Glacier API 集成的具体实现路径。
