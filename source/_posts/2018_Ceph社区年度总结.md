我将基于这125篇2018年会议和视频总结，生成一份Ceph社区2018年度进展报告。

# Ceph 社区 2018 年度进展报告

---

## 一、全年技术演进概览

2018年是Ceph从成熟走向企业级生产就绪的关键一年。全年技术演进呈现出几条清晰的主线：**存储后端现代化**（BlueStore全面替代FileStore）、**下一代OSD架构探索**（Crimson/SeaStore项目启动）、**管理与编排能力跃升**（Dashboard v2、Orchestrator框架）、以及**性能工程的系统化推进**（每周性能会议持续驱动优化）。

从年初的 Luminous 稳定版维护，到年中 Mimic 版本发布，再到年底 Nautilus 版本的密集开发，2018年的技术节奏紧凑而有序。

---

## 二、重大里程碑

### Mimic 版本发布

2018年5月，Mimic 版本进入发布冲刺阶段。据 [2018-MAY-02 开发者月度会议](2018-MAY-02_-_-Ceph_Developer_Monthly) 记录，Mimic 预计在三到四周内发布，主要特性包括：

- RBD 命名空间支持
- 快照修剪性能改进
- Dashboard 功能增强
- NFS Ganesha 集群化支持

[2018-Apr-19 性能周会](2018-Apr-19_-_Ceph_Performance_Weekly) 记录了 Mimic 版本冻结期间的状态，彼时 ARS 活动较少，团队专注于稳定性验证。

### Nautilus 版本开发启动

年底进入 Nautilus 密集开发期。[2018-12-05 开发者月度会议](/VideoSummary/2018/12/06/2018-12-05_-_-_Ceph_Developer_Monthly/) 记录了 Nautilus 引入的新 Python 模块依赖问题，以及设备故障预测模块的打包方案讨论。[2018-MAY-02 开发者月度会议](/VideoSummary/2018/05/03/2018-MAY-02_-_-_Ceph_Developer_Monthly/) 则更早规划了 Nautilus 的核心方向：

- Messenger v2 协议（含 Kerberos 集成）
- PG 合并（PG Merging）
- REST API 正式化

### Luminous 持续维护

全年多次会议涉及 Luminous 的 backport 工作。[2018-Apr-26 性能周会](/VideoSummary/2018/04/26/2018-Apr-26_-_-_Ceph_Performance_Weekly/) 和 [2018-JAN-04 性能周会](/VideoSummary/2018/01/11/2018-JAN-04_-_-_Ceph_Performance_Weekly/) 均提到将优化补丁回滚至 Luminous 版本的工作。

## 三、核心组件年度进展

### 3.1 BlueStore

BlueStore 是 2018 年投入最密集的组件，全年性能周会几乎每期都有相关议题。

**缓存系统重构**是全年最重要的 BlueStore 工作线。[2018-FEB-22 性能周会](/VideoSummary/2018/02/26/2018-FEB-22_-_-_Ceph_Performance_Weekly/) 深入讨论了 BlueStore 缓存的复杂性问题，提出了移除 BlueStore 缓存、仅使用 RocksDB 缓存的激进方案。[2018-May-17 性能周会](/VideoSummary/2018/05/17/2018-May-17_-_-_Ceph_Performance_Weekly/) 提交了优先级缓存（Priority Cache）的 PR，实现了 BlueStore 与 RocksDB 缓存之间的动态平衡分配。[2018-Jun-21 性能周会](/VideoSummary/2018/06/21/2018-Jun-21_-_-_Ceph_Performance_Weekly/) 进一步讨论了基于 RSS 内存的自动缓存调整方案。

**分配器演进**方面，[2018-May-10 性能周会](/VideoSummary/2018/05/10/2018-May-10_-_-_Ceph_Performance_Weekly/) 详细介绍了新位图分配器（Bitmap Allocator）的设计，在所有测试场景中均优于现有分配器，尤其在随机分配场景下优势明显。[2018-May-17 性能周会](2018-May-17_-_Ceph_Performance_Weekly) 记录了 Igor 的新位图分配器 PR 获得 Sage 审查并计划替换旧代码。

**代码架构解析**方面，社区举办了两期 BlueStore 代码走读：[2018-May-29 BlueStore 代码走读第一部分](/VideoSummary/2018/05/30/2018-May-29_-_-_Ceph_Code_Walkthrough_-_BlueStore_part_1/) 覆盖了 BlueFS、块设备接口、分配器和磁盘结构；[2018-June-26 BlueStore 代码走读第二部分](/VideoSummary/2018/06/27/2018-June-26_-_-_Ceph_Code_Walkthrough_-_BlueStore_part_2/) 深入讲解了缓存机制、事务处理、写入路径和延迟 I/O。

**Tiny Writes优化**在 [2018-08-09 性能周会](/VideoSummary/2018/08/09/2018-08-09_Ceph_Performance_Weekly/) 中被详细讨论，Igor 提出在数据库中直接存储小对象的方案，并展示了性能测试结果。

**大页（Huge Pages）支持**在 [2018-Apr-26 性能周会](/VideoSummary/2018/04/26/2018-Apr-26_-_-_Ceph_Performance_Weekly/) 中被提及，蓝鲸快照功能添加了巨大页面支持以提高性能。

### 3.2 Crimson / SeaStore

2018年是 Crimson（基于 Seastar 框架的下一代 OSD）从概念走向实现的元年。

[2018-JAN-03 开发者月度会议](/VideoSummary/2018/01/04/2018-JAN-03_-_-_Ceph_Developer_Monthly/) 最早记录了 C Store（即后来的 SeaStore）的规划，明确使用 Seastar 框架和 SPDK 库，提供日志结构化存储格式。[2018-Apr-12 性能周会](/VideoSummary/2018/04/12/2018-Apr-12_-_-_Ceph_Performance_Weekly/) 讨论了 C-Store 的对象存储接口和事务协议规划。

[2018-08-23 性能周会](/VideoSummary/2018/08/23/2018-08-23_Ceph_Performance_Weekly/) 记录了 Sage 研究 Seastar 缓冲区实现并与现有编码/解码代码兼容的工作，探讨了将 Seastar 与Ceph 集成的可能性。

[2018-11-20 Crimson/Seastar OSD 会议](/VideoSummary/2018/11/21/2018-11-20_Crimson_Seastar_OSD_Meeting/) 是全年专项会议，讨论了多连接支持、缓冲区列表优化、内存存储测试等具体实现问题，标志着 Crimson 项目进入实质性开发阶段。

### 3.3 RGW（RADOS Gateway）

RGW 在 2018 年的主要进展集中在**多区域同步**和**云存储集成**两个方向。

[2018-MAR-07 开发者月度会议](2018-MAR-07_-_Ceph_Developer_Monthly) 讨论了多区域同步模块的改进，实现了回调机制以确保不遗漏任何更改，以及对象变更日志功能（用于备份系统集成）。

[2018-JUN-06 开发者月度会议](/VideoSummary/2018/06/06/2018-JUN-06_-_-_Ceph_Developer_Monthly/) 讨论了跨云文件系统方案，使用快照和同步机制实现跨云数据备份，将 RGW 作为访问外部存储的网关。

RGW 性能优化方面，[2018-08-09 性能周会](/VideoSummary/2018/08/09/2018-08-09_Ceph_Performance_Weekly/) 讨论了 RGW Up Tracker 的优化合并工作。[2018-FEB-22 性能周会](/VideoSummary/2018/02/26/2018-FEB-22_-_-_Ceph_Performance_Weekly/) 记录了 Assaf 对 RBD 的优化，避免了不必要的内存分配。

### 3.4 CephFS

CephFS 在 2018 年的重要进展是**卷（Volume）抽象**的引入。[2018-08-01 开发者月度会议](/VideoSummary/2018/08/03/2018-08-01_Ceph_Developer_Monthly/) 讨论了将文件系统称为"卷"、子文件系统称为"子卷"的命名规范，以及多个文件系统共享相同数据池的方案。

[2018-JUN-06 开发者月度会议](/VideoSummary/2018/06/06/2018-JUN-06_-_-_Ceph_Developer_Monthly/) 讨论了 NFS Ganesha 集群化方案，使用 Rados 作为存储后端，引入 grace period 机制防止节点重启后状态冲突。

MDS 性能方面，[2018-07-19 性能周会](/VideoSummary/2018/07/19/2018-07-19_Ceph_Performance_Weekly/) 记录了 Greg 提交的优化 MDS 最大导出大小的 PR。[2018-08-01 开发者月度会议](/VideoSummary/2018/08/03/2018-08-01_Ceph_Developer_Monthly/) 提出了收集更多 MDS 性能指标、改进 MDS 缓存机制的计划。

CERN 的大规模 CephFS 实践在 [Ceph Day Germany - Ceph for Big Science](/VideoSummary/2018/02/14/Ceph_Day_Germany_-_Ceph_for_Big_Science/) 中有详细记录，CERN 使用 CephFS 存储物理实验数据，最大集群容量达 5.5PB，反馈了元数据性能和可扩展性方面的改进需求。

### 3.5 Dashboard

Dashboard 是 2018 年社区可见度最高的新特性之一。

[2018-FEB-07 开发者月度会议](/VideoSummary/2018/02/13/2018-FEB-07_-_-_Ceph_Developer_Monthly/) 记录了 Dashboard v2 的开发启动，采用 Angular 2 作为前端框架，CheryPy 作为后端，集成到 Manager 中。

[2018-APR-04 开发者月度会议](/VideoSummary/2018/04/05/2018-APR-04_-_-_Ceph_Developer_Monthly/) 讨论了 Dashboard 的新功能、UI 改进和 API 设计，以及 Ceph Manager Python 接口与各种编排工具的集成。

[Ceph Management and Monitoring with Dashboard v2](Ceph_Management_and_Monitoring_with_Dashboard_v2_-_Lenz_Grimer) 详细介绍了 Dashboard v2 的设计理念，以及从 openATIC 迁移功能的计划，包括 NFS 共享管理（Ganesha）和 iSCSI 目标管理。

[Ceph Day Germany - Ceph Management and Monitoring with openATTIC](/VideoSummary/2018/02/14/Ceph_Day_German_-_Ceph_Management_and_Monitoring_with_openATTIC/) 展示了 openATTIC 工具的现状，以及向 Dashboard整合的路线图。

### 3.6 Messenger v2

Messenger v2 是 Nautilus 的核心特性之一，2018 年全年持续推进。

[2018-FEB-07 开发者月度会议](/VideoSummary/2018/02/13/2018-FEB-07_-_-_Ceph_Developer_Monthly/) 记录了 Messenger v2 的身份验证和传输加密工作，计划使用 GSSAPI 支持 Kerberos 和其他认证协议。

[2018-NOV-07 开发者月度会议](/VideoSummary/2018/11/14/2018-NOV-07_-_-_Ceph_Developer_Monthly/) 讨论了协议 V2 的实现、地址端点管理和加密，以及与现有 Ceph 版本的兼容性问题。

[2018-08-16 性能周会](/VideoSummary/2018/09/06/2018-08-16_Ceph_Performance_Weekly/) 讨论了 Messenger 协议优化及与操作员的接口兼容性问题。

### 3.7 OSD 性能工程

2018 年的 OSD 性能工程工作量极大，每周性能会议持续推进。

**内存管理**是全年最重要的优化方向。[2018-FEB-15 性能周会](2018-FEB-15_-_Ceph_Performance_Weekly) 发现 PG log 对CPU 消耗影响显著，提出使用 PG ring bufers 优化。[2018-Jun-28 性能周会](/VideoSummary/2018/06/28/2018-Jun-28_-_-_Ceph_Performance_Weekly/) 系统比较了不同内存分配器（TC malloc、J malloc、libc malloc）的性能，决定继续使用 TC malloc 或 J malloc。

**PG 日志优化**贯穿全年。[2018-MAR-01 性能周会](2018-MAR-01_-_Ceph_Performance_Weekly) 讨论了 RocksDB 元数据空间占用与对象数量的关系，以及动态调整缓存大小的方案。

**OSD Peering机制**在 [2018-10-23 代码走读](2018-10-23_-_Ceph_Code_walk-through_-_Consistency_with_OSD_Peering) 中得到系统讲解，深入分析了基于 Boost State Chart 的状态机实现。

**同步读取**方面，[2018-FEB-01 性能周会](2018-FEB-01_-_Ceph_Performance_Weekly) 讨论了 Blue Store 同步读取支持的大型 PR，以及 OSD 同步基础设施的性能问题。[2018-08-01 开发者月度会议](/VideoSummary/2018/08/03/2018-08-01_Ceph_Developer_Monthly/) 提出将 PG 锁从互斥锁改为读写锁以实现同步读取。

### 3.8 Orchestrator 框架

[2018-12-05 开发者月度会议](/VideoSummary/2018/12/06/2018-12-05_-_-_Ceph_Developer_Monthly/) 和 [2018-NOV-07 开发者月度会议](/VideoSummary/2018/11/14/2018-NOV-07_-_-_Ceph_Developer_Monthly/) 均讨论了 Orchestrator 模块的进展，包括与 Ansible、DepSea 等工具的集成，以及设备状态跟踪和健康警报功能。

[Ceph Day Germany - Development update Ceph mgr and Kubernetes](/VideoSummary/2018/02/14/Ceph_Day_Germany_-_Development_update_Ceph_mgr_and_Kubernetes/) 详细介绍了 CephCO（Ceph 容器编排工具）与 Kubernetes 的集成方案，以及 Brook 框架的设计。

## 五、关键技术趋势

### 性能工程系统化

2018 年最显著的社区变化是**性能工程的系统化**。每周性能会议（Performance Weekly）全年持续举行，形成了稳定的 PR 审查、性能测试、问题讨论的工作节奏。全年性能优化覆盖：

- **内存分配器**：TC malloc vs J malloc vs libc malloc 的系统比较
- **RocksDB 调优**：缓存大小、Bloom 过滤器、压缩策略
- **加密加速**：QAT（Quick Assist Technology）、OpenSSL、AES 硬件加速
- **网络层**：VP 集成探索、Messenger 协议优化、ASIO 异步库引入
- **CPU 安全补丁影响**：Spectre 漏洞对 Intel 处理器性能的影响评估（[2018-JAN-18 性能周会](/VideoSummary/2018/01/20/2018-JAN-18_-_-_Ceph_Performance_Weekly/)）

### 容器化与云原生

Rook 的崛起和 Kubernetes 集成是 2018 年最重要的生态趋势。[2018-08-22 测试周会](/VideoSummary/2018/08/23/2018-08-22_Ceph_Testing_Weekly/) 讨论了在容器化环境下重构测试策略的必要性，[Ceph Day Germany - Development update Ceph mgr and Kubernetes](/VideoSummary/2018/02/14/Ceph_Day_Germany_-_Development_update_Ceph_mgr_and_Kubernetes/) 展示了 CephCO 的容器编排能力。

### 智能运维

[2018-JUN-06 开发者月度会议](/VideoSummary/2018/06/06/2018-JUN-06_-_-_Ceph_Developer_Monthly/) 和 [2018-12-05 开发者月度会议](/VideoSummary/2018/12/06/2018-12-05_-_-_Ceph_Developer_Monthly/) 均讨论了设备故障预测模块，通过收集 SMART 指标、与 Wisconsin 大学合作构建开源故障数据集，推动 Ceph 向智能运维方向演进。

## 六、2019 年展望

基于 2018 年的讨论和规划，可以推断 2019 年（Nautilus 发布年）的主要方向：

1. **Nautilus 正式发布**：Messenger v2（含加密和 Kerberos）、PG 合并、Dashboard REST API GA、Orchestrator 框架正式化

2. **Crimson/SeaStore 持续推进**：基于 Seastar 的新 OSD 架构将进入更广泛的测试阶段，[2018-11-20 Crimson 专项会议](/VideoSummary/2018/11/21/2018-11-20_Crimson_Seastar_OSD_Meeting/) 奠定了基础

3. **BlueStore 缓存自动调优 GA**：优先级缓存和自动调优机制将在 Nautilus 中正式落地

4. **Rook 生产就绪**：Rook 将支持 CSI 插件，实现与更多编排器的集成

5. **智能设备管理**：设备故障预测模块将随 Nautilus 发布，推动 Ceph 向自愈存储演进

6. **Dashboard 功能完善**：NFS、iSCSI 管理功能从 openATTIC 迁移完成，Dashboard 成为统一管理入口
