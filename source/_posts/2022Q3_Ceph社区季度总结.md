# Ceph 社区 2022Q3 季度进展报告

---

## 1. 本季度重点议题

本季度 Ceph 社区的讨论集中在以下几个核心方向：

**Crimson/SeaStore 新一代存储引擎**
多核架构（multi-core）推进是本季度最持续的议题，贯穿整个季度的 Crimson/SeaStore 会议。ZNS（Zone Namespace）设备支持、垃圾回收（GC）优化、对象存储改进均有实质性进展。详见 [Ceph_Crimson_SeaStore_Meeting_2022-07-06](/VideoSummary/2022/07/19/Ceph_Crimson_SeaStore_Meeting_2022-07-06/) 和 [Crimson_SeaStore_Meeting_2022-07-13](/VideoSummary/2022/07/19/Crimson_SeaStore_Meeting_2022-07-13/)。

**BlueStore 性能优化**
共享 Blob 的性能问题、RocksDB 写放大、Tombstone 行为优化是 Performance Meeting 的核心议题，持续讨论了整个季度。详见 [Ceph_Performance_Meeting_2022-09-15](/VideoSummary/2022/09/21/Ceph_Performance_Meeting_2022-09-15/) 和 [Ceph_Performance_Meeting_2022-07-28](/VideoSummary/2022/07/29/Ceph_Performance_Meeting_2022-07-28/)。

**Orchestrator 与部署管理**
NFS HA 部署、RGW Multi-Site 配置自动化、cephadm 二进制分发是 Orchestrator 会议的主线。

**RGW 模块化与性能计数器**
RGW 模块化进程和性能指标管理的可扩展性问题在季度末集中讨论。

---

## 2. 技术亮点

### Crimson/SeaStore

- **ZNS 驱动开发**：Aravind 提交了 ZNS 驱动的多个补丁，解决了 Zone 关闭后磁盘无法重新打开的问题，并修改 ZNS 管理器在写入时填充空间以避免容量浪费。详见 [Ceph_Crimson_SeaStore_Meeting_2022-07-06](/VideoSummary/2022/07/19/Ceph_Crimson_SeaStore_Meeting_2022-07-06/)。
- **多核分支推进**：第二个多核 PR 在 7 月中旬完成，第三个随即启动。iOS 相关功能在 9 月完成。详见 [Crimson_SeaStore_Meeting_2022-07-13](/VideoSummary/2022/07/19/Crimson_SeaStore_Meeting_2022-07-13/)。
- **SMR 硬盘支持探索**：提出为 SMR（叠瓦式磁记录）硬盘创建专用段管理器（Segment Manager）的方向。
- **GC 优化**：Jinyu 提出在 GC 事务中增加判断逻辑，避免将不满足时间局部性原则的 extent 加入 Aerial，减少无效 GC 开销。
- **omap 范围移除优化**：9 月会议讨论了存储节点负载、内存拷贝效率和树状结构平衡的改进。详见 [Ceph_Crimson_Seastore_Meeting_2022-09-23](/VideoSummary/2022/09/23/Ceph_Crimson_Seastore_Meeting_2022-09-23/)。

### BlueStore / RocksDB

- **共享 Blob 重构**：Adam 提出单一实例跟踪器（single instance tracker）方案，通过统一管理所有对象分配来减少共享 Blob 实例数量，实测显著降低 CPU 使用率和写入负载。详见 [Ceph_Performance_Meeting_2022-09-22](/VideoSummary/2022/09/26/Ceph_Performance_Meeting_2022-09-22/)。
- **RocksDB 写放大优化**：开发了按列族（column family）跟踪删除操作、达到阈值后手动触发 compaction 和 flush 的机制，以改善 Tombstone 行为。详见 [Ceph_Performance_Meeting_2022-07-28](/VideoSummary/2022/07/29/Ceph_Performance_Meeting_2022-07-28/)。
- **BlueStore Zero Block Detection**：分析了该特性在 Quincy 17.2.1 中被默认关闭后导致的性能回退问题，Laura 与 DFG 存储团队跟进 17.2.0 与 17.2.1 的性能差异。详见 [Ceph_Performance_Meeting_2022-07-14](/VideoSummary/2022/07/19/Ceph_Performance_Meeting_2022-07-14/)。
- **Snap Map 性能**：讨论了频繁创建快照导致 RBD 镜像性能下降的问题，计划设计专项测试验证。

### Orchestrator / cephadm

- **NFS HA 部署**：Adam 提交了通过虚拟 IP 地址启动 NFS 守护进程的 PR，并与 Manila 团队协调故障转移场景测试。详见 [Ceph_Orchestrator_2022-08-09](/VideoSummary/2022/08/09/Ceph_Orchestrator_2022-08-09/)。
- **RGW Multi-Site 配置自动化**：Sebastian 提出在 cephadm 中引入 `kind` 关键字层级结构，统一 `rgw_spec` 等规范类，实现多站点配置的原子化部署（全成功或回滚）。详见 [Ceph_Orchestrator_Meeting_2022-08-16](/VideoSummary/2022/08/17/Ceph_Orchestrator_Meeting_2022-08-16/)。
- **网络过滤（fb filtering）优化**：放宽子网匹配规则，引入 Python `ipaddress` 库进行子网匹配检查。详见 [Ceph_Orchestrator_Meeting_2022-07-12](/VideoSummary/2022/07/19/Ceph_Orchestrator_Meeting_2022-07-12/)。
- **日志级别配置**：讨论了为 cephadm 二进制程序提供可配置日志级别的方案，以减少默认 debug 级别产生的冗余日志。

### RGW

- **性能计数器管理**：讨论了标签化性能计数器（labeled perf counters）的可扩展性问题，提出"热用户/热存储桶"自动化策略，动态启用相关计数器，避免 Prometheus 端指标爆炸。详见 [RGW_Refactoring_Meeting_2022-09-28](/VideoSummary/2022/09/29/RGW_Refactoring_Meeting_2022-09-28/)。
- **HTTP/3 前端原型**：Ronan 提到 RGW HTTP/3 前端的开发进展，开放社区成员参与测试。

### 测试基础设施

- **Teuthology 错误检测改进**：实习生项目实现了自动扫描日志文件、精确记录单元测试失败信息的功能，替代原有的模糊错误码，以可选方式集成。详见 [Ceph_Tech_Talk_-_Making_Teuthology_a_Better_Detective](/VideoSummary/2022/09/28/Ceph_Tech_Talk_-_Making_Teuthology_a_Better_Detective/)。
- **测试矩阵动态控制**：Patrick 的PR 通过脚本动态控制测试矩阵中的片段合并，提高测试灵活性，已合并。详见 [Ceph_Developer_Monthly_2022-08-03](/VideoSummary/2022/08/05/Ceph_Developer_Monthly_2022-08-03/)。

## 3. 重要决策与里程碑

- **Ceph 发布流程现代化**：签名机器从 OCTA 实验室迁移至 sepia 实验室，GPG 密钥转移至硬件安全令牌（HSM），允许非 Red Hat 成员参与发布流程，降低社区贡献门槛。详见 [Walkthrough_-_Ceph_Release_Process](/VideoSummary/2022/09/28/Walkthrough_-_Ceph_Release_Process/)。
- **Reef 分支准备**：更新 chakra 节点并重新部署 shock，为 Reef 主版本发布做基础设施准备。
- **cephadm 二进制分发**：确认 daily build 和 RPM 包可用，推进解决签名问题，通过社区邮件寻求协助。详见 [Ceph_Orchestrator_Meeting_2022-09-27](/VideoSummary/2022/09/29/Ceph_Orchestrator_Meeting_2022-09-27/)。
- **管理标签（admin label）机制**：确定使用哈希文件管理 `ceph.conf` 和 admin keyring 的部署与移除，避免误删非 cephadm 管理的文件。详见 [Ceph_Orchestrator_2022-07-26](/VideoSummary/2022/08/01/Ceph_Orchestrator_2022-07-26/)。
- **性能计数器允许列表（allowlist）**：决定开发 PoC 验证通过允许列表控制哪些性能计数器上报给 Manager，以减少 Manager 负载。详见 [Ceph_Developer_Monthly_2022-08-03](/VideoSummary/2022/08/05/Ceph_Developer_Monthly_2022-08-03/)。
- **PG Log Dupe Ops内存问题修复**：确定在 OSD 重启时分批修剪（每次 10,000 条）损坏 Dupe 条目的方案，防止无限积累。详见 [Ceph_Performance_Meeting_2022-07-14](/VideoSummary/2022/07/19/Ceph_Performance_Meeting_2022-07-14/)。

## 4. 社区动态

- **Grace Hopper Open Source Day 准备**：社区成员被鼓励标记或新建 "good first issue"，为即将到来的 Grace Hopper 活动吸引新贡献者。详见 [Ceph_Developer_Monthly_2022-08-03](/VideoSummary/2022/08/05/Ceph_Developer_Monthly_2022-08-03/)。
- **实习生项目**：本季度有实习生参与 Teuthology 改进项目，并在 Ceph Tech Talk 上公开展示成果，体现了社区对新贡献者的培养。详见 [Ceph_Tech_Talk_-_Making_Teuthology_a_Better_Detective](/VideoSummary/2022/09/28/Ceph_Tech_Talk_-_Making_Teuthology_a_Better_Detective/)。
- **Orchestrator 测试覆盖率专项**：9 月会议专门讨论了 `video.py` 等文件的测试覆盖率提升计划，通过 Etherpad 协作分工，推动测试质量改善。详见 [Ceph_Orchestrator_Meeting_2022-09-20](/VideoSummary/2022/09/21/Ceph_Orchestrator_Meeting_2022-09-20/)。
- **会议记录归档**：讨论了对长期项目会议记录进行定期归档的必要性，以保持文档可管理性。详见 [Ceph_Orchestrator_2022-07-26](/VideoSummary/2022/08/01/Ceph_Orchestrator_2022-07-26/)。
- **跨团队协作**：Orchestrator 团队与 OpenStack Manila 团队就 NFS 故障转移测试建立了定期协作机制；Performance 团队与 DFG 存储团队联合排查 BlueStore 性能回退问题。

## 5. 下季度展望

基于本季度的讨论方向，预计 2022Q4 将重点推进以下工作：

1. **Crimson/SeaStore 多核稳定化**：多核分支的后续 PR 将陆续提交，ZNS 设备上的 GC 问题需要持续调试，HDD 和 SMR 硬盘支持方案将进入设计阶段。
2. **BlueStore 共享 Blob 重构落地**：Adam 的单一实例跟踪器方案和 Mark 的碎片整理方案将进入性能测试和代码审查阶段，预计对 RBD 快照密集场景有显著改善。
3. **RGW Multi-Site 自动化部署**：Sebastian 的 `kind` 关键字方案将进入后端实现阶段，前端展示方式待后端完成后确定。
4. **Reef 发布准备**：基础设施迁移和 cephadm 二进制签名问题的解决将为 Reef 版本发布铺路。
5. **性能计数器架构改进**：RGW 标签化计数器工具和 Manager 允许列表 PoC 将进入验证阶段，长期可能需要构建动态启停计数器的新机制。
6. **测试基础设施持续改善**：Teuthology 错误检测功能将扩展到更多测试类型，Orchestrator 测试覆盖率专项将持续推进。
