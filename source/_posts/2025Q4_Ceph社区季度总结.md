# 2025Q4 Ceph 社区季度进展报告

## 一、本季度重点议题

2025Q4 是 Ceph 社区极为活跃的一个季度，以下技术方向在多篇材料中反复出现：

**1. Tentacle 版本发布冲刺**

Tentacle 是本季度最核心的主线。多个 RGW 重构会议（[Ceph_RGW_Refactoring_Meeting_2025-10-15](/VideoSummary/2025/10/15/Ceph_RGW_Refactoring_Meeting_2025-10-15/)、[Ceph_RGW_Refactoring_Meeting_2025-10-08](/VideoSummary/2025/10/15/Ceph_RGW_Refactoring_Meeting_2025-10-08/)）均围绕 Tentacle 发布阻塞问题展开讨论，包括 replication lifecycle bug的处置策略、S3 测试迁移、以及 release notes 的完善。

**2. RGW 架构重构与扩展性**

RGW 的 Bucket Index扩展性、BI Log 与FIFO 后端分离、SSE 复制支持、DUP 功能改进等议题贯穿整个季度，在多次 RGW 重构会议中持续推进（[Ceph_RGW_Refactoring_Meeting_2025-11-05](/VideoSummary/2025/12/03/Ceph_RGW_Refactoring_Meeting_2025-11-05/)、[Ceph_RGW_Refactoring_Meeting_2025-11-19](/VideoSummary/2025/12/03/Ceph_RGW_Refactoring_Meeting_2025-11-19/)、[Ceph_RGW_Refactoring_Meeting_2025-12-10](/VideoSummary/2025/12/10/Ceph_RGW_Refactoring_Meeting_2025-12-10/)）。

**3. BlueStore 性能与存储效率优化**

BlueStore 的压缩改进、RocksDB WAL 格式重构、Onode 元数据重构、碎片化问题等是本季度存储引擎层面的核心议题（[BlueStore_Faster_+_Smaller_=_Better_-_Adam_Kupczyk_BM](/VideoSummary/2025/11/19/BlueStore_Faster_+_Smaller_=_Better_-_Adam_Kupczyk_BM/)、[Fragmentation_in_Ceph_-_Why_It_Happens_and_How_We_Fix_It_-_Mark_NelsonClyso](/VideoSummary/2025/11/19/Fragmentation_in_Ceph_-_Why_It_Happens_and_How_We_Fix_It_-_Mark_Nelson_Clyso/)）。

**4. Erasure Coding 性能提升（Fast EC）**

Fast EC 在 Tentacle 版本中的落地及 Umbrella 版本的规划是本季度的重要技术亮点，涉及读写路径优化、Direct Reads、Pool Migration 等方向（[Inking_OutInefficiencies_in_Ceph_Erasure_Coding_-_Alex_Ainscow_Bill_ScalesIBM](/VideoSummary/2025/11/19/Inking_Out_Inefficiencies_in_Ceph_Erasure_Coding_-_Alex_Ainscow_Bill_Scales_IBM/)）。

**5. 大规模生产运维与可观测性**

DigitalOcean、CERN、Bloomberg、LINE 等大型用户分享了各自的 Ceph 运维实践，可观测性工具、自动化运维、性能调优是共同关注点（[Ceph_Operations_at_Scale_-_Matt_Vandermeulen_DigitalOcean](/VideoSummary/2025/11/19/Ceph_Operations_at_Scale_-_Matt_Vandermeulen_DigitalOcean/)、[Enhancing_Ceph_Monitoring_atCERN_-_Our_Approach_and_Solutions-_R._Valverde_Cameselle_E._Bochi](/VideoSummary/2025/11/19/Enhancing_Ceph_Monitoring_at_CERN_-_Our_Approach_and_Solutions_-_R._Valverde_Cameselle_E._Bocchi/)）。

## 二、技术亮点

### 2.1 BlueStore 多项核心优化

[BlueStore_Faster_+_Smaller_=_Better_-_Adam_Kupczyk_BM](/VideoSummary/2025/11/19/BlueStore_Faster_+_Smaller_=_Better_-_Adam_Kupczyk_BM/) 中，Adam Kupczyk 系统介绍了多项改进：

- **压缩效率**：针对 RBD 场景频繁覆写导致的压缩效率损失，新方案可挽回 10-15% 的容量损失
- **RocksDB WAL 格式重构**：合并 IO 操作，降低 10-15% 延迟，修复内存对齐问题
- **Onode 元数据重构**：采用 C++ polymorphic allocators，消除 blob 独立存在性，减少锁竞争
- **并行化崩溃恢复**：完全重写恢复机制，支持多线程加速，可达 60倍提速
- **Discard 操作增强**：实现多线程支持并新增监控指标

### 2.2 Fast EC 性能突破

[Inking_Out_Inefficiencies_in_Ceph_Erasure_Coding_-_Alex_Ainscow_Bill_Scales_IBM](/VideoSummary/2025/11/19/Inking_Out_Inefficiencies_in_Ceph_Erasure_Coding_-_Alex_Ainscow_Bill_Scales_IBM/) 展示了 Fast EC 的实测结果：

- 小块读取 IOPS 提升 3 倍，接近 Replica 50% 性能
- 小块写入延迟显著降低，效率提升 2-3 倍
- 性能不受 K值影响，解决了传统 EC 的扩展性瓶颈
- Umbrella 版本规划：Direct Reads（读性能与 Replica 持平）、非破坏式 Pool Migration、小对象打包

### 2.3 RGW 对象存储路线图

[Ceph_Object_Storage_Roadmap_Session_at_Cephalocon_2025_-_Daniel_Parkes_Matthew_Benjamin_IBM](/VideoSummary/2025/11/19/Ceph_Object_Storage_Roadmap_Session_at_Cephalocon_2025_-_Daniel_Parkes_Matthew_Benjamin_IBM/) 明确了 Tentacle 版本的 RGW 重点方向：

- **Bucket 索引扩展性**：重构 Bucket 索引结构以支持 10 亿级对象规模
- **IAM/STS 增强**：客户托管策略、S3 Public Access Block
- **D4N 缓存（下一代）**：读写加速、智能预取
- **S3 Vector API**：支持向量数据库的索引与查询
- **Lakehouse 支持**：强化与 Iceberg 等开放表格式的集成

### 2.4 RGW Bucket Snapshots

[Ceph_RGW_Bucket_Snapshots_-_Beyond_Versioning_-_Yehuda_Sadeh_Weinraub_Ubiquiti](/VideoSummary/2025/11/19/Ceph_RGW_Bucket_Snapshots_-_Beyond_Versioning_-_Yehuda_Sadeh_Weinraub_Ubiquiti/) 介绍了超越 S3 Object Versioning 的 Bucket 级快照功能：

- 扩展 Object Versioning，引入 snapID 作为新维度
- 支持创建、删除、列出快照，并访问历史快照中的对象数据
- 新增 `snap_id`、`snap_range` 等 S3 API 参数
- 当前为 Zone-local 功能，快照不跨 Zone 同步

### 2.5 CephFS 新特性（Tentacle/Umbrella）

[A_Harbor-side_Chat_on_CephFS_-_Patrick_Donnelly_IBM](/VideoSummary/2025/11/19/A_Harbor-side_Chat_on_CephFS_-_Patrick_Donnelly_IBM/) 介绍了两个版本的 CephFS 新功能：

- **Tentacle**：Case Insensitive Subtree 支持（优化 Samba 性能）、File Block Diff API、MDS Journal Replay进度监控、灾难恢复配置项增强
- **Umbrella**：Per-Subvol Metrics（通过 Prometheus 监控每个 Subvol 的 IO 指标）、用户态 FScrypt 支持（兼容 Samba/NFS Ganesha）

### 2.6 eBPF 性能追踪工具

[Efficient_Ceph_Performance_Troubleshooting_in_Production_Using_eBPF_-_Dongdong_Tao_Canonical](/VideoSummary/2025/11/19/Efficient_Ceph_Performance_Troubleshooting_in_Production_Using_eBPF_-_Dongdong_Tao_Canonical/) 展示了基于 eBPF 的 Ceph Safe Trace 工具集：

- OSD Trace：追踪 OSD 进程，输出每个 IO 操作的详细生命周期延迟
- Rados Trace：追踪任意 librados-based 客户端（VM、Cinder、RGW 等）
- 支持容器化 cephadm 部署，无需安装调试符号，最低内核版本 5.8

### 2.7 3AZ Stretch Cluster 网络分裂解决方案

[Detect_Decide_Fence_-_Resolving_Netsplits_in_3-AZ_Stretch_Cluster_-_Kamoltat_Junior_Sirivadhna](/VideoSummary/2025/11/19/Detect_Decide_Fence_-_Resolving_Netsplits_in_3-AZ_Stretch_Cluster_-_Kamoltat_Junior_Sirivadhna/) 提出了完整的网络分裂检测与隔离方案：

- 利用 monitor 间connection scores 构建连接图，识别断开的数据中心
- BK 算法选择最优幸存 DC clique，优先级基于 OSD 总权重、存活 monitor 数量等
- 支持动态切换隔离目标，并设置 `switch_fence_threshold` 防止频繁切换

### 2.8 高密度 NVMe 与 CRUSH 算法扩容

[Demystifying_Hyper-Dense_Ceph_-_How_To_Design_for_Large_Capacity_NVMe_-_A._Goncalves_M._Nelson](/VideoSummary/2025/11/19/Demystifying_Hyper-Dense_Ceph_-_How_To_Design_for_Large_Capacity_NVMe_-_A._Goncalves_M._Nelson/) 讨论了高容量 NVMe（30TB-100TB）场景下的关键改进：

- CRUSH 算法已修复 65PB 集群总容量限制
- 正在处理单设备 100TB 限制
- BlueStore 自动检测 `optimal_io_size` 并设置合理上限的 PR 推进中

### 2.9 分布式限速服务开源

[An_Open_Source_Distributed_Rate-limiting_Service_for_Ceph-object_and_Other_HTTP_APIs-_Jacques_Heunis](/VideoSummary/2025/11/19/An_Open_Source_Distributed_Rate-limiting_Service_for_Ceph-object_and_Other_HTTP_APIs-_Jacques_Heunis/) 中，Bloomberg 开源了基于 HAProxy + Lua 的 RGW 分布式限速系统（we QoS），支持请求速率、带宽、并发请求三维度控制，协议无关，支持热更新。

### 2.10 RADOS Native Indexing 概念探讨

[Could_Ceph_Become_More_Like_a_Database_-_Radoslaw_Zarzynski_IBM](/VideoSummary/2025/11/19/Could_Ceph_Become_More_Like_a_Database_-_Radoslaw_Zarzynski_IBM/) 提出了利用 BlueStore 底层统一 RocksDB keyspace 实现原生索引的概念，潜在应用包括简化 RGW Bucket Index 维护、优化 CephFS 目录遍历，目前处于早期概念阶段。

## 三、重要决策与里程碑

### 3.1 Tentacle 版本发布

本季度最重要的里程碑是 Tentacle 版本的发布推进。[Ceph_RGW_Refactoring_Meeting_2025-10-15](/VideoSummary/2025/10/15/Ceph_RGW_Refactoring_Meeting_2025-10-15/) 明确了对 replication lifecycle 相关 bug 的处置策略：**不阻塞 Tentacle 发布**，在 release notes 中标注已知问题，严重修复通过标准 backport 流程进入后续点版本。

### 3.2 S3 测试迁移至 Ceph 主仓库

[Ceph_RGW_Refactoring_Meeting_2025-10-08](/VideoSummary/2025/10/15/Ceph_RGW_Refactoring_Meeting_2025-10-08/) 决定将独立的 S3 测试仓库迁移至 Ceph 主仓库，以简化 QA 流程，统一管理。Adam 已提供 POC 验证可行性。

### 3.3 Boto2 依赖移除

同一会议中决定移除 S3 测试中的 `boto2` 依赖（新版 Python 不再支持），并评估使用 Fuzing 替代手工构造的无效请求测试。

### 3.4 AI 生成代码政策讨论

[Ceph_RGW_Refactoring_Meeting_2025-10-22](/VideoSummary/2025/10/23/Ceph_RGW_Refactoring_Meeting_2025-10-22/) 中，IBM 新政策允许在开源项目中使用 AI 生成代码，但需满足特定条件。Dan 计划在 Ceph Steering Committee 推动讨论，由基金会最终决策。这是社区首次正式讨论 AI 生成代码的贡献政策。

### 3.5 EC Direct Reads 安全性改进

[Ceph_Developer_Monthly_December_2025_Made_with_Clipchamp](/VideoSummary/2025/12/04/Ceph_Developer_Monthly_December_2025_Made_with_Clipchamp/) 中，社区就 EC Direct Reads 的Exec 操作安全性达成共识：通过 OSD 端强制检查 + C++ API 安全改造，废弃不安全的旧接口，同时保留 C API兼容性。

### 3.6 RGW BI Log 重构方向确定

[Ceph_RGW_Refactoring_Meeting_2025-11-05](/VideoSummary/2025/12/03/Ceph_RGW_Refactoring_Meeting_2025-11-05/) 初步确定采用单 FIFO 设计分离 BI Log 与 Bucket Index，优先验证同步逻辑，后续逐步启用异步优化。

### 3.7 GSoC 2025 成果合并

[Ceph_Community_Google_Summer_of_Code_2025_Intern_Showcase](/VideoSummary/2025/10/09/Ceph_Community_Google_Summer_of_Code_2025_Intern_Showcase/) 展示了四个 GSoC 项目成果，其中 RGW 持久化桶通知分片优化已合并到上游，RGW API 模糊测试框架发现了 AMZ copy source 头为空时导致 RGW 崩溃的关键漏洞。

## 五、下季度展望

基于本季度的讨论，2026Q1 预计将聚焦以下方向：

**1. Tentacle 版本稳定化与 Umbrella 版本启动**

Tentacle 发布后，社区将进入 Umbrella 版本的规划与开发阶段。CephFS 审计日志（auditman）、Fast EC Direct Reads、Per-Subvol Metrics 等功能预计在 Umbrella 版本推进（[CephFS_Tell-Me-What-Happened_--Yes-I-Really-ReallyMean-It_-_Anthony_D_Atri_IBM](/VideoSummary/2025/11/19/CephFS_Tell-Me-What-Happened_--Yes-I-Really-Really-Mean-It_-_Anthony_D_Atri_IBM/)）。

**2. RGW BI Log FIFO 后端落地**

[Ceph_RGW_Refactoring_Meeting_2025-11-05](/VideoSummary/2025/12/03/Ceph_RGW_Refactoring_Meeting_2025-11-05/) 中确定的 BI Log 与 Bucket Index 分离方案将进入实现阶段，重点验证同步逻辑并逐步启用异步优化。

**3. Bucket 索引重构**

支持 10 亿级对象规模的 Bucket 索引重构是 Tentacle 版本的核心目标，预计在 2026Q1 进入关键实现阶段（[Ceph_Object_Storage_Roadmap_Session_at_Cephalocon_2025_-_Daniel_Parkes_Matthew_Benjamin_IBM](/VideoSummary/2025/11/19/Ceph_Object_Storage_Roadmap_Session_at_Cephalocon_2025_-_Daniel_Parkes_Matthew_Benjamin_IBM/)）。

**4. AI 生成代码政策落地**

Ceph Steering Committee 将就 AI 生成代码的贡献政策进行正式讨论，结果将影响整个社区的贡献规范。

**5. BlueStore 碎片整理与 Deep Scrub 集成**

[Fragmentation_in_Ceph_-_Why_It_Happens_and_How_We_Fix_It_-_Mark_Nelson_Clyso](/VideoSummary/2025/11/19/Fragmentation_in_Ceph_-_Why_It_Happens_and_How_We_Fix_It_-_Mark_Nelson_Clyso/) 中提出的 Deep Scrub 整合碎片整理方案，以及 Elastic Shared Blobs 的推广，预计在下季度加速推进。

**6. 3AZ Stretch Cluster 网络分裂方案集成**

[Detect_Decide_Fence_-_Resolving_Netsplits_in_3-AZ_Stretch_Cluster_-_Kamoltat_Junior_Sirivadhna](/VideoSummary/2025/11/19/Detect_Decide_Fence_-_Resolving_Netsplits_in_3-AZ_Stretch_Cluster_-_Kamoltat_Junior_Sirivadhna/) 中的方案将推进代码集成至 Ceph 主线，并完善 RGW 集成以支持客户端请求路由到幸存 DC。

**7. 高密度 NVMe 支持完善**

自动检测 `optimal_io_size` 的 PR 合并、单设备 100TB 限制修复，以及高密度 NVMe 场景下的 Erasure Coding 最佳实践文档化，预计在下季度完成（[Demystifying_Hyper-Dense_Ceph_-_How_To_Design_for_Large_Capacity_NVMe_-_A._Goncalves_M._Nelson](/VideoSummary/2025/11/19/Demystifying_Hyper-Dense_Ceph_-_How_To_Design_for_Large_Capacity_NVMe_-_A._Goncalves_M._Nelson/)）。

**8. 性能测试标准化**

CBT（Ceph Benchmarking Tool）将继续完善，目标成为社区标准化性能评估工具，并建立公共 GitHub 仓库收集社区性能数据（[Ceph_Performance_-_The_Basics_of_Tentacle_Racing_-_Lee_Sanders_IBMUK](/VideoSummary/2025/11/19/Ceph_Performance_-_The_Basics_of_Tentacle_Racing_-_Lee_Sanders_IBM_UK/)）。
