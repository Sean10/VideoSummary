# Ceph 社区季度进展报告 · 2014 Q2

---

## 1. 本季度重点议题

本季度的 Ceph Developer Summit（CDS）集中讨论了以下几个反复出现的核心技术方向：

**OSD 后端与存储引擎演进**
OSD 后端架构是本季度讨论最密集的议题。从 FileStore 向新型键值存储后端迁移（RocksDB、Kinetic Drive）的路线图被多次提及，详见 [CDS_G_H_Day_1_-_OSD_review](/VideoSummary/2014/06/24/CDS_G_H_Day_1_-_OSD_review/)。

**Erasure Coding 完善**
Erasure Coding 插件生态的完善贯穿整个季度，包括本地可修复代码（LRC）提案、ISA 插件原型、ARM 平台性能问题，详见 [CDS_G_H_Day_1_-_Erasure_Coding_Update](/VideoSummary/2014/06/24/CDS_G_H_Day_1_-_Erasure_Coding_Update/) 和 [CDS_G_H_Day_1_-_OSD_-_Locally_Repairable_Codes](/VideoSummary/2014/06/24/CDS_G_H_Day_1_-_OSD_-_Locally_Repairable_Codes/)。

**RBD 功能扩展**
RBD 的异步复制/日志记录、对象索引（object map）、数据库工作负载优化等方向均有专题讨论，详见 [CDS_G_H_Day_1_-_RBD_review](/VideoSummary/2014/06/24/CDS_G_H_Day_1_-_RBD_review/)。

**CI/CD 与测试基础设施**
Teuthology 路线图和 CI流程改进是本季度的基础设施重点，详见 [CDS_G_H_Day_1_-_CI_Teuthology_Roadmap](/VideoSummary/2014/06/24/CDS_G_H_Day_1_-_CI_Teuthology_Roadmap/)。

**Calamari 管理平台**
Calamari 的功能开发、本地化和部署简化在多个会议中被讨论，详见 [CDS_G_H_Day_1_-_Calamari_Intro](/VideoSummary/2014/06/24/CDS_G_H_Day_1_-_Calamari_Intro/) 和 [CDS_G_H_Day_2_-_Calamari_Localization](/VideoSummary/2014/06/26/CDS_G_H_Day_2_-_Calamari_Localization/)。

## 2. 技术亮点

### OSD 后端

- **RocksDB 后端**：针对 SD 优化的 RocksDB 键值存储后端开发接近完成，预计很快合并到主分支。相比 LevelDB，RocksDB 在并行压缩和读取方面具有明显性能优势。详见 [CDS_G_H_Day_1_-_OSD_review](/VideoSummary/2014/06/24/CDS_G_H_Day_1_-_OSD_review/)。
- **Kinetic Drive 支持**：探索了对具有以太网接口的 Kinetic Drive 的原生支持，通过 TCP 协议与内置键值数据库交互，整体进展顺利。
- **memstore**：内存后端用于基准测试和集群性能验证。

### Erasure Coding

- **本地可修复代码（LRC）**：提出将数据块映射委托给 EC 插件的方案，通过在 RCode 配置文件中添加 `layers` 键实现分层编码，可避免跨机架数据传输，节省带宽。详见 [CDS_G_H_Day_1_-_OSD_-_Locally_Repairable_Codes](/VideoSummary/2014/06/24/CDS_G_H_Day_1_-_OSD_-_Locally_Repairable_Codes/)。
- **ISA 插件**：Andreas 实现了基于 Intel CPU 的 ISA 插件原型，性能优于 Jerasure，正在解决静态库/共享库打包问题。详见 [CDS_G_H_Day_1_-_Erasure_Coding_Update](/VideoSummary/2014/06/24/CDS_G_H_Day_1_-_Erasure_Coding_Update/)。
- **通用 AR 配置文件支持**：提交了 pending PR，支持为 QA、LRC 等不同参数变体定义配置文件。

### RBD

- **异步复制与日志记录**：设计了基于日志文件（通过 Raft 对象条带化存储）的异步复制方案，支持跨数据中心/集群的近实时数据复制，镜像代理架构正在设计中。详见 [CDS_G_H_Day_1_-_RBD_review](/VideoSummary/2014/06/24/CDS_G_H_Day_1_-_RBD_review/)。
- **对象索引（Object Map）**：引入位图（bitmap）记录 RBD 镜像中对象的存在状态，可加速空间分析、镜像删除、克隆等操作，并讨论了多客户端共享写入场景下的一致性保障。详见 [CDS_G_H_Day_2_-_RBD_-_Shared_flag_object_map](/VideoSummary/2014/06/26/CDS_G_H_Day_2_-_RBD_-_Shared_flag_object_map/)。
- **数据库工作负载优化**：针对 PostgreSQL、MySQL 等数据库在 RBD 上的性能问题，讨论了 striping 策略调整、WAL 独立存储、RBD 缓存等优化方案。详见 [CDS_G_H_Day_2_-_RBD_-_Database_Performance](/VideoSummary/2014/06/26/CDS_G_H_Day_2_-_RBD_-_Database_Performance/)。
- **RBD discard 功能**：接近完成，仍在进行测试修复。

### CephFS

- **多 CephFS 实例支持**：讨论了在单个 RADOS 集群中运行多个 CephFS 文件系统的两种方案：多 MDS 映射方案和目录语法糖方案，重点关注安全隔离需求。详见 [CDS_G_H_Day_2_-_CephFS_-_security_multiple_instances_in_a_single_RADOS_cluster](/VideoSummary/2014/06/26/CDS_G_H_Day_2_-_CephFS_-_security_multiple_instances_in_a_single_RADOS_cluster/)。
- **文件创建与对象级回溯优化**：针对回溯信息（backtrace）写入导致 OSD 负载过重的问题，讨论了异步文件创建和将回溯信息存储至数据池/键值存储的方案。详见 [CDS_G_H_Day_2_-_CephFS_-_file_creation_object-level_backtraces](/VideoSummary/2014/06/26/CDS_G_H_Day_2_-_CephFS_-_file_creation_object-level_backtraces/)。

### RGW

- **Bucket Index 分片扩展**：针对单个 bucket index 对象仅能支持 10-20 RPS 的瓶颈，提出了 bucket index 分片方案，允许在创建 bucket 时指定分片数量，并讨论了无序列表操作以降低系统负载。详见 [CDS_G_H_Day_2_-_RGW_-_bucket_index_scalability](/VideoSummary/2014/06/26/CDS_G_H_Day_2_-_RGW_-_bucket_index_scalability/)。

### Monitor

- **I/O 异步化**：针对 Monitor 单线程处理消息时 I/O 操作阻塞其他消息的问题，提出将 I/O 操作异步化、引入 Work Queue 工作线程的方案，并讨论了读写锁保护状态信息。详见 [CDS_G_H_Day_1_-_MON_-_dispatch_messages_while_waiting_for_IOto_complete](/VideoSummary/2014/06/24/CDS_G_H_Day_1_-_MON_-_dispatch_messages_while_waiting_for_IO_to_complete/)。

### OSD 运维

- **Scrub/Repair 改进**：提出在 Scrub PG 时将不一致性信息记录到 LevelDB，并增加查询和修复接口，支持自动修复策略。详见 [CDS_G_H_Day_1_-_OSD_-_Scrub_Repair](/VideoSummary/2014/06/24/CDS_G_H_Day_1_-_OSD_-_Scrub_Repair/)。
- **Scrub/SnapTrim IO 优先级**：讨论了通过独立线程池、内核 IO 优先级机制和令牌桶机制降低后台任务对客户端 IO 的影响。详见 [CDS_G_H_Day_1_-_OSD_-_Scrub_SnapTrim_IO_Prioritization](/VideoSummary/2014/06/24/CDS_G_H_Day_1_-_OSD_-_Scrub_SnapTrim_IO_Prioritization/)。

### 网络与性能

- **RDMA 更新**：Firefly 升级后性能已恢复至 Emperor 水平并有所提升，讨论了单消息传递器、通道支持和混合协议（IPv4/IPv6）访问方案。详见 [CDS_G_H_Day_1_-_RDMA_Update](/VideoSummary/2014/06/24/CDS_G_H_Day_1_-_RDMA_Update/)。
- **SystemTap/LTTng 静态追踪点**：两条并行路径同步推进——集成 lttng 和通过 ops 路径收集操作详细信息，目标是将 OSD 中每个 mutex 的获取与操作关联，支持性能瓶颈分析。详见 [CDS_G_H_Day_2_-_Systemtap_LTTng_static_markers_update](/VideoSummary/2014/06/26/CDS_G_H_Day_2_-_Systemtap_LTTng_static_markers_update/)。

### 构建系统

- **CMake 迁移**：CMake 构建系统已合并到 Firefly 分支并添加了测试，计划合并到 master 分支，通过减少重复构建对象显著提升多核机器上的构建速度。详见 [CDS_G_H_Day_1_-_CMake_Update](/VideoSummary/2014/06/24/CDS_G_H_Day_1_-_CMake_Update/)。

### 冷存储

- **Cold Storage Pools**：讨论了通过 PG 温映射（warm mapping）、PG 强制映射和 Silo 架构实现数据写入后几乎不移动的冷存储池方案，适用于介于磁带和活跃数据之间的存储层。详见 [CDS_G_H_Day_1_-_Cold_Storage_Pools](/VideoSummary/2014/06/24/CDS_G_H_Day_1_-_Cold_Storage_Pools/)。

## 3. 重要决策与里程碑

- **发布周期讨论**：社区对发布节奏进行了深入讨论。过去采用每季度命名版本（两个月编码 + 一个月 QA），Firefly 版本因新功能集成挑战导致时间表延迟。社区正在讨论是否转向定期发布、优先稳定现有功能的策略，该议题将在邮件列表上继续讨论。详见 [CDS_G_H_Day_1_-_librados_review](/VideoSummary/2014/06/24/CDS_G_H_Day_1_-_librados_review/)。
- **技术领导角色引入**：社区决定引入技术领导（Tech Lead）角色，负责代码审查、优先级排序和项目方向，明确了 Sam Jess、Josh Durkin、Yehuda、Greg 等关键人员的职责。
- **CMake 合并到 master**：确认将 CMake 构建系统合并到 master 分支，标志着构建系统现代化的重要里程碑。
- **Calamari CRUSH 管理**：将 CRUSH Map 的 CRUD 操作列为高优先级功能，以支持 Erasure Code 池和 Cache Tiering 特性。详见 [CDS_G_H_Day_1_-_Calamari_Development](/VideoSummary/2014/06/24/CDS_G_H_Day_1_-_Calamari_Development/)。
- **librados 内部线程模型改进**：确认推进 librados 内部线程模型更改以提高 IOPS，以及并行读取以减少延迟。

## 4. 社区动态

- **Ceph Developer Summit（CDS）举办**：本季度举办了为期两天的 CDS，涵盖 OSD、RBD、CephFS、RGW、Monitor、Calamari、CI 等几乎所有子系统的专题讨论，参与者包括 Sage、Zach、Josh、Greg、Yehuda 等核心开发者及来自 HGST、IntelYahoo 等公司的贡献者。
- **Calamari 本地化**：启动了 Calamari 界面的中文本地化工作，使用 Gettext 工具，由社区成员协作完成界面截图标注和翻译。详见 [CDS_G_H_Day_2_-_Calamari_Localization](/VideoSummary/2014/06/26/CDS_G_H_Day_2_-_Calamari_Localization/)。
- **Wiki 与社区资源整合**：讨论了 Ceph 社区 Wiki 页面的重建方案，计划整合演讲者信息、事件日历、硬件兼容性指南、路线图、Chum Bucket/Paper Cuts 等资源，并推动学术推广活动。详见 [CDS_G_H_Day_1_-_WikiIA](/VideoSummary/2014/06/24/CDS_G_H_Day_1_-_Wiki_IA/)。
- **Google Summer of Code**：Veronica 参与了 GSoC 项目，负责 Erasure Coding 可靠性模型的研究与实现。
- **社区参与渠道**：通过邮件列表（ceph-dev、calamari-dev、packaging-maintainers）、IRC（irc.otc.net）和 GitHub PR 进行开发协作，feature tracker 用于工作机会发现和 bug 报告。
- **Ink Scope 合作**：讨论了社区项目 Ink Scope 与 Calamari 的合作可能性，鼓励社区成员参与 UI 开发。

---

## 5. 下季度展望

基于本季度讨论内容，预计 2014Q3 将重点推进以下方向：

1. **RocksDB 后端正式合并**：RocksDB OSD 后端已接近完成，预计将合并到主分支并开始生产验证。
2. **RBD 异步复制落地**：日志记录机制和镜像代理架构设计完成后，将进入实现阶段，推动跨数据中心复制能力。
3. **RBD Object Map实现**：位图对象索引方案设计已基本确定，将进入开发和测试阶段。
4. **Erasure Coding LRC 与 ISA 插件**：本地可修复代码提案和 ISA 插件的打包问题解决后，将推进集成工作。
5. **RGW Bucket Index 分片**：Duong 将提交分片方案的 PR，推动 RGW 在高并发场景下的扩展能力。
6. **CephFS 多实例支持**：收集用户用例后，将确定多 CephFS 实例的实现方案并开始开发。
7. **CI 流程改进**：Teuthology 队列/锁定机制迁移到 Padles 服务，建立类似 Linux Next 的每晚集成分支，引入 Jenkins/Travis CI 自动化测试反馈。
8. **发布策略确定**：社区将在邮件列表上完成发布周期讨论，确定是否转向定期发布模式。
9. **Monitor I/O 异步化**：完成代码实现并进行性能测试，评估提升效果。
10. **Calamari CRUSH 管理功能**：作为高优先级功能，预计将在下季度完成开发并集成到 Calamari REST API。
