# Ceph 社区季度进展报告 · 2019 Q2

## 1. 本季度重点议题

### Nautilus 版本发布与稳定化
本季度最核心的主线是 Nautilus 版本的发布与后续稳定工作。从 Q1 末的 RC阶段，到 Q2 初正式发布，再到 1.0.1/1.0.2 补丁版本修复升级兼容性问题，Nautilus 贯穿了整个季度的讨论。详见 [2019-03-11_-_-_Ceph_Orchestration_Meeting](2019-03-11_-_Ceph_Orchestration_Meeting) 和 [2019-04-15_-_-_Ceph_Orchestration_Meeting](2019-04-15_-_Ceph_Orchestration_Meeting)。

### Crimson/SeaStar OSD 性能研究
Crimson 新一代 OSD 的开发是本季度技术投入最密集的方向，每周均有专项会议跟进。核心目标是基于 SeaStar 异步框架构建高性能 OSD，替代经典 OSD 的线程模型。详见 [2019-04-02_-_-_Crimson_SeaStor_OSD_Weekly_Meeting](/VideoSummary/2019/04/09/2019-04-02_-_-_Crimson_SeaStor_OSD_Weekly_Meeting/)。

### Orchestrator 框架统一化
如何在 Rook、DepSea、Ansible、SSH 等多种部署后端之上建立统一的 Orchestrator 抽象层，是本季度 Orchestrator 会议的持续主题。详见 [2019-03-27_-_-_Ceph_Orchestration_Meeting](/VideoSummary/2019/04/09/2019-03-27_-_-_Ceph_Orchestration_Meeting/)。

### 升级/降级策略与测试
随着 Nautilus 发布，跨版本升级（Mimic → Nautilus）和降级策略的测试成为重点，涉及功能标志兼容性、数据格式向后兼容等问题。详见 [2019-06-05_-_-_Ceph_Developer_Monthly_part_2](/VideoSummary/2019/06/07/2019-06-05_-_-_Ceph_Developer_Monthly_part_2/) 和 [2019-06-12_-_-_Ceph_Testing_Weekly](2019-06-12_-_Ceph_Testing_Weekly)。

### BlueStore 与 RocksDB 性能优化
BlueStore 缓存策略、RocksDB 列族分割、写放大优化等持续在性能会议中讨论，是存储后端的核心优化方向。

## 2. 技术亮点

### Crimson OSD 早期性能数据
[2019-04-02_-_Crimson_SeaStor_OSD_Weekly_Meeting](/VideoSummary/2019/04/09/2019-04-02_-_-_Crimson_SeaStor_OSD_Weekly_Meeting/) 中首次披露了 Crimson 与经典 OSD 的对比数据：4K 随机读取场景下 Crimson 性能提升约 50%–60%，但大块数据场景仍有差距。性能瓶颈定位在 CPU 前端指令缓存命中率不足，以及日志记录开销。

### RocksDB 列族分割优化
[2019-04-18_-_-_Ceph_Performance_meeting](/VideoSummary/2019/04/22/2019-04-18_-_-_Ceph_Performance_meeting/) 中 Adam 的测试表明，将 RocksDB 数据库分割为多个列族可带来最高 29% 的性能提升，主要来自减少写前锁竞争和降低数据移动开销。

### RGW 多站点代码走查
[2019-05-24_-_-_Ceph_CodeWalkthrough_-_RGW_Multisite_Replication](/VideoSummary/2019/05/24/2019-05-24_-_-_Ceph_Code_Walkthrough_-_RGW_Multisite_Replication/) 系统介绍了基于日志的多站点复制架构，包括元数据日志、桶索引日志、数据更改日志三类日志的分片机制，以及基于协程（co-routines）的并发同步框架。元数据同步采用主 Zone 单向同步，数据同步采用主动-主动模式。

### RGW 请求工作流代码走查
[2019-04-25_-_-_Ceph_Code_Walkthrough_-_RGW_Request_Workflow](/VideoSummary/2019/04/25/2019-04-25_-_-_Ceph_Code_Walkthrough_-_RGW_Request_Workflow/) 为新 RGW 开发者系统梳理了前端服务器（CivetWeb/Beast）、认证引擎、操作处理、对象布局等子系统的完整请求链路。

### BlueStore 双重缓存问题识别
[2019-04-11_-_-_Ceph_Performance_meeting](/VideoSummary/2019/04/12/2019-04-11_-_-_Ceph_Performance_meeting/) 中明确指出 BlueStore 节点存在 RocksDB block cache 与 BlueStore 自身缓存的双重缓存问题，建议对 BlueStore 节点禁用 RocksDB block cache。

### Monitor 选举策略改进
[2019-05-01_-_-_Ceph_Developer_Meeting](/VideoSummary/2019/05/13/2019-05-01_-_-_Ceph_Developer_Meeting/) 讨论了基于连接数量、延迟和可靠性评分的新 Monitor 选举策略，以应对多数据中心网络分区场景，通过 iptables 模拟网络故障进行验证。

### OSD 自动错误修复
[2019-03-07_-_-_Ceph_Developer_Meeting](/VideoSummary/2019/04/15/2019-03-07_-_-_Ceph_Developer_Meeting/) 讨论了为副本池实现自动 scrub 修复的方案，包括在 OSD 超级块中维护修复统计、新增 PG 状态标志表示修复失败，以及根据修复结果调整健康告警级别。

### Crimson Pering 功能合并
[2019-06-04_-_-_Crimson_SeaStor_OSD_Weekly_Meeting](/VideoSummary/2019/06/07/2019-06-04_-_-_Crimson_SeaStor_OSD_Weekly_Meeting/) 中 Crimson pering 功能完成合并，可以启动多个 OSD 并执行 PG 创建、pool 拉取等基础操作，下一步推进基于日志的恢复（log-based recovery）。

### RBD 云迁移与快照调度
[2019-06-05_-_-_Ceph_Developer_Monthly_part_1](/VideoSummary/2019/06/07/2019-06-05_-_-_Ceph_Developer_Monthly_part_1/) 讨论了 RBD 跨集群实时迁移的改进方案，以及基于子目录的 CephFS 快照调度（含定时快照和保留策略），并探讨了灾难恢复模式的设计。

## 3. 重要决策与里程碑

### Nautilus 正式发布
本季度最重要的里程碑。Nautilus 在 Q2 初正式发布，随后因主机网络升级兼容性问题（0.9 → 1.0 升级路径）快速推出 Rook 1.0.1 补丁版本。详见 [2019-05-13_-_-_Ceph_Orchestration_Meeting](2019-05-13_-_Ceph_Orchestration_Meeting)。

### Rook 1.0.0 发布
[2019-04-29_-_-_CephOrchestration_Meeting](/VideoSummary/2019/05/13/2019-04-29_-_-_Ceph_Orchestration_Meeting/) 确认 Rook 1.0.0 代码层面无阻塞问题，新官网同步上线。这是 Rook 项目的重要里程碑，标志着其进入生产就绪阶段。

### Python 2.7 → Python 3 迁移决策
[2019-02-27_-_-_Ceph_Testing_meeting](/VideoSummary/2019/04/16/2019-02-27_-_-_Ceph_Testing_meeting/) 确定使用 Alfredo 的补丁推进 Python 3 迁移，计划在 Nautilus 版本发布后合并，为后续版本的 Python 2 EOL 做准备。

### 默认平衡器模式变更
[2019-03-07_-_-_Ceph_Developer_Meeting](/VideoSummary/2019/04/15/2019-03-07_-_-_Ceph_Developer_Meeting/) 决定将新 OSD 的默认平衡器模式设置为 CrushCompat 模式，新加入的 OSD 从零权重开始逐步增加，避免数据迁移冲击。

### 升级降级策略明确化
[2019-06-05_-_-_Ceph_Developer_Monthly_part_2](/VideoSummary/2019/06/07/2019-06-05_-_-_Ceph_Developer_Monthly_part_2/) 确定在特定版本系列中明确不支持降级，并要求在发布说明中显式标注，同时建立自动化测试套件检测向后兼容性。

### 日志记录默认方式变更
[2019-05-02_-_-_Ceph_Performance_meeting](/VideoSummary/2019/05/28/2019-05-02_-_-_Ceph_Performance_meeting/) 确认在 master 分支将日志记录默认方式从 `dout` 更改为 `lttng`，以减少字符串格式化开销，在 NVMe 大 I/O 场景下性能提升显著。

## 5. 下季度展望

基于本季度讨论内容，预计 2019 Q3 的重点方向包括：

**Crimson OSD 功能完善**：本季度完成了 pering 基础功能，下季度预计推进基于日志的恢复（log-based recovery）、复制支持（replication）、对象类（object class）支持，以及与 BlueStore 的集成。性能测试将纳入 CI 自动化流程。

**Orchestrator 接口稳定化**：解决不同 Orchestrator 后端（Rook、DeepSea、Ansible、SSH）之间的 API 不一致问题，推进 Dashboard 与 Orchestrator 的深度集成，完善 TLS 支持。

**RGW 性能与多站点改进**：Beast 前端异步重构、QoS 多站点支持、无序 bucket listing 性能优化等 PR 预计在下季度落地。

**BlueStore/RocksDB 优化落地**：RocksDB 列族分割、双重缓存修复、新位图分配器等优化 PR 预计完成测试并合并。

**升级/降级测试体系建立**：基于 Nautilus 点版本建立系统化的升级降级测试套件，为 Octopus 版本的兼容性保障奠定基础。

**Python 3 迁移推进**：随着 Python 2.7 EOL 临近，预计在 Octopus 开发周期中加速完成各模块的 Python 3 迁移。
