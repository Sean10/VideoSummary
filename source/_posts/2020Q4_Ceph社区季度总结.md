# Ceph 社区季度进展报告 — 2020 Q4

---

## 1. 本季度重点议题

本季度 Ceph 社区围绕以下几个方向持续深入讨论：

**Crimson/SeaStar OSD 的持续演进**
Crimson 项目是本季度最活跃的技术方向，贯穿整个季度的多次周会。核心议题包括 interuptible future 设计、对象上下文锁定（object context locking）、EIO 错误处理、多核支持以及新硬件（NVMe over Fabric、Optane 内存）的适配。详见 [Ceph_Crimson_SeaStor_OSD_2020-10-06](/VideoSummary/2020/10/07/Ceph_Crimson_SeaStor_OSD_2020-10-06/)、[Ceph_Crimson_SeaStor_OSD_2020-10-28](/VideoSummary/2020/11/03/Ceph_Crimson_SeaStor_OSD_2020-10-28/)、[Ceph_Crimson_SeaStor_OSD_2020-11-11](/VideoSummary/2020/11/24/Ceph_Crimson_SeaStor_OSD_2020-11-11/)。

**BlueStore 与 RocksDB 性能优化**
PG 日志条目的存储和回收、RocksDB 动态级别调整、内存碎片化管理等问题在性能会议中反复出现，是本季度性能团队的核心攻坚方向。

**大规模对象存储验证**
10 亿级对象规模测试成为本季度的重要里程碑，为社区提供了实际部署的性能基准和最佳实践参考。

**文档体系建设**
Docubetter 工作组持续推进文档质量改善，重点围绕 Pacific 版本发布前的文档完整性准备。

**用户调查问卷迭代**
User Survey工作组在本季度连续召开三次会议，对调查问卷进行系统性修订，为社区反馈收集做准备。

---

## 2. 技术亮点

### RBD I/O 路径深度解析

Jason Dillman 主导了一次 LibRBD I/O 流程的代码走读，系统梳理了从 librbd API 到 OSD 的完整请求路径，涵盖 I/O 分发层（排队、QoS、独占锁、缓存、加密、日志等子组件）的分层架构。这是面向新贡献者的重要知识传递活动。详见 [Ceph_Code_Walkthrough_-_LibRBD_I_O_Flow_Pt._1_2020-10-27](/VideoSummary/2020/11/02/Ceph_Code_Walkthrough_-_LibRBD_I_O_Flow_Pt._1_2020-10-27/)。

### Crimson 关键技术突破

- **Interruptible Future**：完成设计审查并提交 PR，解决了中断条件在 `safe_then` 调用时的正确性问题
- **GridLock 对象上下文锁定**：对 object context locking 进行重构，采用 GridLock 机制，草稿 PR 已提交审查
- **Journal 改进**：引入基于 UUID 的 nonce 改进段管理，实施 checksum 增强原子性，优化段滚动机制
- **NBD 服务器实现**：为测试目的实现了简单的 NBD 服务器，将 I/O 操作直接传递给事务管理器
- **多核 Crimson**：提出并开始规划多核支持，以提升并行处理能力

详见 [Ceph_Crimson_SeaStor_OSD_Weekly_2020-11-04](/VideoSummary/2020/11/16/Ceph_Crimson_SeaStor_OSD_Weekly_2020-11-04/) 和 [Ceph_Crimson_SeaStor_OSD_2020-11-11](/VideoSummary/2020/11/24/Ceph_Crimson_SeaStor_OSD_2020-11-11/)。

### 性能优化进展

- **PG 日志回收原型**：Gaby 开发了 PG 日志条目键回收原型，初步测试揭示了对 RocksDB 压缩的影响，团队同步研究 MyRocks 实现作为参考
- **BlueStore 动态层级**：RocksDB 动态级别调整 PR 持续推进，正在收集性能数据
- **缓存分桶（Cache Age Bucketing）**：大部分代码已合并，内存碎片化 bug 得到修复
- **PG 自动缩放算法改进**：讨论并同意改进算法，避免初始安装时的频繁数据移动
- **MClock 调度器**：Sridhar 分享了最新测试结果，发现单 shard 和 16 线程配置下存在性能问题，需进一步调查

详见 [Ceph_Performance_Meeting_2020-10-01](/VideoSummary/2020/10/01/Ceph_Performance_Meeting_2020-10-01/)、[Ceph_Performance_Meeting_2020-10-29](/VideoSummary/2020/11/03/Ceph_Performance_Meeting_2020-10-29/)、[Ceph_Performance_Meeting_2020-11-12](/VideoSummary/2020/11/24/Ceph_Performance_Meeting_2020-11-12/)。

### 高效追踪系统设计

Developer Monthly 会议讨论了一个新的高效追踪系统设计方案，目标是解决现有日志系统数据量大、动态添加追踪点需重新编译等局限性。设计要点包括无锁操作、双缓冲技术、在线过滤器支持，并考虑与 Jaeger 等工具集成。详见 [Ceph_Developer_Monthly_2020-10-07](/VideoSummary/2020/10/10/Ceph_Developer_Monthly_2020-10-07/)。

### Replicated Writeback Cache (RWC)

Developer Monthly 11 月会议介绍了基于持久内存的 Replicated Writeback Cache 项目，第一阶段（单副本缓存）已完成，第二阶段将实现跨设备数据复制。详见 [Ceph_Developer_Monthly_2020-11-04](/VideoSummary/2020/11/17/Ceph_Developer_Monthly_2020-11-04/)。

### 10 亿对象规模测试

Red Hat 的Karan Singh 分享了 Ceph 对象存储处理超过 10 亿个对象的规模测试结果。测试环境为 6 个存储节点（每节点 53 个16TB 旋转设备 + 6 个 Intel QLC 3.9 NVMe），运行 Red Hat Ceph Storage 4.1，所有守护进程容器化部署。测试验证了系统在大规模场景下的稳定性，并给出了关键配置建议：推荐 4% 闪存容量作为 BlueStore 元数据存储，增大 OSD 内存目标。详见 [Ceph_Tech_Talk_-_Karan_Singh_-_Scale_TestingCeph_with_10Billion+_Objects_2020-10-01](/VideoSummary/2020/10/02/Ceph_Tech_Talk_-_Karan_Singh_-_Scale_Testing_Ceph_with_10Billion+_Objects_2020-10-01/)。

## 3. 重要决策与里程碑

**Rook Manager Module 定位讨论**
Orchestrator 会议讨论了 Rook Manager Module 的维护状态和优先级。当前资源主要集中在 cephadm（FDM），该模块未默认启用，存在多个已知 bug 且缺乏测试。会议决定需进一步明确使用场景，并加强与 Rook 和 cephadm 的集成测试。详见 [Ceph_Orchestrator_Meeting_2020-10-05](/VideoSummary/2020/10/06/Ceph_Orchestrator_Meeting_2020-10-05/)。

**cephadm 高可用性实施**
Orchestrator 会议确认了 cephadm 代理高可用性部署方案的实施推进，并强调了配套文档的重要性。详见 [Ceph_Orchestrator_Meeting_2020-10-26](/VideoSummary/2020/10/26/Ceph_Orchestrator_Meeting_2020-10-26/)。

**文档 Signed-off-by 要求调整**
Docubetter 工作组决定不再要求 doc 目录内的提交必须包含 `Signed-off-by` 标签，以避免通过 GitHub Web界面提交的文档更改被阻塞，降低文档贡献门槛。详见 [Ceph_Docubetter_Meeting_2020-10-14](/VideoSummary/2020/10/14/Ceph_Docubetter_Meeting_2020-10-14/)。

**Manager 可扩展性问题确认**
Developer Monthly 会议正式确认了 Manager 在高负载下的性能瓶颈（Finisher 队列处理大量完成项导致延迟），制定了短期（减少 OSD 报告频率、优化数据处理）和长期（分解 Manager 模块）两条优化路线。详见 [Ceph_Developer_Monthly_2020-11-04](/VideoSummary/2020/11/17/Ceph_Developer_Monthly_2020-11-04/)。

**Dashboard 设计协作流程改进**
确定通过 Design Pull Request 方式将设计文档提交到开发仓库，改善设计团队与开发团队的协作效率。

## 4. 社区动态

**会议与工作组活跃度**
本季度各工作组保持高频会议节奏：
- Crimson/SeaStar OSD 周会持续进行，团队成员分布在不同时区（含加拿大）
- Performance Meeting 每两周一次，持续跟踪多个并行优化方向
- Docubetter 工作组专注于 Pacific 版本前的文档冲刺
- User Survey 工作组在11 月连续召开三次会议，系统修订调查问卷

**Science Working Group**
科学计算用户工作组在 11 月召开会议，讨论了生产环境中遇到的实际问题，包括 Nautilus 版本内存泄漏、Beast 协议稳定性、多 MDS 性能、BlueStore 配置优化等。会议决定下次会议推迟至明年一月。详见 [Ceph_Science_Working_Group_2020-11-25](/VideoSummary/2020/11/25/Ceph_Science_Working_Group_2020-11-25/)。

**用户调查问卷重启**
User Survey 工作组对2019 年版本的调查问卷进行了系统性修订，新增了 CPU 架构（含 AMD）、存储设备类型、备份方式等问题，并改善了问卷界面（进度指示器、问题分类）。计划通过邮件列表和社交媒体推广。详见 [Ceph_User_Survey_Working_Group_2020-11-05](/VideoSummary/2020/11/24/Ceph_User_Survey_Working_Group_2020-11-05/)、[Ceph_User_Survey_Working_Group_2020-11-12](/VideoSummary/2020/11/24/Ceph_User_Survey_Working_Group_2020-11-12/)、[Ceph_User_Survey_Working_Group_2020-11-25](/VideoSummary/2020/11/26/Ceph_User_Survey_Working_Group_2020-11-25/)。

**Tech Talk 系列**
本季度举办了面向社区的 Tech Talk，Karan Singh 分享了 10 亿对象规模测试的完整过程和结论，为企业用户提供了实际部署参考。

**性能测试基础设施建设**
Performance 团队计划为开发人员提供高性能专用测试机器，Gaby 和 Ronan 将成为首批使用者，同时讨论了基于 CBT 构建数据库模式来系统化存储和查询测试结果的方案。

## 5. 下季度展望

基于本季度的讨论内容，预计 2021 Q1 将重点推进以下方向：

**Crimson OSD 功能完善**
多核 Crimson 实现、interuptible future 的稳定化、SeaStar 磁盘后端性能基准测试，以及 NVMe over Fabric 和 Optane 持久内存的深度集成探索，将是 Crimson 团队的主要工作。

**BlueStore/RocksDB 性能优化落地**
PG 日志回收方案的最终选型（修改 RocksDB vs. 独立解决方案）、动态层级 PR 的合并、内存碎片化问题的系统性解决，预计将在下季度取得阶段性成果。

**MClock 调度器问题修复**
单 shard 和多线程配置下的性能异常需要深入调查，MClock 调度器的生产就绪性将是下季度的验证重点。

**Pacific 版本文档冲刺**
Docubetter 工作组将继续推进 Pacific 发布前的文档完整性工作，包括 RADOS 协议文档的核心部分完成、开发指南全面更新，以及 defio 与 docs.ceph.com 同步问题的自动化解决。

**用户调查发布与数据收集**
修订后的用户调查问卷预计在下季度正式发布，收集社区对 Ceph 功能使用情况、硬件配置和部署规模的最新数据，为产品路线图提供依据。

**Manager 可扩展性改进**
基于本季度确认的性能瓶颈，Manager 模块的分解和优化工作预计将进入实质性实施阶段。
