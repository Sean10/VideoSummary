# Ceph 社区季度进展报告 — 2018 Q3

---

## 1. 本季度重点议题

本季度 Ceph 社区的讨论高度集中在以下几个反复出现的技术方向：

**性能优化**是本季度最核心的主题，贯穿几乎所有 Performance Weekly 会议。重点包括 BlueStore 缓存调优、内存分配器优化、RocksDB 集成改进，以及 buferlist 的使用与重构。详见 [2018-07-12_Ceph_Performance_Weekly](/VideoSummary/2018/07/19/2018-07-12_Ceph_Performance_Weekly/)、[2018-08-09_Ceph_Performance_Weekly](/VideoSummary/2018/08/09/2018-08-09_Ceph_Performance_Weekly/)、[Ceph_Performance_Meeting_2018-09-06](/VideoSummary/2018/09/10/Ceph_Performance_Meeting_2018-09-06/)。

**测试基础设施现代化**是另一条主线，围绕 Teuthology 框架在容器化环境（Kubernetes/Rook）下的适配、OpenSUSE 支持、CI/CD 流程改进、以及 flake 检测服务的引入展开。详见 [2018-08-22_Ceph_Testing_Weekly](/VideoSummary/2018/08/23/2018-08-22_Ceph_Testing_Weekly/)、[Ceph_Testing_Weekly_2018-09-05](/VideoSummary/2018/09/06/Ceph_Testing_Weekly_2018-09-05/)、[Ceph_Testing_2018-09-19](/VideoSummary/2018/09/21/Ceph_Testing_2018-09-19/)。

**OSD 恢复机制改进**，特别是异步恢复（async recovery）的设计与实现，是本季度的重要架构议题。详见 [Ceph_code_walk-through_-_OSD_async_recovery](/VideoSummary/2018/07/31/Ceph_code_walk-through_-_OSD_async_recovery/)。

---

## 2. 技术亮点

### BlueStore 与存储性能

- **RocksDB LRU 缓存集成**：将 RocksDB 的 LRU 缓存集成到 Ceph 中，并修改了高优先级池的使用方式以优化缓存性能。同时探讨了回滚到 Luminous 版本的兼容性问题。详见 [2018-07-12_Ceph_Performance_Weekly](/VideoSummary/2018/07/19/2018-07-12_Ceph_Performance_Weekly/)。

- **动态 BlueStore 缓存调整**：通过分析 OSD 的堆内存（heap memory）与未映射内存（unmapped memory），实现对 BlueStore 缓存大小的动态调整，改善内存受限场景下的 OSD RSS 使用。

- **Tiny Writes 优化**：Igor提出并测试了 BlueStore 的 Tiny Writes 优化方案，将小对象直接存储在数据库中，并与 RocksDB compaction 负载进行了对比分析。详见 [2018-08-09_Ceph_Performance_Weekly](/VideoSummary/2018/08/09/2018-08-09_Ceph_Performance_Weekly/)。

- **Bind Cache（绑定缓存）**：实现了根据使用情况动态平衡缓存的 bind cache，测试结果与预期一致。详见 [2018-08-23_Ceph_Performance_Weekly](/VideoSummary/2018/08/23/2018-08-23_Ceph_Performance_Weekly/)。

### OSD 异步恢复

传统同步恢复会阻塞写操作，影响集群可用性。本季度对 OSD 异步恢复机制进行了深入的代码走读，涵盖：活跃 OSD 选择算法修改、写操作非阻塞处理、元数据更新策略，以及基于日志差异（log delta）和恢复成本的选择标准。详见 [Ceph_code_walk-through_-_OSD_async_recovery](/VideoSummary/2018/07/31/Ceph_code_walk-through_-_OSD_async_recovery/)。

### buferlist 重构

本季度多次讨论 bufferlist 的过度使用问题，包括内存碎片化、迭代器失效、缓存行争用等。提出了用 small vector 替换 standard list 的方案，并由 Braddock 负责清理 bufferlist 接口。同时探索了 SeaStar 缓冲区原语的引入，将原子引用计数改为非原子引用计数以降低开销。详见 [Ceph_Performance_Meeting_2018-09-06](/VideoSummary/2018/09/10/Ceph_Performance_Meeting_2018-09-06/)、[ceph_performance_2018-09-13](/VideoSummary/2018/09/14/ceph_performance_2018-09-13/)。

### EC 与RGW

- **EC Partial Stripe Reads**：新增 EC 部分条带读取功能，本季度进入审查阶段。
- **RGW Up Tracker优化**：对 RGW Up Tracker 进行了多项优化，部分已合并，部分仍在推进中。详见 [2018-08-09_Ceph_Performance_Weekly](/VideoSummary/2018/08/09/2018-08-09_Ceph_Performance_Weekly/)。

### 加密功能

Radek 推进了基于低级 AES 实现的加密功能，本季度完成单元测试，集群级别测试尚在进行中。详见 [2018-08-09_Ceph_Performance_Weekly](/VideoSummary/2018/08/09/2018-08-09_Ceph_Performance_Weekly/)、[ceph_performance_2018-09-13](/VideoSummary/2018/09/14/ceph_performance_2018-09-13/)。

### Messenger 协议

讨论了 Messenger 协议的优化方向及其对操作员接口的影响，并关注协议变更对用户的通知机制。详见 [2018-08-16_Ceph_Performance_Weekly](/VideoSummary/2018/09/06/2018-08-16_Ceph_Performance_Weekly/)。

### SeaStar 兼容性探索

Sage 开始研究 SeaStar 缓冲区实现与有编码/解码代码的兼容性，探索将 SeaStar 集成到 Ceph 以为现有 OSD 提供性能提升的可能性。详见 [2018-08-23_Ceph_Performance_Weekly](/VideoSummary/2018/08/23/2018-08-23_Ceph_Performance_Weekly/)。

### 新开发者代码走读

本季度举办了面向新开发者的 Ceph 源代码结构介绍，覆盖消息传递机制、对象存储后端、librados API、数据完整性保障（CRC/checksum）等核心模块。详见 [Code_walk-through_-_new_developers](/VideoSummary/2018/07/31/Code_walk-through_-_new_developers/)。

## 3. 重要决策与里程碑

- **PG/OSD 限制调整讨论**：讨论将 PG/OSD 默认限制从 200 提升至 600，以避免用户在大规模部署时遭遇过度使用和内存保护问题。详见 [2018-07-19_Ceph_Performance_Weekly](/VideoSummary/2018/07/19/2018-07-19_Ceph_Performance_Weekly/)。

- **存储池权限细粒度控制**：Developer Monthly 会议提出引入存储管理员与普通用户角色分离、存储池命名空间支持，实现租户级别的镜像隔离。详见 [2018-08-01_Ceph_Developer_Monthly](/VideoSummary/2018/08/03/2018-08-01_Ceph_Developer_Monthly/)。

- **Ceph CSI 迁移至 Manager模块**：决定将 Ceph CSI 客户端模块迁移到 Ceph Manager 模块，统一存储管理，并配套开发新的 CLI 工具和 REST API。

- **CephFS 卷/子卷命名规范**：确定将文件系统称为"卷（volume）"、子文件系统称为"子卷（subvolume）"，并支持多个文件系统共享相同数据池。

- **OSD PG 锁优化决策**：提出将 PG 锁从互斥锁（mutex）改为读写锁（read-write lock），并实现同步读取功能，以解决多并发操作下的性能瓶颈。

- **Teuthology 测试框架容器化适配**：决定在现有 Teuthology 框架基础上进行改进以支持容器化环境，而非重新开发，并开发通用接口以集成 Rook、OpenStack 等不同部署平台。详见 [2018-08-22_Ceph_Testing_Weekly](/VideoSummary/2018/08/23/2018-08-22_Ceph_Testing_Weekly/)。

- **Backfill 优化方案立项**：针对快速设备（NVMe）场景下的 Backfill 效率问题，立项研究布隆过滤器（Bloom Filter）和 Merkle 树方案，以减少数据传输量。详见 [2018-07-11_Ceph_Developer_Monthly](/VideoSummary/2018/07/19/2018-07-11_Ceph_Developer_Monthly/)。

## 4. 社区动态

### 会议与活动

- **Developer Monthly**：7月、8月各举行一次，覆盖权限控制、CSI、CephFS、MDS 性能分析等议题。
- **Performance Weekly**：本季度共举行约7次，是本季度最活跃的技术讨论渠道，参与者包括 Sage、Josh、Radek、Casey、Mark、Neha、Braddock 等核心贡献者。
- **Testing Weekly**：本季度共举行约5次，重点推进测试基础设施现代化。
- **Code Walk-through 系列**：本季度举办了两场代码走读，分别面向新开发者（Ceph 整体架构）和 OSD 异步恢复机制，有助于降低社区贡献门槛。详见 [2018-08-02_-Ceph_Code_walk-through_-_Intro_to_Teuthology_not_strictly_a_code_walkthrough](/VideoSummary/2018/08/03/2018-08-02_-_-_Ceph_Code_walk-through_-_Intro_to_Teuthology_not_strictly_a_code_walkthrough/)。

### 贡献者活动

- **实习生参与**：Pavani（实习生）在 Developer Monthly 上演示了 SOFI Fest Shell，获得社区积极反馈。
- **新成员融入**：Testing Weekly 持续推进 OpenSUSE 支持，Nathan 与 David Galloway 协作创建 Fog 镜像，体现了跨团队协作。
- **Red Hat 团队**：引入 flake 工具对 Ceph 代码库进行分析，并在 Testing Weekly 上分享成果。详见 [Ceph_Testing_Weekly_2018-09-05](/VideoSummary/2018/09/06/Ceph_Testing_Weekly_2018-09-05/)。

### 测试基础设施进展

- 引入基于机器学习的 **Flake 分析服务**，通过 REST API 上传测试数据，自动检测测试失败中的虚假阳性（false positive），显著提升测试可信度。详见 [Ceph_Testing_2018-09-19](/VideoSummary/2018/09/21/Ceph_Testing_2018-09-19/)。
- 推进 **Python 3兼容性**迁移，并改进 flake8 代码风格检查。详见 [Ceph_Testing_Weekly_2018-09-12](/VideoSummary/2018/09/12/Ceph_Testing_Weekly_2018-09-12/)。
- 解决测试任务超时（12小时）导致日志无法收集的问题，改进 teardown 流程。详见 [Ceph_Testing_Meeting_2018-09-26](/VideoSummary/2018/09/26/Ceph_Testing_Meeting_2018-09-26/)。

## 5. 下季度展望

基于本季度的讨论方向，预计 2018 Q4 将重点推进以下工作：

1. **buferlist 重构落地**：Braddock 主导的 bufferlist 接口清理和 small vector 替换工作将进入实质性实施阶段，SeaStar 缓冲区原语的集成探索也将继续深入。

2. **BlueStore Tiny Writes 合并**：Igor 的 Tiny Writes 优化经过本季度充分测试，预计将进入合并流程，重点验证 RocksDB compaction 负载下的实际表现。

3. **OSD 异步恢复正式合并**：异步恢复机制的代码走读已完成，后续将推进代码审查和合并，补充流程图文档。

4. **加密功能集群测试**：Radek 的 AES 加密功能完成单元测试后，将进入集群级别的集成测试阶段。

5. **Teuthology 容器化适配**：通用接口开发完成后，将推进与 Rook/Kubernetes 的集成测试，并在实验室部署 Kubernetes 集群用于测试隔离。

6. **Flake 分析服务推广**：将 Flake 分析服务推广至更多团队，并与 bug 追踪系统（JIRA）打通，形成完整的测试质量闭环。

7. **CephFS 卷管理与 CSI 迁移**：CephFS 卷/子卷命名规范确定后，配套的 CLI 工具和 REST API 开发将提上日程，CSI 向 Manager 模块的迁移也将持续推进。

8. **SeaStar 深度集成评估**：Sage 主导的 SeaStar 兼容性研究将进一步明确集成路径，为 Crimson OSD 的长期演进奠定基础。
