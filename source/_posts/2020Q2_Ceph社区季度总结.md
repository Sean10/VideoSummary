# Ceph 社区 2020Q2 季度进展报告

---

## 1. 本季度重点议题

本季度（2020年月至5月）Ceph 社区的讨论高度集中在以下几个方向：

**Crimson/SeaStor OSD 新引擎开发**
这是本季度最活跃的技术线。Crimson 团队持续推进基于 SeaStar 框架的新一代 OSD 实现，涵盖 B+ 树存储结构、事务管理层、PG log based recovery、对象类（CLS）支持、scrubing 重构等核心子系统。详见 [2020-02-04 Crimson 会议](2020-02-04_-_-Ceph_Crimson_Meeting)、[2020-05-12 Crimson/SeaStor 周会](/VideoSummary/2020/05/13/2020-05-12_-_-_Crimson_SeaStor_OSD_Weekly_Meeting/)。

**Orchestrator 与 cephadm 统一部署**
Orchestrator CLI 的规范化、cephadm 作为统一部署工具的确立、与 Rook 的集成测试，是 Orchestration 方向的核心议题。详见 [2020-05-11 Orchestration 会议](/VideoSummary/2020/05/12/2020-05-11_-_-_Ceph_Orchestration_Meeting/)。

**BlueStore 性能优化**
混合分配器（hybrid allocator）、延迟大写入（deferred big writes）、禁用 BlueFS 缓冲 I/O、RocksDB 升级等多项优化贯穿整个季度。详见 [CDS Pacific Performance 会议](/VideoSummary/2020/04/03/CDS_Pacific_-_Performance/)。

**Octopus 版本发布与 Pacific 规划**
Octopus 于 2020 年 3 月正式发布，本季度同步启动了 Pacific 版本的功能规划讨论。

**COVID-19 对社区的影响**
疫情导致线下开发者峰会取消或转为线上，多次会议中提及远程工作适应情况，是本季度特殊背景。

---

## 2. 技术亮点

### Crimson/SeaStor OSD

- **B+ 树存储引擎**：讨论并确定了自顶向下的分裂与合并策略，设计了 O 节点（固定大小 + 可变大小分离）的内部结构，实现了 LBA 树（逻辑块地址映射）和 FS 树的插入、分裂单元测试。详见 [2020-02-18 Crimson 会议](2020-02-18_-_Ceph_Crimson_Meeting)、[2020-04-21 Crimson 会议](/VideoSummary/2020/04/29/2020-04-21_-_-_Ceph_Crimson_Meeting/)。
- **事务管理层**：确立了避免显式锁定、依赖事务层处理并发的设计原则。
- **PG log based recovery**：Josh Anderson 完成手动测试并持续添加测试用例，详见 [2020-03-31 Crimson 会议](/VideoSummary/2020/04/03/2020-03-31_-_-_Ceph_Crimson_Meeting/)。
- **对象类（CLS）支持**：跟踪了 CLS 函数在 Crimson PG 后端的实现进展，详见 [2020-04-14 Crimson 会议](2020-04-14_-_Ceph_Crimson_Meeting)。
- **优雅关机（graceful shutdown）**：讨论了通过停止标志或注销调度器来防止进一步事件处理的实现方案，详见 [2020-05-12 Crimson/SeaStor 周会](2020-05-12_-_Crimson_SeaStor_OSD_Weekly_Meeting)。
- **SeaStar 单元测试框架**：讨论了简化基于 SeaStar reactor 的单元测试编写方式。

### BlueStore 与存储性能

- **混合分配器（hybrid allocator）**：Igor 提交并合并了基于 AVL 和位图的混合分配器 PR，同时合并了延迟大写入 PR，4K 最小分配单元切换回硬盘默认值。详见 [2020-04-16 Performance 会议](/VideoSummary/2020/04/29/2020-04-16_-_-_Ceph_Performance_Meeting/)。
- **禁用 BlueFS 缓冲 I/O**：发现 OSD 在缓存达到上限后触发内核交换导致性能骤降，决定默认禁用 BlueFS 缓冲 I/O，详见 [2020-03-26 Performance 会议](/VideoSummary/2020/04/03/2020-03-26_-_-_Ceph_Performance_Meeting/)。
- **RocksDB 升级**：讨论升级至 6.51 版本以获取数据损坏修复和迭代器性能改进，同时跟踪了升级后出现的数据损坏问题，详见 [2020-05-14 Performance 会议](/VideoSummary/2020/05/14/2020-05-14_-_-_Ceph_Performance_Meeting/)。
- **AVX2 编码优化**：提交了针对缓冲列表编码/解码的 AVX2 加速 PR，预期部分场景速度提升 2 倍，详见 [2020-05-21 Performance 会议](/VideoSummary/2020/05/21/2020-05-21_-_-_Ceph_Performance_Meeting/)。
- **管理器（Manager）性能**：发现 Manager 在 dump OSD stats 和 PG stats 时 CPU 占用过高，David Stockman 提交了优化 PR，详见 [2020-02-27 Performance 会议](/VideoSummary/2020/04/03/2020-02-27_-_-_Ceph_Performance_Meeting/)。

### Orchestrator 与部署

- **cephadm 确立为统一部署工具**：支持容器化部署，提供统一 CLI，集成到 Ceph Dashboard，使用 SSH 进行远程连接，详见 [2020-05-11 Orchestration 会议](/VideoSummary/2020/05/12/2020-05-11_-_-_Ceph_Orchestration_Meeting/)。
- **Orchestrator CLI 重构**：讨论统一 `service apply` 和 `daemon add` 命令，移除冗余参数，详见 [2020-05-18 Orchestration 会议](2020-05-18_-_Ceph_Orchestration_Meeting)。
- **OSD Remover 功能**：讨论了替换和重用 OSD ID 的需求与挑战，详见 [2020-03-16 Orchestration 会议](2020-03-16_-_Ceph_Orchestration_Meeting)。
- **Prometheus 监控高可用**：讨论了在多节点部署 Prometheus 并使用 HAProxy 负载均衡的方案，详见 [2020-04-20 Orchestration 会议](2020-04-20_-_Ceph_Orchestration_Meeting)。
- **Drive Groups设计**：确立了持久性和幂等性原则，讨论了 Rook 直接接受 Drive Groups 作为输入的集成方式，详见 [2020_02_03 Orchestration 会议](2020_02_03_-_Ceph_Orchestration_Meeting)。

### CephFS

- **多文件系统（Multi FS）与快照复制**：讨论了采用 arsenic 作为快照同步初始方案，创建新守护进程处理同步，详见 [CDS Pacific CephFS 会议](/VideoSummary/2020/04/02/CDS_Pacfic_-_CephFS/)。
- **多 MDS 前向扫描（Multi MDS Forward Scrub）**：确定采用冻结所有导出的方式实现。
- **FS top 功能**：持续推进 CLI 包装器编写。
- **MDS 性能**：IO 500 测试中发现 MDS 锁争用问题，讨论了改进锁机制的方向。

### 性能测试基础设施

- **性能 CI 建设**：讨论将 CBT（Ceph Benchmark Tool）集成到 Jenkins，实现自动化性能回归检测，详见 [2020-04-_23 Performance 会议](/VideoSummary/2020/04/29/2020-04-_23_-_-_Ceph_Performance_Meeting/)。
- **IO 500 基准测试**：Ceph 在 IO 500 排名从第 12 提升至第 9，开发了直接与 Loops FS 集成的后端，详见 [2020-03-12 Performance 会议](/VideoSummary/2020/04/03/2020-03-12_-_-_Ceph_Performance_Meeting/)。

## 3. 重要决策与里程碑

**Octopus（15.2）正式发布**
Octopus 于 2020 年 3 月发布，随后发布了 15.2.2 补丁版本，包含大量 bug 修复和文档改进。[2020-05-28 Tech Talk](/VideoSummary/2020/05/28/2020-05-28_-_-_Ceph_Tech_Talk_-_What_s_New_In_Octopus/) 对 Octopus 新特性进行了系统介绍，主要亮点包括：
- Orchestrator API 统一部署管理
- BlueStore 预取和压缩机制改进
- RBD 镜像基于快照的灾难恢复
- Ceph CSI 和 Rook 与 Kubernetes 集成增强

**Pacific 版本规划启动**
CDS（Ceph Developer Summit）Pacific 专题会议讨论了 BlueStore 性能路线图、CephFS 多文件系统、MDS 动态子树分区等方向，Pacific 预计 2021 年 3 月发布。详见 [CDS Pacific Performance](/VideoSummary/2020/04/03/CDS_Pacific_-_Performance/)、[CDS Pacific CephFS](/VideoSummary/2020/04/02/CDS_Pacfic_-_CephFS/)。

**Crimson 项目里程碑确认**
在 [2020-04-07 Crimson 会议](2020-04-07_-_Ceph_Crimson_Meeting) 中明确了 Crimson 在 Pacific 版本中的核心目标：速度和质量提升，snapshot 功能作为扩展目标而非核心需求。

**项目管理工具迁移**
Crimson 团队将项目卡片从 GitHub 迁移到 Trello（后提及 Carrillo），按里程碑分类管理，详见 [2020-03-31 Crimson 会议](/VideoSummary/2020/04/03/2020-03-31_-_-_Ceph_Crimson_Meeting/)。

**cephadm 作为官方部署工具确立**
本季度明确 cephadm 将取代 ceph-deploy 成为 Ceph 的统一部署工具，这是 Orchestration 方向的重要架构决策。

## 4. 社区动态

**开发者峰会（CDS）线上化**
受 COVID-19 影响，原定线下举行的开发者峰会改为线上进行，CDS Pacific 专题会议在本季度末举行，覆盖 CephFS、Performance 等多个方向。

**Ceph Tech Talk 系列**
[2020-05-28 Tech Talk](/VideoSummary/2020/05/28/2020-05-28_-_-_Ceph_Tech_Talk_-_What_s_New_In_Octopus/) 以线上形式举办，由 Red Hat 的 Josh Durgan 和 Sousa 的 Lance Kramer 主讲 Octopus 新特性，面向社区用户开放。

**Science User Group 会议**
[2020-03-25](2020-03-25_-_Ceph_Science_User_Group_Meeting) 和 [2020-05-27](/VideoSummary/2020/05/28/2020-05-27_-_-_Ceph_Science_User_Group_Meeting/) 举行了科学用户组会议，讨论了大型科研集群（Sanger Institute、Diamond Light Source、马里兰大学等）的实际使用经验，包括 Octopus 升级、MDS 崩溃处理、容器化部署等话题。下次会议预定 7 月 22 日。

**Docubetter 文档改进**
文档团队持续活跃，讨论了 PG 修复文档简化、`ceph df`/`ceph osd df` 命令文档更新、对象存储工具文档、网站搜索功能修复、readthedocs 迁移等议题。申请 Google Season of Docs 未获批准，但决定继续推进新手引导文档编写，详见 [2020-05-13 DocUBetter 会议](/VideoSummary/2020/05/13/2020-05-13_-_-_Ceph_DocUBetter_Meeting/)。

**Telemetry 推广**
[2020-02-05 Developer Monthly](/VideoSummary/2020/04/03/2020-02-05_-_-_Ceph_Developer_Monthly/) 中提出推动用户启用 telemetry 模块，目标达到 500-1000 个活跃集群上报数据。

**Rook 社区协作**
本季度 Rook 团队与 Ceph Orchestration 团队深度协作，包括 Python 客户端仓库迁移至 Rook 组织、建立针对 Rook PR 的 Orchestrator 集成测试等。

## 5. 下季度展望

基于本季度讨论，预计 2020Q3 的重点方向包括：

**Crimson/SeaStor OSD 持续推进**
B+ 树核心功能（插入、分裂、合并、垃圾回收、段恢复）将逐步完善，事务管理器和 LBA 管理器趋于可用，预计进入更系统的集成测试阶段。

**Pacific 版本功能开发**
BlueStore 的 column family sharding（Adam 的 PR）、cache age based bidding、node data structure瘦身等优化将进入实质开发；CephFS 快照复制守护进程、Multi MDS scrub 等功能将推进实现。

**cephadm 生产就绪**
Orchestrator CLI 重构完成后，cephadm 将进入更广泛的测试和用户验证阶段，Dashboard 集成、监控高可用方案将进一步完善。

**性能 CI 落地**
CBT + Jenkins 的性能回归检测框架预计在 Q3 正式投入使用，为 Pacific 开发提供持续的性能基线保障。

**RocksDB 数据损坏问题跟踪**
升级 RocksDB 6.5.1 后出现的数据损坏问题需要在 Q3 明确根因并修复，这是存储稳定性的优先事项。

**SMR 磁盘支持**
Octopus Tech Talk 中提及 Pacific 将引入新后端存储以支持 SMR 磁盘，相关设计讨论预计在 Q3 展开。
