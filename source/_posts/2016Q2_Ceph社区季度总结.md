# Ceph 社区季度进展报告 — 2016 Q2

---

## 1. 本季度重点议题

本季度 Ceph 社区的技术讨论高度集中在以下几个方向：

**BlueStore 存储后端**是本季度最核心的议题，贯穿多次会议。从架构设计到缓存策略，再到公开技术分享，BlueStore 的成熟度和落地路径是社区的首要关注点。详见 [2016-JUN-21 -- Ceph Tech Talks - Bluestore](/VideoSummary/2016/06/23/2016-JUN-21_--_Ceph_Tech_Talks_-_Bluestore/) 和 [2016-JUN-01 -- Ceph Developer Monthly](/VideoSummary/2016/06/02/2016-JUN-01_--_Ceph_Developer_Monthly/)。

**Messenger 2协议**作为 Ceph 网络层的下一代实现，在安全性（防降级攻击、签名机制）和协议协商设计上进行了深入讨论。

**性能基准测试体系**的建设也在本季度得到关注，CBT（Ceph Benchmarking Tool）作为社区标准化测试工具被正式介绍推广，详见 [2016-MAY-26 -- Ceph Tech Talks - Ceph Benchmarking Tool](/VideoSummary/2016/05/27/2016-MAY-26_--_Ceph_Tech_Talks_-_Ceph_Benchmarking_Tool/)。

## 2. 技术亮点

### BlueStore：新一代 OSD 存储后端

[2016-JUN-21 -- Ceph Tech Talks - Bluestore](/VideoSummary/2016/06/23/2016-JUN-21_--_Ceph_Tech_Talks_-_Bluestore/) 对 BlueStore 的架构做了系统性阐述：

- **动机**：传统 FileStore 依赖 POSIX 文件系统，存在双重日志开销（OSD journal + 文件系统 journal），且无法提供原子性事务，对象枚举效率低。
- **架构设计**：BlueStore 绕过文件系统，对象数据直接写入裸块设备，元数据通过 RocksDB 管理，配合自研的 BlueFS 为 RocksDB 提供轻量文件系统层。
- **核心能力**：原子性事务、高效对象枚举、内联压缩（inline compression）、数据校验和（checksum）、克隆（clone）支持。
- **演进路径**：Jewel 版本提供实验性支持，目标是在 Kraken 版本中成为默认存储后端。

### BlueStore 缓存设计

[2016-JUN-01 -- Ceph Developer Monthly](/VideoSummary/2016/06/02/2016-JUN-01_--_Ceph_Developer_Monthly/) 专项讨论了 BlueStore 的缓存子系统：

- **缓存结构选型**：对比了全局缓存、按 Collection 缓存、分片缓存三种方案，最终决定采用**分片缓存**（sharded cache），以提升多核并发性能，降低锁竞争。
- **替换算法选型**：对比 LRU 与 MultiQ 算法，决定采用 **MultiQ**（基于多级 LRU 队列，按数据热度分层），以提升缓存命中率，避免热点数据被意外驱逐。

### Messenger 2 协议安全增强

本季度对 Messenger v2 协议的安全机制进行了设计讨论：

- 在消息头中引入**签名（signature）**机制，防止消息篡改。
- 设计客户端与服务端的**协议版本和功能协商**流程，支持向后兼容。
- 针对**降级攻击（downgrade attack）**场景进行了专项讨论，确保协商过程中加密等安全特性不可被强制剥除。

### CBT：社区标准化基准测试框架

[2016-MAY-26 -- Ceph Tech Talks - Ceph Benchmarking Tool](/VideoSummary/2016/05/27/2016-MAY-26_--_Ceph_Tech_Talks_-_Ceph_Benchmarking_Tool/) 介绍了 CBT 的完整能力：

- 基于 Python，通过并行 SSH 驱动多客户端执行测试，支持 RBD（FIO）、CephFS（FIO）、对象存储（S3/Swift）等多种负载类型。
- 支持自动化集群部署、多配置对比测试、节点监控数据采集。
- 测试方法论包括网络基线测试（iperf）、微基准多次迭代建立标准差、客户端数量梯度扫描确定吞吐量上限。

## 3. 重要决策与里程碑

| 决策事项 | 详情 |
|---|
| BlueStore 缓存架构确定 | 采用分片缓存 + MultiQ 替换算法 |
| BlueStore 版本路线确认 | Jewel 实验性支持 → Kraken 默认后端 |
| Messenger v2 协议设计原则确定 | 消息头签名 + 功能协商 + 简洁协议设计 |
| CBT 作为社区标准测试工具推广 | 由 Mark Nelson 开发，本季度正式向社区推介 |

BlueStore 从"实验性功能"到"规划为默认后端"的路线确认，是本季度最重要的架构里程碑。

## 4. 社区动态

- **Ceph Developer Monthly**（6月）：开发者月会聚焦 BlueStore 缓存设计和 Messenger v2 协议，核心开发者参与了技术方案的决策讨论。
- **Ceph Tech Talks 系列**：本季度举办了两场公开技术分享：
  - 5月：[CBT 基准测试工具介绍](/VideoSummary/2016/05/27/2016-MAY-26_--_Ceph_Tech_Talks_-_Ceph_Benchmarking_Tool/)，主讲人 Kyle Bader，面向社区推广标准化测试方法论。
  - 6月：[BlueStore 技术深度解析](/VideoSummary/2016/06/23/2016-JUN-21_--_Ceph_Tech_Talks_-_Bluestore/)，主讲人 Sage，系统介绍新存储后端的设计动机与架构。
- **Calamari 项目**：会议中提及 Calamari（Ceph 管理平台）的后续方向，包括与 Seth Manager 的集成，但尚未形成明确决策。
- **CBT 社区建设**：CBT 项目正在招募更多开发者参与，并建立了邮件列表和 YouTube 频道作为社区沟通渠道。

## 5. 下季度展望

基于本季度的讨论内容，预计 2016 Q3 将重点推进以下方向：

1. **BlueStore 功能完善**：元数据编码效率优化、压缩与 checksum 功能打磨、池级别（pool-level）存储策略属性支持，以及 SMR 硬盘和 SPDK/NVMe 的适配工作。
2. **BlueStore 缓存实现落地**：分片缓存 + MultiQ 算法的代码实现与性能评估。
3. **Messenger v2 协议实现推进**：协议实现完善，以及性能与安全性的系统评估。
4. **ZetaScale 集成探索**：作为 RocksDB 的潜在替代方案，在 BlueStore 中进行评估。
5. **CBT 工具链改进**：错误修复、数据分析能力增强，为 BlueStore 性能测试提供更完善的工具支撑。
6. **Kraken 版本准备**：随着 BlueStore 路线确认，社区将逐步为 Kraken 版本的发布做准备。
